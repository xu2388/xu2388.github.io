# 服务器、训练与实验 · 长对话整理

## 一、背景与目标

本对话（500 条）围绕 HE→IHC 虚拟染色的浓度域扩散模型展开，兼含大量远程服务器训练运维记录。研究目标是以苏木素（H）、伊红（E）、二氨基联苯胺（DAB）的浓度图替代 RGB 图像作为扩散建模对象，由 HE 浓度图条件生成 IHC 的 DAB 浓度图，再经物理染色矩阵渲染为 IHC 的 RGB 图像。

核心研究问题被反复表述为一句可检验的命题：对于空间对应关系不完美的虚拟染色任务，通用扩散训练所采用的噪声水平分配是否仍然合适。该问题由一项前置观察驱动——HE 与连续切片 IHC 之间存在明显空间错位与组织形变，像素级跨图对应基本不可学，而 patch 级聚合统计量（均值、标准差、高浓度占比）仍保持中等强度相关。若"目标粒度上移"成立，则通用图像生成中"高噪声学结构、低噪声学细节"的分工假设在本任务上未必成立。

对话同时承担两项工程目标：在按小时计费的临时 GPU 实例上完成 4000 步训练与多轮诊断；在单卡 12 GB 显存的约束下，判断浓度域路线是否值得继续，以及能否支撑一篇贡献明确的论文。

## 二、主要内容

### （一）模型结构：两条并行路线

**M0：浓度域 DAB 扩散（主线）**

- 扩散状态为单通道 DAB 浓度，条件为 HE 的 H、E 两个浓度通道；训练输入按通道拼接为 `[z_t(DAB), C_H^HE, C_E^HE]`（3 通道），输出 1 通道 `v_DAB`。
- 网络为自建小型 UNet：`UNet2DModel(in_channels=3, out_channels=1)`，不依赖 Stable Diffusion 的 VAE，也不迁就其 RGB 三通道接口。
- 推理自 `z_T ~ N(0,1)` 出发，每步重新拼接当前 DAB 状态与两个 HE 条件，迭代得到 `C_DAB`；渲染时将 H 通道与生成的 DAB 组合为 `[C_H^HE, C_DAB]`，经 `M_IHC` 渲染为 RGB。此即 H-copy 基线，其前提 `C_H^HE ≈ C_H^IHC` 属待验证假设而非物理事实。

**Phikon-patch 条件扩散（对照与诊断对象）**

- 扩散状态为 IHC 的两个浓度通道 `[C_H^IHC, C_DAB^IHC]`；HE 信息不经通道拼接，而由 Phikon（ViT-B/16 病理特征提取器）提取后经 cross-attention 注入。
- 网络为 `UNet2DConditionModel`：`sample_size=128`、`in_channels=2`、`out_channels=2`、`layers_per_block=2`、`block_out_channels=(64,128,256,256)`、三层 CrossAttnDownBlock2D 加一层 DownBlock2D、`cross_attention_dim=768`、`attention_head_dim=8`、`norm_num_groups=32`，参数量 37.52 M。
- 训练目标为 v-prediction：`target_v = √ᾱ_t · ε − √(1−ᾱ_t) · C_0`。
- 数据由 `Stage1PatchDataset` 提供，返回 `cond = [C_H^HE, C_E^HE]` 与 `tgt = [C_H^IHC, C_DAB^IHC]`；训练集 217 166 个 patch，验证集 24 011 个。为复用 Phikon，需由 HE 浓度反推近似 RGB：`rgb = exp(−stack([c_h_he, c_e_he, 0]))`。

### （二）噪声调度的四类问题

对话首先完成概念澄清：文献中笼统称为"优化噪声调度"的做法实际分属四个层面，混为一谈会导致实验设计失效。

| 类别 | 变量 | 控制对象 | 典型方法 |
|---|---|---|---|
| 正向噪声调度 | `ᾱ_t`、`β_t` | 每步信号与噪声的比例 | 线性、余弦、sigmoid |
| 训练时间步采样 | `p(t)` | 各噪声水平被训练的频率 | 重要性采样、非均匀采样 |
| 损失加权 | `w(t)` | 各噪声水平对梯度的贡献 | P2、Min-SNR |
| 反向采样调度 | 步数、跳步、求解器 | 生成时如何遍历噪声水平 | DDIM、快速采样器、SDEdit |

两个关键区分被特别强调：时间步占比不等于噪声占比，第 700 步不意味着已加入 70% 的噪声，不同调度在同一时间步对应的信噪比可能相差一个数量级；改变 `p(t)` 若不作重要性权重修正，实际上是在改变优化目标而非提高采样效率。信噪比定义为 `SNR(t) = ᾱ_t / (1 − ᾱ_t)`，`log SNR = 0`（即 `SNR = 1`）为信号与噪声方差贡献相等的临界区。

### （三）代表性研究及其结论

- **余弦调度**（Improved DDPM，ICML 2021）：原始 DDPM 的 `β_t` 线性变化，但累计保留率 `ᾱ_t` 并非线性，后半段过早退化为近似纯噪声，大量时间步提供的信息很少。余弦调度直接设计 `ᾱ_t = f(t)/f(0)`、`f(t) = cos²((t/T+s)/(1+s)·π/2)`，使首尾平缓、中间衰减；启示是调度应依据信号实际被破坏的程度，而非均匀划分时间步。
- **P2 加权**（CVPR 2022）：不改正向过程，只重分配损失权重，`w_P2(t) = 1/(k + SNR(t))^γ`；出发点是低噪声阶段集中于细小的局部细节，其他噪声水平更能促使模型学习丰富的视觉内容与上下文。
- **Min-SNR**（ICCV 2023）：将不同时间步的去噪视为相互关联的多个优化任务，指出梯度可能冲突并拖慢收敛，据此按信噪比限制各时间步的有效权重，论文报告收敛速度最多提升约 3.4 倍（限于其特定实验条件）。
- **Improved Noise Schedule**（ICCV 2025）：主张提高 `log SNR ≈ 0` 区域的采样频率——此时数据既非近乎干净，也非近乎纯噪声，模型须同时利用残余信号并处理强扰动。此外，EDM（NeurIPS 2022）主张把噪声参数化、训练分布、预条件与采样拆为独立选择，自适应时间步（UAI 2024）则优化离散时间步位置以降低采样离散化误差。

### （四）DDIM 反演与"只加到 70%"的辨析

DDIM（ICLR 2021）构造了一类与 DDPM 训练目标相同、但可采用不同反向轨迹的过程，确定性采样下可逐步不重新注入随机噪声。反演则沿该轨迹的近似逆方向把已有图像映射到某个噪声状态，以支持后续编辑或重建。反演本身并不意味着选择了最优调度，也不证明必须反演到最高噪声水平；若改变了调度却沿用旧的反演轨迹，需格外谨慎。

"只加到 70%"有两种含义：**情况 A（推理／编辑）**指先加噪到中间时间步再从此去噪，如 SDEdit 与图生图流程，此处的 0.7 通常是 strength 参数，实际起始时间步取决于采样步数与调度；**情况 B（训练）**指把最大时间步限制在 `0.7T`，模型几乎未学习最低信噪比区间的去噪任务，若推理仍从纯噪声起步将出现训练—推理不匹配。截断噪声范围可作为独立实验，但须保证训练时见过的噪声水平与生成起点匹配；相较之下，保持完整信噪比覆盖、只调整采样概率是更干净的比较方式。

### （五）统一目标函数与三个设计变量

对话给出统一的训练目标：

```
L = E_{t~p(t), ε~N(0,I)} [ w(t) · ‖ ε − ε_θ(C_t, t, F_HE) ‖² ]
```

其中 `F_HE` 为 HE 图像提取的条件特征，`C_t` 为加噪后的目标浓度图，`p(t)` 为时间步抽样概率，`w(t)` 为损失权重。三个变量与三类研究思路一一对应：`ᾱ_t` 对应调度设计，`p(t)` 对应重要性采样，`w(t)` 对应损失加权，相互关联但不可随意互换。

### （六）实验环境与运维方式

- 平台为按小时计费的临时 GPU 实例（AutoDL／SeetaCloud），显存 12 288 MiB，经跳板域名 `connect.nmb2.seetacloud.com` 加非标准端口接入，密码认证。
- 实例特性：单次会话约 1 小时，到期自动关机；重启后端口与密码均变化，需从控制台重新获取。
- 本地未安装 `sshpass`，认证改由 `expect` 脚本完成，封装上传、启动、日志抓取与 scp 下载四类操作。

- 明确的操作约束：不得使用 timeout 与 sleep 等待，命令须立即返回或后台运行，该约束在对话中被多次重申。

### （七）时间步损失诊断

诊断目的为验证线性（或余弦）调度是否在早期时间步（`t < 200`）过于激进，导致低噪声水平下预测能力不足。脚本迭代五版，问题依次为：输出重定向失效；Phikon 从 Hugging Face 在线加载（实例无外网，报 `[Errno 101] Network is unreachable`）；UNet 从 Hub 下载（同样失败）；验证集目录 `val_he_patches`／`val_ihc_patches` 不存在。最终修正为：Phikon 改从远程实例上的本地模型目录读取（记作 `<本地模型目录>/phikon_model`）并设 `local_files_only=True`；UNet 按训练脚本构造参数从头实例化，再以 `safetensors.load_file` 载入 EMA 权重；数据改用 `Stage1PatchDataset("val")` 而非直接读图。

### （八）诊断结果的解读与假设修正

初版解读认为"模型在高噪声区学习困难，应改用线性调度以抬高 `t ≥ 700` 处的信噪比"。该解读随即被推翻：低噪声区损失低，部分源于像素级目标本身不可学（前置实验测得像素级跨图相关 `r ≈ 0`），损失下降并不代表学到有意义的结构；高噪声区损失高是扩散训练的常态，信号被噪声淹没时预测误差必然上升；更关键的是生成结果几乎退化为均值图，若高噪声区负责学习全局均值，则该区任务实际已完成。

修正后的判断是：真正承载条件信息学习的是 `log SNR ≈ 0` 的中等噪声区（本调度下约 `t = 300–600`），此区间模型需同时利用残余信号与强扰动，才能建立 HE 结构与 IHC 聚合统计之间的对应关系，故实验重点应从"改调度"转向"提高中等噪声区的采样概率或损失权重"。这一修正同时厘清了两类不同问题：不同时间步去噪任务之间的优化冲突（Min-SNR 所处理），与蛋白表达约束和去噪目标之间的冲突（前置工作中担忧的问题），二者不可混为同一命题。

### （九）Beta(2,2) 重采样实验

按上述判断，训练脚本第 156 行的时间步采样由均匀分布改为 Beta(2,2)：

```python
from torch.distributions import Beta
beta_dist = Beta(2.0, 2.0)
t_normalized = beta_dist.sample((b,)).to(dev)
t = (t_normalized * scheduler.config.num_train_timesteps).long().clamp(
    0, scheduler.config.num_train_timesteps - 1)
```

新脚本为 `train_phikon_patch_v1_snr1_focus.py`，启动命令：

```
nohup python3 train_phikon_patch_v1_snr1_focus.py \
  --phikon_path <本地模型目录>/phikon_model \
  --steps 4000 --save_every 1000 \
  --out runs/phikon_patch_v1_snr1 > train_v1_snr1.log 2>&1 &
```

基线设置不变：正向调度仍为 `squaredcos_cap_v2`（余弦），网络结构、数据与训练预算均保持，仅采样分布一项改动，以保证单因素对照。损失轨迹为：50 步 0.148 → 100 步 0.052 → 300 步 0.024 → 500–1000 步稳定于 0.013–0.016 → 1350 步 0.010；训练速度约每 50 步 45 秒，GPU 占用 9146 MiB，功耗由 232 W 升至 322–328 W，温度 71–73 ℃，利用率接近 100%。

值得注意的是，基线（均匀采样）4000 步终值约 0.015，而 Beta(2,2) 版本在 1000 步即达 0.0153、1350 步降至 0.010。损失下降更快符合预期——集中于中等噪声区意味着训练目标更"集中"，但这本身不能证明生成质量提升，须以聚合级指标与条件置换实验判定。

### （十）可视化产物与拼接方式

验证样本按固定格式横向三联：`np.concatenate([rgb_he, rgb_pred, rgb_gt], axis=1)`，从左至右为 HE 输入、生成的 IHC、真实 IHC，分别经 `M_HE` 与 `M_IHC` 染色矩阵渲染。已产出并下载的批次为 `val_step_0001000`（4 张，sample_00888／02814／07423／16232）与 `val_step_0002000`（4 张）。一次"更换样本"的额外生成请求因 checkpoint 键名不匹配（脚本读取 `unet_ema`，实际为 `ema`）失败，未产出独立批次；此后服务器失联，该批次始终未补。

### （十一）故障记录

对话后段约三分之二的消息为连接失败与重试，构成一份完整的运维清单：`Connection closed by 127.0.0.1 port 7890`（本地代理在认证前切断连接）、`port 18075: Connection refused`（实例关机或端口变更）、`[Errno 101] Network is unreachable`（实例无外网）、`KeyError: 'unet_ema'`（checkpoint 键名不符）、`unrecognized arguments`（实际参数为 `--steps` 与 `--out`），以及 `ENOTFOUND`、`Error 524`、`gpt-6-luna` 模型不可用等客户端故障。该阶段实质产出接近于零，暴露的问题是结构性的：临时实例的凭据轮换与长任务相冲突，1 小时的窗口不足以支撑 4000 步训练、诊断与样本回传的完整闭环。

### （十二）研究路线与论文定位

**浓度域是否值得继续**：值得，但"把 RGB 换成浓度图"本身不构成创新。浓度域虚拟染色已有邻近工作——MICCAI 2026 的 CFM-HES 在浓度空间保留已知 H/E 浓度、只生成缺失的 Saffron 浓度，再以 Beer–Lambert 定律重建；HistDiST 已将 SD1.5 latent diffusion、病理形态特征条件与专门采样策略用于 H&E→IHC。因此论文不能停留在"提出一种浓度域扩散"，须回答"相比已有浓度域方法解决了什么不同问题"。

**是否改造 SD 的 VAE**：不改造。方案 A（自建小型 UNet 直接预测 DAB 浓度）为主线；方案 B（复用 HistDiST／SD1.5 的 RGB latent 流程）作对照；方案 C（改 VAE 输入输出卷积以接受两个浓度通道）需解决预训练编解码能力的迁移问题，在现有时间与算力下不建议。关键事实是 M0 只生成单通道 DAB，三通道适配问题对它并不存在。

**分阶段路线**：P0 跑通 M0 最小管线，同时设四个基线（常量平均 DAB、无条件扩散、条件扩散、条件扩散＋H-copy 渲染），回答"H&E 条件是否比无条件模型提供可测量信息"；P0.5 将评价从逐像素转向聚合级（DAB 均值、标准差、`p_high`、高浓度区域比例、局部空间自相关），若逐像素相关性低而聚合级相关性稳定存在，应视为任务本质的反映而非实验失败；M1 加入多尺度结构条件（保留 H/E 拼接，增加低分辨率全局条件与局部高分辨率条件，或用轻量 skip injection），目标是改善核结构保持与局部纹理合理性，而非继续压低扩散损失；M2 引入 PSPStain 伪 IHC 提取的 DAB／FOD 蛋白统计作为条件，须防范循环论证（模型可能只学到 PSPStain 的偏差），故伪标签仅作条件、不替代真实目标，并须做有／无消融与外部验证；M3 的真实 IHC 分布先验引导工程风险最高，非首篇论文必选。

**条件有效性的硬门槛**：固定噪声只换 H&E，输出 DAB 的空间或统计特征应发生系统变化；固定 H&E 只换噪声，输出应有合理随机性但表达统计不失控；配对与打乱条件相比，打乱后聚合级指标应明显变差；有条件模型应优于无条件模型，后者应优于常量均值基线。该不等式须体现在 `mean`、`std`、`p_high`、HER2 分级条件下的表达分布与多次采样多样性上——v-prediction 损失本身不能证明模型学会了条件，无条件模型同样可以把边际分布学得很好。

**论文叙事**：主张定为"面向弱配准 H&E–IHC 对的蛋白感知浓度域生成"。论证链条为：HE 与 IHC 非严格像素对齐；H 通道提供可共享的组织结构；DAB 是需生成的蛋白表达通道；像素级映射不可靠但 patch 级表达分布存在条件信号；故模型应在浓度空间中分离可共享的 H 结构、需生成的 DAB 与 patch 级表达分布。评价因连续切片错位而不能只用 RGB 的 PSNR／SSIM，须结合 patch 级 DAB 统计、蛋白表达指标与条件置换实验。

## 三、结论与关键决策

1. **概念与实测**：噪声调度被拆为正向调度、时间步采样、损失加权与反向采样四类，分别对应 `ᾱ_t`、`p(t)`、`w(t)` 与推理轨迹，"只加到 70%"须区分 strength 参数与训练截断两种含义；诊断结果则否证了"早期时间步是瓶颈"的原假设——`t ≤ 200` 的平均损失仅为 `t ≥ 700` 的 0.28 倍，峰值位于 `t = 500–700`。
2. **假设修正**：高噪声区损失高属训练常态，且该区主要负责全局均值，与"生成图退化为均值"一致；真正瓶颈在 `log SNR ≈ 0` 的中等噪声区。
3. **实验决策**：在保持正向调度、网络结构与训练预算不变的前提下，仅将时间步采样由均匀分布改为 Beta(2,2)，聚焦 `t ≈ 300–600`，作为单因素对照。
4. **路线决策**：浓度域 DAB 扩散为唯一主线，RGB／latent 路线降为对照；不改造 SD VAE；按 P0→P0.5→M1→M2 顺序推进，未通过条件有效性检验前不进入 M1／M2。
5. **评价与叙事**：以聚合级 DAB 统计与条件置换实验替代单纯像素指标与训练损失，作为判断模型是否利用 H&E 条件的主要依据；论文问题定位为"弱配准条件下的蛋白感知浓度域生成"，而非"浓度域扩散"本身。

## 四、遗留问题与下一步

1. **条件有效性尚未验证**。四项硬门槛测试均未执行，故"M0 是否成功"目前无法判定，为最高优先级。
2. **诊断指标不完整**。现有诊断仅算 MSE，未纳入 SSIM 与 Pearson 相关系数；配准误差存在时 MSE 会因位移急剧放大，而相关系数可能仍保持较好水平。此外仅测试 1 个样本，需扩展为多样本统计与按 SNR 区间分组的误差分布。
3. **Beta(2,2) 缺少对照结论**。损失下降更快，但未与基线在同一评价体系下比较，需在相同验证集上比较聚合级指标、采样多样性与条件置换后的性能跌落幅度。
4. **额外样本批次未补**。因键名不匹配与服务器失联，指定批次始终未生成；重新获得实例后须按 `ema` 键修正生成脚本并单独存放。
5. **训练—推理的调度一致性待核查**。`squaredcos_cap_v2` 在 `t ≥ 700` 处 SNR 已降至 0.04 以下，若推理仍按 1000 步从纯噪声起步，需确认该区间的采样质量是否影响最终图像。
6. **创新性与工程可持续性**。"浓度域"本身不构成新颖性（CFM-HES 与 HistDiST 已在该空间工作），需调研确认弱配准下的噪声水平分配、以及 patch 级聚合统计作为训练目标是否已有先例；临时实例的 1 小时窗口与凭据轮换亦使长周期实验难以推进，需改用长期实例或建立断点续训与自动回传流程。
