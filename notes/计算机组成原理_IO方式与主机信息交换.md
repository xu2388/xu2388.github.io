# 计算机组成原理 · I/O 方式与主机信息交换

## 一、概述与分工

外设与主机交换信息，表面上问的是「有几种方式」，实质上只有一个变量：**CPU 介入的粒度**。逐字节盯着设备叫程序查询，等设备找上门叫中断，把一整块交给硬件叫 DMA，把一串块交给通道程序叫通道。粒度越粗，CPU 花在搬运上的时间越少，但硬件越复杂、启动与收尾的延迟越大。本文沿着这条线，把每种方式的流程、CPU 开销与总线占用都算到可以核对的程度。

| 笔记 | 负责的部分 | 本文的处理 |
|---|---|---|
| 计算机组成原理 · 总线、Cache 与存储层次 | 总线分类与仲裁（链式、计数器定时、独立请求）、存储层次、磁盘属直接存取的定性判断 | 不重述仲裁算法与存储层次；本文只把「DMA 抢占总线」展开成三种占用方式，并给出挪用比例 |
| 计算机组成原理 · 总线地址译码与指令执行 | 中断周期的五步微操作、总线定时与带宽、端口地址译码 | 不重复那五步微操作；本文从「中断源与向量」讲到服务程序与返回，并补齐 CPU 开销的定量 |
| 本文 | 接口的基本结构与端口编址、四种方式的完整流程、中断向量与屏蔽嵌套、DMA 三阶段与总线占用、磁盘访问时间 | 所有算例标明主频、设备速率与块大小，可复算 |

上一轮把中断周期归入指令周期，只讲到「$PC$ 写出去、向量读进来」；本文接着讲向量从哪里来、服务程序做完之后怎样回到断点，两篇合起来才是完整的一次中断。

## 二、外设接口的基本结构

### 2.1 为什么必须有接口

设备不能直接挂到系统总线上，原因有四条，每条都对应接口里的一块电路：

| 矛盾 | 接口中的对策 |
|---|---|
| 速度不匹配（设备比总线慢几个数量级） | 数据缓冲寄存器，先攒够再传 |
| 数据格式不同（串行与并行、模拟与数字） | 串并转换、电平转换 |
| 总线地址与设备内部结构无关 | 地址译码与端口选择 |
| CPU 需要知道设备状态 | 状态寄存器与中断请求逻辑 |

一个典型接口内部有五组寄存器：**数据缓冲寄存器**暂存一个编址单位的数据；**状态寄存器**给出就绪、忙、完成、出错等位；**控制寄存器**接收启动、方向、中断允许等命令；**地址译码电路**把总线上的端口地址译成片选信号；**中断逻辑**把「完成」与「中断允许」相与，产生中断请求。前三个构成通常说的「三个端口」——数据端口、状态端口、控制端口。

### 2.2 端口编址的两种方案

| 方式 | 地址空间 | 访问指令 | 译码特点 | 代价 |
|---|---|---|---|---|
| 与主存统一编址 | 与主存共用同一地址空间 | 普通访存指令即可 | 全部地址线参与译码，占用一块主存地址 | 减少可用主存容量；访存与访端口在指令上无法区分 |
| 独立编址 | 单独的 I/O 地址空间 | 专用输入输出指令 | 只用少量地址线，另需一条「访端口」控制信号 | 指令集多出专用指令；需额外的控制线区分空间 |

统一编址的好处是任何访存指令都能操作端口，寻址方式丰富；独立编址的好处是端口地址短、译码简单，且不占主存空间。无论哪种，接口的片选都必须由地址译码产生，这一点与存储器扩展没有区别——只是端口的译码通常更依赖「读/写控制信号也参与译码」，否则同一个地址在读和写时会选中同一寄存器，状态端口与数据端口就分不开。

### 2.3 三种联络方式

数据什么时候可以传，靠联络信号决定：

- **同步联络**：双方按固定节拍工作，不查状态，适合速度确定的设备，最快但不容忍抖动。
- **异步联络**：靠「请求—回答」握手，慢的一方用就绪信号拖住快的一方，可靠但每次多几个节拍。
- **中断联络**：设备准备好后主动发请求，CPU 在处理器的指令边界响应，是异步联络的特例，把「等」变成了「被打断」。

程序查询用的是第二种的极端形式——CPU 主动反复读状态位；中断方式用第三种；DMA 则把联络下沉到 DMA 控制器与设备之间，CPU 不再参与每一次握手。

## 三、程序查询方式

### 3.1 流程

1. 向控制端口写启动命令与方向；
2. 从状态端口读状态字；
3. 检查就绪位，未就绪则回到第 2 步；
4. 就绪则从数据端口读入（或写出）一个单位；
5. 修改主存地址与计数器；
6. 计数器为零则结束，否则回到第 2 步。

整个过程中，第 3 步的循环是纯等待。CPU 与设备**完全串行**：设备准备数据时 CPU 在空转，CPU 传送时设备在等。数据传送与主程序同样串行，因为查询与传送代码本身就插在主程序中间。

### 3.2 占用率的两种口径

同一个「查询」，按「是否原地空转」分成两种口径，算出的占用率差三个数量级，混用会得出完全相反的结论：

| 口径 | 做法 | CPU 占用 |
|---|---|---|
| 独占查询 | 程序停在循环里反复读状态，直到就绪 | 接近 100%，等待时间全被浪费 |
| 定时查询 | 主程序照常运行，按定时器每隔一段时间查一次 | 每次约 20 个时钟周期，与间隔成反比 |

设主频 100 MHz（时钟周期 10 ns）、每次查询加传送共 20 个周期即 200 ns，则定时查询的占用率为

$$
U_{\text{poll}}=\frac{200\ \text{ns}}{T_{\text{dev}}}.
$$

| 设备就绪间隔 | 独占查询 | 定时查询（20 周期） | 中断（125 周期） |
|---|---|---|---|
| 1 ms | 100% | 0.02% | 0.125% |
| 100 µs | 100% | 0.2% | 1.25% |
| 10 µs | 100% | 2% | 12.5% |
| 1 µs | 100% | 20% | 125% |
| 0.1 µs | 100% | 200% | — |

读表要抓两件事。其一，定时查询的占用率与间隔成反比：间隔缩短十倍，占用率涨十倍，所以「查询适合慢设备」这句话的确切含义是「间隔足够长时，查询的固定开销可以被摊薄」。其二，定时查询在中低速段比中断更省——20 个周期对 125 个周期，差了六倍多。查询真正的害处不是这几个周期，而是**它可能漏掉设备**：两次查询之间设备就绪又失效，数据就丢了。这是查询方式在工程上被中断取代的根本原因，而不是「占用 CPU 多」。

### 3.3 一个具体账

设磁盘每 1 ms 产生一个字节，查询一次加传送 200 ns。若采用独占查询，CPU 在这 1 ms 里一步也走不开，占用率 100%；若采用定时查询，每 1 ms 查一次，占用 0.02%，但要求查询周期严格小于设备就绪的保持时间。这两个数字放在一起说明：**查询方式的问题从来不是算术，而是同步**。

## 四、中断方式

### 4.1 中断源与分类

| 分类角度 | 类型 | 例子 |
|---|---|---|
| 来源 | 外中断（硬件） | 设备完成、定时器、电源故障 |
| 来源 | 内中断（异常） | 除零、溢出、缺页、非法指令 |
| 可否屏蔽 | 可屏蔽 | 一般外设请求，受中断允许标志控制 |
| 可否屏蔽 | 不可屏蔽 | 电源掉电、总线错误 |
| 入口方式 | 向量中断 | 由设备给出类型号，硬件查表得入口 |
| 入口方式 | 非向量中断 | 入口固定，由软件查询是哪个设备 |

外中断又可分**可屏蔽**与**不可屏蔽**两类，这与「中断允许触发器」是两回事：前者由接口的屏蔽位决定是否发出请求，后者由处理器的总开关决定是否受理。

### 4.2 一次中断的完整流程

原料把「中断周期中由硬件把允许中断触发器置 0」作为考点，这句话要放进完整流程里才看得懂：

1. **请求**：设备完成一次传送，置中断请求触发器，若屏蔽位为 0 则向 CPU 发请求；
2. **判优**：多个请求同时到达时，由硬件排队或软件查询决定先服务谁；
3. **响应**：满足三个条件才响应——有未屏蔽请求、中断允许标志为 1、当前指令执行完毕；
4. **中断隐指令**：由硬件完成、不由程序指令完成的三件事——关中断（允许标志清 0）、保存断点（$PC$ 入栈或存入指定单元）、取向量（向量地址送 $PC$）；
5. **保存现场**：服务程序把通用寄存器压栈；
6. **服务**：完成本次传送或处理；
7. **恢复现场**：弹栈恢复寄存器；
8. **中断返回**：返回指令弹出断点与状态字，允许标志随之恢复。

第 4 步之所以叫「隐指令」，是因为它没有对应的机器指令编码，却占用了指令周期中的一个节拍序列。第 8 步恢复的并不是常数 1，而是**断点处保存的那个状态字**——若中断发生在关中断的临界区里，返回后仍然是关中断。把「返回时自动开中断」当成无条件规律，在嵌套场景下就会出错。

响应必须发生在一条指令结束之后，原因是中断隐指令要保存的断点是「下一条指令的地址」；若在指令中间响应，保存下来的 $PC$ 无法让程序正确续跑。DMA 不受这条约束，它的请求可以在存取周期边界被受理，这正是 DMA 响应比中断快得多的结构性原因。

### 4.3 向量表

向量中断的入口由**中断类型号**索引一张表得到。按「每项 4 字节、类型号从 0 开始」的口径，类型号 $i$ 的表项地址为

$$
A_{\text{entry}}=A_{\text{base}}+4i .
$$

256 个类型号对应 $256\times4=1\ \text{KB}$ 的表。取 $i=0\text{x}21=33$，则偏移为 $4\times33=132=0\text{x}84$。表项里放的通常是入口的偏移与段基址两部分，各占两字节，故每项 4 字节。这个「乘 4」只对应这一种表结构；若表项改为 8 字节（64 位口径），同一个类型号的偏移就变成 $8i$，答题时必须先确认表项宽度。

向量表的好处是把「设备是谁」编码进了硬件：CPU 不必知道接了几个设备、各自入口在哪，只按类型号取表项即可。代价是类型号必须唯一分配，且表本身要放在主存的固定区域，不能被普通程序覆盖。

### 4.4 屏蔽与嵌套

多级中断系统给每个中断源配一个**屏蔽字**：某级服务程序执行时，把自己的屏蔽字写入屏蔽寄存器，优先级不高于自己的请求被挡在门外，高于自己的仍可打断，这就是嵌套。

| 概念 | 作用对象 | 存放位置 |
|---|---|---|
| 中断允许标志 | 全部可屏蔽中断的总开关 | 程序状态字 |
| 屏蔽触发器 | 单个设备是否允许发请求 | 接口内部 |
| 屏蔽字 | 当前服务程序允许哪些级别打断自己 | 屏蔽寄存器 |

三层各管一段，不能互相替代。总开关关掉时，任何可屏蔽请求都进不来；总开关打开但某设备屏蔽位为 1 时，该设备的请求发不出去；两者都放行，仍可能被当前服务程序的屏蔽字挡住。

### 4.5 CPU 开销

设每次中断的固定开销为 125 个时钟周期（隐指令 5 个、保存与恢复现场约 80 个、服务程序约 40 个），主频 100 MHz，即每次 1.25 µs。设备每传送一个字节请求一次，则中断方式能支撑的最高速率是

$$
f_{\max}=\frac{1}{1.25\ \mu\text{s}}=0.8\ \text{M 次/s},
$$

即约 0.8 MB/s 的字节流。超过这个速率，中断服务本身就把 CPU 占满了，这就是高速设备必须改用 DMA 的定量理由。反过来看低速侧：键盘每秒几十个字符，中断开销不到万分之一，几乎免费。

## 五、DMA 方式

### 5.1 为什么中断还不够

中断方式下，每传一个字节都要经历「保存现场—服务—恢复现场」这一整套程序切换，开销以百周期计。DMA 的思路是把这套动作整体省掉：数据不经过 CPU 的寄存器，直接在设备与主存之间搬，CPU 只在**一块开始前**与**一块结束后**各参与一次。

### 5.2 控制器的组成

| 部件 | 作用 |
|---|---|
| 主存地址寄存器 | 存放本次要访问的主存地址，每传一个单位加一 |
| 字计数器 | 记录还要传多少单位，减到零表示块结束 |
| 数据缓冲寄存器 | 暂存总线上的一个单位 |
| 设备地址寄存器 | 指明当前服务哪台设备 |
| 控制与状态逻辑 | 产生总线请求、接收总线允许、发出读/写命令 |
| 中断逻辑 | 块结束后向 CPU 发中断，报告完成 |

注意 DMA 控制器自己没有「程序」，它只会按寄存器里的地址与计数做加法与比较。这一点是它与通道的分水岭。

### 5.3 三个阶段

1. **预处理**：CPU 用几条指令把主存首址、传送长度、方向、设备号写入 DMA 控制器，然后启动设备。这一段是程序，CPU 必须参与。
2. **数据传送**：DMA 控制器接管。每个单位的过程是「设备请求 → 控制器向 CPU 申请总线 → 获得允许 → 发地址与读写命令 → 传送 → 地址加一、计数减一」。这一段的每一个节拍都由硬件完成，CPU 不执行任何指令。
3. **后处理**：计数到零，控制器释放总线并发中断，CPU 进服务程序检查是否出错、是否还有下一块。

三段的开销都在两端，中间与 CPU 无关。这正是「按块搬运」的含义：块越大，摊到每字节上的开销越小。

### 5.4 总线占用的三种方式

DMA 与 CPU 争的是同一条总线，谁先走决定了 CPU 被拖慢多少：

| 方式 | 做法 | CPU 受影响程度 | 适用 |
|---|---|---|---|
| 停止 CPU 访问主存 | 整块传送期间 DMA 独占总线，CPU 停摆 | 整块时间完全停 | 高速设备、大块传送，CPU 无事可做时 |
| 周期挪用 | 每传一个单位挪用一两个存取周期，其余时间还给 CPU | 按挪用比例减慢 | 最常用，兼顾两者 |
| 交替访问 | 把存取周期分成两半，前半给 CPU、后半给 DMA | CPU 不停止，但每个周期只能用到一半时间 | 高速缓存式主存，硬件最复杂 |

原料说 DMA 期间「CPU 与设备高度并行、数据传送与主程序并行」，这话只在周期挪用与交替访问下成立，而且还要加一个条件：CPU 执行的是不需要访问主存的指令（寄存器运算、Cache 命中）。若 CPU 正在访存，它的请求会被推迟一到几个周期。停止 CPU 方式下这句结论根本不成立。

### 5.5 周期挪用的定量

设主存存取周期 500 ns、DMA 每次传 4 字节、设备速率 0.5 MB/s。每秒需要挪用的次数为

$$
\frac{0.5\times10^{6}}{4}=1.25\times10^{5}\ \text{次/s},
$$

每次占一个存取周期，故总线被 DMA 占用的时间比例为

$$
1.25\times10^{5}\times500\ \text{ns}=0.0625,
$$

即 6.25%。若 CPU 每条指令都要访存，它的性能最多下降 6.25%；若大部分指令命中 Cache，实际下降更小。这个 6.25% 就是「DMA 不是免费」的价钱，它随设备速率线性增长。

### 5.6 与中断方式的开销对比

设设备速率 0.5 MB/s、块大小 1 KB、主频 100 MHz。一块的传送时间为

$$
\frac{1024\ \text{B}}{0.5\ \text{MB/s}}=2048\ \mu\text{s}.
$$

| 项目 | 中断方式（每字节一次） | DMA 方式（每块一次） |
|---|---|---|
| CPU 周期数 | $1024\times125=128000$ | 50（预处理加后处理） |
| CPU 时间 | 1280 µs | 0.5 µs |
| 占块传送时间 | 62.5% | 0.024% |
| 块结束通知 | 不需要额外通知 | 一次中断，已计入 50 周期 |

两种方式相差约两千六百倍。差距的来源不是「DMA 更快地搬数据」——总线的搬运速度是一样的——而是「DMA 把每字节一次的程序切换，换成了每块一次」。把块从 1 KB 加到 64 KB，DMA 的开销占比还要再降 64 倍，而中断方式的占比纹丝不动。

### 5.7 与中断的区别

| 维度 | 中断 | DMA |
|---|---|---|
| 请求者 | 设备 | DMA 控制器（代表设备） |
| 响应时机 | 一条指令结束之后 | 存取周期边界，可插在指令中间 |
| 数据通路 | 经 CPU 寄存器 | 设备与主存直连，不经 CPU |
| CPU 做的事 | 执行服务程序搬数据 | 只在两端设参数、查结果 |
| 优先级 | 一般低于 DMA | 通常最高，否则数据会丢 |
| 适用 | 随机、少量、低速 | 成块、高速 |

优先级这条常被问：DMA 请求若被中断拖住，设备侧的数据缓冲可能溢出，丢失无法恢复；而中断晚几个周期只是响应变慢，数据仍在接口里等着。所以硬件上一般让 DMA 优先。

## 六、通道方式

### 6.1 通道是什么

通道是一台**专用的 I/O 处理器**，它能执行自己的指令序列（通道程序），独立完成一组块的传送。CPU 只需执行一条启动指令，把通道程序的首址与设备号告诉通道，之后连「每块设一次参数」都省了。

通道与 DMA 的差别只有一句话：DMA 控制器执行的是寄存器里的参数，通道执行的是**程序**。因此通道能处理「读 A 块、跳过若干道、再写 B 块」这样的复合任务，DMA 不能。

### 6.2 三种通道

| 类型 | 服务方式 | 并行性 | 适用设备 |
|---|---|---|---|
| 字节多路通道 | 轮流为多台设备服务，每次传一个字节 | 多台低速设备分时共用 | 键盘、打印机、终端 |
| 数组多路通道 | 轮流服务，每次传一个数据块 | 多台高速设备分时共用 | 磁盘、磁带 |
| 选择通道 | 一次只为一台设备服务，直到整批传完 | 单台设备独占 | 高速磁盘 |

字节多路通道的容量可以直接算：设通道每服务一个字节需 500 ns，则上限为 $1/500\ \text{ns}=2\times10^{6}$ 字节每秒即 2 MB/s；若每台设备 10 KB/s，理论上可带 200 台。数组多路通道的账要按块算：每块 512 B、每字节 500 ns，则一块占用通道 256 µs，块与块之间的间隙才轮得到别的设备。

### 6.3 四种方式的粒度

| 方式 | CPU 介入频率 | 一次介入的工作量 |
|---|---|---|
| 程序查询 | 每个数据单位 | 查状态、传送、改地址 |
| 中断 | 每个数据单位 | 保存现场、服务、恢复现场 |
| DMA | 每个数据块 | 设地址与计数、查结果 |
| 通道 | 每个通道程序 | 启动通道、处理结束中断 |

粒度每加粗一级，CPU 的介入次数就降一个量级，代价是硬件自主性提高、出错时更难排查。

## 七、四种方式的整体对比

| 维度 | 程序查询 | 中断 | DMA | 通道 |
|---|---|---|---|---|
| CPU 与设备 | 完全串行 | 准备阶段并行、传送阶段串行 | 高度并行（周期挪用下） | 高度并行 |
| 数据传送与主程序 | 完全串行 | 串行（交替执行） | 并行 | 并行 |
| 数据通路 | 经 CPU | 经 CPU | 设备与主存直连 | 设备与主存直连 |
| CPU 开销 | 极高 | 中，与设备频率成正比 | 极低，与块数成正比 | 最低 |
| 硬件复杂度 | 最低 | 中 | 较高 | 最高 |
| 典型速率上限 | 取决于轮询周期 | 约 0.8 MB/s（本文口径） | 受总线与主存带宽限制 | 受通道带宽限制 |
| 适用 | 慢速、单任务、确定性时序 | 随机、低速、需及时响应 | 成块、高速 | 多设备、大批量 |

这张表里最容易被误读的是「CPU 与设备」一列。它的准确含义是「CPU 是否被占用」，而不是「两者是否在物理上同时通电工作」——任何时刻设备都在工作，问题只是 CPU 有没有被拖住。

## 八、磁盘结构与访问时间

### 8.1 结构

磁盘由若干盘片叠成，每面一个磁头，盘面划分成同心圆磁道，磁道再分成扇区，各面上半径相同的磁道组成柱面。寻址方式是「柱面号、磁头号、扇区号」，读取时先移动磁头到目标磁道，再等目标扇区转到磁头下，最后连续读出。

### 8.2 三段时间的公式

$$
T_{\text{access}}=T_{\text{seek}}+T_{\text{rotation}}+T_{\text{transfer}} .
$$

平均旋转延迟取半圈，理由是目标扇区相对磁头的位置均匀分布，平均要等半圈：

$$
T_{\text{rotation,avg}}=\frac{1}{2}\cdot\frac{60}{n}\ \text{s},
$$

其中 $n$ 为每分钟转数。

### 8.3 算例

设转速 7200 r/min、平均寻道 9 ms、接口传输率 100 MB/s、扇区 4 KB。

| 项目 | 计算 | 结果 |
|---|---|---|
| 转一圈 | $60/7200$ | 8.333 ms |
| 平均旋转 | 半圈 | 4.167 ms |
| 平均寻道 | 给定 | 9.000 ms |
| 传输 4 KB | $4096/100\times10^{6}$ | 40.96 µs |
| 合计 | 上式相加 | 13.208 ms |

读 1 MB 的对比更能说明问题。若 256 个扇区在同一柱面上连续存放，只需一次寻道与一次平均旋转，传输 $1\ \text{MB}/100\ \text{MB/s}=10.486\ \text{ms}$，合计约 23.65 ms；若这 256 个扇区随机分布，每次都要重新寻道与旋转，合计 $256\times13.208\ \text{ms}=3.38\ \text{s}$。两者相差一百四十余倍，这就是「顺序访问远快于随机访问」的算术来源，也是文件系统尽量让大文件连续存放的原因。

### 8.4 盘片数据率与接口速率

上面用的 100 MB/s 是接口传输率，不是盘片能读出的速率。盘片的数据率由「每道字节数 × 每秒转数」决定：若每道 256 KB、每秒 120 转，则

$$
256\ \text{KB}\times120=30.72\ \text{MB/s}.
$$

两个数中较小者才是实际瓶颈。接口速率高而盘片速率低时，100 MB/s 的接口只能跑出 30 MB/s 左右，这也解释了为什么机械盘的顺序读速度长期停在百兆字节每秒的量级。

### 8.5 接口在磁盘读中的作用

一次磁盘读的路径是：CPU 设好 DMA 参数并启动 → 磁盘控制器寻道、等待、读出扇区到控制器缓冲 → 控制器向 DMA 发请求 → DMA 把缓冲内容写入主存 → 一块传完发中断。这条路径上，CPU 只在两端出现，中间的寻道与旋转时间与 CPU 无关，所以磁盘的慢不会直接拖慢 CPU，只会拖慢发起读操作的那个进程。

## 九、易错点

1. **把「中断方式 CPU 与设备并行」理解成全程并行**。准备阶段并行，传送阶段串行，服务程序执行时 CPU 完全被占用。
2. **认为中断可以在指令中间响应**。响应点固定在一条指令结束之后，否则断点无法正确保存。
3. **把中断隐指令当成一条机器指令**。它没有指令编码，是硬件在中断周期完成的固定动作序列。
4. **认为中断返回一定开中断**。返回恢复的是断点处保存的状态字，嵌套或临界区内返回后可能仍关中断。
5. **向量地址一律按类型号乘 4**。这个系数由表项宽度决定，表项 8 字节时是乘 8。
6. **认为 DMA 完全不占 CPU**。预处理与后处理都是程序，周期挪用还会拖慢 CPU 的访存。
7. **认为 DMA 期间 CPU 一定停摆**。只有停止 CPU 访问主存的方式才停，周期挪用下 CPU 照常运行。
8. **把通道当作多个 DMA 的堆叠**。通道执行通道程序，DMA 只执行寄存器参数，前者能处理复合任务。
9. **平均旋转延迟按整圈算**。均匀分布下取半圈，按整圈算会把旋转时间高估一倍。
10. **用接口速率代替盘片数据率**。两者取小才是实际吞吐。
11. **把查询的「20 个周期」当成查询的全部代价**。独占查询时 CPU 全程空转，代价是整个等待时间。

## 十、小结

| 知识块 | 必记结论 |
|---|---|
| 接口结构 | 数据、状态、控制三个端口加地址译码与中断逻辑；统一编址省指令、独立编址省地址 |
| 查询 | 独占查询占用近 100%，定时查询占用与设备间隔成反比；致命缺点是可能漏掉就绪窗口 |
| 中断流程 | 请求、判优、响应、隐指令（关中断、保存断点、取向量）、服务、恢复、返回 |
| 向量 | 入口地址等于基址加类型号乘表项宽度；256 项、每项 4 字节时为 1 KB |
| 中断开销 | 每次约 125 周期；主频 100 MHz 时上限约 0.8 MB/s |
| DMA 三阶段 | 预处理、数据传送、后处理；中间段 CPU 不执行指令 |
| 总线占用 | 停止 CPU、周期挪用、交替访问；0.5 MB/s 设备挪用 6.25% |
| 通道 | 字节多路、数组多路、选择；按通道程序工作，CPU 只启动一次 |
| 磁盘 | 访问时间等于寻道加平均旋转加传输；4 KB 扇区算例 13.21 ms |
| 选择原则 | 慢而确定用查询，随机中低速用中断，成块高速用 DMA，多设备大批量用通道 |

四种方式的取舍可以压成一句话：**CPU 每介入一次都要付一笔固定开销，方式的演进就是把这笔开销从「每个字节」摊到「每个块」再摊到「每个通道程序」**。开销的绝对值由主频与现场大小决定，摊薄的倍数由粒度决定；把这两个量分别写出来，任何一道对比题都能算，而不是背。

## 十一、勘误与口径说明

| 序号 | 原料表述 | 复核结论 | 判据 |
|---|---|---|---|
| 1 | 「DMA 方式下 CPU 与设备高度并行、数据传送与主程序并行」 | 结论保留，但需补条件：仅周期挪用或交替访问、且 CPU 当前不访存时成立；停止 CPU 访问主存时 CPU 停摆 | 三种占用方式对 CPU 的影响不同 |
| 2 | 「中断方式 CPU 资源占用率中等」 | 定性可接受，但开销与设备频率成正比；设备间隔 1 µs 时达 125%，已不可行 | $125\times10\ \text{ns}/1\ \mu\text{s}$ |
| 3 | 「程序查询方式 CPU 完全被占用，没有空闲时间」 | 仅对独占查询成立；定时查询可让主程序继续运行，代价是可能漏掉就绪窗口 | 两种查询口径的占用率差三个数量级 |
| 4 | 「中断周期中硬件将允许中断触发器置 0」 | 正确；但「中断返回时硬件自动恢复为 1」应改为「恢复断点处保存的状态字」 | 嵌套与临界区返回后可能仍为 0 |
| 5 | 「中断方式适合设备多、IO 频繁但单次数据量小的场景」 | 成立，但「频繁」有上限：每字节 125 周期，100 MHz 下上限约 0.8 MB/s | 超过上限须改 DMA |
| 6 | 加减法器实验中 `cf` 在减法时取进位取反 | 该式给出的是**借位**，与「减法产生借位则 CF 置 1」的口径一致；若教材把 CF 定义为「加法进位」，则减法时应另作说明 | 两种 CF 定义在不同教材中并存 |
| 7 | 实验约束文件只绑定 `a[1:0]`、`b[1:0]`，设计端口为 8 位 | 约束与端口位宽不匹配，未约束的位会悬空或综合报错，需补齐全部引脚 | 端口位宽与约束条目数不对应 |

四处自设口径需标明：其一，第三节的 20 周期、第四节的 125 周期、第五节的 50 周期均为本文设定，主频统一取 100 MHz，换参数后数值变、结论形态不变；其二，向量表「每项 4 字节、基址加类型号乘 4」对应 16 位实模式口径，其他表结构需按表项宽度换算；其三，磁盘算例的 7200 r/min、9 ms 寻道、100 MB/s 接口、4 KB 扇区为教学常用值，非任何具体型号的实测参数；其四，第五节的 6.25% 按「每个单位传 4 字节、每次挪用 1 个 500 ns 存取周期」估算，未计总线仲裁本身的开销。
