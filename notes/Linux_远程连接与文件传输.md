# 操作系统/Linux · 远程连接与文件传输

## 一、概述：三种需求，一条链路

远程使用一台 Linux 主机，需求通常只有三类：要一个终端敲命令，要传文件，要一个图形桌面。三者的底层往往都是同一条 SSH 连接，区别在于上层跑的是 shell、sftp 子系统，还是被隧道转发的桌面协议。把这条链路看清楚，配置就不会散成一堆互不相干的技巧。

本文不写任何真实地址。主机名统一用 `host` 或 `jump-host`，用户名用 `user`，端口用 `port` 或环境变量表示，本地目录统一写 `项目目录`，远端目录也写 `项目目录`。凡是要填写具体值的地方，都应由使用者按自己的环境替换，而不是从文章里抄一个看起来像真的地址。

与已有笔记的分工：《医学影像实验室 Linux 工具链》只把 `scp` 与 `tmux` 当作日常工具简单带过，重点在环境与训练流程；本文展开认证、传输协议、隧道与排错，不重复环境配置。《Linux 进程、线程与作业控制》讲 `nohup`、`tmux` 与进程生命周期；本文只在「传输过程中断线」这一场景提到会话保持，不重复作业控制。

先给一张总表，后文逐项展开：

| 需求 | 首选手段 | 备选 | 关键限制 |
|---|---|---|---|
| 远程终端 | `ssh` | 网页终端、串口 | 需要网络可达与认证 |
| 传少量文件 | `scp` | `sftp` | 无断点、无增量 |
| 传大量或反复同步 | `rsync` | `sftp` 递归 | 两端都要有 rsync |
| 图形界面 | SSH 隧道加 VNC 或 RDP | X11 转发 | 带宽与安全边界 |
| 穿越内网 | `ssh -J` 跳板 | 端口转发、VPN | 跳板机需允许转发 |

## 二、SSH 连接是怎么建立的

### 2.1 五个阶段

一次 SSH 登录可以拆成五段，排错时先判断卡在哪一段，比盯着最终报错有效：

| 阶段 | 做什么 | 失败时的典型表现 |
|---|---|---|
| TCP 连接 | 客户端向目标端口发起三次握手 | `Connection refused`、`timed out` |
| 版本交换 | 双方发送协议版本字符串 | 极少见，通常是中间设备干扰 |
| 密钥交换 | 协商算法，交换参数，服务器用主机密钥签名 | 算法不匹配、`no matching key exchange method` |
| 用户认证 | 公钥、口令或键盘交互 | `Permission denied` |
| 会话通道 | 开 shell、执行命令、启 sftp 或转发 | `subsystem request failed`、`administratively prohibited` |

`ssh -vvv` 会把每一段的细节打出来。读日志的顺序是自下而上找第一个 `debug1` 级别的失败点，而不是从头逐行看；`debug2` 与 `debug3` 里大量是算法列表，真正的错误往往只有一行。

### 2.2 首次连接与 known_hosts

第一次连接某台主机时，客户端会提示无法确认主机身份，并给出一个指纹。这个指纹来自服务器的主机密钥，确认无误后输入接受，客户端把主机名与公钥写进 `~/.ssh/known_hosts`。之后再连接，客户端用同一份记录验证对方，防止中间人冒充。

```bash
ssh-keygen -F host
ssh-keygen -R host
ssh -o StrictHostKeyChecking=accept-new user@host
```

`-F` 查询某主机在 `known_hosts` 里的记录，`-R` 删除旧记录。`accept-new` 只自动接受从未见过的主机，遇到密钥变更仍然拒绝；`StrictHostKeyChecking=no` 则连变更也放过，不适合长期使用。

出现 `REMOTE HOST IDENTIFICATION HAS CHANGED` 时，先不要删记录了事。可能的原因有三种：服务器重装过、地址被重新分配给了另一台机器、真的有人在中间拦截。正确做法是通过带外渠道核对服务器指纹，确认是前两种之后再 `ssh-keygen -R` 删除旧条目并重新接受。直接关掉校验，等于把这一层保护作废。

### 2.3 公钥认证

公钥认证的做法是：客户端持有私钥，服务器上的 `authorized_keys` 里放着对应公钥；登录时服务器发一个挑战，客户端用私钥签名，服务器用公钥验证。私钥从不离开客户端，比口令更难被服务器侧泄漏。

```bash
ssh-keygen -t ed25519 -C "user@host"
ssh-copy-id -i ~/.ssh/id_ed25519.pub -p "$PORT" user@host
```

`ssh-keygen` 会询问保存路径与口令。给私钥设口令，私钥文件被盗后仍多一层保护；配合 `ssh-agent` 可以只输一次：

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
```

没有 `ssh-copy-id` 时，可以手工追加，但要注意权限：

```bash
cat ~/.ssh/id_ed25519.pub | ssh -p "$PORT" user@host \
  'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys'
```

服务端对权限的要求很严，宽一点就拒绝：

| 对象 | 建议权限 | 原因 |
|---|---|---|
| `~/.ssh` | 700 | 防止他人读取或替换 |
| 私钥 `id_ed25519` | 600 | 客户端拒绝加载过宽的私钥 |
| 公钥 `id_ed25519.pub` | 644 | 可公开，无敏感性 |
| `authorized_keys` | 600 | 防止他人添加自己的公钥 |
| 家目录 | 不可组可写 | 服务端 `StrictModes` 会检查 |

私钥权限过宽时，客户端报 `Permissions 0644 for 'id_ed25519' are too open`，`chmod 600` 即可。服务端 `authorized_keys` 或家目录权限不对，表现则是「公钥明明装了还是 `Permission denied`」，此时要看服务端日志，而不是反复重新生成密钥。

一个客户端有多把密钥时，可能遇到 `Too many authentication failures`：agent 把每把钥匙都试一遍，超过服务端 `MaxAuthTries` 就被断开。指定密钥并禁止试探其他身份：

```bash
ssh -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes user@host
```

### 2.4 认证方式怎么选

| 方式 | 安全性 | 便利性 | 适用 |
|---|---|---|---|
| 口令 | 依赖强度，可被爆破 | 简单 | 临时环境，配合失败限制 |
| 公钥 | 高，私钥不外传 | 配置一次 | 日常登录、自动化 |
| 键盘交互 | 可实现多因素 | 取决于实现 | 口令加动态码 |
| 主机信任 | 低，绑定主机 | 少用 | 受控内网 |

生产环境通常关掉口令登录，只留公钥；需要多因素时在公钥之外再加一层键盘交互或网络层访问控制。关掉口令前必须确认公钥能登录，并且保留一个已登录的会话用于回滚，否则容易把自己锁在门外。

### 2.5 常见失败对照

| 报错 | 常见原因 | 先查什么 |
|---|---|---|
| `Connection refused` | 服务未启动、端口不对、防火墙拒绝 | 服务端 `ss -lntp`，本地 `nc -vz host "$PORT"` |
| `Connection timed out` | 路由不通、防火墙丢包、地址错误 | `ping`、`traceroute`、安全组规则 |
| `No route to host` | 网络层不可达 | 本机路由表、网关 |
| `Permission denied (publickey)` | 公钥未装、权限过宽、用户或端口错 | 服务端日志、`authorized_keys`、`id` |
| `Host key verification failed` | 主机密钥变更或记录冲突 | 核对指纹后再删旧记录 |
| `Too many authentication failures` | agent 提供了过多密钥 | `IdentitiesOnly=yes` 加 `-i` |
| `Address family not supported` | `-6` 与配置里的 `AddressFamily inet` 冲突 | `ssh -G host` 看生效配置 |
| `Broken pipe` | 连接被中间设备或超时切断 | 心跳配置、网络稳定性 |

`ssh -G host` 会打印最终生效的配置，包含主机名、用户、端口、地址族、密钥文件等。配置写了多份、不知道哪份生效时，这一条命令比逐个文件翻更快。命令行选项优先于用户配置，用户配置优先于系统配置；同一文件内，绝大多数选项以第一次出现的值为准。

## 三、客户端配置

### 3.1 常用选项

| 选项 | 作用 | 易错点 |
|---|---|---|
| `-p` | 指定 SSH 端口 | `scp` 与 `sftp` 用大写的 `-P` |
| `-i` | 指定私钥 | 权限必须 600 |
| `-J` | 经跳板机连接 | 跳板机需允许 TCP 转发 |
| `-L` | 本地端口转发 | 方向是「本地听，远端目标」 |
| `-R` | 远程端口转发 | 方向相反，受服务端 `GatewayPorts` 限制 |
| `-D` | 动态转发，起 SOCKS 代理 | 不是万能代理，只转发 TCP |
| `-N` | 不执行远程命令 | 只做转发时必加 |
| `-T` | 不分配终端 | 自动化脚本常用 |
| `-v` | 调试输出，可叠加到 `-vvv` | 信息量大，先找第一个失败点 |
| `-6` | 强制 IPv6 | 与 `AddressFamily inet` 冲突 |

选项位置也有讲究。`ssh user@host -p "$PORT"` 在很多实现上能跑，是因为参数解析会重排；但 `scp`、`rsync -e` 以及部分旧版本不一定这么宽容。统一写成 `ssh -p "$PORT" user@host`，把选项放在目标之前，可以少一类莫名其妙的错误。

### 3.2 ssh_config 的 Host 块

把常用参数写进 `~/.ssh/config`，命令行就只剩一个别名：

```
Host lab
    HostName host
    User user
    Port 端口
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
    ServerAliveInterval 30
    ServerAliveCountMax 3
    TCPKeepAlive yes

Host *
    ServerAliveInterval 30
```

`Host` 后面是别名，`HostName` 才是真实主机名。`Host *` 作为兜底，给所有连接加心跳。通配符 `*` 与 `?` 可用，多个 `Host` 模式可以写在一行；匹配是按文件顺序，先匹配到的块先提供值，后面的块只补未设置的项。

需要区分「别名」与「真实主机名」：`ssh lab` 用的是别名，`ssh host` 用的是真实名，两者可以指向同一台机器但走不同配置。把测试环境与生产环境写成两个 Host 块，比每次敲一长串参数可靠。

### 3.3 服务端的关键项

服务端配置在 `/etc/ssh/sshd_config`，改完先用 `sshd -t` 做语法检查，再 reload。几个常调的项：

| 项 | 作用 | 注意 |
|---|---|---|
| `PubkeyAuthentication` | 是否允许公钥 | 关闭前确认还有其他登录方式 |
| `PasswordAuthentication` | 是否允许口令 | 关掉可显著减少爆破 |
| `PermitRootLogin` | 是否允许直接登录超级用户 | 设为 `prohibit-password` 或禁止 |
| `AllowUsers` / `AllowGroups` | 白名单 | 写错会全员被拒 |
| `MaxAuthTries` | 单次连接允许的认证尝试次数 | 与 agent 多密钥冲突时调大或限制密钥 |
| `ClientAliveInterval` | 服务端探测客户端的时间间隔 | 与客户端心跳配合 |
| `Subsystem sftp` | 启用 sftp 子系统 | 注释掉会导致 sftp 失败而 ssh 正常 |

直接在配置文件里写 `Port 端口` 只是示意，实际应填自己的端口号。改端口能减少扫描噪音，但不等于安全措施；真正的边界是密钥、白名单与网络层控制。

### 3.4 心跳与断线

NAT 设备与防火墙会清理长时间空闲的连接，表现为「放着不动几分钟就断」。客户端心跳让连接上始终有少量流量：

```
ServerAliveInterval 30
ServerAliveCountMax 3
```

含义是每 30 秒发一次探测，连续 3 次无响应就断开。服务端的 `ClientAliveInterval` 做类似的事，方向相反。两边都设不是冗余，而是覆盖不同方向的空闲清理。

心跳只能减少「假死」，不能防止网络真的中断。长任务仍应放在 `tmux` 或 `screen` 里，传输任务也应如此；断线后重新连上，会话还在，传输可以继续。

### 3.5 IPv6 与地址族

主机同时有 IPv4 与 IPv6 地址时，客户端按解析结果与系统偏好选择，选错就会超时。可以强制地址族：

```bash
ssh -6 user@host
ssh -4 user@host
ssh -G host | grep -i addressfamily
```

`-6` 强制 IPv6，`-4` 强制 IPv4。若配置文件里写了 `AddressFamily inet`（只要 IPv4），命令行再加 `-6` 就互相矛盾，表现为 `Address family not supported` 或连接直接失败。这类问题常被误判成防火墙：先确认域名解析出的地址、实际使用的协议族、以及配置里的 `AddressFamily`，三者一致再去看网络策略。反过来，目标只有 IPv6 地址而本地优先走 IPv4，也会表现为长时间无响应，用 `-6` 可以快速排除。

## 四、文件传输：scp、sftp 与 rsync

### 4.1 scp：最短的路径

```bash
scp -P "$PORT" 项目目录/数据.csv user@host:项目目录/
scp -P "$PORT" -r 项目目录/数据集 user@host:项目目录/
scp -P "$PORT" -p 项目目录/数据.csv user@host:项目目录/
```

`-P` 是大写，指定端口；`-p` 是小写，保留时间戳与权限；`-r` 递归。两个参数只差大小写，作用完全不同，这是远程传输里最常见的输入错误之一。`scp` 的目标参数不能省，只写远端路径会直接报参数不足；写成本地路径时，同名文件会被覆盖。

`scp` 的优点是语法短、所有 OpenSSH 环境都有；缺点是能力有限：不能断点续传，不能只传差异，递归大目录时中途失败只能重来。较新的 OpenSSH 默认用 SFTP 协议实现 `scp`，行为与旧协议略有差异，符号链接与权限的处理要以实际版本为准，跨版本传大量小文件前先做小样测试。

### 4.2 sftp：交互式传输

```bash
sftp -P "$PORT" user@host
```

进入交互界面后，常用命令分本地与远端两套：

| 命令 | 作用 |
|---|---|
| `ls`、`cd`、`pwd` | 远端目录操作 |
| `lls`、`lcd`、`lpwd` | 本地目录操作 |
| `put 文件` | 上传 |
| `get 文件` | 下载 |
| `reget 文件` | 从本地已有大小处续传下载 |
| `reput 文件` | 从远端已有大小处续传上传 |
| `mkdir`、`rm`、`rename` | 远端文件操作 |
| `chmod` | 改远端权限 |
| `!命令` | 执行本地 shell 命令 |

`sftp` 支持断点续传，`reget` 与 `reput` 会先看目标已有多大，再从断点继续。它适合「传一个几十 GB 的文件、中途断过」的场景，但不做增量比较：源文件改了中间一段，续传不会识别，只会按大小拼接，结果可能是坏的。文件被修改过就应重新传，而不是续传。

批处理可以用 `-b`：

```bash
sftp -P "$PORT" -b 项目目录/传输清单.txt user@host
```

清单里一行一条命令，适合固定流程；出错时默认继续还是停止，取决于 `-b` 之外是否加了 `-e` 之类的选项，脚本里应显式处理返回码。

### 4.3 rsync：增量同步

```bash
rsync -avz --progress 项目目录/数据/ user@host:项目目录/数据/
rsync -avz --dry-run --delete 项目目录/数据/ user@host:项目目录/数据/
rsync -avz -e "ssh -p $PORT -i ~/.ssh/id_ed25519" 项目目录/数据/ user@host:项目目录/数据/
```

`-a` 是归档模式，等价于递归、保留权限、时间、属主属组、符号链接与设备文件等一组选项；`-v` 输出详情；`-z` 传输时压缩；`--progress` 显示进度；`--dry-run` 只演练不落盘；`--delete` 删除目标端多余的文件。

尾斜杠是 rsync 最著名的坑：

| 源写法 | 结果 |
|---|---|
| `项目目录/数据/` | 把「数据」目录里的内容放进目标目录 |
| `项目目录/数据` | 在目标目录下再建一层「数据」 |

记忆方法是：源路径以斜杠结尾表示「取内容」，不以斜杠结尾表示「取目录本身」。目标端是否带斜杠不影响这个规则。

rsync 判断「要不要传」的默认依据是文件大小与修改时间，不是内容。大小与时间都相同就跳过，所以时间被改动过、或从不同文件系统复制导致时间精度不同，可能出现「明明不一样却没传」。此时用 `--checksum` 按内容校验，代价是两端都要完整读一遍文件，大目录会慢很多。

真正传输时，rsync 会把文件切成块，用滚动校验和找出两端相同的块，只传不同的部分。这就是「增量」的来源：改了一个大文件的几行，不必重传整个文件。压缩对文本有效，对已经压缩过的图片、压缩包、张量文件往往只浪费 CPU，可以按扩展名排除。

`--delete` 必须与 `--dry-run` 搭配使用一次，看清要删哪些再执行。源路径写错、尾斜杠写反，都可能让目标端的整棵目录被清掉。稳妥的习惯是先演练、再传、最后抽查。

### 4.4 三者怎么选

| 能力 | scp | sftp | rsync |
|---|---|---|---|
| 断点续传 | 不支持 | 支持 `reget`、`reput` | 支持 `--partial` 与增量 |
| 只传差异 | 不支持 | 不支持 | 支持 |
| 递归 | `-r` | 部分版本支持 `-r` | 原生 |
| 删除目标端多余文件 | 不支持 | 不支持 | `--delete` |
| 保留元数据 | `-p` 有限 | `-p` 有限 | `-a` 完整 |
| 交互式浏览 | 不支持 | 支持 | 不支持 |
| 依赖 | OpenSSH 自带 | OpenSSH 自带 | 两端都要安装 |

小文件一两个，`scp` 最快；要在远端目录里挑挑拣拣，`sftp` 顺手；目录同步、反复传输、大文件续传，用 `rsync`。

### 4.5 断点续传的边界

`sftp` 的续传按字节位置拼接，适合「文件没有变、只是连接断了」；`rsync --partial` 保留未完成的临时文件，下次接着传，但它仍会用校验和判断哪些块需要重传，比盲目拼接可靠。`--append-verify` 则假设目标文件是源文件的前缀，只追加剩余部分并校验整体，适合持续追加的日志，不适合内容被改写的文件。

```bash
rsync -avz --partial --progress 项目目录/大文件.bin user@host:项目目录/
rsync -avz --append-verify 项目目录/日志.txt user@host:项目目录/
```

用错模式的后果不是报错，而是得到一个大小正确、内容错误的文件。所以续传之后必须做校验，不能只看「传完了」。

### 4.6 校验

```bash
sha256sum 项目目录/数据.csv
ssh -p "$PORT" user@host "sha256sum 项目目录/数据.csv"
```

两端输出一致才算传对。文件名相同、大小相同都不足以证明内容一致；网络传输有校验和，但那只保证「这一段没坏」，不保证「两端是同一版本」。

长度也能帮助判断算法：SHA256 输出 64 位十六进制，MD5 输出 32 位。原料里有一处把 32 位的值称作 SHA256，实际上那是 MD5，空文件的 MD5 恰好是一串常见的 32 位值。校验命令与摘要长度必须对应，不能拿 MD5 的结果去和 SHA256 比。

只想比较摘要、不想被路径干扰时：

```bash
sha256sum 项目目录/数据.csv | cut -d' ' -f1
```

大目录可以生成清单再比较：

```bash
find 项目目录/数据 -type f -print0 | sort -z | xargs -0 sha256sum > 项目目录/清单.sha256
sha256sum -c 项目目录/清单.sha256
```

清单在本地生成、随文件一起传到远端，再在远端 `-c` 校验，可以一次覆盖整棵树。生成清单时用了绝对路径，换机器后路径对不上，所以要在项目目录内用相对路径生成。

### 4.7 大目录的传输流程

1. 先看空间：`df -h` 与 `df -i`，块空间与 inode 都要够。
2. 先演练：`rsync -avz --dry-run --delete 源/ 目标/`，确认增删清单。
3. 正式传：加 `--partial`，断线可续；放 `tmux` 里跑。
4. 再校验：抽样 `sha256sum`，或整树清单 `-c`。
5. 最后切换：传到临时目录，校验通过后再 `mv` 到正式位置，避免半成品被下游读到。

### 4.8 图形客户端与编辑器

命令行之外，图形客户端适合浏览目录、拖拽少量文件、临时改权限。以 FileZilla 为例：在站点管理器新建站点，协议选 SFTP，主机填 `host`，端口填 `port`，登录类型选密钥文件，用户填 `user`，再选中私钥文件。首次连接会弹出主机密钥确认，指纹应与服务器一致；选错协议（例如选成 FTPS）会一直连不上，因为两者虽然都叫「安全文件传输」，底层完全不同。

WinSCP 在 Windows 上提供类似功能，可以导入其他工具格式的密钥；macOS 上常见的是 Cyberduck。图形客户端的能力边界与 `sftp` 接近：能续传单个文件，但不做目录级增量比较，也不擅长处理几十万个碎文件。批量同步仍应交给 `rsync`，图形界面只用于查看与应急。

编辑器的远程模式走的是同一条 SSH 链路。VS Code 的 Remote-SSH 直接读取 `~/.ssh/config`，把 Host 别名填进去即可，密钥、跳板、端口都复用已有配置，不必在编辑器里再填一遍。JetBrains 系列的远程开发同理。这样做的附带好处是：命令行能连上，编辑器基本也能连上；编辑器连不上时，先用 `ssh -vvv 别名` 验证配置，而不是怀疑插件。

## 五、跳板机与端口转发

### 5.1 经过跳板机

目标主机在内网、只能从跳板机到达时，用 `ProxyJump`：

```bash
ssh -J user@jump-host -p "$PORT" user@host
```

`-J` 让本地先连跳板机，再由跳板机建立到目标的 TCP 连接，认证仍然是端到端的：跳板机只转发加密流量，看不到目标主机的私钥或会话内容。多层跳板用逗号分隔，按顺序串联。

写进配置更清爽：

```
Host target
    HostName host
    User user
    Port 端口
    ProxyJump jump-host
```

对应的文件传输也走同一条路：

```bash
rsync -avz -e "ssh -J user@jump-host -p $PORT" 项目目录/数据/ user@target:项目目录/数据/
```

`scp` 与 `sftp` 同样支持 `-J`，但选项位置与大小写要注意。跳板机需要允许 TCP 转发；如果服务端 `AllowTcpForwarding no`，`-J` 会在建立通道时失败，报 `administratively prohibited`。

旧方案是 Agent 转发加 `ProxyCommand`。Agent 转发（`-A`）把本地 ssh-agent 的套接字暴露到跳板机，跳板机上的管理员理论上可以借用它登录其他机器；`ProxyJump` 不需要这样做，权限更小。能在 `-J` 与 `-A` 之间选时，选 `-J`。

### 5.2 三种端口转发

| 类型 | 选项 | 监听方 | 流量方向 | 典型用途 |
|---|---|---|---|---|
| 本地转发 | `-L` | 本地 | 本地端口 → 远端网络中的目标 | 访问内网 Web、VNC |
| 远程转发 | `-R` | 远端 | 远端端口 → 本地网络中的目标 | 把本地服务临时暴露给远端 |
| 动态转发 | `-D` | 本地 | 本地 SOCKS 代理 → 任意远端目标 | 浏览器走远端出口 |

本地转发的语法是 `-L 本地地址:本地端口:目标主机:目标端口`。省略本地地址时只监听回环，这是安全的默认；把本地地址写成通配地址、让所有网卡都监听，会把端口暴露给本地网络，非必要不要这么做。

```bash
ssh -N -L "$LOCAL_PORT:host:$TARGET_PORT" user@jump-host
```

`-N` 表示不执行远程命令，只做转发；命令会一直挂在前台，要后台跑就配合 `tmux`，而不是简单地加 `&` 后关掉终端。

远程转发方向相反，语法是 `-R 远端地址:远端端口:目标主机:目标端口`。它常被用来把本地开发服务临时映射到远端，是否对外可见取决于服务端的 `GatewayPorts` 设置；默认只绑回环，改成对外监听要明确知道风险。

动态转发 `-D` 在本地起一个 SOCKS 代理，应用把流量交给它，由 SSH 侧转发。它只处理 TCP，不处理 UDP，也不是完整的 VPN；浏览器配置 SOCKS 后可以访问远端能到达的地址。

### 5.3 转发的安全边界

端口转发把网络可达性复制了一份，配置时要问三个问题：谁在监听、监听在哪个地址、谁能连进来。只监听回环、只开必要的目标、用完就关，是最低要求。把数据库或桌面端口通过 `-L` 长期挂在公网主机的通配地址上，等于绕过了原有的网络隔离。

服务端可以用 `AllowTcpForwarding`、`PermitOpen` 限制可转发的目标；跳板机场景下这些限制比在客户端自律更可靠。

## 六、远程桌面：VNC、RDP 与 X11

### 6.1 四种图形方案

| 方案 | 传什么 | 带宽 | 安全边界 | 适用 |
|---|---|---|---|---|
| SSH 终端 | 文本 | 低 | 强，走 SSH | 命令行、训练、运维 |
| X11 转发 | 单个程序的绘图调用 | 中 | 走 SSH | 轻量 GUI 工具 |
| VNC | 帧缓冲像素 | 高 | 默认弱，需隧道 | 跨平台完整桌面 |
| RDP | 桌面协议 | 中高 | 较好，需正确配置 | Windows 桌面、xrdp |

SSH 终端是默认选择：绝大多数训练、编译、文件操作都不需要图形界面。只有必须用图形工具（标注软件、浏览器、IDE 的图形调试器）时，才考虑后面三种。

### 6.2 VNC 与 RDP 的差别

VNC 工作在帧缓冲层：服务器把屏幕像素编码后发给客户端，客户端把键鼠事件发回去。它不关心上层是什么操作系统，所以 Linux、macOS、Windows 都能用；代价是像素传输对带宽敏感，画面变化大时明显卡顿。多数 VNC 服务端默认不加密，必须套 SSH 隧道或配 TLS。

RDP 是 Windows 的桌面协议，传输的是绘图指令与窗口内容，带宽利用比 VNC 好，支持剪贴板、磁盘映射、多显示器、音频重定向。Linux 上可以用 xrdp 提供 RDP 入口，但桌面体验取决于后端会话与窗口管理器。

| 维度 | VNC | RDP |
|---|---|---|
| 传输层 | 帧缓冲 | 桌面协议 |
| 跨平台 | 好 | Windows 为主，Linux 靠 xrdp |
| 带宽 | 较高 | 较低 |
| 剪贴板与磁盘重定向 | 部分实现支持 | 原生支持 |
| 默认加密 | 多数实现较弱 | 较好 |
| 多用户会话 | 取决于实现 | 服务端支持 |

### 6.3 把桌面藏进 SSH 隧道

正确做法是让 VNC 或 RDP 只监听回环，客户端先建 SSH 隧道，再连本地端口：

```bash
ssh -N -L "$LOCAL_PORT:localhost:$VNC_PORT" user@host
```

然后 VNC 客户端连接 `localhost:$LOCAL_PORT`。服务端启动 VNC 时加 `-localhost` 之类的选项，确保它不直接对外监听。RDP 同理，把 `$VNC_PORT` 换成 RDP 的端口即可。

这条链路的安全性与 SSH 相同：认证、加密、主机密钥校验都由 SSH 负责，桌面协议本身是否加密变得不重要。缺点是多一层转发，延迟略增；对交互式桌面，这点延迟通常可以接受。

### 6.4 X11 转发

```bash
ssh -X user@host
ssh -Y user@host
```

`-X` 开启可信转发，`-Y` 放宽访问控制。登录后在远端运行图形程序，窗口显示在本地。它只传这个程序的绘图调用，不传整个桌面，所以比 VNC 轻；但每个绘图操作都要过网络，复杂界面会明显变慢。

`-Y` 的安全边界更宽，远端程序对本地 X 服务器的访问权限更大，只在信任远端时使用。日常优先 `-X`，并且只运行必要的程序。

### 6.5 第三方远控工具

TeamViewer、AnyDesk、向日葵一类工具靠厂商服务器做 NAT 穿透，不需要公网地址，适合给外部人员临时协助。代价是流量经过第三方、客户端权限较大、企业环境可能不合规。能通过 SSH 隧道解决时，不必引入这类工具；必须用时，设置临时密码、限时访问、事后解除。

## 七、可靠性：断线、续传与收尾

### 7.1 断线从哪里来

| 现象 | 原因 | 处理 |
|---|---|---|
| 空闲几分钟后断开 | NAT 或防火墙清理空闲连接 | 客户端与服务端都设心跳 |
| 大文件传到一半停住 | 网络切换、链路抖动 | `rsync --partial` 或 `sftp reget` |
| 睡眠唤醒后连接失效 | 本机休眠，TCP 连接已断 | 重连，任务放 `tmux` |
| 传输速度骤降 | 链路拥塞、压缩开销、磁盘瓶颈 | 看 `iftop`、`iostat`，调整 `-z` |
| 传完文件大小不对 | 磁盘满、配额、中断未发现 | `df -h`、`df -i`、校验和 |

### 7.2 会话与传输分离

传输命令放在 `tmux` 里跑，SSH 断线不影响它；重新登录后 `tmux attach` 接回，看进度、重试都方便。直接在交互 Shell 里跑 `scp`，终端一断，进程收到 SIGHUP，传输就停了。

```bash
tmux new -s transfer
# 在会话里执行 rsync
# 断线后重新登录
tmux attach -t transfer
```

### 7.3 原子替换

传到一半的文件如果直接被下游读取，会得到不完整的结果。稳妥流程是传到临时名，校验通过后再改名：

```bash
rsync -avz --partial 项目目录/数据.csv user@host:项目目录/数据.csv.part
ssh -p "$PORT" user@host "sha256sum 项目目录/数据.csv.part"
sha256sum 项目目录/数据.csv
ssh -p "$PORT" user@host "mv 项目目录/数据.csv.part 项目目录/数据.csv"
```

`mv` 在同一文件系统内是原子改名，读方要么看到旧文件，要么看到新文件，不会看到半个。跨文件系统时 `mv` 退化为复制加删除，原子性不成立，临时文件要放在目标同一目录下。

### 7.4 权限与时间的保留

跨机器复制最容易丢的是权限与时间。`rsync -a` 保留权限、时间、属主属组；`scp -p` 保留时间与模式；`sftp` 的 `-p` 类似。目标端 umask 会影响新建文件的权限，必要时用 `--chmod` 明确指定，而不是传完之后再批量 `chmod`。

属主属组只有 root 才能任意保留；普通用户传到远端，文件属主会变成登录用户，`-a` 里的属主保留会失败或报警告。这种场景下用 `-rlptgo` 里去掉 `o`、`g` 的组合，或者接受属主变化，只保留权限与时间。

### 7.5 带宽与压缩的取舍

传输时间近似等于数据量除以有效带宽：

$$
t \approx \frac{S}{B}.
$$

压缩是否划算，取决于省下的字节是否多于压缩消耗的 CPU 与时间。文本、日志、代码、未压缩的表格压缩收益明显；图片、视频、压缩包以及不少科学数据格式本身已经压缩过，再加 `-z` 往往只是让两端 CPU 更忙。带宽充足而 CPU 紧张时，关掉压缩；带宽紧张而 CPU 有余时，再打开。

带宽受限的链路上可以用 `--bwlimit` 限速，避免一个同步任务占满整条线路，影响其他人的交互登录。限速值应低于链路可用带宽，留出余量；限得太低会让小文件传输的往返延迟占比变大，反而更慢。

## 八、原料勘误与概念澄清

| 原料或常见表述 | 问题 | 本文口径 |
|---|---|---|
| SFTP 就是加密的 FTP | SFTP 是 SSH 的子系统，与 FTP 协议无关；FTPS 才是在 FTP 上加 TLS | 4.2 节 |
| `scp` 示例只写远端路径 | 缺少本地目标参数，命令不完整 | 4.1 节补全目标 |
| 把 32 位十六进制摘要称为 SHA256 | 32 位是 MD5，SHA256 是 64 位 | 4.6 节 |
| `ssh user@host -p 端口` 是标准写法 | 选项放在目标后依赖参数重排，不通用 | 统一选项在前 |
| `scp` 支持断点续传 | `scp` 没有续传能力 | 用 `sftp reget` 或 `rsync --partial` |
| `rsync` 默认按内容比较 | 默认按大小与修改时间快速判断 | 需要内容比较时加 `--checksum` |
| VNC 可以直接暴露在公网 | 多数 VNC 实现默认不加密 | 只监听回环，走 SSH 隧道 |
| 改 SSH 端口就等于安全 | 改端口只减少扫描噪音 | 密钥、白名单、网络控制才是边界 |

## 九、总结

| 知识块 | 必记结论 |
|---|---|
| SSH 握手 | TCP、版本、密钥交换、用户认证、会话五段；排错先定位段 |
| 主机密钥 | 首次确认指纹，变更先核对再删记录；`accept-new` 不放过变更 |
| 公钥认证 | 私钥 600、`.ssh` 700、`authorized_keys` 600；`IdentitiesOnly` 防试探过多 |
| 配置 | `~/.ssh/config` 的 Host 块；`ssh -G` 看生效值；命令行优先 |
| scp | `-P` 端口、`-p` 保留、`-r` 递归；无断点无增量 |
| sftp | 交互式，`reget`、`reput` 续传；按字节拼接，文件变了不能续 |
| rsync | 尾斜杠决定取内容还是取目录；默认快速判断；`--delete` 先演练 |
| 校验 | SHA256 64 位、MD5 32 位；两端对比，或整树清单 `-c` |
| 跳板 | `-J` 端到端认证，优于 agent 转发；跳板需允许转发 |
| 端口转发 | `-L` 本地听、`-R` 远端听、`-D` SOCKS；只绑回环 |
| 桌面 | 优先 SSH 终端；VNC 与 RDP 只监听回环，经 SSH 隧道进入 |
| 可靠性 | 心跳防假死，`tmux` 保会话，临时文件加校验再原子改名 |

远程连接的配置项很多，但判断标准只有三条：身份有没有被正确验证，数据有没有完整到达，暴露面有没有超出必要。把这三条套到密钥、传输与隧道上，具体选项就有了取舍依据；遇到报错时，也能先判断是「连不上」「进不去」还是「传不对」，而不是在配置文件里盲目改参数。
