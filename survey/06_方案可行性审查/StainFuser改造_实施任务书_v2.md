## §1 背景与目标（一段话）

现有工作：H&E→IHC 虚拟染色，非配对设定，baseline 是 PSPStain（PALS + PCLS 两个 loss），之前基于 HistDiST + DB-DCE 自建过一个版本（有结构性缺陷，已单独审查）。

**本次目标**：以 StainFuser（SD 2.1 latent diffusion + ControlNet）为骨架，改造成 H&E→IHC 生成框架，路线为

```
H&E → 语义染色表示 Z → 扩散生成 → 物理渲染 → IHC RGB
```

**核心待验证假设**：把生成空间从「RGB 潜码」换成「有物理意义的染色浓度三通道」，能让模型**可解释**（浓度可直接做 H-score 监督）且**不牺牲可复现性**。

**优先级（用户明确给定，冲突时按此排序）**：可复现 > 可解释 > 改动小 > 有公开代码 > 有实验收益 > 复杂度。

## §2 铁律（不许违反）

| # | 铁律 | 为什么 |
|---|---|---|
| 1 | **不许改 `conv_in` 的通道数。** UNet 的 `conv_in` 是 4 通道、`down_blocks`/`mid_block` 冻结且承载预训练先验。 | 改了 = 放弃预训练权重，与「改动小」直接冲突 |
| 2 | **`controlnet_cond` 必须保持 3 通道。** 见 §5.2。 | 条件编码器第一层写死 `Conv2d(3,16,3,1)`；且改通道数会让 checkpoint 加载报错 |
| 3 | **不许对正交补通道（`C_res`）加非负约束。** 只对真实染色（`C_H`/`C_DAB`）加 softplus。 | `C_res` 是投影，真实数据会落在负侧；clamp 会静默抹掉负分量并归零梯度 |
| 4 | **不许用 `clamp(min=0)` 处理任何物理量。** 要非负就用 `softplus`。 | 历史教训：`clamp` 会静默吞掉梯度 |
| 5 | **每一个 clamp / clip 都要记日志：被截断的像素比例。** | 这是「隐藏失败」的计数器。把可检测的失败变成不可检测的失败，本项目已犯过三次 |
| 6 | **不许用单一指标（尤其 PSNR）判断成败。** | 非配对病理生成里 PSNR 高 ≠ 质量好 |
| 7 | **不许在采样循环内不做钳位、只钳终点。** 若要钳，逐通道、每一步都钳，并记录比例。 | 末端补救来不及 |
| 8 | **stain matrix 在监督侧必须固定（队列级），不许逐图估计。** | 逐图估计会让「浓度」吸收每张片的染色差异，而那个差异正是 H-score 要保留的信号 |
| 9 | **不许把「条件控制」写成「显式解耦」。** | 表述准确性要求 |
| 10 | **任何「效果变好」的结论，必须同时给出它的极值/尾部是否变差。** | 均值变好 + 尾部变差是最典型的「掩盖失败」 |

### E0.1 ★ 三通道重建上限测试（最高优先级）

**目的**：回答「把生成空间换成染色浓度，表示本身会不会丢信息」。

**关键前提（已数学验证）**：RGB→C→RGB 这个往返**在数学上是恒等式**，只要 ① `M` 是满秩 3×3、② 不做非负截断。**`I₀` 不需要已知——它在往返中精确抵消**（`I₀·(I/I₀) = I`）。

**所以往返误差只可能有两个来源**：`M` 秩亏、非负截断。（`I₀` 误差与 uint8 量化**不造成往返误差**，见 §4.1 表。）

**输入**：50–100 张真实 IHC patch（512×512 uint8 RGB，覆盖不同 DAB 强度）

**步骤**：

```python
import numpy as np

# ---- 三个待比较的 M ----
# s_H, s_DAB：单位化的 OD 向量（Ruifrok 归一化）
s_H   = np.array([0.65, 0.70, 0.29]); s_H  /= np.linalg.norm(s_H)
s_DAB = np.array([0.27, 0.57, 0.78]); s_DAB /= np.linalg.norm(s_DAB)

M_32 = np.column_stack([s_DAB, s_H])                       # 现状：3x2
M_33 = np.column_stack([s_H, s_DAB, np.cross(s_H, s_DAB)]) # 3x3，第三列未归一
# M_33_orth：对 M_33 做 Gram-Schmidt 正交化 → M^-1 == M^T

def od(img, I0=1.0):
    return -np.log10(np.clip(img, 1e-6, 1.0) / I0)

for name, M in [("3x2 现状", M_32), ("3x3 叉积", M_33), ("3x3 正交", M_33_orth)]:
    OD_in = od(patch.astype(np.float32) / 255.0)      # (N,H,W,3)
    C     = np.einsum('ij,...j->...i', np.linalg.pinv(M), OD_in)
    OD_out = np.einsum('ij,...j->...i', M, C)
    img_out = 255.0 * 10.0 ** (-OD_out)

    mae   = np.abs(img_out - patch).mean()
    psnr  = 10*np.log10(255.0**2 / (np.mean((img_out-patch)**2) + 1e-12))
    frac_neg_C = (C < 0).mean(axis=(0,1,2))           # 逐通道负值比例

    # 理论残差（不依赖数据）：M 到自身张成空间的投影
    P = M @ np.linalg.pinv(M)
    proj_residual = np.abs(P @ OD_in.reshape(-1,3).T - OD_in.reshape(-1,3).T).mean()

    print(name, "MAE=%.5f PSNR=%.2f 负C比例=%s 投影残差=%.5f"
          % (mae, psnr, np.round(frac_neg_C,4), proj_residual))
```

**必须额外报告的指标**：

| 指标 | 为什么必须报 |
|---|---|
| 浮点往返 MAE / PSNR / SSIM / ΔE(CIELAB) | 主判据 |
| **被非负截断的像素比例（逐通道）** | 铁律 5。它是原因 2 的直接度量 |
| **`C_res` 的分布（min / p1 / mean / p99 / max）** | `C_res` 有符号，这个分布决定它是不是个有用的诊断通道 |
| **理论投影残差** `‖P·OD − OD‖` | 不依赖数据，直接量化「M 的秩亏有多严重」 |
| **uint8 重量化后的 MAE** | 单独报，说明它是量化底噪而非方法误差 |

**判定标准（硬性）**：

- `3x2` 的 MAE 应在 **0.02 量级**（对应用户已测的 `‖Render(Deconv(x))−x‖ = 0.023`）
- `3x3` 的浮点往返 MAE 应降到 **1e-5 以下**（理想是 1e-7 量级）
- **若 `3x3` 没有显著下降 → 停下来报告**，说明 `M` 的向量本身与你的数据不匹配（→ 改用 Macenko/Vahadane 在你的数据上重估）

**参考量级（我用随机 OD 实测，仅作数量级参考）**：

| M | 往返 MAE(OD) | 最大 |
|---|---|---|
| 3×2 `[s_DAB, s_H]` | 0.208 | 0.961 |
| 3×3 `[s_H, s_DAB, s_H×s_DAB]` | **0.000** | 0.000 |

**产出**：`e01_closedloop.json` + 4 张对比图（原图 / 3×2 还原 / 3×3 还原 / 误差热图）+ 一段结论。

### E0.1b 为什么 `I₀` 和 uint8 不算在内（**别搞错，这是已修正的结论**）

| 原因 | 是否造成往返误差 | 说明 |
|---|---|---|
| **① M 秩亏** | **是（主因）** | 确定性。`M·pinv(M) = P` 是正交投影，残差 = 正交补分量。可修：加第三个正交分量 |
| **② 非负截断** | **是** | 仅当真实 `C` 有负分量。可修：去掉 clamp |
| ③ `I₀` 估计误差 | **否** | **精确抵消**。实测：`I₀=1.0` 与 `I₀=0.87` 的往返 MAE 都是 `~7e-17` |
| ④ uint8 量化 | **否** | 往返本身精确（输入 uint8 → 还原同一个 uint8）。它的真实作用是**给 C 目标加噪声**：`dC/dI = 1/(I·ln10)·M⁻¹`，`I≈0.1` 时 `ΔOD≈0.017`，`I≈0.04` 时 `ΔOD≈0.043` |

**⇒ 但 ③ ④ 仍然必须处理**：
- ③：`I₀` **必须固定为队列级 3 通道**。它不影响重建，但影响 `C` 的**可比性**，进而影响 H-score 阈值位置。
- ④：**这是监督浓度的精度上限**，必须在报告里写清楚，因为它决定了 `C_DAB` 监督能有多准。

**⇒ 诊断顺序**（`‖I′−I‖` 大时）：

```
├─ 第 1 步：看被截断像素比例
│   ├─ 高（>1%）→ 原因 ②。去掉 clamp，重测
│   └─ 低 → 继续
├─ 第 2 步：看 M 的秩
│   ├─ 3×2 → 原因 ①（主因）。加到 3×3，重测
│   └─ 3×3 且几乎不变 → M 向量本身不对 → 在你自己数据上重估
└─ 第 3 步：都排除了 → 不该再有误差（只剩浮点精度）
    └─ 若仍有 → 检查是不是在某处偷偷 clamp 了
```

### E0.2 你的 IHC 片子到底有没有伊红复染？

**目的**：决定第三通道用「正交补残差」还是「伊红」。

**步骤**：用三染矩阵（H / E / DAB）对真实 IHC patch 做解混，**单独可视化 E 通道**。

**判定**：
- E 通道有**空间相干的结构**（能看出细胞质/间质形态）→ 有伊红 → 第三通道可用 `C_E`
- E 通道基本是噪声/均匀 → **没有伊红**（标准 IHC 流程通常不加）→ **用正交补残差 `C_res`**

**产出**：E 通道的可视化图 + 它的空间自相关值 + 结论。

> **背景**：常规 IHC 流程不加伊红复染（伊红是粉色的，会干扰 DAB 判读）。所以**预期结果是没有**，但必须实测——这是「有条件成立」的条件。

### E0.3 stain matrix 敏感性

**目的**：回答「换 M 会不会改变 DAB 浓度图，从而改变 H-score」。

**步骤**：取 20–30 张真实 IHC，用 4 种 M 各算一遍 `C_DAB`：

1. Ruifrok 固定标准向量
2. Macenko（逐图估计）
3. Vahadane（逐图估计）
4. **队列级 Macenko**（在全部训练图上估一次，然后固定）

然后按 DAB-OD 阈值分箱（IHC Profiler 四箱或阴性对照标定）算逐细胞 H-score。

**必须报告**：
- 四种 M 下 H-score 的 **ICC（组内相关系数）**
- **Bland–Altman 的 95% 一致性界限**
- 不同 M 之间 H-score 的**绝对偏差分布**

**判定**：
- ICC > 0.9 → M 的选择不敏感，可以放心用固定 M
- ICC < 0.75 → **M 的选择直接决定 H-score**，必须在论文里明确报告用的是哪一个，并把它作为方法的一部分写清楚

> **已知上界**：Ruifrok 2001 量化过——DAB 饱和时，被误分解出来的「苏木素」可达实测 IOD 的 **65%**。所以不能假设「M 换了但结果差不多」。

```python
# src/dataset.py L195
self.paired_stems = list(itertools.product(source_stems, target_stems))   # ← 笛卡尔积 = 非配对

# src/dataset.py L239-241
source_idx = list(self.source_lookup.keys()).index(idx_pair[0])
stylized_img_n = self.mmap[idx_pair[1]][source_idx]      # ← 决定性的一行
```

`mmap[target_id]` 是一个数组，用 **`source_idx`** 去索引它。所以 `stylized_dir/{target_id}.npy` 里存的是「**把源图 i 染成目标 j 的色**」的结果，**逐张源图预先算好**。

| batch key | 原任务（染色归一化） | 在训练里的角色 | **H&E→IHC 要换成什么** |
|---|---|---|---|
| `Source Images` | 源图（结构 A） | → `controlnet_cond`（原始 RGB，未过 VAE） | **H&E patch** |
| `Target Images` | 目标图（另一张图，外观 B） | → VAE encode → 拍平 `(B,4096,4)` → `encoder_hidden_states` | **从 IHC 域里随机抽的参考片**（**必须非配对**，见 §5.3） |
| `Transformed Images` | **源图 i 用目标 j 的颜色重上色**（结构 A + 外观 B） | → 加噪成扩散输入 **+ 作为损失目标** | **与 H&E 源图同区域的真实 IHC**（BCI 的配对片） |

**★ 为什么这一节是整份任务书的地基**：原任务的 `Transformed` 是「**源图的重新上色版**」⇒ **结构与源图恒等**。H&E→IHC 里**不存在这样的东西**——真实 IHC 的蛋白分布不是 H&E 的颜色变换能得到的。所以：

- **`Transformed Images` 必须换成真实配对 IHC**（BCI 的 H&E / IHC 配对片，按区域配准后裁同一坐标的 patch）。这是唯一让「损失目标」有意义的做法。
- **`Target Images` 必须保持非配对**（随机抽另一例的 IHC）。理由见 §5.3 与 §5.6。

**作者自己 README 的那句话可以当旁证**：*"transforms a source image to have **the staining characteristics** of an input target image"* —— 搬的是**染色特征**，内容不变。

**⇒ 一句话检查**：如果你实现完之后，`Transformed` 还是「用某个颜色变换算出来的」，那**你做的还是染色归一化，不是虚拟染色**。这一条是阶段 1 的自检门禁。

### §5.1 先搞清楚要改什么（读代码，不要猜）

StainFuser 有**两条**条件通道，两条都携带目标图信息：

| 通道 | 代码位置（**已回源逐行核对**） | 现在喂什么 | 我们要改成什么 |
|---|---|---|---|
| `controlnet_cond` | `recipe.py` **L269**（`StainFuserEngine.training_step`）/ **L343**（`validation_step`）/ **L400**（`InferenceRecipe.predict_step`） | **原始 RGB 像素**：`src_latents = batch["Source Images"]`（3ch，`[0,1]`，512²，**未过 VAE**） | H&E 的**染色分解结构分量**（3ch，见 §5.2） |
| `encoder_hidden_states` | `recipe.py` **L268 + L277**（同一次前向喂给 conditioner **和** noise_predictor **两条路**）/ L342+L351 / L399+L408 | 参考片 VAE latent 拍平成 `(B,4096,4)` | **IHC 参考片的 VAE latent，形状不变，原样复用**（见 §5.3） |

**★ v1 在这里的判断是错的，v2 已修正。** v1 写「推理时目标图根本不存在 ⇒ 训练目标被短路」——**口径不对**。已核实 `paired_stems = itertools.product(source_stems, target_stems)`（`dataset.py` L195），**target 本来就是非配对的**，所以「目标图 = 答案」这个说法不成立。

**真正的问题在损失目标那一侧**（见 §5.0）：原任务的 `Transformed` **结构与源图恒等** ⇒ 网络若去抄参考片的**空间内容**，输出结构就变成参考片的结构 ≠ 损失目标的结构 ⇒ **损失变大**。⇒ 那条 4096 token × 4 维的高带宽通道**被逼着**只能当「外观规格」用。

**⇒ unpaired 不是「unpaired 也能行」的例证，unpaired 恰恰是它安全的原因。** 反过来说更清楚：如果源图和参考片**配对**（结构相同），这条通道立刻退化成抄答案通道。

**★ 换到 H&E→IHC 之后，安全条件必须重新检查**：真 IHC 的结构**不是** H&E 的颜色变换能得到的 ⇒ 上面那条「抄了就亏」的约束**消失了**。此时是否安全，完全取决于 `corr(结构(参考片), 结构(真值))`：

| 参考片 R | corr | 后果 |
|---|---|---|
| **随机另一例 IHC（必须用这个）** | ≈0 | **安全**。R 只提供 DAB 的边缘统计（多黑 / 背景多白 / 纹理尺度），不含任何空间信息 |
| BCI 配对 IHC（同组织相邻切片） | **≈1** | **抄 R 就是最优解** ⇒ 退化成 IHC→IHC 重上色，H&E 分支变装饰；推理时无 IHC 可喂 ⇒ 崩 |

**⇒ 铁律：`Target Images` 必须是随机非配对 IHC。** 判定方法见 §5.6。

**⚠️ 关于 `encoder_hidden_states` 的一个重要事实（别理解错）**：
参考片 latent 是**拍平成 4096 个 token** 的，而 4096 个 token 与 **64×64 潜码网格一一对应**。所以那个 `Linear(4,1024)` 仿射映射是**逐 token** 施加的——**它保留了完整的空间结构**，不是把图像压成一个全局颜色向量。

**⇒ 这意味着**：这条通路的带宽**足够把参考片的空间内容原样搬进 UNet**。在原任务里（抄了就亏）这是无害的；换成 H&E→IHC 后**约束消失**，所以「带宽」本身就成了风险源 —— 必须靠 §5.6 去测、靠「非配对」去掐断。

**⇒ 并且**：正因为这条通路保留了完整空间结构，**结构信息不能指望它**。源图的结构必须由 `controlnet_cond`（§5.2）完整提供 —— 这不是可选优化，是必需的。

### §5.2 改 `controlnet_cond`：换成染色分解的结构分量

**★ 硬约束：必须保持 3 通道。**

| 约束 | 实测事实 |
|---|---|
| 条件编码器第一层写死 3 通道 | `conv_in = Conv2d(3, 16, 3, 1)`。喂 1 通道 → `RuntimeError: expected input[1,1,512,512] to have 3 channels` |
| `conditioning_embedding_in_channels` 是**死参数** | `arch.py` L52–61 只把 `conditioning_embedding_out_channels` 传进 `super().__init__()`，输入通道数从未被使用。**改它不会生效** |
| 改通道数会让 checkpoint 加载报错 | 实测：`load_state_dict(strict=False)` 只忽略「缺键/多键」，**不忽略尺寸不匹配** → `size mismatch for controlnet_cond_embedding.conv_in.weight` |

**⇒ 推荐做法**：保持 3 通道，只换内容。

```python
# ---- 默认（秩 2 代表）：H&E 的染色分解 ----
cond = torch.stack([C_H_he, C_E_he, C_H_he + C_E_he], dim=1)   # (B,3,H,W)

# ---- 消融 1：秩 1（丢掉伊红，用来看「膜形态」到底靠谁）----
cond = C_H_he.repeat(1, 3, 1, 1)

# ---- 消融 2：秩 3（唯一带泄漏风险的那一臂，只作反面教材）----
cond = torch.stack([C_H_he, C_E_he, C_DAB_漂移配对], dim=1)
```

**★ 为什么候选只有这三个（这是本节最容易浪费算力的地方）**

`controlnet_cond` 的入口是 `Conv2d(3,16,3,1)`，**首层权重可训**（ControlNet 默认全量可训）。设首层权重为 `(a,b,c)`，则：

| 输入 | 首层能算出的东西 | 秩 | 信息量 |
|---|---|---|---|
| `(H,H,H)` | `(a+b+c)·H` | **1** | **丢掉了伊红** |
| `(H,H,E)` | `(a+b)·H + c·E` | **2** | **与下一行完全等价** |
| `(H,E,E)` | `a·H + (b+c)·E` | **2** | **完全等价** |
| `(H,E,0)` | `a·H + b·E` | **2** | **完全等价** |
| `(H,E,DAB)` | `a·H + b·E + c·DAB` | **3** | **唯一秩 3** |

因为 `(a+b)`、`(b+c)`、`a` 都能取任意实数，**中间三行能表达的函数集合完全相同** ⇒ `(H,H,E)` / `(H,E,E)` / `(H,E,0)` 互为**近似空操作**，在它们之间做消融**是浪费算力**。

**并且：「重复通道」≠「加权」。** 网络可以把 `w₁` 设成 1、`w₂` 设成 0 ⇒ `(H,H,E)` 并不会让 H「更重要」。**要加权必须显式乘系数。**

⇒ **消融表就三行**：`(H,H,H)` / `(H,E,·)` / `(H,E,DAB)`。

**★ 关于 `(H,E,DAB)` 这一臂的一个重要纠正**：v1 把它标成「候选」，**应当改标为「泄漏对照」**。理由：H-score / 阳性比例 / DAB-IOD **全是「量」指标**。喂入「量正确、结构漂移」的 DAB ⇒ 模型可学「量 → 量」，**验证集 H-score 会很漂亮**；推理时无量可依 ⇒ 退化为数据集均值。而**结构错恰好掩盖了这个泄漏**（空间上看起来「DAB 没帮上忙」，全局量却在静默泄漏）。读出方法见 §5.6。

**一个降低风险的好消息**（已核对代码）：`controlnet_cond_embedding` **不在从预训练 UNet 复制的那批层里**——`arch.py` 只复制 `conv_in / time_proj / time_embedding / class_embedding / down_blocks / mid_block`，条件编码器是新建的（末层 `conv_out` 是 zero-conv）。**所以换输入内容不会丢掉任何预训练先验**，只是让已训练好的条件编码器面对一个新输入分布。**这是低风险操作。**

### §5.3 `encoder_hidden_states`：**原样复用 StainFuser 风格注入分支**

**★ 决策（2026-10-06，用户定）**：这一路**不动架构**，按 StainFuser 原本的用法复用 —— 喂一张**真实 IHC 参考片**的 VAE latent，拍平成 `(B,4096,4)`，走原来的 `encoder_projector`（`Linear(4,1024)`）→ cross-attn。**不换成 token、不改维度、不改层。**

| 项 | 取值 | 说明 |
|---|---|---|
| 形状 | `(B, 4096, 4)` | **与 baseline 完全相同** |
| 来源 | `prepare_latent(batch["Target Images"])` | **`recipe.py` 一行都不用改** |
| 改动点 | 只改 `dataset.py` 里 `Target Images` 的**抽样规则** | 见下 |
| `encoder_projector` | `Linear(4, 1024)` **不动** | 无尺寸问题，checkpoint 直接加载 |
| 新增可学习参数 | **0 个** | 这是「改动最小」的那个选项 |

#### §5.3.1 ★ 抽样规则：**必须显式排除配对组合**

`dataset.py` L195 现有逻辑是：

```python
self.paired_stems = list(itertools.product(source_stems, target_stems))
```

**每个 epoch 会见到所有 (源, 目标) 组合 —— 其中包含配对的 (H&E_i, IHC_i)。** 直接沿用就等于把 §5.1 表里「corr ≈ 1」那一行**亲手造出来**。

**必须改成**（二选一，推荐第一种）：

```python
# 方案 1（推荐）：每个样本随机抽一张「不同病例」的 IHC
#   在 __getitem__ 里：
#   target_id = random.choice([t for t in target_stems if case_of(t) != case_of(source_id)])
#   注意：必须按「病例」排除，不是按「文件名」——
#         同一病例的不同切片仍高度相关（相邻切片、同一组织块）
#
# 方案 2（更省事但有风险）：排除 target_id == source_id
#   只有当 BCI 里 H&E 与 IHC 的文件名能一一对应时才可用。
#   ⚠️ 若命名对不上，这个排除是空的，泄漏照旧发生 —— 必须打印排除前后的组合数核对。
```

**★ 必须记录的诊断量**：每个 epoch 打印
① 抽样出的 `(source_case, target_case)` 配对中**同病例的比例**（**必须为 0**）；
② 参考片与真值的 **DAB 浓度图相关系数**（见 §5.6，这是泄漏的直接读数）。

#### §5.3.2 备选对照臂：可学习 token（**不是默认，只作消融**）

如果 `Target Images` 换成「随机非配对 IHC」之后发现**参考图几乎没被用上**（§5.6 的 B ≈ C），那说明这条路只是在提供「目标域染色外观」—— 此时用一个可学习 token 就能达到同样效果，且推理时不需要额外输入。**所以要保留这条对照臂。**

**★ 维度选 4 还是 768：**

| | **A：`dim=4`（推荐）** | B：`dim=768` |
|---|---|---|
| 要改的文件 | **0 个** | **2 个**：`train.py` L60 + `src/misc/model_utils.py` L40 的 `encoder_hid_dim` |
| `encoder_projector` | 仍是 `Linear(4,1024)`，**不动** | `Linear(4,1024)` → `Linear(768,1024)` |
| checkpoint 加载 | **完全正常** | **尺寸不匹配 ⇒ 必须剔掉 `encoder_projector.*` 键** |
| 容量 | **与 baseline 相同** | 更大 |

**为什么 `dim=4` 不是降级**：原设计的 `encoder_hidden_states` **本来就是 `(B, 4096, 4)`**
（`recipe.py` L258–263：4 通道 × 64×64 拍平成 4096 个位置）⇒ 每个位置本来就是 4 维。
`dim=4` 与 baseline **同容量**，而且把「改动小」这条优先级落到了实处。

```python
# ---- 默认：什么都不加，复用原分支 ----
# encoder_hidden_states = prepare_latent(随机抽的非配对 IHC 参考片)      # (B, 4096, 4)
# encoder_projector 保持 nn.Linear(4, 1024) 不动

# ---- 对照臂 A：可学习 token，dim=4（零文件改动）----
self.stain_token = nn.Parameter(torch.zeros(1, 4096, 4))   # 零初始化，广播到 (B,4096,4)
# encoder_projector 保持 nn.Linear(4, 1024) 不动
# 注：cross-attn 的 K/V 长度不受约束，只给 256 个 token 也合法（容量更小），
#     但 4096 才与 baseline 严格同容量 ⇒ 对照实验用 4096。

# ---- 对照臂 B：可学习 token，dim=768（要更大容量，代价是改 2 个文件）----
self.stain_token = nn.Parameter(torch.zeros(1, 4096, 768))
self.encoder_projector = nn.Linear(768, 1024)
nn.init.zeros_(self.encoder_projector.weight)
nn.init.zeros_(self.encoder_projector.bias)
```

**⚠️ 三个必须处理的细节**：

**(a) 零初始化只影响「对照臂」。** **默认方案（复用原分支）不做零初始化** —— 此时 cross-attn 从 step 0 就带着 checkpoint 里已训练好的 `encoder_projector` 权重参与，这是**有意的**（我们要复用 StainFuser 已经学会的「风格注入」能力，而不是从零学）。
对照臂 A/B 的零初始化语义是：投影输出全 0 ⇒ cross-attn 的 V 全 0 ⇒ attention 输出 0 ⇒ **cross-attn 分支在 step 0 完全不贡献**。这**不等于**「与 StainFuser checkpoint 数值恒等」（checkpoint 的 `encoder_projector` 是训练过的），它等于的是「**无交叉注意力条件的模型**」。**这个性质正是对照臂要的**：从零贡献起步，必须自己挣出贡献来。

**(b) 只有对照臂 B 会让 checkpoint 加载报错。** 尺寸从 `(1024,4)` 变成 `(1024,768)`，`strict=False` 挡不住尺寸不匹配。
**默认方案与对照臂 A 因为尺寸不变，这一条根本不发生** —— 这是它们的又一个优势。
**B 的修法**：加载前把 `encoder_projector.*` 的键从 state_dict 里剔掉。

```python
sd = torch.load(ckpt_path, map_location="cpu")
sd = {k: v for k, v in sd.items() if not k.startswith("encoder_projector.")}
missing, unexpected = model.load_state_dict(sd, strict=False)
print("missing:", missing)      # 应当只剩 encoder_projector.*
print("unexpected:", unexpected) # 应当为空
```

**加载后必须打印 missing/unexpected 并核对**，不许静默通过。

**(c) `encoder_hid_dim` 硬编码在两处，漏一处会静默不生效。** 见上表；
`arch.py` L152 `if encoder_hid_dim != self.config.cross_attention_dim` 才建投影层，
所以**只改 `train.py` 而忘了 `model_utils.py`**，会导致**训练和推理用不同的维度**，
而推理端不会报错（它会照旧建 `Linear(4,1024)`），只会在加载权重时炸或静默错。

### §5.5 阶段 1 验收标准

| 项 | 标准 |
|---|---|
| **`Transformed` 是真实配对 IHC** | **★ 门禁**。若它还是「用某个颜色变换算出来的」，**你做的是染色归一化不是虚拟染色**（见 §5.0） |

### §5.6 ★ 泄漏判定（**v2 新增，这一步不做，训练成功与泄漏无法区分**）

换了条件内容之后，「模型到底是在推断蛋白分布，还是在抄参考片」**必须可测**。零成本，只改推理时的 condition。

#### 5.6.1 三臂推理对照

| arm | 推理时喂的 IHC 参考 | 怎么读 |
|---|---|---|
| **A** | **BCI 配对 IHC**（同组织相邻切片） | **A ≫ B ≈ C ⇒ 抄图确认，这个设计不能要** |
| **B** | **随机另一例 IHC**（= 训练时的抽样方式） | A ≈ B ≈ C ⇒ 参考片根本没被当空间信息用（那不如用 §5.3.2 的 token） |
| **C** | **常量**（训练集均值图 / 空白图） | **B > C 且 A ≈ B ⇒ 参考提供的是合法「外观」（边缘统计），可以留，但必须非配对** |

**⚠️ 注意 A 臂只在评测时出现，绝不出现在训练里。** 它的作用是把「抄图能力」显式暴露出来。

#### 5.6.2 更省事的直接读数（推荐同时做）

在**训练过程中**就算，不用等训完：

```python
# 参考片 R 与真值 Y 的 DAB 浓度图（用固定的 M 解卷积，见 E0.3 结论）
rho = pearsonr(C_DAB(R).flatten(), C_DAB(Y).flatten())
```

| `rho` | 含义 |
|---|---|
| ≈ 0 | 参考片不含真值的空间信息 ⇒ **安全** |
| ≈ 1 | 参考片≈答案 ⇒ **必须修抽样**（见 §5.3.1） |

**这个数必须每个 epoch 记进日志。** 它比任何 loss 曲线都更能说明问题。

#### 5.6.3 DAB 置零读出（专门针对 §5.2 的 `(H,E,DAB)` 那一臂）

在评测时把 `controlnet_cond` 的 **DAB 通道置零**，再算 H-score：

| 结果 | 结论 |
|---|---|
| H-score **崩塌** | **确认泄漏** —— 模型在从输入通道读 DAB 的量 |
| H-score **不崩** | 说明模型学到了真信号（H/E 里确实有信息） |

**这是唯一能把「量正确」和「结构正确」分开的读出。**

#### 5.6.4 主判据不是 PSNR/FID

| 指标 | 能不能判泄漏 |
|---|---|
| PSNR / SSIM / FID | **不能**。抄参考片的图在所有这些指标上都会更好 |
| **下游核 / 膜分割 DICE** | **能**。抄来的 DAB 结构在细胞级别上对不上 |
| **`rho`（§5.6.2）** | **能**，且最便宜 |
| **DAB 置零后的 H-score 落差** | **能** |

**⇒ 阶段 1 的验收必须包含 DICE 与 `rho`，不许只看 PSNR/FID。**

### §5.7 ★ 尺度一致性（**v2 新增，原代码自带的不一致，改这条路径一定会踩**）

`src/misc/utils.py` L796-797：

```python
if is_tsf:
    transform.append(T.Normalize([0.5], [0.5]))
```

**只有 `is_tsf=True` 才归一到 `[-1,1]`。** 而 `prepare_latent`（`recipe.py` L177-191）**同时**用在两个来源上：

| 输入 | 走的变换 | 数值范围 | VAE 期望 |
|---|---|---|---|
| `Transformed Images`（`tsf_latents`） | `transform_tsf` | `[-1, 1]` | `[-1, 1]` ✅ |
| `Target Images`（`tgt_latents`） | `transform_src_trg` | **`[0, 1]`** | `[-1, 1]` ❌ |

**⇒ 同一个 SD VAE，两个输入尺度。** 原作者就这么跑的（网络只是学到一组偏移过的 latent，能训），但：

1. **你要换 condition 内容，这个尺度差会被一起继承**；
2. **更糟的是它会把两个原因混进同一个日志值**：「参考片没用」和「参考片尺度不对」会看起来一样。**这正是方法论 #3（日志缺字段 = 信号消失）。**

**动作**：

```python
# 在 prepare_latent 里显式区分，不要靠调用方的变换隐式决定
def prepare_latent(self, batch_input, is_tsf: bool):
    if not is_tsf:
        batch_input = batch_input * 2.0 - 1.0        # [0,1] -> [-1,1]
    ...
```

**并且必须做一次对照实验**：`Target` 保持在 `[0,1]`（原代码行为）vs 修正到 `[-1,1]`，**两臂都跑**，否则你无法知道这个修正到底有没有影响。

## §6 阶段 2 · 表示重构（2–4 周，分两步）

**原则：一次只引入一个新失败模式。**

### §6.1 阶段 2a · 只加物理渲染通路，**不动生成空间**

生成空间仍然是 SD VAE 的 RGB latent。**新增**：

1. 从 UNet 的中间特征接一个**小头**，预测 `Ĉ = [Ĉ_H, Ĉ_DAB, Ĉ_res]`
2. 物理渲染：`OD̂ = M₃·Ĉ`，`x̂_phys = I₀·10^(−OD̂)`
3. 加物理损失 `L_phys = ‖x̂_phys − x̂₀‖`（`x̂₀` 是模型预测的干净潜码解码结果）
4. 加蛋白损失 `L_prot`：直接在 `Ĉ_DAB` 上算 FOD / PALS 一致性（**这是改造的一个红利：搬到染色空间后不再需要反演**）

**为什么先做这一步**：它给你染色空间的可解释性与监督，但**完全不碰预训练的生成能力**。风险最低。

**验收**：
- `Ĉ_H` / `Ĉ_DAB` 的分布与 E0.1 里真实 IHC 的 `C_H` / `C_DAB` 分布**同量级**
- `L_phys` 单调下降
- **图像质量不下降**（与阶段 1 对比 PSNR/SSIM/FID）

### §6.2 阶段 2b · 换生成空间

**只有 2a 全过才做。**

把扩散的输出通道从「SD VAE 4 通道 latent」换成 **`Z = [C_H, C_DAB, C_res]`**，用 `M₃` 的物理渲染器替代 VAE 解码器。

**这需要新训一个解码路径**（原 VAE 解码器是为 RGB latent 训的，不适用）。代价与风险最高。

**关键实现点**：
- `M₃ = [s_H, s_DAB, normalize(s_H × s_DAB)]` 做 **Gram–Schmidt 正交化** ⇒ `M₃⁻¹ = M₃ᵀ` ⇒ **重建精确可逆**
- `C_H, C_DAB → softplus`；**`C_res` 保持有符号**（铁律 3）
- 采样循环内**逐通道、每一步**钳位，并记录被截比例（铁律 7）

**★ 止损条件（硬性）**：**若 2b 的视觉质量相比 2a 明显崩坏 → 停在 2a**，并在论文里明确写：

> 「为保真度保留了预训练的 VAE 解码器，代价是生成空间不是纯物理的。」

**这句话必须写，不许含糊。** 诚实的边界陈述比虚假的完整性有价值。

## §7 Channel Attention 具体设计

### §7.1 先确定一个更干净的判据

**「染色通道注意力」只有在那个张量的通道维真的是染色语义时才存在。**

| 位置 | 通道维是什么 | 能做「染色通道注意力」吗 |
|---|---|---|
| **输入侧** `controlnet_cond`（3ch） | 换成染色分解后就是 `[C_H, C_E, …]` | **能** |
| **输出侧** `Z_pred`（3ch） | 就是 `[C_H, C_DAB, C_res]` | **能** |
| UNet 内部（320 / 640 / 1280ch） | **特征维**，无语义、可任意置换 | **不能**。在这里无论怎么设计都只是「特征通道注意力」 |

**⇒ 位置问题塌缩成一个二元问题：主干之前，还是主干之后。**

**⇒ 明确不推荐 UNet 内部（原「方案 C」）**：不是它不好，是**它上面根本不存在「染色通道」这个对象**。另外它还动冻结的预训练层、参数量最大、颜色泄漏风险最高。

### §7.2 推荐：**主位置 = 输入侧（主干之前）**，次位置 = 输出侧

**推荐输入侧的理由（比原来的理由更强）**：
1. 在输入侧，注意力**塑造网络看到的东西**，`C_pred` 本身不被乘性扭曲 ⇒ **监督目标保持干净可比**
2. 在输出侧，注意力会乘性扭曲 `Z_pred` ⇒ 与 `C_target` 的尺度关系变复杂，**必须先解决尺度归一化**
3. 输入侧不碰任何预训练权重，改动最小

### §7.3 具体形式：**逐通道空间掩码（对角），不是逐像素 3×3**

**必须避免的形式**：逐像素的稠密 3×3 混合矩阵。
**为什么**：那等价于「在每个像素上重新解混」，而这个自由度**已经在 `M` 里了**（只是被约束为全局共享）。评审必然问这个。

**推荐形式**：

```python
# 输入侧：cond (B,3,H,W) → 逐通道空间掩码
feat = self.attn_net(cond)                     # (B,3,H,W)，一个小 UNet/CNN
delta = 0.5 * torch.tanh(feat)                 # 限制在 (-0.5, 0.5)
w = 1.0 + delta                                # 初始 ≈ 1，即恒等
w = w / w.mean(dim=(2,3), keepdim=True)        # ★ 关键：逐通道归一到均值 1
cond_out = cond * w
```

**★ 那个均值归一化是必需的**，不是可选优化：
`w` 和 `C` 是相乘关系，存在**逐通道尺度简并**（`w_k × α`、`C_k ÷ α` 输出不变）。不归一化的话，**注意力会吸收浓度的整体尺度 ⇒ 浓度失去可解释性 ⇒ H-score 失去意义**。
归一化到均值 1 把这个简并把 `C` 的均值钉死，注意力只能表达**空间重分布**。

**参数量**：一个小 CNN，几万到几十万参数，相对 878 M 可训参数可忽略。

**正则（防注意力退化成主体）**：

```python
L_attn = lam_attn * ((w - 1.0) ** 2).mean()    # 拉回恒等，lam_attn ~ 1e-3
```

### §7.4 必须做的可证伪检验（这是「语义」与「通用」的分界）

**若 `w_DAB` 的掩码图与 DAB 阳性区域不相关 → 这个「语义染色通道注意力」的说法不成立，必须如实报告。**

具体：训练后取 `w` 的第 2 通道（对应 DAB 分量），与真实 IHC 的 DAB 阳性 mask 算：
- 逐像素 Pearson / Spearman 相关
- 在阳性区 / 阴性区里 `w_DAB` 的均值差 + 配对检验

**报分布，不只报均值。**

### §7.5 消融

| 消融 | 目的 |
|---|---|
| 有 / 无 attention | 净效果 |
| 输入侧 vs 输出侧 | 位置是否重要 |
| 逐通道对角 vs 单一共享空间掩码 | 「不同染色成分获得不同空间权重」是否真的发生了 |
| 去掉均值归一化 | 验证尺度简并假设（**预期：浓度变得不可解释**） |
| **`[H, DAB, H]` 重复通道版本** | **反面教材，用数据证实「秩亏 + 不可辨识」的论证** |

## §9 评价体系（六层，禁止单指标）

| 层 | 指标 | 必须吗 |
|---|---|---|
| 1 图像相似 | PSNR / SSIM / LPIPS / FID | 是 |
| 2 颜色 | ΔE(CIELAB)，报**均值 + 95 分位** | 是 |
| 3 **逐通道浓度误差** | `C_H` / `C_DAB` / `C_res` **分开报** | **是**。`C_DAB` 的误差直接决定 H-score 可信度 |
| 4 **被截断像素比例** | 每个 clamp 点 | **是**。隐藏失败的计数器 |
| 5 `I₀` 敏感性 | 改变 `I₀` 估计法时 **`C` 数值**的散布（**不是** `‖I′−I‖`） | 是 |
| 6 下游一致性 | DAB-OD 直方图 KL / **H-score 相关性** | 是 |

**★ 铁律**：
- **分布级 ≠ 实例级**。FID 低不代表单张图对。**必须同时给实例级证据。**
- **凡「均值变好」，都要同时报尾部是否变差。**

**H-score 计算前提**：先**固定 stain matrix** → 定义浓度 → 验证闭环 → **最后**才接 H-score。没有固定 `M` 的 H-score 不可比、不可复现，**比没有更糟**。

## §10 禁止事项（汇总）

| 禁止 | 原因 |
|---|---|
| **把 BCI 的配对 IHC 当 `Target Images`** | **corr ≈ 1 ⇒ 抄答案，模型退化成 IHC→IHC 重上色**（§5.1 / §5.6.1） |
| **让 `Transformed Images` 继续是「颜色变换的结果」** | 那训的是**染色归一化**，不是虚拟染色（§5.0）。这是最容易被忽略、后果最大的一条 |
| **原样沿用 `itertools.product` 抽样** | 会抽到配对组合，泄漏当场成立（§5.3.1） |
| **用 PSNR / SSIM / FID 判断有没有泄漏** | 抄参考片的图在这些指标上**更好看**，指标方向与泄漏方向一致（§5.6.4） |
| **在 `(H,H,E)` / `(H,E,E)` / `(H,E,0)` 之间做消融** | 信息等价，是空操作，浪费算力（§5.2） |
| **把「重复通道」当「加权」** | 网络可以把权重设为 0，重复通道不改变可表达的函数集（§5.2） |
| 改 `conv_in` 通道数 | 放弃预训练权重 |
| `controlnet_cond` 改成 1 通道 | 会 RuntimeError；且 checkpoint 加载失败 |
| 改 `conditioning_embedding_in_channels` 指望它生效 | 死参数 |
| 对 `C_res` 加非负约束 | 静默抹负 + 归零梯度 |
| 用 `clamp(min=0)` 处理物理量 | 同上 |
| 用单一 PSNR 下结论 | 分布级指标看不见实例级失败 |
| 逐图估 stain matrix 当监督 | 浓度吸收染色差异，H-score 不可比 |
| 采样只钳终点 | 末端补救来不及 |
| 逐像素稠密 3×3 通道混合 | 等价于每像素重新解混，与 `M` 打架 |
| 把「条件控制」说成「显式解耦」 | 表述准确性 |
| 跳过阶段 0 直接改架构 | 门禁的意义就在这 |
| 阶段 2b 崩了还硬上 | 止损：停在 2a 并明写边界 |
| 静默通过 checkpoint 加载 | 必须打印 missing/unexpected |
| **静默忽略 `target_latents` 的尺度不一致** | 会把「参考片没用」与「尺度不对」混成同一个日志值（§5.7） |

```
【C. 主干与输出】

  controlnet_cond ──┐
                    ├──> ControlNet ──> UNet (SD2.1) ──┬──> 阶段1/2a: RGB latent
  encoder_hidden ───┘                                 └──> 阶段2b:   Z=[C_H,C_DAB,C_res]
                                                                          │
                                                                          ▼
                                                               OD = M₃·Z
                                                               IHC = I₀·10^(−OD) ──> IHC RGB

【D. 训练信号】

  loss = MSE( UNet 预测的噪声 , noise(Transformed Images) )
                                    ↑ 真实配对 IHC，不是颜色变换的结果
```

## §14 不确定与已知局限（执行前必读）

1. **没在真实 IHC 数据上跑过任何实验。** 本文档所有结论来自代码审查与合成数据验证。E0.1 是第一个真实数据实验。
2. **E0.1 的参考量级（3×2 → MAE 0.208 OD）是用随机 OD 算的**，只作数量级参考，你的真实数据会不同。
3. **StainQuant（最接近的先例）的代码没有克隆成功**，其实现细节未逐行核实，仅来自论文正文。
4. **没找到「逐空间位置给不同染色分量不同权重」的文献先例。** §7 的设计是工程判断，不是文献结论。
5. **「878.49 M 可训练参数」是从 `train.py` 的 `param_dict` 逻辑推出的**，实际训练显存未测。
6. **StainFuser 只有 8 次引用、0 次有影响力引用**（Semantic Scholar, 2026-10-05）。**没有社区生态可依赖。**
7. **`[H, DAB, H]` 的秩亏与不可辨识是数学结论**，不依赖实验。但把它作为反面教材跑一次仍有价值（消融 3）。
8. **★ BCI 的 H&E 与 IHC 能不能按文件名/病例一一对应，我没有核实。** §5.3.1 的抽样排除**依赖这一点**。⇒ **执行前必须先做一次数据侧配对关系盘点**（打印文件名 → 病例号的映射，统计能配上的比例）。**配不上的话，「排除配对组合」是空操作，泄漏照旧发生。**
9. **★ `corr(结构(R), 结构(Y))` 我用「DAB 浓度图相关系数」做代理**，这是工程近似，不是严格的结构相似度。它可能低估（DAB 稀疏时相关系数不稳），也可能高估（两边都被染色强度主导）。⇒ **至少同时报一个不由强度主导的量**（例如二值化阳性区域后的 IoU）。
10. **★「复用 StainFuser 风格注入分支」能否真的学到东西，我没有先例可引。** StainFuser 的 style injection 是在**同域染色归一化**上训出来的；H&E→IHC 是**跨域**。它学到的「复制外观」先验是否可迁移，**是本文档最大的未知**。若 §5.6.1 出现 A ≈ B ≈ C（参考片没用），就是它没迁移过来的证据。
11. **「非配对参考片只提供边缘统计」是推理，不是实测。** 它成立与否，正好就是 §5.6.1 里 B vs C 那一格。
12. **§5.7 的尺度不一致是「原代码就这样」还是「我看漏了某处缩放」，我未完全排除。** 已核对的链路是：`transform_src_trg` 无 `Normalize`（`utils.py` L796-797 只在 `is_tsf=True` 时加）→ `prepare_latent` 直接 `encode`。**执行前请用 §5.4 的 `target_latent_range` 字段实测确认。**
