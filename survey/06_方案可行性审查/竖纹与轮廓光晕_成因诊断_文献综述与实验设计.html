1 · 结论摘要

1.1 竖纹：最值得怀疑的成因（按证据强度排序）

候选成因机制证据强度如何证伪/证实
① 预处理 BICUBIC resize + 训练/测试分辨率不一致Resize(1024, BICUBIC) 的负瓣在边缘产生 overshoot；训练 512、测试 1024 使生成器看到不同的空间频率内容，混叠/周期纹理被放大中–强（代码确证参数，未做实验）同一图分别用 preprocess='none' / resize / resize_and_crop，512 vs 1024 出图对比
② InstanceNorm(affine=False) 低方差放大背景/纯色区某通道 σ≈0 → (x−μ)/σ 把微小周期残差放大成可见竖条中常量输入（全 0 / 均值图）过 G；背景区 CSS；normG='batch' 对照
③ 弱抗混叠核的残余混叠默认 [1,2,1]（下）/ [1,3,3,1]（上）是弱低通，仍可能残留周期分量；no_antialias_up=True 时直接变普通转置卷积中对比 --no_antialias_up 开关；换 filt_size=5/7；频谱看峰值
④ 推理 tiling / stitching 接缝分块推理 + 重叠融合，接缝处出现固定间隔的竖线中（若你用了 tiling）关闭 tiling / 改 tile 大小 / 单图整图推理；看条纹间距是否随 tile 变
⑤ 数据/扫描/JPEG 列方向伪影WSI 扫描条带、JPEG 8×8 块、染色不均弱–中直接看原始输入；对输入做同样的 CSS/DSR；换数据集
⑥ 经典反卷积棋盘格转置卷积不均匀重叠弱（默认已抗混叠）确认训练命令是否 --no_antialias_up；否则基本排除

结论：不要先改生成器。先证明竖纹是「管线/预处理」还是「生成器内部」，再决定改哪。

1.2 轮廓发亮 / 白边 / 浮雕：最值得怀疑的成因

候选成因机制证据强度如何证伪/证实
① BICUBIC resize 的 overshootBICUBIC 核有负瓣，强边缘两侧出现亮/暗过冲（halo / ringing）中–强把 preprocess 换成 none 或 INTER_AREA 下采样，比较边缘剖面
② 上采样 + 卷积 + IN 的边缘过冲模糊上采样后接 conv，强边缘处产生 overshoot；IN 进一步放大局部反差中逐层 tap 的 EHS；no_antialias_up 对照；normG 对照
③ 浓度→RGB 的 exp 非线性放大I=I0·exp(−M·C)：C 的小过冲经 exp/矩阵映射后变成可见亮边；clamp 会截断成硬边中对比「原始 H/DAB 输出」与「重建 RGB」；用合成浓度斜坡过重建器看是否自带过冲
④ 感知/对抗损失鼓励边缘锐化GAN/perceptual 目标偏好高频锐利边缘，可能学出 overshoot中看训练曲线/不同 epoch 的 EHS；换 loss 权重对照
⑤ 真·振铃（sinc/Lanczos）插值核振荡弱（除非用了 Lanczos/sinc）确认 resize 核；BICUBIC 也会振铃但幅度较小
关键区分：「亮边」不一定等于振铃。BICUBIC overshoot、上采样过冲、exp 非线性、GAN 锐化都会产生亮边，但频谱与剖面不同（见 §2）。先定位它出现在浓度图还是RGB，再谈抑制。

2 · 伪影分类与鉴别方法

类型视觉表现频谱特征典型来源
周期性条纹（periodic stripe）等间距、方向一致的细线；空白区更明显频谱中出现离散亮点/亮线，沿某一方向（竖纹 → f_y≈0 的水平线）上采样/下采样混叠、tiling 接缝、扫描条带
棋盘格（checkerboard）2D 网格状、块状明暗交替频谱在两个方向都有谐波峰（f_x≈f_y 附近）转置卷积不均匀重叠（Odena 2016）
一般方向性纹理（directional texture）沿某一方向的连续纹理，不一定是等间距频谱在某个方向有宽带能量，而非离散峰数据本身、GAN 学到的纹理、卷积核方向性
边缘过冲（overshoot/undershoot）强边缘两侧出现亮/暗带空间域看边缘剖面；频域表现为高频相位/幅度异常，不一定是离散峰BICUBIC/上采样、锐化、IN、GAN 锐化
Halo（光晕）边缘外侧一圈浅色/发亮的宽带空间域：边缘外 +d 处正过冲；频域不突出边缘保持滤波、tone mapping、过冲
Ringing（振铃）边缘两侧出现多条明暗交替的“鬼影”空间域：边缘剖面多次符号反转；频域：靠近截止频率的振铃sinc/Lanczos/bicubic 插值、去卷积
鉴别口诀：「等间距 + 频谱离散峰」= 周期条纹；「2D 网格 + 双向谐波」= 棋盘格；「单侧宽带亮边」= halo/overshoot；「多次明暗交替」= ringing。不要看到亮边就判振铃。

4 · PSPStain 场景的成因排查顺序

原则：从最便宜、最可能共享的环节往上查；每一步只改一个变量，并记录 CSS/DSR/PPS/EHS。

步检查怎么做若指标变化 → 结论
0复现基线固定输入、固定 seed、固定 tile，保存官方 RGB 与 2 通道各一张建立可比基线
1预处理 resize同一图：preprocess='none' vs 'resize' vs 'resize_and_crop'；下采样用 INTER_AREA 对照竖纹/亮边随 resize 变 → 预处理是主因
2训练/测试分辨率同图分别以 crop_size=512 与 1024 推理（整图或滑窗）只在 1024 出现 → 尺度/混叠

4绕过浓度→RGB保存原始 H/DAB 输出与重建 RGB，分别算指标只在 RGB 有 → 重建/映射；只在浓度有 → 生成器

① 常量输入过 G：G(torch.zeros(1,2,256,256)) 与 G(torch.ones(...)*mean)；
② 只跑重建器：把一张合成浓度斜坡（含硬边）过 C→RGB，看是否自带 overshoot。

5 · ResBlk 逐层实验设计

5.1 要保存什么

  • 输入 H/E（或 RGB）与最终输出（浓度 + RGB）。
  • 6 个 ResnetBlock 的输出 f_1…f_6，形状均为 [B,256,H/4,W/4]。
  • 每个 tap 的通道均值图 m_i = mean_c f_i（用于指标），以及同一解码器解出的可视化图（仅定性）。
  • 最终 head 前的特征（可选）。

5.2 如何公平解码（避免投影头差异被误判为 ResBlk 差异）

方案做法公平性建议
A · 共享解码器（零训练）所有 tap 用同一个已训练 decoder（权重完全相同）中：decoder 为最终块分布而训，浅层会糊仅定性看「糊→清」
B · 共享 1×1 线性探针（轻训练）每个 tap 接同一个 1×1 conv→3ch，共享权重，用同一损失训少量步较高：无独立投影头推荐做定量
C · 特征空间直接统计（零训练）不解码，直接对 m_i 算 CSS/DSR/PPS/HFER最高：完全无 decoder 混淆首选
关键：不要给每个 tap 各训一个不同的 decoder/head——那会把「投影头差异」混进「ResBlk 差异」。要么共享权重，要么直接在特征空间算指标。

5.3 指标定义（可直接实现）

预处理：转灰度 Y=0.299R+0.587G+0.114B（或直接用 H/DAB 单通道）
        I = (I-mean)/std；裁掉 16px 边框；FFT 前乘 Hann 窗

1) CSS  列方向条纹强度
   I_hp = I - gaussian_blur(I, sigma=3)
   col  = mean_y I_hp                     # 长度 W
   CSS  = std(col) / (std(I_hp)+eps)
   平区域版本：只在 |∇I|<τ 的背景像素上算 std(col_flat)

2) DSR  方向性能量占比（竖纹）
   F=fft2(I*hann); P=|fftshift(F)|^2
   band_v = { 0.05<=|fx|<=0.5, |fy|<=0.02 }   # 竖纹 → fx 方向、fy≈0
   DSR_v  = sum(P[band_v]) / (sum(P)-P[DC])
   同理 DSR_h（|fx|<=0.02, 0.05<=|fy|<=0.5）

3) PPS  周期性峰值
   col = mean_y(I-mean(I))
   A   = |rfft(col-mean(col))|^2
   PPS = max(A[k]) / (median(A[k])+eps)   # k 在条纹带内

4) HFER 高频能量占比（不是越低越好！）
   r=sqrt(fx^2+fy^2); HFER=sum(P[r>0.25])/sum(P)

5) EHS  边缘光晕/过冲
   在输入 H 通道上取 Sobel/Canny 强边缘；沿梯度法线取 ±d (d=6px) 剖面
   plateau_L/R = 两侧外侧 2px 的中位数
   overshoot  = max(0, max(profile)-max(plateau_L,plateau_R))
   undershoot = max(0, min(plateau_L,plateau_R)-min(profile))
   EHS = mean(overshoot+undershoot) over strong edges
   配准不完美时：允许 ±3px 搜索最大梯度；或直接在输出自身边缘上算（免配准版）

5.4 相邻 ResBlk 的变化量

Δ_i = metric(f_i) - metric(f_{i-1}),  i=2..6
找 argmax_i Δ_i(CSS) 与 argmax_i Δ_i(DSR_v)：
  若突增在 f_1→f_2：浅层（编码/第一次下采样后）引入
  若突增在 f_5→f_6：深层/上采样前引入
  若全程平缓、只在最终输出突增：head 或 C→RGB 重建引入

5.5 若某阶段显著增强，如何做消融验证

  • 只替换该阶段的算子（如该级上采样 Upsample ↔ no_antialias_up 的 ConvTranspose2d），其余不动，重训/微调，比较 CSS/DSR。
  • 或冻结其它层，只对该阶段做短微调（adapter），看指标是否回落。
  • 用同一 seed、同一数据、同一评估；每次只改一个变量。

6 · 最小改进方案

6.1 优先方案 P1：先修「管线/分辨率 + 低方差归一化」（零/短训练，低风险）

项内容
设计依据代码已证实：默认抗混叠、normG=instance(affine=False)、preprocess=BICUBIC、训练 512/测试 1024。这四项里，预处理与分辨率不一致是唯一能同时解释「官方权重也有竖纹」的共享环节；IN 低方差放大解释「空白区更明显」。
实现位置① 推理统一到训练分辨率（512 滑窗 + 重叠融合），或至少在 512/1024 两档都测；② resize 下采样改 INTER_AREA，上采样避免 BICUBIC 直接放大（先 INTER_AREA 下/最近邻上，再做轻模糊）；③ 若确认 IN 主导：把 InstanceNorm2d 换成方差下限 IN (x−μ)/sqrt(σ²+ε)（ε=1e-2）或 SafeIN（方差门控）。
预计收益若竖纹来自 resize/分辨率，CSS/DSR 可显著下降且零训练；若来自 IN，短微调后背景条纹明显减弱。
风险改推理分辨率会改变输出观感；IN 改动需短微调，可能轻微影响染色强度。
参数开销0（IN 方差下限）或极小（SafeIN 的 1×1 门控）。

6.2 备选方案 B1：方向性频域约束 + 结构保持（需训练，中风险）

项内容
设计依据FFL（Jiang 2021）证明频域损失能补高频；但普通高频惩罚会抹掉细胞核/膜纹理（你已明确警告）。因此只惩罚竖纹对应的窄带（|fy|≈0, 0.05≤|fx|≤0.5），并配结构保持项。
实现位置加在H/DAB 浓度输出（不是最终 RGB）：L_stripe = || M_stripe ⊙ (FFT(Ĉ)−FFT(C)) ||，M_stripe 只覆盖条纹带；权重 0.01–0.05；同时加 L_edge（梯度/SSIM）保结构。
预计收益若条纹在浓度域已存在，可定向压低而不伤真实高频；对 DAB 通道可单独设权重。
风险mask 设计不当会误伤真实竖直线（如纤维）；需配合 HFER 监控，避免过度平滑。
参数开销0 新增参数（纯损失）。
不要同时上：DySample + 小波下采样 + H/E 注意力 + 频域损失 + DAB 增强。你现在的首要任务是定位，不是堆模块。等 §4 的结论出来，再决定 P1 还是 B1。

9 · 最终建议

下一步只做一件事：用官方 3 通道权重和你的 2 通道权重，在同一张图上跑这 4 个零训练条件，算 CSS / DSR_v / PPS / EHS：

  1. 512 推理（训练分辨率）；
  2. 1024 推理（官方测试分辨率）；
  3. preprocess='none'（不 resize）；
  4. 常量输入（全 0 / 均值图）。

这 4 个条件能一次性回答「竖纹是管线还是生成器」：

  • 512 有、1024 更重 → 分辨率/混叠；
  • none 明显减轻 → BICUBIC resize；
  • 常量输入仍有 → 生成器固有（IN / 弱抗混叠）；
  • 都没有、只有重建 RGB 有 → 浓度→RGB 映射。

在这个结果出来之前，暂缓：DySample、小波下采样、H/E 注意力注入、频域损失、DAB 强度增强。它们都可能「对症但不对因」，会把你现在最宝贵的诊断信号掩盖掉。

结果出来之后：若是管线 → 直接做 P1（零训练）；若是生成器 → 先做 A3（方差下限 IN）或 A4（更强抗混叠），再考虑 B1（方向性频域）。H/E 形态注入（A6）留到伪影定位之后单独消融，避免和伪影抑制混在一起说不清贡献。

诚实边界：以上代码结论基于本机 PSPStain 官方仓库；你的 2 通道 psp_diffusion 代码不可访问，§0.3 的清单需你在服务器上核对后再下最终判断。

附录 · 指标公式与检查清单

A. 指标速查

CSS  = std(mean_y(I - blur(I))) / (std(I - blur(I)) + eps)
DSR_v= ΣP[0.05≤|fx|≤0.5, |fy|≤0.02] / (ΣP - P[0,0])
PPS  = max|FFT(col)|² / median|FFT(col)|²   (col=列均值，去直流)
HFER = ΣP[r>0.25] / ΣP          # 只作相对比较，不追求最低
EHS  = mean(overshoot + undershoot) over strong edges

B. 代码只读检查清单（服务器上补）

  • grep -rn "no_antialias" .：训练命令是否显式关闭抗混叠？
  • grep -rn "load_size\|crop_size\|preprocess" .：训练/测试是否一致？
  • grep -rn "InstanceNorm\|normG" .：是否 affine=False？
  • 找 C→RGB 重建函数：exp、clamp、I0、M 的来源。
  • 找 tiling/stitching：tile 大小、overlap、blending。
  • 保存原始 H/DAB 输出与重建 RGB，分别算指标。

C. 一句话总结

PSPStain 默认已经是抗混叠的，所以「加抗混叠」不是第一刀；第一刀是证明竖纹到底来自 BICUBIC resize/分辨率、InstanceNorm 低方差放大，还是生成器内部——用 4 个零训练条件就能分开。
