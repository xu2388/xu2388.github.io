一句话结论

这不是「某个超参数没调好」，而是三条结构性缺陷叠在一起：辅助损失的梯度对 UNet 完全无门控、无裁剪，而它本身含两个 1/x 放大器；同时辅助损失被一个比数据流形宽 4.26 倍的 clamp 训练。三者组合产生正反馈——生成图变暗 → 梯度爆炸 → 全局 clip 把主损失的学习率压掉 → 辅助损失接管更新方向 → 生成图更暗。step 3500→4000 的「突然崩成纯噪声」与这个正反馈的形态吻合。

而且其中那个 1/x 放大器不是独立 bug，是策略选择的后果：代码走的是 scheme B（从生成的 RGB 反演浓度），而 R2 报告里你定的 M1 是正演（U-Net 直接输出浓度图 → Beer-Lambert 渲染）。整条正演路径在这个仓库里是死代码（render_ihc 从未被调用）。正演方案里 log 的自变量恒大于 0，那个梯度炸弹结构上不可能存在。详见 §9。

需要诚实标注：三条缺陷本身是代码事实（可逐行复核）；把它们串成崩溃原因是高置信度假说，不是已证实的结论。第 5 节给了可证伪的预测与判定实验。

1P0 缺陷：三条结构性错误

1.1 辅助损失的梯度对 UNet 完全无门控，却被全局裁剪

门控参数在 training_dbdce.py L204 定义：

gate_params = list(dbdce.parameters()) + list(protein_adapter.parameters())
gate = GradSurgery(gate_params, mode=args.gate, ema=args.gate_ema)

而辅助损失的梯度路径是 l_prot / l_freq → c_pred → pred01 → pred_rgb → x̂₀ → model_pred → UNet。这条链穿过 UNet。在 losses.py L116–120：

for k, (name, aux) in enumerate(aux_losses.items()):
    for p in self.params:          # 只清 gate_params 的梯度
        p.grad = None
    aux.backward(retain_graph=(k < n_aux - 1))   # UNet 的梯度在这里被直接累加

aux.backward() 对非门控参数（即 UNet 的全部权重）是累加写入的，从不经过 cos 判定，也从不清零。所以：

  • 辅助损失进 UNet 的梯度 —— 无门控、无监控、无单独裁剪；
  • 随后 L667 执行 clip_grad_norm_(trainables, 1.0)，这是对 UNet + dbdce + adapter 全体参数总范数的一次性裁剪。
这才是真正的伤害机制

设某步 l_diff 的梯度范数为 ‖g_main‖，辅助损失的梯度范数为 ‖g_aux‖。全局裁剪系数为

clip_coef ≈ 1.0 / (‖g_main‖ + ‖g_aux‖)

当 ‖g_aux‖ ≫ ‖g_main‖ 时，主损失的梯度也被同一个系数乘小——也就是说：辅助损失一旦梯度爆炸，就顺手把主损失的学习率压到接近 0，把这一步的更新方向整个交给辅助损失。

代码里有一条注释（L578–580）表明作者意识到了这个风险：

# Pre-filter non-finite aux losses: a NaN aux backward would
# accumulate NaN into UNet grads and make GradScaler skip the ENTIRE step
if math.isfinite(l_prot.item()): ...

但守的是「损失值」不是「梯度」。一个有限的损失完全可以有非有限或极大的梯度——losses.py L136 的 isfinite(g_aux) 检查正是为此写的，可它只覆盖门控参数。UNet 完全裸露。这个「写了守、守错了地方」的模式是本项目最值得记住的一课。

两种坏结局，取决于裸露的 UNet 梯度是 inf 还是 NaN

情形clip_grad_norm_ 行为结果本 run 是否发生
UNet 梯度 有限但极大clip_coef ≈ 0全体梯度被压向 0，该步近乎空转；方向由辅助损失主导最可能
UNet 梯度含 infclip_coef = 1/(inf+1e-6) = 0静默空转步（无报错、无日志）可能
UNet 梯度含 NaNclip_coef = NaN → 梯度全变 NaNoptimizer.step() 把 全部 860M 权重写成 NaN，一步毁模型未发生

本 run 权重始终有限（step 4000–4525 的 l_diff 仍是 0.43–0.93），所以第三种没发生。但它是已经埋好的地雷：只要某一步 UNet 收到 NaN 梯度，整个模型一步报废，而且 NaN 检测器（L592）是在下一次前向才会发现——那时权重已经坏了。

1.2 辅助损失的梯度为什么能无界：两个 1/x 放大器

两个地方用了同一个错误模式——clamp 限住了函数值，但没限住梯度。

放大器 A：颜色解卷积（physics.py L49）

return (-torch.log10((img.clamp(1e-6, 1.0)) / i0)).clamp(min=0.0)

值域确实被夹住了：OD ∈ [0, 6]（因为 img/i0 最小 1e-6，-log10(1e-6)=6）。但梯度是

d(OD)/d(img) = -1 / (img · ln10)
预测图该像素的亮度 img1.00.11e-31e-4
梯度放大倍数0.43×4.3×434×4340×

生成图一旦整体变暗，大量像素落进 10⁻³–10⁻⁴ 这个高增益带。再乘上 l_prot 的 λ=0.1 与伪逆矩阵的量级，单元素梯度就能到 10³–10⁴。这就是 1.1 里 ‖g_aux‖ ≫ ‖g_main‖ 的来源。

放大器 B：频带能量的 log（losses.py L61–63）

ok = sy > 0                                    # ← 退化参考：处理了
n = ok.sum().clamp(min=1)
d = (sx.clamp(min=1e-8).log() - sy.clamp(min=1e-8).log()).abs()
#    ↑ 退化预测：没处理

作者为「整块苏木精解卷积为 0 的退化参考」写了逐样本屏蔽（注释 L57–60 写得很清楚），但对退化的预测 sx→0 完全没有防护。同样是 clamp 只保值不限梯度：d/d(sx) ∝ 1/sx，sx=1e-5 时梯度 10⁵。

这是一个不对称的疏忽，而且方向很关键

参考图（真实 H&E）退化是数据问题，概率低；预测图退化是模型自己造成的，恰恰在模型学坏的时候大量出现。防护写在了不常发生的那一侧，没写在必然发生的那一侧。

辅助损失是在浓度空间算的（DAB 的 L1 + 矩匹配）。要让 DAB 更浓，一个廉价解就是把潜码推到极端值。于是：辅助损失有明确的梯度动机把潜码推出流形；采样器再按数据箱把它截回来；截回来的那个潜码是「被削平过的离流形点」——正是解码出黑团/噪声的输入。

这也顺带解释了为什么单靠收紧采样端的 clamp 只能把黑团减半：训练端在持续地把潜码往外推，你在推理端收紧只是把推出去的部分截掉，推力本身没消失。

2P1 缺陷：六条设计问题

2.1 p_tok 是唯一无界、无监控的可训练注入

condition.py L84–95 的 ProteinAdapter：

self.proj = nn.Linear(cond_ch, d_model)     # 64 → 768
nn.init.zeros_(self.proj.weight); nn.init.zeros_(self.proj.bias)
...
return self.proj(tokens)                     # (B,256,768) —— 输出完全无界

上游 DBDCE.prot_branch（encoders.py L54–59）最后一层是裸 conv2，也没有输出归一化。所以从 DBDCE 到 p_tok 这条链上没有任何幅度约束。而 p_tok 直接充当 cross-attention 的 K/V。

为什么这能造成「全图噪声」

K/V 的幅度直接决定 attention logits 的尺度。K/V 一大，softmax 进入饱和区，256 个 token 的权重会塌到极少数几个上——相当于把条件信息换成一个常数偏置。表现就是整张图失去结构，而不是局部出黑团。

监控缺口

NaN 检测器（L603–605）只打印 |noisy_lat| / |model_pred| / |s_lat|。p_tok 只出现在 prov 列表里（L599），而且只在 l_diff 已经变成非有限之后——损伤已经发生了。

一个很说明问题的反差

死代码 StructAdapter（v6 已弃用）身上带着一整套幅度控制：RES_SCALE、逐通道 RMS 归一化、3σ 裁剪、raw_max 监控（condition.py L22 / L64–80），注释里连「tanh 会在 resmax>2 时饱和杀掉梯度」的教训都记下了。

而真正在用的 ProteinAdapter 一个都没有。纪律被用在了死路上，活路上是裸的。把 StructAdapter 那套（RMS 归一化 + 3σ clamp + 每 25 步记录 rms）原样搬到 ProteinAdapter，是改动最小、最可能直接见效的一步。

2.2 采样器只钳位终潜码，20 步 DDIM 全程无约束

training_dbdce.py L276–283：

    pred = unet(unet_in, t, encoder_hidden_states=p_tok.to(lat.dtype), return_dict=False)[0]

轨迹可以在 20 步里跑到任意远的地方，只有终点被截回来。「每一步都逐通道钳位」不是可选项，是必需项——这也印证了此前给出的 Tier 1 建议（推理端逐步收紧）在代码层面的必要性。

2.3 l_freq 不具尺度不变性：有非零底噪，且逼模型匹配一个任意的绝对浓度尺度

losses.py L37–69。x 是预测 IHC 的苏木精通道，y 是真实 H&E 的苏木精通道。两者都由颜色解卷积得到，而 estimate_background（physics.py L36–42，q=0.95）是逐图独立估计背景光强 i0。

d = (sx.clamp(min=1e-8).log() - sy.clamp(min=1e-8).log()).abs()

关键点：如果 sx 和 sy 之间存在一个整体尺度差（这完全任意——取决于两张图各自的 i0，以及染色矩阵的归一化常数），.abs() 不会把它消掉，而是给每个频带加一个常数偏移。

两个后果
  1. 损失有非零底噪。这就是为什么 l_freq 的中位数是 3.52、最小值是 1.51，从来不接近 0 —— 它不可能到 0，因为底下垫着一个任意的尺度差。
  2. 它逼模型去匹配一个没有物理意义的绝对浓度尺度。模型为了让 log 差变小，会去调整预测苏木精的绝对幅值，而不是它的空间结构。这不是我们想要的监督信号。

修法（标准做法，改动很小）：把两个谱都按各自的总能量归一化后再取 log，即比较「相对频带分布」而不是绝对能量。这样损失就是尺度不变的，底噪趋近 0，梯度的量级任意性也一并消失。可验证：改完后中位数应显著向 0 移动。

2.5 GradSurgery 两个设计问题：共享 cos_ema，且日志打的是瞬时 cos

问题一：单一标量管两个损失。losses.py L98 只有一个 self.cos_ema，却在 L141 被每个辅助损失各更新一次。于是 l_freq 的冲突历史会污染 l_prot 的判定，反之亦然。正确做法是每个辅助损失一个独立的 EMA。

问题二：判定量从不打印。判定用的是 cos_ema（L144），日志记的是瞬时 cos（L161）。于是日志里出现了这种行：

('protein', 'kept', -0.5175)      ← cos 是负的，却判定为 kept

这不是 bug（cos_ema 当时仍 ≥0），但它让门控无法从日志审计——决定行为的那个变量一次都没被记录。把 cos_ema 加进返回的 tuple 即可。

顺带一个语义问题：ema=0.9 时单次观测只移动 10%，但判定发生在把当前观测算进去之后（L141→L144）。对成对里的第一个损失，cos_ema 从 0 附近起步，一次大的负 cos 就能当场把判定翻掉。所以这个机制的有效记忆约 10 步，更接近「逐步骤门控」而非「冲突历史门控」。如果意图是后者，应该：① 判定前不含当前观测；② 把有效记忆窗口写进注释。

2.6 gate=off 无法区分「条件 dropout」与「解码非有限被静默跳过」

training_dbdce.py L562–586：dropped 只由 dropout 分支设置（L549）。当 pred_rgb 非有限（L567）时，代码直接跳过整个 aux 块，gate_info 保持 "off"——在 log.txt 和 log.csv 里与 dropout 步完全无法区分。

③ stat-match 的「改善」是假象，属于同一类陷阱

原因是 ③ 只把潜码的 mean/std 重新标定了一遍，把数值从 −1 这个阈值附近挪开，于是「越界像素的计数」变少了，图本身还是噪声。这既不是修复，也不是压缩——是把「可检测的失败」变成「不可检测的失败」，与 2.6 节的 gate=off、以及报告反复点名的「分位数 clamp 把黑团压到质检阈值以下」是同一种错误模式。

方法学推论：凡是「某指标下降」的改进，都要同时看它的极值是否变差。只看占比会误判。

补充：arXiv 2604.12152 自己的三个数据集是膝关节 MRI / 脑 MRI / 胸片，从未测过病理，所以它的 +2.91~3.29 dB 不能外推到本任务。它的价值在于「VAE 选择是主要约束」这个结论，而不是那个具体数字。

9浓度图策略：代码用的是 scheme B，与你原方案不是一回事

你的直觉是对的，而且这不是小差异

你在 R2 报告里定的方案（M1 物理输出头 / Step A）是：扩散 U-Net 不预测 RGB，直接输出浓度图 D̂，再用可微 Beer-Lambert 前向模型转成 RGB —— 生成发生在浓度空间。

而这份代码走的是它自己明确标注的 scheme B：保留 RGB 潜码输出 → 解码出 RGB → 再用颜色解卷积「倒推」出浓度 → 在浓度空间算损失 —— 生成发生在 RGB 空间，浓度只是一个事后读出。

方向正好相反：一个是正演，一个是反演。而这个差异，恰好就是我上一节报的 P0-2（梯度炸弹）的成因。

9.1 先确认：代码里前向物理渲染是死代码

training_dbdce.py 文件头的自述（L8）：

aux losses in Beer-Lambert concentration space (scheme B: decode predicted x0)

hdadapt/__init__.py L6 说得更直白：

RGB latent (kept, scheme B)  =>  decode predicted x0 -> Beer-Lambert
                                  concentration space losses

然后我做了一次全仓库检索，看物理模块的每个函数到底有没有被调用：

函数方向调用点状态

也就是说：R2 报告里的 L_phys 一致性损失没有实现；R2 里的 M1 模块没有实现。代码实现的是 M1 的反向版本。

9.2 两条策略的形式化

策略 A · 正演（你的原方案 / M1）

U-Net 输出浓度 C = (DAB, H)，然后

x = x̄₀ · exp(−S·C)

浓度是一等输出：非负性是结构保证的，单调性可检验，可直接可视化。

策略 B · 反演（代码实际）

U-Net 输出 latent，解码得 RGB，然后

C = pinv(S) · OD(x̂₀)

浓度是派生量：它是对一张已经画好的图的「解释」，解释得对不对没人检查。

9.3 四个后果，全部量化

后果 1：A 的输出天然在物理流形上；B 的浓度只是一个「投影」

S 是 3×2，所以它的像空间只是 RGB 三维空间里的一个二维曲面。用 pinv(S) 反演任意一张 RGB，得到的 C 只有在这张 RGB 本来就落在这个曲面上时才准确；否则 Render(Deconv(x)) ≠ x，差值就是这张图的物理不可行度。

但生成图崩坏时残差高达 0.64 —— 此时 Deconv 读出的「浓度」是纯粹的垃圾，而 l_prot 会拿这个垃圾去和真实浓度比 L1、算矩匹配，并给出一个看起来很正常、数值有限的损失值。

它是策略选择的直接后果。你选正演，那个 log 根本不会出现在训练图上；你选反演，它就必然出现，而且必然在生成图变暗时爆炸。

这也解释了一个此前想不通的地方：为什么「给浓度加值域约束」（R2 里给 M1 写的必做项）在 scheme B 里没有对应物 —— 因为 scheme B 里根本没有「浓度预测」这个东西可加约束，只有从 RGB 反推出来的一个派生量。

后果 3：策略 B 的损失对一个 1 维子空间完全盲

pinv(S) 是 2×3、秩 2，所以它的零空间是 1 维的。也就是说存在一个 OD 扰动方向 n，沿它改变图像时，读出的浓度 C 一个数字都不变。

这个方向可以解析求出：n ∝ s_DAB × s_H（两个染色向量的叉积）。用代码里的矩阵算出来是：

n = (-0.658, +0.697, -0.285)          # OD 空间，已归一化

  · 与 H   染色向量内积 = 0（精确）
含义：R 更亮 · G 更暗 · B 更亮   → 偏品红/洋红的方向

ΔC 是机器零（1.1e−16），ΔRGB 却到 0.553 —— 超过动态范围的一半。l_prot 和 l_freq 都从 C 算，所以它们共享同一个盲区。

换句话说：辅助损失对图像施加的约束是「投影后相等」，而不是「图像相等」。模型有一条完全无监督的自由通道，而这条通道正好就是「非物理颜色」的方向。

补充：这个盲区在 OD 的 clamp(min=0.0) 生效的边界上会失效（clamp 是分段线性的，会在拐点处破坏线性性）。所以严格地说盲区存在于「三个通道 OD 都为正」的内点区域——这恰好是生成图正常时的区域。

后果 4：clamp(min=0.0) 静默抹掉负浓度

physics.py L79：

return c.clamp(min=0.0), i0

反演出来的浓度可以是负的（因为 pinv(S)·OD 对任意 OD 都有解，包括物理上不可能的）。代码把负值直接夹成 0 —— 值上是对的（浓度不能为负），但梯度在这部分元素上变成 0，于是「反演给出了非物理结果」这件事既不会被记录，也不会产生任何学习信号。

这和第 2.6 节的 gate=off 是同一个错误模式：把一个可检测的失败，变成一个不可检测的失败。这个模式在本项目里已经出现了至少三次（gate=off、clamp(min=0)、分位数箱）。

9.5 三个选项（按改动成本排序）

选项 1 · 一行改动：给 log 的自变量加 ε
physics.py L49 · 改动 1 行 · 可复现性高
立即做
# 现在
return (-torch.log10((img.clamp(1e-6, 1.0)) / i0)).clamp(min=0.0)
# 改成
return (-torch.log10(img.clamp(0.0, 1.0) + 1e-3) / 1.0 + torch.log10(i0)).clamp(min=0.0)

效果：把梯度放大器从 434,000× 封顶到 434×（降低 1000 倍）。因为 d(−log10(x+ε))/dx = −1/((x+ε)·ln10)，在 x=0 处取到最大值 1/(ε·ln10)。

代价：OD 上限从 6 降到 3（ε=1e-3）。对 IHC 完全够用——真实 IHC 的最深 DAB 区域 OD 在 2–3 之间，OD=3 已经是很深的棕黑。如果你觉得不够，ε=1e-4 给 OD 上限 4、放大器封顶 4340×，仍是 100 倍的改善。

注意：img.clamp(1e-6, 1.0) 这个写法本身就同时犯了两个错——它既让 log 在 1e-6 处取到 6 的大值，又让梯度在 (1e-6, 1e-3) 这个带里达到 10⁴–10⁶。+ε 的写法把这两件事一起解决。

选项 2 · 小改动：把死代码 render_ihc 用起来，加 L_phys
即 R2 报告里的 L_phys · 改动 ~10 行 · 可复现性高
推荐
from hdadapt import render_ihc          # 这个函数已经写好了，只是没人调用

C_pred, _ = ihc_rgb_to_concentration(pred01, i0=ihc_i0)
x_hat     = render_ihc(C_pred, i0=ihc_i0)
l_phys    = (x_hat - pred01).abs().mean()      # 物理不可行度

为什么它能治后果 3 的盲区：Render(Deconv(·)) 是把图像投影到 2 染色流形上。沿零空间方向 n 移动图像时，投影点不变、但图像本身变了，所以残差会变——L_phys 恰好对这一方向有梯度。这是唯一一个用现成代码就能堵住盲区的做法。

额外收益：l_phys 本身就是一个可以写进论文的指标——「物理不可行度」。R2 报告里说「不要在论文里声称物理上正确而不给证据，要么给出 Beer-Lambert 分解重构的残差」——这个残差就是它。顺手把它记进日志（每 25 步一个数），你就有了一条曲线。
