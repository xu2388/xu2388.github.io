0.2 四条改变决策的结论

结论 1 · 这一层工作的真实形态是「把已验证的零件重新组合」，不是「发明新损失」

SAStainDiff 的四个组件，没有一个是它原创的：染色增强来自 DDCA（Marini 等，2023）的 (R, N) 门控；少步 DDIM 来自 guided-diffusion；输入派生初始噪声来自 SDEdit 那一族。它的贡献是把「用增强造对」和「扩散去噪」接起来，并让它在一个新任务上工作。这直接回答了你最初的困惑——你缺的不是方法，是把已有零件对齐到你任务上的判据。

结论 2 · 训练时间步分辨率与推理步数是两个相反方向的旋钮

StainDiffuser（arXiv:2403.11340）的步数消融显示：训练 T 从 500 提到 4000，FID 从 54.09 降到 23.46——训练侧越多越好。而 SAStainDiff 在推理侧只用 5 步。两者不矛盾，因为它们调的是不同的东西。这正好补上了我上一份报告里「含义 C（步数少）」缺的那块实证：砍推理步数可以，砍训练 T 不行。

结论 3 · 在病理领域，「改训练分布」比「改后处理」被实证证明更有价值

Tellez 等（Med Image Anal 2019）在 9 个中心、4 个任务上量化后给出的结论是：任何形式的染色增强都应该一直开着；而染色归一化「不是达到高分类性能的必要条件」，在算力受限时可以省掉，代价是「可忽略的性能下降」和「显著的提速」。这与我在噪声调度报告里发现的「改 p(t) 优于改 w(t)」是同一个结构性事实：扩大训练分布 > 事后校正。

结论 4 · 你遇到的配准问题，是被同类工作明确点名但未做的空白

StainDiffuser 要求 H&E 与 IHC 图块「registered at pixel level accuracy」，并在局限性里逐字写下：「Our study also does not assess StainDiffuser's sensitivity to registration accuracy between H&E and IHC images, leaving this as a direction for future research.」。同时它承认单中心训练会在跨中心时因输入分布漂移而掉性能。这两条加起来 = 你的问题定义在文献里是开放的。

1「这个层面」指哪一层

你给我的判断是「他这个就是在这个层面的一些创新吧」。为了后面能说清「哪些能搬」，先要把「层面」定义清楚——因为同一个方法在不同层面上看，可移植性完全不同。

1.1 三层创新

任务层

改的是问题本身。例：把 H&E→IHC 从 RGB 域搬到 OD 域（Kang 2025）；把染色归一化重新定义为「灰度域重建」的自监督问题（StainLUT）。

风险：需要重新定义监督信号，改动最大。

方法层

改的是建模方式。例：用扩散替代 GAN（StainDiff, MICCAI 2023）；双扩散联合分割（StainDiffuser）；改噪声调度 / 时间步概率（上一份报告）。

风险：需要重训，但通常能复用现成 backbone。

工程层 ★

改的是怎么把已有方法跑通。例：(R,N) 门控的增强合法性校验；5 步 DDIM + 起点前移；输入派生初始噪声；滑窗拼接。

风险：最低，多数零训练或一行改动。

SAStainDiff 的位置

它是方法层（用扩散替代传统归一化）+ 工程层（四个零件）的混合体，但它的「新」几乎全在工程层。这就是为什么它能发在 BSPC 而不是 NeurIPS——它解决的问题是「这套零件在这个任务上到底能不能用、要怎么配」，而不是「有没有更好的数学」。

你在上一份报告的收尾里说过：「你现在并不缺少可以尝试的扩散方法，真正需要的是找出一个有证据支撑的假设，再通过最小实验判断它是否成立。」 这句话在本层尤其成立，原因有三：

2.2 组件 A：染色增强自监督（两种增强 + KD-tree 合法性门控）

这是 SAStainDiff 的核心机制。它不收集配对数据，而是把一张图重新染一次色造出「同一个结构、不同染色风格」的对。增强有两个分支，按 80/20 概率选择：

分支 A1 · HSV 扰动（80%）
Augmentation.py:123-154 · new_color_augmentation
概率 0.8

用 albumentations 对色相/饱和度/明度做随机位移，位移幅度 shift_value=25（训练脚本里；函数默认 70）。然后不是直接用，而是：

  1. 对扰动后的图跑 H_E_Staining() 反解出它的 6 维染色矩阵；
  2. 用 KD-tree 查它的 5 个最近邻，距离上限 beta=0.1；
  3. 只有当这 5 个近邻互不相同时才接受，否则重试（最多 1000 次）。
分支 A2 · 染色矩阵重染（20%）
Augmentation.py:157-194 · new_stain_augmentation
概率 0.2

从染色数据库里随机抽一个真实染色矩阵，做乘性 + 加性扰动，再用它把原图重新染一遍：

HE_ref = data[random_choice(N)]          # 从真实染色库里抽
alpha_sig = U(1 - sigma1, 1 + sigma1)    # sigma1 = 0.7  → 乘性 [0.3, 1.7]
beta_sig  = U(-sigma2, sigma2)           # sigma2 = 0.7  → 加性 [-0.7, 0.7]
HE_ref = HE_ref * alpha_sig + beta_sig
# KD-tree 合法性门控（同 A1，但阈值 stain_threshold = 1e6）
A_np = normalizeStaining(patch_np, HE_ref)   # ← 用扰动后的矩阵重新染色

另有 50% 概率的 Gaussian blur（ksize 取 5–21 的奇数，σ~U(0.1, 2)），只加在 condition 上，不加在 x₀ 上。

★ 这里有一个直接和你「浓度空间建模」相关的发现

normalizeStaining() 的实现是标准 Beer–Lambert 三步：

OD = −log((I + 1) / I₀)
C = lstsq(HE, OD) # 解出浓度
I′ = I₀ · exp(−HE_ref · C) # 用新染色矩阵重混

也就是说，SAStainDiff 的染色增强本质上是在浓度空间里换混合矩阵——和你想做的「浓度域扩散」是同一个空间对象。它不是把 RGB 调一调，而是分解出浓度、换矩阵、重渲染。这一点在论文摘要里完全看不出来，只有读代码才知道。

2.3 组件 B：rescheduled sampling（实算起点是 t=720，不是 900）

这是全篇最容易被误读的一处。README 写的是：

--timestep_step: The initial sampling point. Default is 900.

但它并不是起点。追踪接线：test.sh 传 --timestep_step 900 --timestep_respacing ddim5，script_util.py:424 把它接到

use_timesteps = space_timesteps(timestep_step if not is_train else steps,
                                timestep_respacing)

而 space_timesteps(900, "ddim5") 的语义是「在 [0, 900) 上找一个整数 stride，使保留点数恰好为 5」：

配置保留的原始时间步实际起点起点 ᾱ起点 σ起点 SNR起点 logSNR
timestep_step=1000 + ddim5（默认）{0, 200, 400, 600, 800}t = 800（80%）0.001510.99920.00151−6.50
timestep_step=900 + ddim5（论文设置）{0, 180, 360, 540, 720}t = 720（72%）0.005150.99740.00518−5.26

ᾱ/SNR 由 guided-diffusion 的 scaled linear 调度（β: 1e−4·s → 0.02·s，s=1，T=1000）逐项累乘算出，可复现。

这个数字修正有两层意义
  1. 「起点 900」是误读。真实起点是 t=720，也就是「只加噪到 72%」——这正好是你问过的那个「70%」。它属于我上一份报告里的含义 A（推理期低噪声起点），不是含义 B（训练截断）。
  2. 但它和 t=800 的差别其实很小：σ 从 0.9992 变到 0.9974，σ² 都 ≈ 1。所以真正省时间的是「5 步」，不是「起点前移」。把这两个效果混为一谈，是读这篇论文时最容易犯的错。

2.4 组件 C：输入派生初始噪声（残留 7.2% 输入信号）

test.py:101（any-size 分支）与 test.py:153（普通分支）都是同一行：

noise = diffusion.q_sample(HE_input, th.tensor(len(diffusion.betas) - 1))

因为 diffusion 是 SpacedDiffusion，len(betas) = 5，索引 4 对应保留的最大原始时间步。又因为 SpacedDiffusion 会把 betas 按 ᾱ 比例重标定，所以累计乘积恰好等于原过程的 ᾱ₇₂₀。于是初始状态是：

x_T = √0.00515 · x_input + √0.99485 · ε ≈ 0.0718 · x_input + 0.9974 · ε

也就是说，初始状态不是纯高斯，而是「输入图加了强噪」——保留了 7.2% 的输入信号。对比：如果起点是 t=800，保留比例只有 √0.00151 = 3.9%。所以「起点前移」的真实效果是把输入信号的残留量提高约 1.85 倍。

为什么这个零件对你的结构保持诉求是「同向」的

你一直在解决「结构保持」。这个零件给出的是一条零训练成本的软锚定：不去改损失、不去加分支，只在初始状态里塞进一点输入信号。它比 H 浓度锚定投影更弱，但成本低到可以立刻试，而且天然可调（起点越靠前，锚定越强）。

2.5 组件 D：any-size 滑窗采样

gaussian_diffusion.py:403-410：

def overlapping_grid_indices(self, x_cond, output_size=256, r=256-62):  # r = 194
    h_list = [i for i in range(0, h - output_size + 1, r)]; h_list.append(h - output_size)
    w_list = [i for i in range(0, w - output_size + 1, r)]; w_list.append(w - output_size)
    return h_list, w_list

即：256×256 窗口、stride 194（重叠 62 像素），网格点累加到 x_grid_mask 后归一化。目的很明确——让 256×256 训练的模型能推理任意尺寸图，不必对 WSI 做无重叠切块（无重叠切块会在边界产生接缝）。

因此本报告对 SAStainDiff 的所有机制结论都来自官方代码（这比正文更可靠），而所有性能数字一律留空。下面是拿到 PDF 后必须优先核对的 6 件事：

  1. 它有没有对 timestep_step / timestep_respacing 做消融？如果做了，「起点前移 vs 步数减少」哪个贡献更大就有了答案——这是本报告最想补上的数字。
  2. 它有没有对染色增强强度 sigma1/sigma2=0.7 做消融？（对比 Tellez 的「轻增强更好」，见 §5.2。）
  3. (R, N) = (0.1, 5) 是调出来的还是照抄的？DDCA 原文的最优是 (0.05, 10)，两者方向相反（更宽 + 更少邻居）。
  4. 80/20 的 HSV / 重染比例是否消融过？
  5. MITOS-ATYPIA'14 / Camelyon16 / GlaS 三个数据集上分别是哪些指标、多少分？
  6. 摘要说「reduces the inference time, which is comparable to mainstream methods」——对比的 mainstream 是哪些、具体秒数是多少？

3谱系：四个组件分别来自哪里

把 SAStainDiff 的零件往上追溯，你会发现它站在三条已经很成熟的线上。知道线在哪，比知道这一个点更有用——因为你可以沿线下手，而不必只盯着这一篇。

3.1 (R, N) 门控来自 DDCA

SAStainDiff 的 README 自己承认：「we performed stain augmentation referring to Data_Driven_Color_Augmentation」。那篇是 Marini 等，Journal of Pathology Informatics 2023, 14:100183（DOI 10.1016/j.jpi.2022.100183，PMC9852546 开放全文）。它的核心思想一句话：

"the color variation of an augmented sample A is considered admissible only if it is near to more than N admissible samples."
DDCA，用 R（Euclidean 半径）与 N（最少近邻数）两个参数做增强合法性门控

DDCA 的具体构造（全文可核）：

要素DDCA 原文SAStainDiff 的实现
染色矩阵表示2×3 矩阵（H、E 各自的 RGB 吸收分量），Macenko 法估计同样 6 维（np.reshape(HE_ref, 6)）
数据库规模>200 万个 H&E 矩阵（TCGA 123 中心 + ExaMode + Camelyon 4 中心 + 其他），10× 密采 → >800 万样本Aperio.pickle + Hamamatsu.pickle 两个扫描仪

一个值得注意的偏离

SAStainDiff 把 R 放宽了一倍（0.05→0.1）、N 减半（10→5）。方向上是「允许更远离真实染色的增强，但要求更少的邻居背书」——这会让增强分布更宽、更激进。这与 Tellez 的「轻增强更好」结论（见 §5.2）方向相反。是调出来的还是随手设的，只能等正文。

3.2 ★ 染色增强 vs 染色归一化：Tellez 的实证结论

如果只能从这一整条线里带走一个结论，就是这个。Tellez 等，Medical Image Analysis 2019, 58:101544（DOI 10.1016/j.media.2019.101544；arXiv:1902.06543 有开放 HTML）。他们在 4 个任务、9 个中心上第一次量化了这两类方法的真实作用。逐字结论：

"we found that any type of stain color augmentation, i.e. HSV or HED transformation, should always be used."
"overall top performance was achieved without the use of color normalization. This piece of evidence suggests that color normalization is not a necessary condition to achieve high classification performance in histopathology images."
"In setups with reduced computational resources, color normalization could be omitted, resulting in a negligible performance reduction and a substantial improvement in processing speed."
"we recommend tuning the intensity of the color augmentation to light or strong in case color normalization is enabled or disabled, respectively."

另外两条有用的细节：HED 与 HSV 增强没有显著差别（「We did not find, however, any substantial performance difference between using HED or HSV color augmentation」）；强增强与轻增强总体接近，轻增强略优，强增强在内部测试集上平均掉不到 1%。

这条结论为什么重要——它与上一份报告是同一个结构
领域「改训练分布」「事后校正」实证结论
自然图像扩散改时间步采样 p(t)（等价于改调度）改损失权重 w(t)p(t) 优于 w(t)（ICCV 2025 Table 9：FID 7.98 vs 8.88）
病理染色染色增强（训练时扩大分布）染色归一化（推理前确定性变换）增强必开；归一化非必要（Tellez 2019）

两件事在数学上不同、在结构上同构：让模型见过多样性，比事后把输入拉齐更有效。这是本报告最值得记住的一句话。

但请注意 SAStainDiff 的定位是「反例」

SAStainDiff 本身是一个归一化方法，却用增强来监督。也就是说，它没有在「增强 vs 归一化」之间选边，而是把两者接成了一个循环：增强造出训练对 → 训练出归一化能力。这解释了它为什么比传统归一化泛化好，也解释了它为什么必须要求像素级对齐（因为增强是在同一张图上做的）。

3.3 少步采样来自 DDIM / guided-diffusion

组件 B 里除了「起点前移」，其余全是 openai/guided-diffusion 的原生能力：space_timesteps、SpacedDiffusion、_WrappedModel 的 timestep 重映射。SAStainDiff 的改动只是把 timestep_step 从 1000 改成 900（见 script_util.py:424 的那行三元表达式）。

这一点值得单独说：它证明「rescheduled sampling」这个听起来像新方法的名字，实现代价是一行参数。所以在你评估「值不值得试」时，答案几乎总是「值得，因为成本近乎为零」。

4.2 三条跨表结论

结论 A · 这个子领域的方法级创新集中在「怎么造监督信号」，不在「怎么改扩散」

10 篇里有 4 篇（SAStainDiff、DDCA、StainLUT、Tellez）的核心贡献是监督信号的构造：增强造对（SAStainDiff）、合法性门控（DDCA）、灰度域自监督（StainLUT）、量化哪类监督更有用（Tellez）。只有 3 篇（StainDiff、StainDiffuser、Jeong）动的是扩散模型本身，而其中 2 篇闭源。

结论 B · 「结构一致性」这个假设的强度，决定了方法能不能用在你身上
方法它对输入/目标关系的假设与你的连续切片（有配准误差）的匹配度
SAStainDiff像素级完全一致（同一张图重染）不匹配
StainDiffuser像素级配准（原文要求 registered at pixel level accuracy）不匹配（且作者承认未测敏感性）
StainLUT同疾病类型的组织结构近似一致（跨中心，无对齐）最匹配
HistDiST / Kang配对切片（假定可配准）部分匹配

⇒ StainLUT 的监督假设（结构近似一致、无需对齐）在原理上比 SAStainDiff 更贴近你。虽然它不是扩散模型，但它的假设形式值得移植：把「结构一致性」当监督信号，而不是把「像素一致性」当监督信号。

结论 C · 这个子领域的「时间步」这一层基本没被动过

SAStainDiff 用 均匀 p(t) + 无加权；HistDiST 也是（torch.randint + snr_gamma=None）。两篇都是这个领域里调度配置最讲究的工作，而它们的 p(t) 都是最朴素的均匀分布。这与上一份报告的结论一致：这是真实存在的空白，且改动成本低。

5三条分歧

把 10 篇放在一起看，有三处结论方向不一致。它们不是「有人错了」，而是调的是不同旋钮。分清楚这三处，你才不会在实验设计里把两个效果搅在一起。

5.1 训练 T 越多越好，推理步数却能砍到 5

证据调的是什么结论
StainDiffuser Table 3（CK818，128²）训练时的扩散步数 T500 → PSNR 15.89 / SSIM 0.544 / FID 54.09；1000 → 18.11 / 0.605 / 30.18；2000 → 17.01 / 0.578 / 43.80；4000 → 21.67 / 0.676 / 23.46 ⇒ 越多越好（4000 最优）
StainDiffuser Table 9（64²）同上CK818：250 → 22.97/0.782/27.25；1000 → 22.83/0.775/22.86；4000 → 23.08/0.782/22.09。非单调（2000 反而差）⇒ 不是「无脑加」，需调
SAStainDiff test.sh推理时的 DDIM 步数ddim5 ⇒ 只用 5 步，论文称性能保持
必须分清：这是两个不同的旋钮

训练 T 决定的是「模型见过多少个不同的噪声水平、噪声水平的分辨率有多细」；推理步数 决定的是「用多少个离散点去积分 PF-ODE」。前者是模型能力问题，后者是数值积分精度问题。

所以两条结论并不冲突，而且合起来给出一个很实用的组合：训练时把 T 开大（4000 级），推理时砍到 5 步。这正是 StainDiffuser 自己在局限里说的方向——它说推理慢「could be addressed by exploring fast-sampling diffusion methods」，而 SAStainDiff 恰好就是那个答案。

A 推理期低噪声起点（SDEdit 式）SAStainDiff 起点 t=720有工程实例，且是它的「rescheduled sampling」的一部分
B 训练时截断高噪段无正面证据；StainDiffuser 反而显示训练 T 要开到 4000不建议——间接证据方向相反

5.2 增强强度：轻、窄、还是宽

来源强度设置结论方向
Tellez 2019（全文）轻 vs 强轻增强略优；强增强在内部测试集平均掉 <1%；建议「归一化开启时用轻增强、关闭时用强增强」
DDCA（全文）R=0.05 · N=10收窄：只接受靠近真实染色分布的增强
SAStainDiff（代码）σ1=σ2=0.7（乘性 [0.3,1.7]）· R=0.1 · N=5放宽：扰动幅度大、门控松
这处分歧是真实的，而且没有被任何一篇正面解决

三方给的参数方向互不相同：Tellez 说轻、DDCA 说窄、SAStainDiff 说宽。可能的原因是任务不同——Tellez 做分类（要域不变特征），DDCA 做分类（要真实分布），SAStainDiff 做生成/归一化（要覆盖足够大的风格空间才能外推）。

对你的启发：你的任务是生成，所以倾向「宽」；但你的数据有配准误差，宽增强可能放大伪影。这是一个需要你自己测的交叉点，也是 §7 实验要覆盖的一项。

5.3 归一化到底还要不要做

三种立场并存
  • Tellez 2019：归一化「不是必要条件」，算力受限时可省，代价可忽略。
  • StainLUT 2025：归一化是核心价值——它让单中心模型在跨中心时恢复可用（「仅用中心 1 数据训练的原始 CNN 在中心 2 的肿瘤定位任务中几乎完全失效，采用 StainLUT 后能准确识别大多数肿瘤区域」）。
  • SAStainDiff 2025：归一化是任务本身，但用增强来监督它。

这不是矛盾，是「谁在训练、谁在推理」的区别：

场景归一化的作用对应文献
你自己训练模型、自己用可用增强替代（模型自己学会不变性）Tellez（分类任务）
别人训好的模型、你要用归一化是唯一手段（你改不了模型）StainLUT（跨中心部署）
你要生成新图归一化就是输出目标SAStainDiff

⇒ 你的处境属于第一类（你要训自己的 H&E→IHC 模型）。所以 Tellez 的结论对你直接适用：先把预算投在增强/训练分布上，而不是先做归一化预处理。这也和你「不做过多辅助损失、不做大架构改动」的约束一致——增强是数据管线里的改动，不是模型里的。

Tellez 的「增强优先」原则 可直接用（作为决策原则） 低 把增强强度当成一个受控变量纳入消融，而不是拍一个值 低

这意味着什么

SAStainDiff 的「自监督」之所以成立，是因为它人为制造了一个像素级配准的数据集。它的监督信号强度等同于有配对数据——只是配对是合成的。

你的连续切片没有这个性质。你的 H&E 与 IHC 之间存在空间偏移与配准误差，所以：

  • 你无法用「重染同一张图」造对；
  • 你无法假定逐像素监督可靠；
  • 因此 SAStainDiff 的核心机制（组件 A）在你这里不成立——不是实现难度问题，是前提不成立。
但这恰恰是一个可写的机会

StainDiffuser 逐字承认：「Our study also does not assess StainDiffuser's sensitivity to registration accuracy between H&E and IHC images, leaving this as a direction for future research.」

而 StainLUT 给出了另一条路：把监督假设从「像素一致」降级为「结构近似一致」（它的依据是「不同中心同一疾病类型的组织样本在形态学结构上具有高度一致性」）。你的连续切片正处在两者之间：比跨中心更接近（同一块组织的相邻切面），比配准切片更远（有偏移）。

⇒ 「配准误差下，监督假设该降到什么粒度」是一个被点名但没人做的题。而它需要的第一个实验恰好是零成本的（§7）。

6.3 三条可执行移植路线

路线 1 · 零成本推理侧移植（建议最先做）
对应组件 B + C · 不改模型、不重训
成本最低

假设：在你的 baseline 上，把推理步数砍到 5 步量级、并把初始状态换成「输入图加噪」，性能下降可忽略，且结构指标改善。

做法：在冻结的 baseline 检查点上做 2×2 对照：{步数 5 / 步数 50} × {纯高斯初始 / 输入派生初始}。四个格子跑同一批测试图。

为什么先做：不需要训练、不需要新代码（只改采样入口）、结果当天可见。即使全阴性也有价值——你会知道「推理侧还有没有免费的午餐」。

路线 2 · 把「增强合法性门控」搬到浓度域
对应 DDCA 的 (R, N) 范式 · 需建库
中等成本

假设：你现有的增强（若有）会产生不真实的浓度分布，收窄它可改善对未见样本的表现。

做法：先用你已有的无配对 IHC 数据统计出一个浓度分布库（每个 patch 的 DAB/FOD 的均值 + 分位数 + 直方图向量）；对每个增强样本，只有当它在库中的近邻数超过阈值时才接受。

关键差异：SAStainDiff/DDCA 的库是6 维单点（染色矩阵），你的库必须是分布级（因为你有配准误差，单点不可靠）。这是你相对原方法必须做出的改动，也是可以写进论文的地方。

路线 3 · 用「结构近似一致」替代「像素一致」做监督
对应 StainLUT 的假设降级 · 改动最大
高成本

假设：在配准误差存在时，以区域级/结构级一致性（而非逐像素）作为监督，能得到更可靠的 H&E→IHC 映射。

做法：把逐像素重建损失替换/补充为「结构级一致性」（例如核掩膜 Dice、区域浓度排序一致性），并用 §6.2 提到的人工劣化配准做对照，验证「监督粒度 vs 配准误差」的关系。

风险：这条路线与你的「不做过多辅助损失」约束有张力。建议先把它当作路线 1/2 结果不理想时的备选，而不是起点。

三条路线的推荐顺序

路线 1 决定「推理侧有没有免费的午餐」；路线 2 决定「增强该不该收窄」；路线 3 决定「监督粒度要不要改」。三者成本递增、假设强度递增。不要同时做——否则你无法归因。

7最小验证实验（RTX 4060）

本节只写路线 1——因为它是唯一「零训练、当天可出结果」的实验，也最符合你「先找有证据支撑的假设再最小验证」的要求。

7.1 前置：先冻结 baseline

必须冻结的项为什么要冻
检查点（同一份权重）本实验不改模型，只改推理入口；换权重就失去可比性
噪声调度 β / ᾱ本实验不碰调度（那是路线 2 之后的事）
训练时的 p(t) 与 w(t)同上，保持均匀 + 无加权
测试集与随机种子否则 4 个格子的差异分不清是配置还是采样噪声
评测脚本与指标定义尤其「浓度类指标」的口径（见 7.3）

7.2 实验矩阵（2×2，四个格子）

格子推理步数初始状态它回答什么
E0（对照）50 步纯高斯 randn_like()基线
E15 步纯高斯「砍步数」单独的影响（= 你的「含义 C」）
E250 步输入派生 q_sample(x_input, t_start)「输入锚定」单独的影响（= 你的「含义 A/C 的锚定部分」）
E35 步输入派生两者的组合（SAStainDiff 的实际配置）

起点 t_start 怎么选：不要直接抄 720。按 保留信号比例来定更稳：SAStainDiff 的 √ᾱ ≈ 0.072。建议扫 t_start 使 √ᾱ ∈ {0.03, 0.07, 0.15} 三个档（对应不同的锚定强度），因为你的结构与 SAStainDiff 的染色归一化任务不同，最优锚定强度未必一样。

RTX 4060 上的算力预算：只给方法，不给数字

我无法可靠估计你的模型单步耗时（取决于分辨率、通道数、是否 latent）。所以这里给的是测量模板，不是时长：

1. 先跑 E0 一次，记录：总秒数 / 图数 / 单步秒数
2. 单步秒数 × 步数 = 每张图的推理成本
3. 用 step 2 的结果外推 4 个格子 × 测试集大小的总成本
4. 只有当 4 个格子的总成本 < 一次完整训练成本时，这个实验才划算

参照量级：SAStainDiff 用 5 步 而非 1000 步，理论上推理成本差 200 倍——但这是它论文的说法，具体秒数我没有拿到（见 §2.6 第 6 条）。

7.3 必须同时记录的两组指标

这一条是 HistDiST 用一手数据教给我们的（见 §4.1）：加 DDIM 反演使 SSIM 变好、FID 变坏；注噪越多 FID 变好、MRA 变坏。只看一组，你一定会把「变了」读成「好了」。

指标族它能支持什么它不能支持什么配准误差下怎么办
分布类
（FID / KID / Precision / Recall）		「生成的 IHC 在统计上像不像真实 IHC」不能说明结构对不对、浓度对不对可用，因为它是集合级统计，不依赖逐像素对齐
浓度类
（DAB/FOD 均值 · 标准差 · 高分位数 · 直方图）		「表达强度分布对不对」——这是病理上最有意义的量不能说明空间分布对不对首选。对配准误差最鲁棒
结构类
（核掩膜 Dice / 区域一致性）		「组织结构有没有被破坏」不能说明染色对不对用分割掩膜而非原图比，可吸收部分配准误差
逐像素类
（PSNR / SSIM）		参考值，便于和文献比在配准误差下会被系统性低估，不可作为主判据只作辅助；务必与上面三类同报
判读规则（事先定好，避免事后解释）
  1. E1 vs E0：分布类 + 浓度类都没有显著变差 ⇒ 5 步可用，拿到免费提速。
  2. E2 vs E0：结构类显著变好而浓度类不变差 ⇒ 输入锚定有效。
  3. E3 vs 全部：若 E3 ≈ E0 或更好 ⇒ SAStainDiff 的配置在你的任务上成立，可以写进方法。
  4. 止损：若 E1/E2/E3 全部在分布类或浓度类上显著变差 ⇒ 记为阴性，直接放弃推理侧移植，转路线 2。不要为了「让它work」去调参。
两条必须做的控制
  • 两个种子：推理采样有随机性（即使 DDIM 确定性，输入派生初始噪声也引入了输入依赖）。至少跑两个种子确认差异不是噪声。
  • 人工劣化配准对照：对同一批测试图，人工施加不同幅度的空间偏移（如 0 / 2 / 5 / 10 像素），看 E2/E3 的「结构类指标收益」是否随偏移增大而衰减。这一条能直接验证 §6.2 的假设，而且几乎零成本。
