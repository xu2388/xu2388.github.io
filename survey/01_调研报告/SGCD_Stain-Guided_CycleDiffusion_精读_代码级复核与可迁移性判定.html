SGCD：Stain-Guided CycleDiffusion
—— 代码级复核与「能不能搬到 H&E→IHC」的判定

一篇 NeurIPS 2025 Spotlight 的病理 UDA 论文，用「双扩散 + 双向约束 + stain-guided 一致性损失」做跨医院/跨扫描仪的图像转换。它和本项目最像，也最容易误引。本报告读完了原文 31 页，并把官方实现逐行看了一遍——发现它的旗舰机制在代码里是死代码。

NeurIPS 2025 · Spotlight Poster DOI 10.52202/085713-1305 pp. 39107–39137 任务：UDA 分类（非虚拟染色） 原文 31 页已通读 官方实现已逐行复核 2026-10-07

0先说结论

★ 一句话

它是「同染色、跨实验室」的域适应论文，不是虚拟染色论文；它的核心机制在 H&E→IHC 上语义错位；而且它的官方实现把这个机制硬关掉了。它可以给你三条关于染色标定的独立互证，但不能当基线、也不能当先例引用。

2方法逐件拆解

先把它怎么工作讲清楚，后面才有资格判定「哪一件能搬」。SGCD 的全部构件只有四个：两个预训练 DDPM、一个循环、一个 stain-guided 引导项、一个一致性损失。

2.1 双扩散 + 两阶段循环

它假设你手上已经有两个分别在源域 S、目标域 T 上训好的 DDPM（记 D_S、D_T）。转换不做「学一个映射」，而是做「先加噪到第 k 步，再换另一个域的模型反向去噪」：

阶段一（单程）：
  S′ = { f_DS(x, k) | x ∈ S }          # 源图加噪到第 k 步
  T′ = { f_DT(x, k) | x ∈ T }          # 目标图加噪到第 k 步
  T_S = { r_DT(x^(k_G), k′) | x ∈ S′ } # 用目标模型反向 → 目标风格图
  S_T = { r_DS(x^(k_G), k′) | x ∈ T′ } # 用源模型反向 → 源风格图
  k′ = k − k_G

阶段二（回程，形成闭环）：
  T′_S = { f_DT(x, k) | x ∈ T_S }      # 再给 T_S 加噪
  Ŝ    = { r_DS(x^(k_G), k′) | x ∈ T′_S }   # 用源模型反向 → 回到源域
  Ŝ_T  = { f_DS(x, k) | x ∈ S_T }
  T̂    = { r_DT(x^(k_G), k′) | x ∈ S′_T }   # 回到目标域

⇒ 得到两个完整的环：S → T → S  和  T → S → T
关键点：它不需要配对数据

因为两个 DDPM 都是各自域内预训练的，所以「加噪 + 换模型去噪」本身就会落到另一个域的分布上。环的两端都是自己的原图 ⇒ 不需要配对、也不需要指定参考图。这是它 Table 1 里主打「X（不需要 paired data / reference image）」的原因，也是它相对 StainDiff / BBDM / A-Bridge（都要配对或参考）的卖点。

注：代价是它必须先在两个域上各训一个 DDPM。对 H&E→IHC 来说，这要求你有一个 IHC 的 DDPM——这个你其实能有（IHC 非配对数据你有），但见 §5：真正卡住的不是这一步。

2.2 stain-guided 过程（Eq.3）

光靠「加噪 + 换模型」会丢特征（这是它 Fig.1(a) 的动机实验：噪声加得越多，越像目标域，但越丢源域特征）。所以它加了一个引导项。给定参考图 I_ref：

G(xt, Iref) = x̂t−1 − ∇xt ‖ x̂0(xt) − Iref ‖     (Eq.3)

其中单步估计的干净图是 x̂₀(x_t) = a_t·x_t − b_t·D(x_t, t)，a_t = √(1/β̄_t)、b_t = √(1/β̄_t − 1)。这个 x̂₀ 形式与 DDPM 的标准写法一致（b_t = √(1−ᾱ_t)/√ᾱ_t = SNR(t)−1/2，记住这个 SNR−1/2，§3.3 会用到）。

★ 参考图怎么造——这是整篇论文最关键、也最不能迁移的一步：

I_ref = I₀ · exp(− W_T · H_S)        # 目标域的染色颜色矩阵 × 源域的染色密度图
                                     # 对回程方向：I_ref = I₀ · exp(− W_S · H_S)

也就是说，它把「源图的染色密度」用「目标图的染色颜色」重新渲染一遍，当成引导目标。这一步是 Beer–Lambert 正演——而库内既有报告此前把这一点标为「未核实」，本报告已结案：确实用了（代码见 §4）。

这一步为什么能在 Camelyon17 上成立

因为 S 和 T 都是 H&E。两个域的染色集合相同（都是 {苏木素, 伊红}），所以「把 A 医院的密度图用 B 医院的颜色渲染一遍」是良定义的：密度图的两行（H 密度、E 密度）与颜色矩阵的两列（H 色、E 色）一一对应。

H&E→IHC 时这个对应关系断裂——详见 §5.1。这是本报告判定「不可直接迁移」的核心依据。

引导只在时间窗内施加。论文设置是「guidance 从 timestep 600 施加到 100」，其余 timestep 走标准反向扩散（Eq.2）。k_G 就是控制引导范围的那个超参。Appendix Table 10 的消融显示：k=600, k_G=100 最优（AUC 95.8），k_G=150 掉到 90.9，k=1000 时掉到 83.9。

这条消融对你其实有用（先记下，§6 再展开）

它给出了一个「引导项不该铺满整条轨迹」的实测证据：末期不引导更好，起点也不能太高。这和你在梯度冲突报告里得到的「训练进程 s 轴：warmup 渐入 + 末期关闭」是同一个直觉作用在另一个轴上——但注意两者不是一回事：Lantern 是训练期末期关闭辅助损失；SGCD 是采样期末期不施加引导。不要混为一谈。

2.3 SGC 损失与 task 损失

Stain-Guided Consistency（SGC）损失（Eq.8）——用来微调两个扩散模型：

lossSGC = ‖S − Ŝ‖² − Σ y·CS(Ŝ) + ‖T − T̂‖² − Σ y·CT(TS)

四项分别是：源域环回重建 L2 · 源分类器对回程图的分类约束 · 目标域环回重建 L2 · 目标分类器对目标风格图的分类约束。注意后两项是负号——原文写的是 −Σ y·C(·)，实现里用 CrossEntropyLoss（内部已含负号），等价。

task 损失（Eq.9）——用来训目标分类器：

losstask = − Σ y·CT(TS) + lossMMD( CT(TS), CT(T) )

即「在带标签的合成目标风格图上做交叉熵」+「用 MMD 拉近合成图与真实目标图的特征分布」。Appendix Table 7 拆了这两步的贡献：Source-Only 75.9 → 只用 T_S 训就 92.6 → 再加真实 T 到 95.8。

2.4 交替训练

循环：
  ├─ 阶段 D（训扩散）：固定 C_S、C_T
  │     用 loss_SGC 更新 D_S、D_T
  └─ 阶段 C（训分类器）：固定 D_S、D_T
        用 loss_task 更新 C_T

C_S 全程冻结（原文：「CS is fixed during all the training phases」）
这个「交替」结构本身值得警惕

你在梯度冲突报告里已经证明过一条：当两个损失的参数子集不相交时，g₁ᵀg₂ ≡ 0，PCGrad 空转，冲突不会消失——它变成「序列耦合 → 振荡」。

SGCD 的交替训练正是一个参数子集不相交的设计（阶段 D 只更新 UNet，阶段 C 只更新 ResNet50 的 fc）。所以：它理论上没有梯度冲突，但也没有任何机制防止两个阶段互相拆台。论文对这个稳定性是断言（「Since the process involves only fine-tuning, it is inherently stable」），不是测量——checklist 第 7 项答 [No]，没有误差棒。

            sample = checkpoint(denoise_step, sample, t, model, scheduler)
        return sample
★★★ 结论：stain-guided 引导在发布的代码里是死代码

所有调用点都传 guide=True（共 6 处），但函数体第 5 行无条件把它改成 False。因此：

  • 整个 if guide: 分支一次都不会执行；
  • denoise_step_with_guidance 一次都不会被调用；
  • vahadane 对象在训练主循环里从不构造；
  • 反向过程退化成纯粹的无引导 DDPM 采样；
  • guide_until（论文的 k_G）完全无效——因为引导根本没开，关不关它都一样。

也就是说：论文里名为 SGC 的「stain-guided 一致性」机制，在代码里只剩下 Eq.8 的环回 L2 + 分类约束两项，stain 引导那一项是不存在的。

为什么我确信这不是我读错：我把同一份文件用两条独立路径抓取（raw.githubusercontent 的 raw 文本、GitHub blob 页），两次都返回了完全相同的 scale = 10 / guide = False 两行，以及相同的函数签名（guide=True 默认值）。这是§8里说明的核实方式。

3.3 ★ 被关掉的那段「梯度」并不是梯度

假设你把 guide = False 改成 True 让它跑起来，会发生什么？看 denoise_step_with_guidance 里真正算引导的那几行：

    residual = model(sample, t_tensor, return_dict=False)[0].detach()   # ★ 注意 .detach()
    alpha_prod_t = scheduler.alphas_cumprod[t_int]
    beta_prod_t = 1 - alpha_prod_t
    pred_x0 = (sample - residual * (beta_prod_t).sqrt()) / (alpha_prod_t).sqrt()

    ref_x0 = batch_process_vahadane(x0_path, ref_T_path, vhd)

    l2_diff = pred_x0 - ref_x0.to(sample.device)
    l2_norm = torch.norm(l2_diff)

    norm_grad = (l2_diff / l2_norm)      # ★★ 这不是梯度，是残差方向的单位向量

    return norm_grad * guidance_scale
★★ 三处偏差，逐个说
  1. 它不是 ∇‖x̂₀ − I_ref‖。按链式法则，∇x_t‖x̂₀(x_t) − I_ref‖ = (x̂₀ − I_ref)/‖x̂₀ − I_ref‖ · ∂x̂₀/∂x_t。代码把 Jacobian ∂x̂₀/∂x_t 整个丢掉了，只留了前面那个单位向量。所以它做的是「沿残差方向推一个固定长度」，不是梯度下降。
  2. 没有梯度回传。residual 后面挂了 .detach()，而 pred_x0 完全由 sample 和 residual 算出。sample.requires_grad_(True) 因此无意义——norm_grad 到不了任何参数。引导只移动样本，从不更新网络。
  3. 变量名是命名陷阱。叫 norm_grad，实际是 normalized residual。你的方法论里已经记过这条（命名陷阱是真实成本）。
★ 这条偏差反而解开了一个你担心的隐患

你在梯度冲突报告里给「把 FOD 挂在 x̂₀ 上」标过一个隐患：Jacobian 含 SNR(t)−1/2，高 t 处发散 ⇒ 幅度劫持。

SGCD 恰好绕开了它——不是设计出来的，是因为它压根没求导。它用 .detach() + 单位向量，把「对 x̂₀ 求导」这件事整个删掉了。代价是引导失去了「距离越远推得越多」的自适应能力，收益是不存在 1/√ᾱ_t 放大。

对你的启示：「挂 x̂₀ 有 SNR−1/2 隐患」这句话是有条件的——条件是你对 x̂₀ 求导。如果你只把 x̂₀ 当被监督的变量（损失作用在它上面、梯度经它回传），隐患成立；如果你像 SGCD 一样把它当引导方向且 detach，隐患不成立，但你也拿不到梯度。这是两条不同的路，别混。

def read_image(path):
    img = cv2.imread(path)
    img = cv2.resize(img, (96, 96))
    img = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
    p = np.percentile(img, 90)                          # ★ 每图 90 分位
    img = np.clip(img * 255.0 / p, 0, 255).astype(np.uint8)   # ★ 白点归一化
    return img
class vahadane(object):
    def __init__(self, STAIN_NUM=2, THRESH=0.9, ...):    # ★ STAIN_NUM 固定为 2
        ...

    def getV(self, img):
        I0 = img.reshape((-1,3)).T
        I0[I0==0] = 1
        V0 = np.log(255 / I0)                            # ★ Beer–Lambert：OD = log(255/I)
        img_LAB = cv2.cvtColor(img, cv2.COLOR_RGB2LAB)
        mask = img_LAB[:, :, 0] / 255 < self.THRESH      # ★ 组织掩膜（L 通道 < 0.9）
        I = img[mask].reshape((-1, 3)).T                 # ★ 只取组织像素
        I[I == 0] = 1
        V = np.log(255 / I)
        return V0, V                                     # V0=全像素，V=组织像素

    def getW(self, V):                                   # ★ W 只用 V（组织像素）拟合
        W = spams.trainDL(np.asfortranarray(V), K=self.STAIN_NUM,
                          lambda1=self.LAMBDA1, iter=self.ITER,
                          mode=2, modeD=0, posAlpha=True, posD=True, verbose=False)
        W = W / np.linalg.norm(W, axis=0)[None, :]
        if (W[0,0] < W[0,1]):
            W = W[:, [1,0]]                              # ★ 列排序规范化
        return W

    def getH(self, V, W):
        if (self.getH_mode == 0):
            H = spams.lasso(np.asfortranarray(V), np.asfortranarray(W),
                            mode=2, lambda1=self.LAMBDA2, pos=True, verbose=False).toarray()
        ...

    def stain_separate(self, img):
        V0, V = self.getV(img)
        W = self.getW(V)                                 # ★ 组织像素拟合 W
        H = self.getH(V0, W)                             # ★ 全像素求 H
        return W, H

    def SPCN(self, img, Ws, Hs, Wt, Ht):
        Hs_RM = np.percentile(Hs, 99)                    # ★ 每图 99 分位
        Ht_RM = np.percentile(Ht, 99)
        Hs_norm = Hs * Ht_RM / Hs_RM                     # ★ 密度归一化
        Vs_norm = np.dot(Wt, Hs_norm)                    # ★ 目标颜色 × 源密度
        Is_norm = 255 * np.exp(-1 * Vs_norm)             # ★ Beer–Lambert 正演
        I = Is_norm.T.reshape(img.shape).astype(np.uint8)
        return I

逐条对账

你的 E0.3 / E0.3b 结论SGCD 代码里对应什么判定
① 白点/背景归一化是主要误差项。E0.3b 实测：把 X0 从 [1,1,1] 换成每瓦片白点后，M_A 的 MAE 0.02396 → 0.00779（好 3.08×）；「固定 M 的代价」里约 2/3 其实是背景/白点误差，不是染色矩阵误差 read_image 里 p = np.percentile(img, 90); img = clip(img*255/p)——每张图先做 90 分位白点归一化，然后才做染色分离。另外 SPCN 里还有第二道 np.percentile(Hs, 99) 密度归一化 方向一致
一个公开实现独立地认为必须逐图做白点归一化
② M 应在「减背景后的组织像素」上标定。E0.3b：减背景后 u 移出 cone(M)（NMF 残差 2.8e-2），而减背景前 u 在锥内（系数 +0.73/+0.34）⇒ 光照泄漏进 C_DAB getV 用 mask = L/255 < 0.9 建组织掩膜；getW(V) 只在组织像素上拟合 W；getH(V0, W) 才用全像素求密度。这正是「减背景后再标定 M」 做法一致
而且它同时保住了 H 的全像素求解——W 去背景、H 不去，分工干净
③ 用 NMF，不要用 Macenko-arc。E0.3b：Macenko-arc 减背景后 MAE 0.00338 → 0.01690（差 5×）、两列自夹角塌到 21.79°、s_H 变成蓝通道最大（不是苏木素）；NMF 0.00334 最好 spams.trainDL(..., posAlpha=True, posD=True) = 稀疏 NMF（Vahadane 2016 的方法）；getH 用 spams.lasso(..., pos=True) 求非负密度 选择一致
用 NMF，且 W 与 H 都加了非负约束
④（E0.3b 的新判据）angle(u, span(M)) > 5° 且 u ∉ cone(M)，其中 u=(1,1,1)/√3 是无色轴 代码没有显式写这条判据，但通过「拟合 W 时剔除背景像素」在构造上就避开了把无色轴包进锥内（E0.3b 实测：减背景后 u 移出锥外） 等价效果、不同实现
它没有判据，是用数据裁剪代替了断言

5.1 I_ref 构造在 H&E→IHC 上语义错位

语义错位——把伊红的密度图当成 DAB 的密度图渲染
★★★ 这就是判定：矩阵乘法在维度上完全合法，在语义上是错的

Wt 是 3×2、Hs 是 2×n，乘积 3×n —— 不会报错，会安静地产出一张看起来很像 IHC 的图。而它渲染的内容是「伊红分布用 DAB 的颜色画出来」。

为什么这个错误在 SGCD 里不会被发现：因为 S 和 T 都是 H&E。两个域的染色集合相同、STAIN_NUM=2 相同、列序经 getW 的排序规则统一 ⇒ 「第 2 行 = 伊红」在两个域里都成立，对应关系恒等地成立。论文的整个实验设计没有能力暴露这个假设。

对你项目最具体的后果：HER2 是膜染色

你在 StainFuser 审查里已经确立过一条领域事实：「HER2 是膜染色，H&E 里膜/胞质形态主要由伊红承载」。把这两件事接起来：

I_ref 里 DAB 的分布  =  源图里「伊红」的分布
                     ≈  胞质 / 间质 / 胶原 的区域
                     ≠  细胞膜（HER2 真正该着色的位置）

⇒ 若照搬这个引导，它会主动把生成的 IHC 往「DAB 在胞质」推
⇒ 而 DAB 在胞质正是 HER2 评分里最典型的假阳性形态
所以这一条不是「效果可能差一点」，而是「引导方向本身是错的」

引导项的作用是把生成结果往 I_ref 拉。如果 I_ref 的 DAB 位置就是错的，那么引导越强，错得越系统——它不会随机地伤害图像质量，它会定向地把膜染色做成胞质染色。

这比「不适用」更糟：它是一个会主动伤害你最关心的指标（膜定位）的机制。

5.2 染色列排序只在同染色域内成立

getW 里有一条排序规则，容易被忽略但很关键：

if (W[0,0] < W[0,1]):
    W = W[:, [1,0]]        # 保证第 0 列的「红通道 OD」更大

这条规则的唯一作用就是让「第 1 列 = 哪个染色」在两个域之间保持一致——因为 SPCN 的 Wt @ Hs 逐行逐列地假定「目标的第 i 列」对应「源的第 i 行」。没有这条规则，两个域的列序可能互换，Wt @ Hs 会算出「用苏木素色渲染伊红密度」。

问题说明
这条规则是什么一个数据驱动的启发式（按红通道 OD 排序），不是语义标注。spams.trainDL 输出的列序本身是任意的，这条规则只是把它规范化
为什么在 H&E 内部够用两个域都是 {H, E}，只要排序规则一致，两边的「第 0 列」就都是同一个染色（苏木素 R 通道吸收强于伊红）
为什么 H&E→IHC 不够用两边的染色集合不同（{H,E} vs {H,DAB}）。即使排序规则把两边都排成「第 0 列 = 苏木素」，第 1 列仍然是 E vs DAB——排序正确反而更危险，因为它会让 Wt @ Hs 安静地跑完，不触发任何异常
STAIN_NUM=2 的结构性限制构造函数里 STAIN_NUM=2 写死。而 {H&E} ∪ {H&DAB} 的染色并集是 3 个（H、E、DAB）。要表达「共享的 H + 独有的 E + 独有的 DAB」需要 3 通道 ⇒ 这个实现从结构上就表达不了
★ 有意思的呼应

这条「第 0 列共享、第 1 列不共享」的结构，正是你项目里那条核心论证的代码级镜像：

「H&E 与 IHC 共享苏木素通道（DeReStainer 2409.00649）⇒ 苏木素=可保持的共享成分，DAB=必须生成的目标成分」

SGCD 的 Wt @ Hs 恰好就是「假定两列都共享」。你在架构层面已经否决了这个假定（所以你要双 SPADE、要 [C_H, C_DAB, C_res] 而不是 [H, DAB, H]）。SGCD 提供的是一个「如果假定两列都共享会怎样」的实测案例——它在同染色域内成功，正好说明这个假定在跨染色域内不成立。

7实验建议（含一个零成本可视化）

本节只给值得做的，并且明确标注成本。两个实验，都不需要训练、不需要 SGCD 的权重。

实验 A · p90 vs p95 白点归一化（零成本对照）
成本 ≈ 15 分钟 · 零训练 · 复用 E0.3b 脚本
建议做

动机：§4 发现 SGCD 用 np.percentile(img, 90) 做白点，而你的 E0.3b 用 p95。两个数字差在哪、对 M 的标定与 MAE 有什么影响，你还没测过。

做法：把 E0.3b 的 X0 = per-tile bg 分支改成扫分位数 p ∈ {85, 90, 95, 99, 100}，其余不变，输出 M_A_fixed 的 rgb_roundtrip_mae 与新的无色轴判据 angle(u, span(M))。

判据：如果 MAE 对 p 不敏感（±10% 内），说明这条不是关键变量，记录为「无关」并停止；如果敏感，就得到一条可写进方法学的「白点分位数需固定为 X」。

★ 注意你已有的教训 #22：换超参前先检查它有没有偷偷改变别的变量。这里 p 会改变组织掩膜下的像素集，掩膜必须只定义一次、各栏共用，否则又是在不同像素集上比。

★★ 实验 B · 退化参考图的定量证据（决定性，零训练）
成本 ≈ 1 小时 · 零训练 · 只需要 BCI 的 H&E 与 IHC 各一张
强烈建议

动机：§5.1 说 I_ref 的 DAB 通道实际上就是源图的伊红密度。这句话可以被直接测出来，不需要训练任何模型。

做法：

# 1. 取 BCI 的一张 H&E 瓦片 x_HE 和一张 IHC 瓦片 x_IHC
# 2. 各做一次染色分离（用你 E0.3 的 NMF，或 Vahadane 的 spams 版）
W_HE, H_HE = deconvolve(x_HE)      # W_HE: 3×2 [苏木素, 伊红]; H_HE: 2×n
W_IHC, H_IHC = deconvolve(x_IHC)   # W_IHC: 3×2 [苏木素, DAB]; H_IHC: 2×n

# 3. 按 SGCD 的构造造参考图（这就是 Wt @ Hs）
OD_ref = W_IHC @ H_HE              # ★ 目标颜色 × 源密度
I_ref  = 255 * np.exp(-OD_ref)     # ★ Beer–Lambert 正演

# 4. 关键测量：I_ref 里的「DAB 分量」到底是什么？
DAB_of_ref   = H_HE[1]             # ← 因为 OD_ref 的第 2 项就是 W_IHC[:,1] * H_HE[1]
DAB_of_true  = H_IHC[1]            # ← 真 IHC 的 DAB 密度

# 5. 两个数：
r1 = corr( DAB_of_ref, DAB_of_true )        # ★ 参考图的「DAB」和真 DAB 像不像
r2 = corr( DAB_of_ref, H_HE[1] )            # 应当 ≈ 1（恒等，只是验证代码没写错）

判据（可证伪，三档）：

结果含义行动
r1 < 0.3参考图的「DAB」与真 DAB 基本无关 ⇒ 机制确实不可迁移把 §5.1 从「代码级论证」升级为「实测结论」，写进报告
0.3 ≤ r1 < 0.7有部分相关（伊红与 DAB 在间质/胞质上有共同成分）机制部分可用但方向偏 ⇒ 仍需改，但可以讨论「只借 H 通道」的变体
r1 ≥ 0.7伊红密度与 DAB 密度高度相关我的 §5.1 判定需要修正——请把这个结果告诉我，我会改报告

为什么这个实验值钱：它是零训练、零权重、一小时，但它把「能不能搬」从论证变成了数字。而且它还顺便产出一样东西——r2 ≈ 1 是一个自检（正例），r1 是待测（反例），符合你「自检要同时有正例和反例」的纪律 #18。

前置条件：需要先定 X0（每图白点），否则 H_HE 与 H_IHC 的密度不在同一尺度上，r1 会被系统色偏污染——这与你「C 阶段前置：先定 X0」的既有结论一致。

  • 不要照搬它的 k / k_G。理由见 §6 的降级说明。
