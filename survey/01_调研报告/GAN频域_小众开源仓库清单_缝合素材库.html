GAN × 频域：小众开源仓库清单（缝合素材库）

前提已经确认：频域模块挂在 loss 层或生成器的 conv 上，它不关心骨架是 CUT、CycleGAN 还是 pix2pix。所以这一份不再限定 CUT，改为按「缝合落点」把 GAN × 频域的开源仓库铺开，并优先标注小众、星数低、还没被用烂的那一批——因为那些才是能缝进论文里的东西。

任务：为 H&E→IHC（PSPStain）找可缝合的频域模块筛选偏好：小众 > 热门核实：GitHub API 逐条取元信息报告日期：2026-10-15

0先给结论

总判定：真正小众且能缝的，集中在这四个
  1. FreGAN（NeurIPS 2022，57★）—— 用高频分量训练 GAN，专治数据量不足。它同时给了「高频损失」和「高频判别器」两个可拆件。你只有几十张配对片，这条最对症。
    github.com/kobeshegu/FreGAN_NeurIPS2022
  2. WaveFill（ICCV 2021，61★）—— 小波域分频生成 + 频带一致性约束。它的「把不同频带分开监督」是你可以直接搬的 loss 结构。
    github.com/yingchen001/WaveFill
  3. DualFormer（ICCV 2023，65★）—— 系统研究频谱判别器到底有没有用。这是你唯一能找到的「频谱 D」严肃开源实现。
    github.com/Luciennnnnnn/DualFormer
  4. UFFC（ICCV 2023，38★）—— 修正了 FFC 的两个已知缺陷（频谱偏移、意外空间激活）。如果你要动生成器结构，用它而不是原版 FFC。
    github.com/1911cty/Unbiased-Fast-Fourier-Convolution
一条必须先说清的边界

上面四个都不是病理域，也都不是图像翻译任务（FreGAN 是无条件生成，WaveFill 是修复，DualFormer 是超分/复原，UFFC 是修复）。它们提供的是算子与损失，不是「已验证的 H&E→IHC 方案」。缝合之后必须做单因素复现——这一条与库内 GAN+频域+门控 报告的止损逻辑一致。

2缝合的四个落点

不管骨架是什么，频域的东西只能进四个地方。改动成本从低到高：

3.2 FreGAN 的高频损失 —— 本清单里对你最对症的一个

FreGAN: Exploiting Frequency Components for Training GANs under Limited Data
Yang, Wang, Chi, Zhang · NeurIPS 2022 · arXiv:2210.05461
57★ 小众 有限数据

仓库：github.com/kobeshegu/FreGAN_NeurIPS2022（Python，无 LICENSE 文件）

为什么它比 FFL 更值得缝：FFL 是「通用的频域损失」，而 FreGAN 的出发点是训练数据不足。你的配对片数量通常是几十到几千张量级，这正是它的目标场景。

从论文正文可确认的两个可拆件（本轮读到原文片段，非二手转述）：

  • 高频分量作为监督信号：正文提到「把三个高频分量相加，可近似得到图像的全部细节信息」，并把高频分量引入训练。
  • 高频判别器（high-frequency discriminator）：正文 3.2 节明确写了「to raise the frequency awareness of D, we devise high-frequency discriminator」——这是为了提高判别器对高频的敏感度，正好对应库内 GAN+频域+门控 报告里「判别器看不到高频」这个故障。
诚实标注

本轮没有逐行读它的损失实现代码，也没有读完整篇论文。上面两条来自原文片段的直接引述；损失的具体形式（用 L1 还是 L2、在几个尺度上算、权重如何设）未核实。缝合前请自行打开 loss.py / train.py 确认。

缝合建议：它天然提供两个独立可拆件，正好可以做成单因素两档消融——只加高频损失、只加高频判别器、两者都加。这是零成本的消融设计。

3.3 WaveFill 的频带损失 —— 「把频带分开监督」的现成结构

WaveFill: A Wavelet-based Generation Network for Image Inpainting
Yu, Zhan, Lu, Pan · ICCV 2021
61★ 小众 小波域

仓库：github.com/yingchen001/WaveFill（Python，无 LICENSE 文件；依赖 pytorch_wavelets，需先装 fbcotter/pytorch_wavelets）

它的核心思路（对本课题的映射）：不把图像当一个整体去生成，而是分解成小波子带、在频带上分别做生成与监督。这正好是你库里那份扩散侧报告反复强调的「把结构（低频/轮廓）与细节（高频/纹理）分开处理」——只是它在 GAN 里、用 DWT 实现。

可拆件：它的频带一致性 / 频带分离损失是独立的 loss 项，可以只拿损失、不拿它的生成器结构。这是本清单里「最纯粹的损失素材」。

诚实标注

本轮只核实了仓库存在、星数、会议、依赖（pytorch_wavelets）。它的损失具体分几项、各项权重、是否含跨频带抑制项——未核实。另外它的小波基与层数是针对 256×256 修复任务选的，搬到 1024×1024 病理片需要重新确认尺度。

4落点 B：频域判别器（改 define_D）

库内 GAN+频域+门控 报告已把这条路的机制讲清楚（让 D 同时从空间域和频谱域判断真伪，补上 downsampling 造成的高频盲区），并给出了风险（频域 D 可能学到 scanner / site 的频谱签名而非病理真实性）。这里只补开源实现。

DualFormer —— 唯一能找到的「频谱判别器」严肃开源实现
Luo, Zhu, Xu, Liu · ICCV 2023 · arXiv:2307.12027 · On the Effectiveness of Spectral Discriminators for Perceptual Quality Improvement
65★ 小众 双域 D

仓库：github.com/Luciennnnnnn/DualFormer（Python，无 LICENSE 文件，最后推送 2023-09）

它解决的问题正好是你的顾虑：论文标题里的「Effectiveness」说明它做的不是「提出频谱 D」，而是检验频谱 D 到底什么时候有效、为什么很多实现无效。这比直接抄一个 D 更有价值——它会告诉你哪些做法是白费的。

缝合落点：把它的频谱分支嫁接到 CUT 的 NLayerDiscriminator 上，与空间域 logit 加权相加。务必分别记录 spatial / spectral 两条分支的 logit 与梯度范数，否则崩溃时无法归因（库内报告已给这条止损要求）。

诚实标注

本轮核实了仓库元信息与论文标题/会议；没有读论文正文确认它的频谱分支具体建在「图像频谱」还是「特征频谱」上，也没有读它的代码。不要凭标题推断实现细节。

这一层怎么选

如果只是想「换掉一个 conv 试试频域」，选 UFFC（38★，作者已经替你修过 FFC 的坑，而且论文标题就是「重新思考 FFC」，属于有明确诊断结论的算子）。
如果想改的是输入表示而不是内部算子，DCTNet 的动态通道选择思路值得看——它回答的是「哪些频率分量该留」，这和你在 DWT 上做频带加权是同一个问题。

但这一层的成本提醒

把残差块里的 conv 换成 FFC/UFFC/WTConv，会同时改变参数量、感受野、归一化统计和梯度尺度。一旦结果变化，你无法区分是「频域有效」还是「只是变大了」。先把 §3 的 loss 做完，再考虑这一层。

6落点 D：频域注意力与特征融合（插中间层）

这一类不是「频域生成」，而是把注意力/特征融合搬到频域做。它比 C 层温和（不改卷积本体），但仍会改变中间特征分布，属于「第二优先级」。

为什么这一层放第二位

MSCA / GFNet 都是为分类任务设计的（ImageNet），不是生成任务。它们在分类上的增益来自「更强的特征表达」，而生成任务里你关心的是「输出的频谱对不对」。两者不自动等价。如果要用，建议只当作「比 SE 更强的通道注意力对照」——库内 GAN+频域+门控 §4.2 已经把 SE 定位为「低成本基线而非最终创新」，MSCA 同理。

9只做三个的话选哪个

你的第一步永远是：验证「频域约束有没有用」，不动结构
│

9.1 五条可直接执行的命令

# 1. 装两个基线 loss，先跑通
pip install focal-frequency-loss fdl-pytorch

# 2. 取 FreGAN 与 WaveFill 的源码，只看损失部分（不覆盖你的仓库）
git clone --depth 1 https://github.com/kobeshegu/FreGAN_NeurIPS2022 /tmp/fregan
git clone --depth 1 https://github.com/yingchen001/WaveFill /tmp/wavefill
grep -rn "def .*loss\|class .*Loss\|fft\|rfft\|dwt" /tmp/fregan /tmp/wavefill --include=*.py

# 3. 取 DualFormer 的判别器实现

12.2 为什么它不能 fork：它是分割，而且跑不起来

  1. 任务不匹配。MSCWNet.forward() 返回 logits（形状 [n_classes, H, W]），是语义分割网络。你的任务是 H&E→IHC 图像生成。整个仓库不能 fork。
  2. ★ 缺文件，import 直接失败。MSCAM.py 第 4 行 from MLA import MLA，但整个文件树里没有 MLA.py。而这个 MLA 实际是 EfficientViT 的 LiteMLA（多尺度线性注意力，ICCV 2023，mit-han-lab/efficientvit）—— 作者改名后忘了上传。⇒ MSCAM 整条路（含 CCSABlockWithLiteMLA）断掉。
  3. 另有两处死代码。losses.py 的 LovaszHingeLoss 依赖未 vendored 的 LovaszSoftmax 包；dependencies.py 引用了不存在的 training/ 包（from training.metric import * 等）。

12.4 ★ 最有价值的发现：DySample 正好对着你已知的故障

为什么这个模块比它所在的仓库重要

你的 ResnetGenerator 用 转置卷积 / nn.Upsample 做上采样。而库内 05_伪影与失败模式/GAN棋盘格伪影_底层成因_卷积信号处理与频域机制 已经证明：棋盘格不是学习现象，而是转置卷积的多相增益不平衡——固定权重就会出现，周期 = stride。

DySample 把上采样重写成「学出来的偏移 + grid_sample 双线性采样」：

offset = self.offset(x) * 0.25 + self.init_pos      # 学习采样偏移
coords = 2 * (coords + offset) / normalizer - 1     # 归一化坐标
F.grid_sample(x, coords, mode='bilinear', align_corners=False, padding_mode="border")

它根本不经过转置卷积 ⇒ 从机制上绕开了多相增益不平衡。这是本清单里唯一一个「直接对着你已知故障」的模块，而且只有 3.9 KB、零额外依赖。

缝合建议（比频域 loss 更早可以试）

它不属于「频域」，所以不能和频域 loss 混在同一个消融里（否则归因失败）。但它是独立的一条线：如果你的生成结果有棋盘格，把 Up 里的转置卷积换成 DySample 是一个单因素、改动小、机制明确的对照实验。
注意：它的默认 scale=2、groups=4、style='lp'，接到你的上采样块时需要确认通道数能被 groups 整除。

12.5 顺带可借的：它的 Down / Up 设计

# Down：池化后接小波卷积，而不是直接卷积
class Down(nn.Module):
    def __init__(self, in_channels, out_channels):
        self.maxpool_conv = nn.Sequential(
            nn.MaxPool2d(2),
            WTConv(in_channels, in_channels),   # ← 小波卷积
            DoubleConv(in_channels, out_channels))

# Up：可学习上采样 + 1×1 卷积，而不是转置卷积
class Up(nn.Module):
    def __init__(self, in_channels, out_channels):
        self.up = nn.Sequential(
            DySample(in_channels // 2),         # ← 可学习上采样
            nn.Conv2d(in_channels // 2, in_channels // 2, kernel_size=1))

可借的是什么：「用频域算子替换下采样、用可学习采样替换上采样」这个组合范式本身。不可借的是什么：它的整体架构（编码器-解码器 + skip + n_classes 输出）是分割专用的，搬到生成任务上没有任何意义。

MSCW 的 WTConv.py 是官方 ECCV 2024 实现的拷贝——类体、forward() 主干、变量名、_ScaleModule、构造函数签名全部逐字/逐行一致。作者的改动只有两处：类名从 WTConv2d 改成 WTConv，把 util/wavelet.py 内联进来，外加把 stride 分支从 AvgPool2d 重写成带 ones 核的 conv2d。

法律上没问题（官方 MIT，MSCW 也是 MIT，MIT 允许拷贝），但学术规范上有瑕疵：文件级没有标注出处。对比之下，同一个仓库的 DySample.py 反而老老实实写了论文标题 + arXiv 地址 + 即插即用库地址——同一个作者，两个文件的标注习惯不一致。

⇒ 对你的纪律含义：官方 WTConv 是 MIT，你可以放心用；但引用必须写 Finder et al., Wavelet Convolutions for Large Receptive Fields, ECCV 2024，并且保留 MIT 许可声明。不要学 MSCW 那种「只改类名、不写出处」的做法。

14.3 ★ 关键：医学来源 ∩ 频域 = 空集

对你方案最要紧的一条

对上表 20 个医学来源模块逐个 grep fft|rfft|dwt|pywt|wavelet|小波|fourier|dct，命中数为 0 —— 20 个全部为 0。

⇒ 这个仓库里，「医学来源」和「频域算子」是两个完全不相交的集合。你要的「医学 + 频域」组合件，这里一个都没有。这与 §8 的结论（病理域 × 频域 × GAN × 开源 ≈ 空）是同一件事在两个不同仓库上的重演。

⇒ 含义：你不可能「从这份合集里挑一个医学频域模块直接缝」。可缝的只有两条路：① 挑一个通用频域模块（下表 10 个里选）缝进你的 CUT 骨架；② 挑一个医学来源的通用模块（上表 20 个里选）当作结构件。两条路的模块来自两个不相交的池子，不能互相替代。

三句话
  1. 你问的「专门适配医学图像」——没有。这份仓库是通用算子池，「医学」只出现在出处论文的标题里，不出现在模块的设计里。
