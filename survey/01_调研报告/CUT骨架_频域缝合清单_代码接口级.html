CUT 骨架 × 频域：可缝合工作清单（代码接口级）

你上一轮确认了 PSPStain 是「CUT 骨架 + 附加损失 + 辅助分割网」。这一轮的问题因此变成一个纯工程问题：还有哪些工作已经长在 CUT 这套代码上、频域模块挂在哪个文件、能不能直接 drop-in？本文不重复回答「哪个机制更好」（那已由库内 GAN+频域+门控 报告回答），而是按 代码接口 组织可缝合清单，并对关键仓库做逐字源码取证。

骨架约束：CUT / FastCUT（taesungp 系）目标：H&E→IHC 虚拟染色（PSPStain）取证等级：逐字源码 / 官方 README报告日期：2026-10-15

0先给结论

总判定：CUT 骨架 + 频域确实有货，但「频域」在这条代码线上分三种完全不同的东西

检索结果指向一个反直觉的事实：在 CUT 系的病理代码里，被命名为 frequency_loss 的那个文件，里面根本没有傅里叶变换。它是一个高斯金字塔 L1 重建损失，源码逐字来自 CVPR 2021 的 LPTN。真正做 FFT/DCT 的频域损失（FFL、FDL）反而都是独立的 pip 包，需要自己挂上去。

对你的三条可执行结论
  1. 要「真频域 loss」→ 装 pip 包，挂 3 行。focal-frequency-loss 或 fdl-pytorch，加在 compute_G_loss 里，不动任何网络结构。这是改动最小、可复现性最高的一条路。
  2. 要「已经长在 CUT 上的频域工作」→ 直接 fork PPT。coffeeNtv/PPT（MICCAI 2024）是 CUT 骨架 + H&E→IHC + 金字塔频域损失 + FocalNCE + VGG 内容损失，代码里连 models/frequency_loss.py 都给你写好了。它是本清单里唯一一个同时满足「CUT 骨架」「病理域」「频域损失」「代码开源」的仓库。
  3. 不要照抄 PSPStain 的 weight_norm='spectral' 与 lambda_gp=10 当成自己的设计。本轮逐字取证发现这两项连同整个 launcher 参数块，与 MICCAI 2023 的 ASP 仓库 mist_launcher.py 逐项相同。这不是频域，是别人的超参默认值（详见 §8）。
三条必须避开的误读
  1. 「PPT 用了 frequency loss」这句话，按论文措辞成立、按算子类型不成立。它的 loss_freq 是高斯金字塔多尺度 L1，不含 FFT/DCT/小波。若你要在论文里写「已有工作用频域损失做 H&E→IHC」，会被审稿人一眼看穿（附录给了逐字源码）。
  2. 「FDL」是一个缩写撞车点。PSPStain/ASP 的 GP loss 来自 LPTN（拉普拉斯/高斯金字塔），与 CVPR 2024 的 FDL（Frequency Distribution Loss）是两个东西；仓库里还有个 util/fdlutil.py，用途未核实（很可能是 Fréchet Distance Library 的 util，不是 Frequency Distribution Loss）。
  3. FFC（Fast Fourier Convolution）是图像修复的算子，不是图像翻译的先例。它是可插拔的，但把它塞进 CUT 的 ResnetGenerator 属于「结构改造」，改动成本远高于加一个 loss，且没有 H&E→IHC 的先例。

2「CUT 骨架」怎么识别

你说「PSPStain 是围绕 CUT 图像翻译模型改动的」，这个判断在代码层面有一个非常明确的指纹。识别它不需要看论文，只看文件树和函数签名。

2.1 识别特征（文件树级）

CUT（taesungp/contrastive-unpaired-translation）的目录结构在 PyTorch 图像翻译圈里是独有的，凡是从它 fork 的仓库都会保留以下全部特征：

├── models/
│   ├── cut_model.py          ← 核心：训练循环 + PatchNCE
│   ├── networks.py           ← define_G / define_F / define_D
│   └── patchnce.py           ← PatchNCELoss（InfoNCE 变体）
├── data/
│   ├── unaligned_dataset.py  ← CUT 默认
│   ├── aligned_dataset.py    ← 配对改造版（病理域常用）
│   └── single_dataset.py     ← 单图翻译
├── options/
│   ├── base_options.py       ← input_nc / output_nc 默认 3 / 3
│   └── train_options.py
├── experiments/
│   └── *_launcher.py         ← 用 Options() 字典覆盖默认超参（CUT 特色）
├── util/
│   ├── util.py  image_pool.py  visualizer.py
└── train.py  test.py
三个硬指纹（任一缺失就不是 CUT 骨架）
  1. models/networks.py 里同时存在 define_G、define_F、define_D 三个工厂函数；
  2. netF 用的是 PatchSampleF + mlp_sample，调用形式是 netF(feat_k, num_patches, sample_ids)——先算 sample_ids 再复用，这是 CUT 独有的采样契约；
  3. 有 experiments/*_launcher.py，用 Options(...) 字典而不是命令行覆盖超参。

本文后面判断「某仓库是不是 CUT 骨架」，用的就是这三条。其中第 2 条最关键：只要 calculate_NCE_loss 里出现 sample_ids 的两段式调用，就基本可以确认是 CUT 血统。

2.2 四个缝合接口

频域的东西要进 CUT，只有四个落点。按改动成本从低到高排列：

#接口改哪个文件典型改动量风险本文对应章节
Aloss 层models/cut_model.py 的 compute_G_loss / compute_D_loss+3~15 行最低§3
B生成器内部算子models/networks.py 的 ResnetGenerator / ResnetBlock+1 个类，替换若干 conv中§4

一句话选路

如果你的目的是「让论文有一个频域增量」，走 A；如果目的是「改进生成质量」，先走 A，A 无效再考虑 B；C 和 D 只在前两者都验证过之后再动，否则归因会失败——这正是 GAN+频域+门控 报告 §8 的止损逻辑，本文完全同意，不再重复。

3接口① loss 层：改动最小，优先走这条

这是唯一一个「不动网络结构、不动物理语义、只加一项损失」的落点。挂载位置固定：models/cut_model.py 的 compute_G_loss()，返回 loss_G 之前加一项。

3.1 Focal Frequency Loss（FFL）—— 真正做 FFT 的那个

Focal Frequency Loss for Image Reconstruction and Synthesis
Jiang, Dai, Wu, Loy · ICCV 2021 · arXiv:2012.12821
官方实现 pip 包

仓库：github.com/EndlessSora/focal-frequency-loss（MIT）

机制：把 real / fake 变到频域，计算频率分量差异，并自适应提高「难合成频率」的权重、降低已合成好的频率权重。论文明确把它定位为 complementary to existing spatial losses，并在 VAE、pix2pix、SPADE、StyleGAN2 上验证。

安装与调用（官方 README 逐字）：

pip install focal-frequency-loss
from focal_frequency_loss import FocalFrequencyLoss as FFL
ffl = FFL(loss_weight=1.0, alpha=1.0)   # nn.Module
# fake, real: (N, C, H, W)
loss = ffl(fake, real)

可用超参：loss_weight、alpha（越大越聚焦）、patch_factor（切成 patch 算，默认 1）、ave_spectrum、log_matrix、batch_matrix。README 明确说主要调的就两个：loss_weight 与 alpha。

挂进 CUT 的位置：

# models/cut_model.py → compute_G_loss()
self.loss_G = self.loss_GAN + self.loss_NCE + self.loss_NCE_Y
# ↓ 新增
self.loss_ffl = self.criterionFFL(fake_B, real_B)
self.loss_G = self.loss_G + opt.lambda_ffl * self.loss_ffl

关键限制（必须写进你的实验设计）：FFL 在全 RGB 全局频谱上工作。对 H&E→IHC，全图 RGB 频谱是「图像外观统计」，不是蛋白表达量。scanner 噪声、JPEG 压缩纹理、tile 边界都会进频谱。建议至少做两版对照：全 RGB vs 只在 H 通道/结构图上算。

证据等级：官方 README 与 API 已逐字核实 H&E→IHC 无直接先例

3.2 FDL（Frequency Distribution Loss）—— 专门为「错位」设计的

Misalignment-Robust Frequency Distribution Loss for Image Transformation
Ni, Wu, Wang, Yang, Wang, Ma · CVPR 2024 · arXiv:2402.18192
官方实现 pip 包

仓库：github.com/eezkni/FDL（MIT）

机制（官方 README 逐字）：用 DFT 把图像特征变换到频域，对幅度（amplitude）与相位（phase）分别处理，构成分布距离损失。论文的卖点是对像素级错位鲁棒——它解决的是「配对数据配不准」这个具体痛点，并顺带验证了 style transfer（完全错位数据）场景。

安装与调用（官方 README 逐字）：

pip install fdl-pytorch
from FDL_pytorch import FDL_loss
fdl_loss = FDL_loss()
# X, Y: (N, C, H, W)
loss_value = fdl_loss(X, Y)
loss_value.backward()

为什么这条对你的课题特别相关：你的 H&E 与 IHC 是连续切片，天然存在组织形变与错位。你已经有一个 PatchAlignmentLoss（见 §3.4）在处理实例级错位；FDL 处理的是分布级错位。两者是互补的，不是替代关系。

挂进 CUT 的位置：同 §3.1，加在 compute_G_loss 里，real_B 对 fake_B。改动量与 FFL 相同。

证据等级：官方 README 与 API 已逐字核实 论文主战场是增强/超分，style transfer 是次要验证 H&E→IHC 无直接先例

3.3 高斯金字塔 L1 —— 被叫做 frequency_loss 的那个（重要澄清）

本轮最重要的一个事实纠正

PSPStain 系代码里的「频域损失」，实际是高斯金字塔多尺度 L1 重建损失，不含任何 FFT / DCT / 小波算子。它在 ASP 与 PPT 两个仓库里的文件名都叫 gauss_pyramid.py / frequency_loss.py，类名统一是 Gauss_Pyramid_Conv，两处文件顶部都写着同一句注释：

#reference: https://github.com/csjliang/LPTN   （PPT 版）
Code borrowed from: https://github.com/csjliang/LPTN   （ASP 版）

上游来源已核实：csjliang/LPTN（437★，Apache-2.0）= High-Resolution Photorealistic Image Translation in Real-Time: A Laplacian Pyramid Translation Network，CVPR 2021。

算子本体（逐字源码）：

class Gauss_Pyramid_Conv(nn.Module):
    def __init__(self, num_high=3):
        self.kernel = self.gauss_kernel()   # 5×5 高斯核 / 256

    def gauss_kernel(self, device=..., channels=3):
        kernel = torch.tensor([[1., 4., 6., 4., 1],
                               [4., 16., 24., 16., 4.],
                               [6., 24., 36., 24., 6.],
                               [4., 16., 24., 16., 4.],
                               [1., 4., 6., 4., 1.]])
        kernel /= 256.
        kernel = kernel.repeat(channels, 1, 1, 1)
        return kernel

    def downsample(self, x):
        return x[:, :, ::2, ::2]            # 隔点下采样

    def conv_gauss(self, img, kernel):
        img = F.pad(img, (2,2,2,2), mode='reflect')
        return F.conv2d(img, kernel, groups=img.shape[1])

    def forward(self, img):                  # 返回 [L0, L1, ..., L_num_high]
        current = img; pyr = []
        for _ in range(self.num_high):
            filtered = self.conv_gauss(current, self.kernel)
            pyr.append(filtered)
            current = self.downsample(filtered)
        pyr.append(current)
        return pyr

三点必须注意：

  • 它返回的是逐级高斯模糊后的图，不是 Laplacian 带通分解。虽然上游论文叫「Laplacian Pyramid Translation Network」，但这个损失函数用的是高斯金字塔逐级 L1，不是带通残差。
  • 损失形式极简：loss = mean(Σ w_k · L1(P(fake)_k, P(real)_k))。PPT 用 num_high=5、gp_weights=[1.0]*6（等权）；ASP 用 gp_weights='[0.015625,0.03125,0.0625,0.125,0.25,1.0]'（几何递增，越粗的尺度权重越大）。两者权重策略完全不同，这是可以直接做的消融。
  • 它本质是多尺度重建损失，不是频域约束。写论文时若要引用它作为「频域先例」，会站不住。

证据等级：两个仓库的源码 + 上游仓库元信息均已逐字核实

3.4 FocalNCE 与 PatchAlignmentLoss：CUT PatchNCE 的两个直接替代品

这两个不属频域，但它们是「CUT 骨架 + 病理域」这条线上最容易被忽略、却最直接可用的两个 loss 模块。它们已经在 PPT 里和金字塔损失共存，说明兼容性已经被原作者验证过。

FocalNCE（models/focalnce.py）

在 CUT 的 PatchNCE 上叠加 Focal 机制，缓解正负样本类别不平衡。PPT 的 compute_G_loss 里实例化为 self.criterionNCE = FocalNCELoss(opt)，直接替换掉 CUT 原生的 PatchNCELoss，接口不变。

PatchAlignmentLoss（models/patch_alignment_loss.py）

处理配对数据中 patch 级错位。PPT 中调用为 self.criterionMisalignment(self.real_B, self.fake_B)。对你的连续切片错位问题是直接对症的。

PPT 的完整 G 损失（逐字源码，models/ppt.py）
self.loss_G = (self.loss_G_GAN
               + self.loss_freq            # 高斯金字塔 L1
               + self.loss_contrast        # = loss_NCE + loss_NCE_Y + loss_NCE_Y_hat
               + self.loss_patch_alignment # 错位
               + self.loss_content)        # VGG 感知

注意 loss_contrast 是三项 PatchNCE 之和（A→fakeB、B→idtB、idtB→B），比原生 CUT 的两项多一项。这是可以直接借鉴的结构。

4接口② 生成器内部：可插拔的频域算子

这一层的改动是「替换 ResnetGenerator 里的卷积」，改动成本明显高于加 loss，且三个候选都没有 H&E→IHC 先例。列出是为了让你知道「如果要动结构，有哪三个现成的算子」，而不是推荐你先做这一步。

为什么不建议把 FFC 当成你的第一版

CUT 的 ResnetGenerator 是 7×7 反射卷积 → 2 次下采样 → 6 个残差块 → 2 次上采样 → Tanh 的固定结构。把残差块里的 conv 换成 FFC，会同时改变参数量、感受野、归一化统计和梯度尺度。一旦结果变化，你无法区分是「频域有效」还是「只是变大了」——这正是 GAN+频域+门控 报告 §4.3 的反对理由，本文采信该判断。先把 loss 做完，再考虑算子。

5接口③ 判别器：本轮没有找到可直接缝合的仓库

阴性结论（如实报告）

本轮检索没有找到任何一个「基于 CUT 骨架、且实现了频域判别器」的开源仓库。CUT 的 define_D 只提供 basic / n_layers / pixel / patch 四种空间域判别器，没有频谱分支。

库内 GAN+频域+门控 报告已经给出这条路线的机制先例（SSD-GAN 的 spatial + spectral 双分支），并明确指出风险：H&E→IHC 中 scanner、切片批次、压缩、tile 边界都会产生频谱差异，频域 D 可能学到 domain/site signature 而非 DAB 真实性。本文不重复论证，只补一句工程事实：

如果你确实要做，落点是 models/networks.py 的 define_D：新增一个 NLayerDiscriminator 的兄弟类，在它的倒数第二层接一个 torch.fft.rfft2 + 可学习 1×1 卷积，输出一个标量 logit，再与空间域 logit 加权相加。这段代码需要你自己写，没有现成实现可抄。改动量约 40–60 行，且必须记录 spatial / spectral 两条分支各自的 logit 与梯度范数，否则崩溃时无法归因。

8一处硬发现：PSPStain 的 launcher 与 ASP 逐字同源

本轮最有价值的单点发现

你上一轮的判断是「PSPStain 在 CUT 基础上加了谱归一化和 GP 损失」。本轮逐字取证后可以把它说得更准：这两个「改动」不是 PSPStain 自己的设计，而是 MICCAI 2023 的 ASP 仓库 launcher 里就有的默认值。换句话说，PSPStain 的配置是从 ASP 直接继承的，而不是从 CUT 演化出来的。

证据：下面左侧是 ASP 的 experiments/mist_launcher.py（本轮 API 抓取，逐字）：

这条发现对你的实际意义
  1. 论文里不要写「我们在 CUT 基础上引入谱归一化」——审稿人若追代码，会指向 ASP（MICCAI 2023）。如果要保留 spectral norm，应显式引用 ASP 并说明继承关系。
  2. 你现在做频域消融时的基线超参，其实是 ASP 在 MIST/HER2 上调出来的。这些值在你的数据上未必最优，尤其是 lambda_NCE 已被 PSPStain 从 10.0 改成 1.0，说明原作者也认为默认值需要调。
  3. gp_weights 是一个现成的免费消融点。ASP 用几何递增 [0.0156…1.0]（偏重粗尺度），PPT 用等权 [1.0]*6。你的代码目前用的是哪个？这是一个「同一骨架、两种设定、结果是否不同」的零成本对照实验。

9可执行缝合路线

起点：现有 PSPStain（CUT 骨架 + 已有 GP 金字塔损失 + MLPA/CTPC）

▼ 第 0 步（30 分钟）：确认你现在的 GP 权重是哪一版
   ├─ grep -n "gp_weights" 你的仓库
   ├─ 若 = [1.0]*6        → PPT 版（等权）
   └─ 若 = [0.015625,...] → ASP 版（几何递增）
   → 记录为 F0 基线的既定配置，不要中途改

▼ 第 1 步：加「真频域」loss（接口 A，唯一推荐的第一步）
   ├─ pip install focal-frequency-loss    （FFL，ICCV 2021）
   └─ 或 pip install fdl-pytorch          （FDL，CVPR 2024，抗错位）
   → 在 compute_G_loss 里加一项，lambda 从 0.05 起
   → 单因素：只加这一项，其余全部冻结

▼ 判定 1：3 个 seed，结构指标 + 伪影指标
   ├─ 有稳定改善 → 进第 2 步
   └─ 无改善     → 停。不要继续堆模块（见 GAN+频域+门控 §8 止损）

▼ 第 2 步：换一个「已在 CUT 骨架上验证过」的 loss 做交叉验证
   ├─ 从 coffeeNtv/PPT 抄 FocalNCE 替换 PatchNCELoss
   └─ 或抄 PatchAlignmentLoss（对连续切片错位对症）
   → 这一步同时验证「PPT 的组件能不能在你的骨架里跑通」

▼ 判定 2：频域 loss 与 PPT 组件的增益是否可叠加
   ├─ 可叠加 → 你有了一个「CUT 骨架 + 频域 + 错位鲁棒」的组合，可写
   └─ 不可叠加（互相抵消）→ 说明两者在优化同一个方向，选更简单的一个

▼ 第 3 步（可选，高风险）：动生成器算子
   └─ 只在第 1–2 步都有稳定增益后才做
      FFC（advimman/lama）或 WTConv（BGU-CS-VIL/WTConv）
      ⚠ 会同时改变参数量/感受野/梯度尺度，归因困难

▼ 始终不做（除非有明确理由）
   ├─ 频域判别器（无现成 CUT 实现，需自写 40–60 行）
   └─ 频带门控 / 多专家路由（见 GAN+频域+门控 §4.3 的反对理由）

9.2 一份必须同时记录的四类指标

分布级

FID / KID、precision / recall、病理特征距离。单独用 FID 会掩盖表达量退化。

表达级

DAB / OD / FOD mean、p90 / IOD、阳性面积、细胞级 precision / recall、HER2/H-score 一致性。

结构级

细胞核 / 膜边界、membrane continuity、下游分割或分类精度。

频域级

log radial power-spectrum distance、金字塔各级 L1、周期峰能量、自相关。频域指标要单独算，不能混进 FID 当成功证据。
