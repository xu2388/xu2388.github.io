01一句话总结

先抓住骨架，再钻细节。

核心思想

用 DDIM 反演把两张图（输入的 H&E、GAN 生成的风格模板）各自反推到噪声，得到两条"轨迹模板"；然后逐时间步优化一张图像尺寸的视觉提示图（visual prompt），让前向采样同时逼近这两条轨迹，最后换成目标染色域的条件做一次确定性采样出图。

它是"免训练"（不微调扩散模型）但"测试时优化"（每张图都要跑一次 prompt 优化）。核心卖点是结构一致性——在 SSIM / MS-SSIM / PSNR / CSS 上全面领先，且病理医生盲评得分最高。

维度结论
任务H&E → MAS / PAS / PASM（肾脏特殊染色，不是 IHC）
数据ANHIR 肾脏数据集，患者 1–4 训练、患者 5 测试，无像素级配对
扩散模型自己从零训的类别条件扩散模型（HE/MAS/PAS/PASM 四类），不是 Stable Diffusion
是否需要微调不需要——只优化一张 prompt 图，模型权重完全冻结
风格从哪来一个预训练的 GAN（UMDST / StainGAN）先做一次粗翻译，输出当"风格模板"
核心机制双路径（结构路径 + 风格路径）+ null visual prompt 优化 + 确定性采样
最大优势结构一致性（SSIM 0.92 vs 次优 0.81）+ 病理医生盲评第一
最大短板FID 并不领先（部分设定略逊于 StainGAN）；每张图需上千次网络前向+反传

02它到底在做什么（易误解）

先纠正三个常见误解。

误解 1：这是 H&E → IHC 的工作

不是。它的目标域是 MAS（Masson 三色）、PAS（过碘酸-雪夫）、PASM——肾脏病理的特殊染色，用于看胶原纤维、肾小球与肾小管结构。跟 IHC（免疫组化，看蛋白表达）是两类任务。数据集是 ANHIR 的肾脏切片。
这意味着：它的"风格"是颜色分布，不涉及蛋白表达语义。你的 PSP-Diffusion 面临的分子级语义问题，它没有正面处理。

误解 2：它是"training-free"，所以不需要训练

"Training-free" 指的是"不微调预训练扩散模型"，不是说整个流程不用训练。实际上需要三样预训练物：① 一个在 ANHIR 上训练 80k 迭代的类别条件扩散模型；② 一个预训练的 GAN（UMDST 或 StainGAN）当"特征适配函数"；③ prompt 优化本身是每张图都要跑的测试时优化（约上千次网络前向+反传）。所以更准确的说法是 "training-free, test-time optimization"。

误解 3：它像 Null-text Inversion 那样优化文本嵌入

不是。Null-text Inversion（Mokady 等）优化的是 文本嵌入空间的 null embedding。这篇优化的是一张与图像同尺寸的、逐时间步的像素图 ϕ ∈ ℝ^(T×3×256×256)——是"视觉提示"（visual prompt），不是文本提示。这个区别很重要，后面第 7 节会展开。

03动机：虚拟染色为什么难

论文把难点归结为两个，这两个也是全文的设计目标。

挑战 1：结构一致性要求比自然图像翻译严格得多

自然图像翻译里，非核心细节变化不影响语义（比如马变斑马，背景变化无所谓）。但病理图像每个细节都有诊断意义——染色剂给特定组织上色，内容的任何改变都可能导致诊断语义偏移。论文 Figure 1 专门画了这个对比。

挑战 2：内容与风格的解耦需求更高

论文指出一个反直觉的点：病理图像中"形态"与"语义"的耦合程度比自然图像更低，所以内容提取更难。加上没有像素级配对数据，完全分离风格与内容非常困难。

他们对 GAN 路线的批评

论文明确指出：GAN 的对抗训练让生成器-判别器互相博弈，而端到端的生成性质使风格与内容的分离变得困难。这是他们转向扩散反演的根本理由——扩散的 DDIM 反演天然提供"确定性的、可逆的"内容-噪声映射，解耦能力更强。

一个值得注意的细节

论文还指出：当时没有专门针对病理图像的大规模预训练模型。这正是他们选择"不微调、只优化 prompt"路线的原因之一——没有好的预训练底子，微调意义不大。这个判断在 2024 年是合理的，但到 2026 年已经不成立（现在有 UNI、CONCH、Virchow 等）。这也是为什么后续 PGVMS 立刻引入了 CONCH。

04理论基础：DDIM 反演

不理解这一节，后面全是天书。

DDIM 采样（正向，噪声 → 图像）

x_{t−1} = √ᾱ_{t−1} · [ (x_t − √(1−ᾱ_t)·ε_θ(x_t, t)) / √ᾱ_t ] + √(1−ᾱ_{t−1})·ε_θ(x_t, t) 从 t=T 走到 t=0，逐步去噪

DDIM 反演（反向，图像 → 噪声）

把上面这个式子倒过来走，就是 DDIM 反演：

x_{t+1} = √ᾱ_{t+1} · [ (x_t − √(1−ᾱ_t)·ε_θ(x_t, t)) / √ᾱ_t ] + √(1−ᾱ_{t+1})·ε_θ(x_t, t) 从 t=0 走到 t=T，把图像"编码"成噪声
关键前提：近似相等（approximate equality）

DDIM 反演之所以成立，依赖一个前提：同一步上"前向预测的噪声"与"反向预测的噪声"近似相等。但这个近似不精确——反演会累积误差。

论文的解决办法就是引入一个额外的可优化变量当"算子（operator）"，把反向过程里偏掉的特征向量掰回与正向过程同方向。这个可优化变量就是 StainStructPrompt（初始化为全零的特征图）。

误差随 t 的变化

论文附录给了误差分析：

x_0 = x*_t + (1/ᾱ_t − 1)·σ , σ > 0 ε_θ(x_t, t) = ε*_θ(x_t, t) + σ , σ > 0 t 增大时误差减小 → 无条件 DDIM 反演通常需要较大的时间步来压低误差

这解释了他们为什么把 DDIM 反演步数设得较大（论文说 100，发布的脚本里是 50）。

为什么 DDIM 反演能"解耦内容与风格"

因为 DDIM 反演是确定性的（eta=0.0，无随机噪声注入），图像到噪声的映射是一一对应的。图像编辑领域（如 Null-text Inversion、Direct Inversion）利用的正是这一点：反演得到的噪声里保留了内容的"骨架"，而风格可以在正向采样时通过改条件/加引导注入。这篇把这套思路第一次搬到虚拟染色上。

05核心方法：双路径提示反演

三个阶段，两条轨迹，一张待优化的提示图。

整体数据流

输入 H&E
x₀ → GAN 特征适配器
F(·) = UMDST → 风格模板
F(x₀) ↘ DDIM 反演
(条件 = None) → 风格轨迹
{y*_t}
输入 H&E
x₀ → DDIM 反演
(条件 = 源域) → 结构轨迹
{x*_t} → 两条轨迹 + 目标域条件 → 优化 visual prompt ϕ → 确定性采样出图

Stage 1 · 构建双路径轨迹

1结构目标路径（Structural Target Path）

对输入 H&E x₀ 做 DDIM 反演，条件是源域类别 C_S（即 HE 的类标签）：

x*_{t+1} = √ᾱ_{t+1} · [ (x*_t − √(1−ᾱ_t)·ε_θ(x*_t, t, C_S)) / √ᾱ_t ] + √(1−ᾱ_{t+1})·ε_θ(x*_t, t, C_S)

得到轨迹 {x*_t}_{t=0}^T。它的作用是保住内容——因为反演是无损的（近似），正向走回来就能还原结构。

1风格目标路径（Style Target Path）

先用特征适配函数 F(·) 把输入 H&E 粗翻译成目标染色（这篇用的是预训练 GAN：UMDST 或 StainGAN），得到风格模板 y*_0 = F(x₀)。再对它做 DDIM 反演，条件是 None（无条件）：

y*_{t+1} = √ᾱ_{t+1} · [ (y*_t − √(1−ᾱ_t)·ε_θ(y*_t, t, C_φ)) / √ᾱ_t ] + √(1−ᾱ_{t+1})·ε_θ(y*_t, t, C_φ) C_φ 表示"不加额外条件"，目的是避免条件变量污染风格轨迹

得到轨迹 {y*_t}_{t=0}^T。它的作用是提供目标染色的颜色分布。

为什么用 GAN 的输出当模板，而不是直接用相邻切片？

论文明确说：理想情况下，相邻切片的真实目标染色图是最好的模板。但那样就违反了虚拟染色的初衷——虚拟染色就是为了不切那张片子。所以他们改用"预学习的映射关系"，即一个已经训好的 GAN。并且强调：特征适配函数可以被任何能生成目标域特征图像的方法替代（消融里验证了 UMDST 和 StainGAN 两个都能用，且都比各自的 baseline 好）。

这里有一个必须注意的设计选择

两条路径的条件变量不一样：结构路径用源域条件 C_S，风格路径用无条件 C_φ。而最终的确定性采样用目标域条件 C_T。
论文附录的 Figure 7 专门讨论了条件选择（用 N/M/E 表示无/目标域/源域，第一个字母是反演条件、第二个是采样条件）。他们的发现是：只用类别条件（EM）能得到匹配真实分布的目标染色风格，但结构一致性严重丢失。这就是为什么必须走双路径。

Stage 2 · StainPrompt 优化

这是全文的核心。优化目标：

arg min_ϕ Σ_{t=1}^{T} ‖ (y*_{t−1}, x*_{t−1}, y_{t−1}(ȳ_t + ϕ_t, C_T)) ‖ 让"带 prompt 的正向采样结果"同时逼近两条轨迹

具体地，每个时间步：

ŷ_t = ȳ_t + ϕ_t 把 prompt 加到当前 latent 上 y_{t−1}(ŷ_t, C_T) = √ᾱ_{t−1}·[ (ŷ_t − √(1−ᾱ_t)·ε_θ(ŷ_t, t, C_T)) / √ᾱ_t ] + √(1−ᾱ_{t−1})·ε_θ(ŷ_t, t, C_T) ȳ_{t−1} = y_{t−1}(ȳ_t + ϕ_t, C_T) 用优化后的结果更新，往下走

注意 C_T ∈ {1,2,3} 对应 MAS / PAS / PASM——正向采样时用的是目标染色域的类别条件。这是风格注入的来源。

两个损失项

l_StainPrompt = λ · l_struct + (1 − λ) · l_style l_struct = Σ_{t=0}^{IST} 2(σ_z σ_y + c₁)(σ_zy + c₂) / [(σ_z² + σ_y² + c₁)(σ_z σ_y + c₂)] SSIM 形式 l_style = Σ_{t=0}^{IST} ‖ y*_t − y_t ‖²₂ MSE c₁ = c₂ = 1e-8（论文实验设置）
⚠ 论文的公式与实测结论自相矛盾，以代码为准

论文 Eq (7) 写的是 λ·l_struct + (1−λ)·l_style，字面意思是 λ 加权结构损失。但：

  • 论文 Table 7 的实测行为是：λ 越大，结构指标越差、风格指标越好（λ=0.05 时 SSIM 最高 0.909；λ=0.85 时 FID 最低 246.999）。
  • Table 7 的说明也写："A larger λ value improves style, while a smaller λ enhances structural integrity"——与 Eq (7) 的标注相反。
  • Table 1 的说明又把 λ=0.05 称为 "struct weight"——再次矛盾。
  • 而代码里是 loss = alpha*loss1 + (1-alpha)*loss2，其中 loss1 是 MSE（对应风格轨迹）、loss2 是灰度 SSIM（对应结构轨迹）。所以 alpha 加权的是风格损失，与 Table 7 的实测行为一致。

结论：论文 Eq (7) 的符号标反了。复现时以代码为准，并且不要照搬论文给的 λ 值，自己扫一遍。

优化步数的线性衰减调度

论文发现误差会随反向过程累积，过多迭代并不显著改善输出质量。所以每个时间步的迭代次数按线性衰减：

IST_t = (1 − t/T) × IST_init 越靠近 t=0（图像端）迭代越少，越靠近 t=T（噪声端）迭代越多 IST_init = 50（论文实验设置）

消融（Table 6）显示 IST_init 从 50 增到 250，SSIM 只从 0.9285 掉到 0.9241，FID 从 251.487 微降到 248.789——影响很小，所以选 50 省时间。

Stage 3 · 确定性采样

y_{t−1} = √ᾱ_{t−1}·[ (y_t + ϕ_t − √(1−ᾱ_t)·ε_θ(y_t + ϕ_t, t, C_T)) / √ᾱ_t ] + √(1−ᾱ_{t−1})·ε_θ(y_t + ϕ_t, t, C_T) 从 T 走到 0，每步都加上优化好的 ϕ_t，条件用目标域 C_T 输出 y₀ 就是虚拟染色结果
一个实用的副产品

论文指出：一次反演得到的结构 null-prompt 嵌入，可以复用于多个无配对染色迁移——只需在输入图上加不同特征。也就是说，结构路径的 prompt 是"输入图特定"的，而风格注入靠改条件 C_T。这意味着一个 H&E 输入，反演一次，就能出 MAS / PAS / PASM 三种结果。

06StainPrompt 优化（损失与调度）

把两个 prompt 的角色讲清楚。

名称角色论文原话对应轨迹
StainStructPrompt 结构矫正算子 "correcting the slightly deviated feature vectors in the reverse process back to the same direction as in the forward process" 结构路径 {x*_t}
StainStylePrompt 风格减法算子 "functioning as a 'style subtraction operator'" 风格路径 {y*_t}

两者通过一个常数 λ 加权平衡。论文的措辞是：视觉提示充当"算子"，逼近这两条模板轨迹，寻找最优平衡点。

为什么"减法算子"这个说法值得琢磨

风格模板 F(x₀) 是 GAN 生成的、带有目标染色颜色的图。反演它得到风格轨迹。在正向采样时，如果把风格轨迹直接"加上去"，就会把 GAN 的伪影也带进来。所以 prompt 在这里的作用更像是从风格模板里提取"纯颜色分量"、剥离 GAN 的结构伪影——因为结构由另一条路径负责。这就是"subtraction"的含义。消融 Table 3 也印证了：加上 StainStylePrompt 后 SSIM 0.8015 → 0.8121、FID 268.491 → 255.261，两项都改善。

07代码级细节

读了官方实现后才发现的东西。

关键代码（guided_diffusion/gaussian_diffusion.py 的 stainpromptInversion）

# 核心：在反演轨迹与正向轨迹之间优化 visual prompt
def stainpromptInversion(self, model, noise, latents, latents_source, num_inner_steps,
                          alpha=0.5, clip_denoised=True, model_kwargs=None, device=None):
    latent_cru = noise                                  # x_T，起点噪声
    indices = list(range(int(self.num_timesteps)))[::-1]

    visual_prompt = th.zeros([self.num_timesteps, 3, 256, 256],
                            requires_grad=True, device=device)   # ← 逐时间步的图像尺寸提示图

    for i in indices:
        t = th.tensor([i], device=device)
        optimizer = th.optim.Adam([visual_prompt], lr=1e-2)
        latent_prev        = latents[i].unsqueeze(0)         # 风格模板轨迹 @ t
        latent_prev_source = latents_source[i].unsqueeze(0)  # 结构模板轨迹 @ t

        for j in range(int(num_inner_steps * (1. - i / self.num_timesteps))):   # ← Eq (10) 衰减调度
            latents_prev_rec = self.ddim_sample(model, latent_cru + visual_prompt[i], t, ...)["sample"]

            ssim_loss = StructuralLoss(window_size=11, size_average=True)
            tarns = transforms.Compose([transforms.Grayscale(num_output_channels=...)])

            loss1 = th.nn.MSELoss()(latents_prev_rec, latent_prev)                       # MSE
            loss2 = ssim_loss(tarns(latents_prev_rec), tarns(latent_prev_source))        # 灰度 SSIM
            loss = alpha * loss1 + (1 - alpha) * loss2
            optimizer.zero_grad(); loss.backward(); optimizer.step()

        with th.no_grad():
            latent_cru = self.ddim_sample(model, latent_cru + visual_prompt[i], t, ...)["sample"]
    return visual_prompt
发现说明重要性
prompt 在图像空间 th.zeros([num_timesteps, 3, 256, 256]) —— 是逐时间步的一张 RGB 图，不是文本嵌入。加的方式是直接相加：latent_cru + visual_prompt[i]。 高
参数量约 10M / 图 T=50 时 50×3×256×256 = 9,830,400 ≈ 9.8M；T=100 时 ≈ 19.7M。相比之下 Null-text Inversion 在 SD 上是 T×77×768 ≈ 3M。这里每张图要优化的参数量大得多。 高
变量命名与论文相反 main.py 里 latents 来自 fake_image（风格模板），latents_source 来自 sample（输入 H&E）。但在 stainpromptInversion 里，latent_prev = latents[i] 被用在 loss1、latent_prev_source 被用在 loss2。命名与直觉相反，极易读错。 中
优化器每步重建 每个时间步 i 都 th.optim.Adam([visual_prompt], lr=1e-2) 新建一次优化器——动量状态不跨时间步保留。这是一个实现选择，不是笔误。 低
总计算量 内层总迭代数 ≈ Σi IST_init·(1−i/T) ≈ IST_init · T/2。T=50、IST_init=50 → 约 1250 次带反传的 DDIM 步。每步都要过一遍网络并反向传播。这是这个方法的主要成本。 高
类别条件是关键 扩散模型用 --class_cond True 训练，四个类 HE=0, MAS=1, PAS=2, PASM=3。"多域"能力来自这个类别条件模型，不是来自 prompt。 高
结构 prompt 可复用 论文明确说一次反演得到的结构 prompt 可复用于多种染色迁移。代码里 model_kwargs={'y': target_label} 是唯一的域切换开关。 好

                 --noise_schedule linear --use_ddim True --rescale_timesteps True"

两处版本差异，复现时注意
  • DDIM 步数：论文写"DDIM inversion timesteps = 100"，发布的脚本里是 --diffusion_steps 50。
  • 风格路径的条件：README 说 H&E→PAS 时风格路径用 extra（源域条件），但 main.py 里风格路径硬编码为 model_kwargs=None，只有注释提示了这个选择。所以要跑 PAS 得自己改代码。
  • --rescale_timesteps True 是必须的。README 专门警告："When you use improved-diffusion to pretrained diffusion model, you shoud set --rescale_timesteps True"。漏了会导致时间步语义错位。

10局限

论文自己承认的 + 我读出来的。

论文自陈的局限

风格漂移（style drift）

当特征适配函数生成的染色与预训练模型的染色先验差距较大时，条件编码采样会导致风格特征逐渐偏离。论文 Figure 10 展示了失败案例：当参考染色图错误地给本不该染色的区域上了色时，StainPrompt 优化会引入风格伪影。
但作者把这个失败模式转成了正面论证——"即使风格错了，结构一致性依然保持，这恰恰说明了内容与风格的强分离"。这个辩护是合理的，但也说明方法对风格模板的质量有依赖。

我读出来的局限

#局限说明
1 计算成本高 每张图约 IST_init · T/2 次带反传的 DDIM 步（T=50、IST_init=50 → 约 1250 次）。且每张图要优化约 10M 参数。对全切片推理（WSI 有上万个 patch）来说，这个成本非常可观。论文没有报单张图的推理时间。
2 任务范围窄 只做了肾脏特殊染色（MAS/PAS/PASM），没有做 IHC，也没有蛋白表达语义的验证。指标全是图像质量类（SSIM/FID/PSNR），没有 IoD / 染色量 / 分子相关性这类临床定量指标。
3 风格质量未超越 GAN FID 上打平或略输（见第 8 节）。所以它的定位是"结构保真的增强器"，不是"风格生成的替代者"。
4 依赖 GAN 提供风格模板 虽然消融证明"换哪个 GAN 都行"，但没有一个 GAN 就完全跑不起来。所以它不是"完全免训练"——它免的是扩散模型的微调，但依赖一个预训练 GAN。
5 论文与代码的符号不一致 Eq (7) 的 λ 语义与 Table 7 矛盾（见第 5 节）；变量命名 latents / latents_source 与直觉相反。这会影响复现效率。
6 扩散模型是自己从零训的 没有用任何病理基础模型。论文的理由是"当时没有病理预训练模型"（2024 年的判断），但这个前提现在已经不成立。后续 PGVMS 立刻转向了 CONCH，说明团队自己也意识到了。
7 没有物理/光学建模 整个方法纯粹在 RGB 空间操作，没有任何光学密度、Beer–Lambert 或染色矩阵的概念。这跟同团队 PSPStain / PGVMS / USIGAN 大量使用 OD 的风格形成鲜明对比。

11对 PSP-Diffusion 的启示

这篇能给你什么。

启示 1 · 它验证了"扩散反演是解耦的天然工具"，但只在 RGB 空间

DDIM 反演的确定性映射天然把"内容"（留在噪声里）和"风格"（靠条件注入）分开。这是你讨论的轴 3（内容 ⟂ 外观）解耦的一个成熟实现。但它的解耦发生在 RGB 空间的噪声轨迹上，不是浓度空间。你的 RDCS 把解耦挪到表示层，是同一个思想的更进一步——而且你的解耦有物理含义（S 与 C），它只有几何含义（轨迹方向）。

启示 2 · "可替换的接口"是它最强的叙事，你也可以有

消融 Table 5 是全文最有说服力的一段：换任何 GAN 当风格模板，结果都大幅优于该 GAN 单独使用。这证明价值在框架而不在组件。
你的 L4 渲染器 R_S 天然就是这种接口——而且比它更彻底：它的"风格模板提供者"还是要训练一个 GAN，你的"换 S"是换一个矩阵，零训练。这个对比可以直接写进你的 motivation。

启示 3 · 它把"结构保真"打成了主战场——你可以从另一个方向切

它在 SSIM / MS-SSIM / PSNR 上大幅领先，但 FID 没赢。这意味着："结构保真"这个山头已经被它占了。你的浓度空间路线如果也去比 SSIM，胜算不大（而且 SSIM 在错位数据上本来就不可靠）。
你应该切"染色量准确性"这个山头——DAB KL / IOD / COD 曲线 / 通道串扰。这些指标它是空白的（它一个都没报），而同团队的 USIGAN、PGVMS 都在用。这是差异化定位的机会。

启示 4 · 它的双路径结构可以映射到你的 L2/L3

它的"结构路径 + 风格路径 + 加权 λ"结构，本质上是两个约束的加权平衡。你的 RDCS 里也有类似结构：L3（形态引导）管结构、L2（浓度先验）管合理性、L4（渲染）管风格。
它的教训是：单项最优不如平衡最优（Table 4 显示双路径在两个单项上都不是最好，但综合最好）。你在设计损失权重时可以直接借鉴这个思路，并把它作为消融实验的一个论点。

启示 5 · 别低估它的计算成本，你的方案要报时间

每张图约 1250 次带反传的网络前向。论文没有报推理时间——这是一个可攻击的点。你的方案如果能在推理成本上做到更优（比如用 Marker-wise 的单步微调法），就是一个明确的 practical contribution。建议：你的论文里一定要报单张 patch 的推理时间，并跟它对比。

启示 6 · 它是"团队唯一没碰光学密度的工作"

对比看：PSPStain 用 FOD、PGVMS 用 COD 曲线、USIGAN 用 OD + IoD。只有这一篇（熊兵主导的扩散线）完全没有光学密度概念。
这说明团队内部的"OD 路线"和"扩散路线"还没有合流。而"在浓度空间做扩散"正是这两条线的交汇点。谁先合流谁就拿下这个方向——这是你最大的机会，也是最大的时间压力。

12复现陷阱清单

如果你要跑它或改造它，先看这一页。

#陷阱具体表现与对策
1 论文 Eq (7) 的 λ 标反了 论文写 λ·l_struct + (1−λ)·l_style，但 Table 7 的实测是 λ 越大风格越好。代码是权威：loss = alpha*loss1 + (1-alpha)*loss2，loss1=MSE（风格轨迹）、loss2=灰度SSIM（结构轨迹），alpha 加权风格。
对策：以代码为准；自己扫 alpha（附录 Fig 8/9 给了扫描曲线）。
2 变量命名与直觉相反 latents ← fake_image（风格模板）；latents_source ← sample（输入 H&E）。名字叫 "source" 的那个其实是结构路径，不叫 source 的那个是风格路径。
对策：读代码时先看 main.py 的赋值，再进函数。
3 --rescale_timesteps True 必开 README 明确警告。漏了会导致时间步语义与预训练模型不匹配。
4 DDIM 步数：论文 100 / 脚本 50 不一致。发布脚本里是 --diffusion_steps 50。想复现论文数字可能需要改成 100。
5 风格路径的条件是硬编码的 main.py 里风格路径写死 model_kwargs=None，只对 H&E→MAS 有效。README 说 H&E→PAS 应该用 extra。
对策：跑 PAS 要自己改代码。
6 数据集有坑 README 特别标注："val folder is for test, but we only use H&E folder. other stain type is only use for calculate FID."——测试时只用 val 里的 H&E 文件夹，其他染色文件夹只用来算 FID。搞错会算不出指标。
7 需要 MPI 代码里 from mpi4py import MPI，数据集按 rank 分片。单卡跑要设置好环境变量。
8 预训练物有三样 ① 扩散模型 model770000.pt；② GAN（ANHIR_params_latest.pt 对应 UMDST，或 latest_net_G_A.pt 对应 StainGAN）；③ 数据集。三样都要下。
9 prompt 参数量很大 [T, 3, 256, 256]。T=100 时约 19.7M 参数/图。显存要留够（论文用 A6000 48G）。
10 优化器每步重建 每个时间步都新建 Adam([visual_prompt], lr=1e-2)，动量不跨步保留。这是有意为之，不是 bug——但如果你改代码时想"优化"它，先验证是否真的更好。
