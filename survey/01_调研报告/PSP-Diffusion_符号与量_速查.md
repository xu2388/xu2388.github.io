# PSP-Diffusion：符号与量 · 速查手册

> 目标：把 `C`、`S`、"通道"这些量彻底讲清楚。
> 阅读顺序建议：先看 §1（一张表认全所有量），再看 §2（最容易搞混的"两种通道"），然后 §3–§5。

---

## 1. 一张表认全所有量

| 符号 | 形状 | 一句话含义 |
|---|---|---|
| `H`、`W` | 标量 | 图像的高、宽（像素数） |
| `N` | 标量 | 像素总数，`N = H × W` |
| `K` | 标量 | **染色数量**。H+DAB 时 `K = 2` |
| `X` | `3 × H × W` | **RGB 图像**。你肉眼看到的颜色 |
| `X₀` | `3`（或 `3 × H × W`） | **空白参考**：完全没有染色时透过的光（通常取白色背景） |
| `Y` | `3 × N` | **光密度（OD）**。染色在这里是线性相加的 |
| `S` | `3 × K` | **染色矩阵**。K 列 = K 种染色各自的"颜色方向" |
| `s_k` | `3` | `S` 的第 k 列，是 R³ 里的一个向量 |
| `C` | `K × N` | **染色浓度图**。每个像素、每种染料各有多少 |
| `c_i` | `K` | 第 i 个像素的浓度向量 |
| `Ĉ` | `K × N` | 模型**预测**的浓度（扩散的输出） |
| `C_real` | `K × N` | 从**真实 IHC** 分解出来的浓度（训练目标） |
| `X̂` | `3 × H × W` | 由 `Ĉ` 渲染出的 RGB（生成结果） |
| `F_struct`、`F_protein` | `D × h × w` | 条件编码器输出的**特征图**（不是图像，是抽象特征） |
| `C_t`、`C_0`、`C_T` | `K × N` | 扩散过程的状态：`C_0` 是干净数据，`C_T` 是纯噪声，`C_t` 是中间态 |
| `ε`、`v` | `K × N` | 扩散网络预测的目标（噪声 / v-prediction） |
| `ᾱ_t` | 标量 | 累积噪声系数，控制第 t 步加了多少噪声 |

### 形状速记

```
X : 3 × H × W     ← 3 是 RGB（光的三个原色）
Y : 3 × N         ← 3 还是 RGB；N 是像素数（把图摊平成一列像素）
S : 3 × K         ← 3 是 RGB，K 是染色数
C : K × N         ← K 是染色数；N 是像素数
```

**只有 `S` 和 `C` 里有 `K`。** 凡是出现 3 的地方，都是因为"光的 RGB 三原色"，
和染色数量没有任何关系。

---

## 2. 最容易搞混的：两种完全不同的"通道"

这是理解整件事的关键，务必分清：

| | RGB 通道 | 染色通道 |
|---|---|---|
| 有几个 | **固定 3 个**（R、G、B） | **K 个**，由染色数量决定 |
| 为什么是这个数 | 人眼有三种视锥细胞 | 你用了 K 种染料 |
| 每个通道代表什么 | "这个像素看起来有多红/绿/蓝" | "这个像素上有多少这种染料" |
| 单位 | 光强（0–255） | 浓度（无量纲，OD 空间的系数） |
| H+DAB 场景下 | R、G、B 三通道 | `C_H`、`C_DAB` 两通道 |

**所以 H+DAB 时：**

```
输入/输出图像：  3 个通道（RGB）
中间浓度表示：   2 个通道（C_H、C_DAB）
```

这两组通道之间不是一一对应的，中间隔着 `S`：

```
2 个染色通道  ──S(3×K)──►  3 个 RGB 通道
   C (K×N)                  Y (3×N)
```

> 一句话：**`C_H` 不是"R 通道"，`C_DAB` 也不是"G 通道"。**
> `C_H` 是"苏木精的用量"，它同时会影响 R、G、B 三个通道——影响多少由 `S` 决定。

---

## 3. `S` 到底是什么

`S` 是一个 `3 × K` 的矩阵。以 H+DAB（K=2）为例，典型的数值长这样：

```
             苏木精 s_H      DAB s_DAB
   R  [        0.65           0.35      ]
   G  [        0.70           0.55      ]
   B  [        0.29           0.75      ]
```

### 怎么读它

- **一整列 = 一种染色的"颜色指纹"**
  `s_H = [0.65, 0.70, 0.29]` 表示：苏木精主要吸收红光和绿光（数值大），
  少量吸收蓝光（数值小）——**吸掉红绿、剩下蓝，所以苏木精看起来是蓝紫色**。

  `s_DAB = [0.35, 0.55, 0.75]` 表示：DAB 主要吸收蓝光——**吸掉蓝、剩下红绿，
  所以 DAB 看起来是棕黄色**。

- **一个元素 `S[r, k]`** = 第 k 种染色对第 r 个 RGB 通道吸光度的贡献权重。

- **行数 = 3**，永远来自 RGB 通道数；**列数 = K**，来自染色数量。

### 为什么 `S` 可以固定下来

`S` 只描述"染料本身是什么颜色"，这是染料的物理化学性质，**和具体图像无关**。
所以可以从一批真实 IHC 图像里统计估计出来，然后在整个训练/推理过程中固定不动。

固定 `S` 的收益：让 `C` 变得**可辨识**（下面 §5 详述）。

---

## 4. `C` 到底是什么

`C` 是 `K × N`，也就是 **K 张和原图同样大小的"用量图"**。

H+DAB（K=2）时，`C` 就是**两张图**：

```
C_H  图：每个像素上"苏木精用了多少"
C_DAB 图：每个像素上"DAB 用了多少"
```

### 具体例子：一个 2×2 的小图块

**`C_H` 图（苏木精用量）**

| 0.90 | 0.10 |
|---|---|
| 0.45 | 0.05 |

**`C_DAB` 图（DAB 用量）**

| 0.05 | 0.90 |
|---|---|
| 0.45 | 0.05 |

**合起来看，每个像素就是一个 2 维向量：**

| 像素 | `c_H` | `c_DAB` | 物理含义 |
|---|---|---|---|
| 左上 | 0.90 | 0.05 | 大量苏木精、几乎没有 DAB → **深紫蓝色的细胞核** |
| 右上 | 0.10 | 0.90 | 几乎没有苏木精、大量 DAB → **深棕色（强阳性表达）** |
| 左下 | 0.45 | 0.45 | 两种都有 → **混合的紫褐色** |
| 右下 | 0.05 | 0.05 | 两种都很少 → **接近白色背景** |

### 渲染出来的 RGB（用上面的 `S`，`X₀ = 255`）

| `rgb(64, 56, 128)` | `rgb(106, 69, 50)` |
|---|---|
| `rgb(90, 70, 87)` | `rgb(227, 221, 226)` |

**看，`C` 的两个通道 → `X̂` 的三个通道。** 这就是 `S` 和 Beer–Lambert 做的事。

### 关键结论

> `C` **不是**一张彩色图，而是 **K 张灰度"用量图"叠在一起**。
> 它之所以重要，是因为"苏木精用量"和"DAB 用量"是有物理含义的量，
> 而"R 通道的值"没有——后者只是前者的副产品。

## 5. 完整走一遍：一个像素怎么从 `c` 变成 RGB

设某个像素的浓度向量 `c = [c_H, c_DAB]ᵀ = [0.90, 0.05]ᵀ`。

**第 1 步：光密度线性混合**（这是 `Y = S·C` 在单个像素上的样子）

```
Y = c_H · s_H + c_DAB · s_DAB

Y_R = 0.90 × 0.65 + 0.05 × 0.35 = 0.585 + 0.018 = 0.603
Y_G = 0.90 × 0.70 + 0.05 × 0.55 = 0.630 + 0.028 = 0.658
Y_B = 0.90 × 0.29 + 0.05 × 0.75 = 0.261 + 0.038 = 0.299
```

**第 2 步：Beer–Lambert 回到 RGB**

```
X̂ = X₀ · 10^(−Y)          ← 注意底数是 10（若用自然对数则是 e^(−Y)）

X̂_R = 255 × 10^(−0.603) = 64
X̂_G = 255 × 10^(−0.658) = 56
X̂_B = 255 × 10^(−0.299) = 128
```

结果：`rgb(64, 56, 128)` —— 深紫蓝色，符合"大量苏木精"的预期。✓

**反向（构造训练目标时走的路）**

```
真实 IHC RGB  ──OD──►  Y  ──乘 pinv(S)──►  C_real
```

其中 `pinv(S) = (SᵀS)⁻¹Sᵀ` 是伪逆。因为 `S` 是 `3×2`，`Y = SC` 是
**3 个方程解 2 个未知数（超定）**，最小二乘解唯一 —— **所以 `C` 是可辨识的**。

> 这也是为什么"固定 S"很重要：
> 若 `S` 和 `C` 同时自由变化，`S·C` 保持不变时两者可以互相补偿，
> 渲染出的 RGB 可能很好看，但 `C` 已经失去了物理含义。
> （这个问题在 **K ≥ 3** 时会真实出现 —— 你刚翻译的 InverseAE 那篇处理的正是这种情况。）

## 6. `F_struct` / `F_protein` 是什么（注意：它们不是图像）

它们**不是** RGB 图，也不是浓度图，而是编码器输出的**抽象特征图**：

```
F_struct : D × h × w     D 是特征维度（比如 256），h、w 是下采样后的空间尺寸
F_protein: D × h × w
```

- 空间尺寸通常比原图小（因为编码器里有下采样）
- 每个空间位置是一个 `D` 维向量，代表"这一小块组织在结构上/染色上是什么样"
- 它们的作用是作为**条件**喂给扩散 U-Net，告诉它"这里应该生成什么"

⚠️ 需要你自己确认的一点：如果两个编码器的输入**都是 H&E**，
那么 `F_protein` 里的"蛋白信息"实际上是模型**推断**出来的，而不是测出来的。
这种情况下建议改名为"表达潜变量"更准确。

## 7. 三个标量的取值范围（容易忽略但很要命）

| 量 | 典型范围 | 说明 |
|---|---|---|
| `X` | 0 – 255（或归一化到 0–1） | RGB 光强 |
| `Y` | 0 – 约 3 | 光密度，深染区可以到 2–3 |
| `C` | 0 – 约 4 | 浓度。**注意：最小二乘解出的 `C_real` 可能为负**，而预测端是 `Softplus ≥ 0`，两者必须对齐 |
| `S` 的每列 | 各元素 0 – 1 | 通常归一化为单位向量 |

> `C` 的分布极度偏斜（背景处大量 0，深染区是重尾）。
> 直接把 `C` 丢给标准扩散会不稳定 —— 必须**逐通道**做 robust 标准化
> （如按 99 分位数缩放），并保证训练与推理一致。
