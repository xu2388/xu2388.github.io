0先给结论

我给你的主推荐：Star-Diff

如果你现在只想找一个今天可以开始复现的“扩散虚拟染色 + 结构/随机性分离”工作，我推荐：Star-Diff。

  1. 任务与研究方向最接近：H&E → IHC，并且直接在 BCI-HER2 上报告结果。
  2. 方法上最接近你想要的解耦：它把确定性的结构/恢复路径与随机的噪声路径显式分开。
  3. 代码虽然是非官方实现，但 README 提供训练、采样、评估命令，并且给出了作者结果与复现结果的差距。
  4. 仓库含 YAML 配置、测试、插件式 runner、评价脚本，甚至明确报告“复现没有完全达到论文结果”的原因。这比只有一句“code will be released”可靠得多。

但是要诚实：Star-Diff 不是“content/style/protein/physics”意义上的显式解耦。它是残差结构路径 + 随机噪声路径的结构—随机性解耦。对你来说，先复现它，再把 PSPStain 的 PALS/PCLS 加进去，是目前最稳妥的起点。

第二推荐：DiffVS

如果你的第一目标是“官方代码 + 真实公开数据 + 训练/推理脚本完整”，选 DiffVS。它是 AAAI 2026 的官方实现，支持 ORION-CRC 和 HEMIT，代码含两阶段训练、推理、测试 split 脚本和数据布局说明。

但它不是显式解耦。它是marker-wise condition：用 marker token 控制目标染色，同一个模型共享不同 marker 的生成能力。它更适合作为可复现扩散 baseline，不是你的最终解耦模型。

不推荐现在把 StainDiffuser 当作第一复现对象

方法概念很接近“结构 + 辅助任务”，但目前公开页面仍缺少可用官方仓库、checkpoint、环境文件、数据准备脚本和运行命令；数据还需要机构 DTA。它是很好的文献参考，不是当前最好的工程复现起点。

1我筛选了什么

你的原始要求是：目前市面上已有的、与扩散模型解耦虚拟染色相关、并且真正可以复现的工作。这里“解耦”我不再宽泛地把所有条件扩散都算进去，而是分为三类：

A · 显式结构—随机性解耦

模型内部明确分出两个路径、两个变量或两个扩散过程，例如确定性 residual/restoration path 与 stochastic noise path。

Star-Diff 最符合这一类。

B · 隐式任务/染色因素分离

通过辅助任务、双分支、marker token、双向训练或任务特定条件，让结构和染色因素在功能上分开，但没有显式 disentanglement loss。

StainDiffuser / DiffVS / HistDiST 属于这一类。

C · 真正显式 content/style disentanglement

具有结构 latent、染色 latent、独立性/正交性/互信息约束，或者显式 style-content factorization，并且用于虚拟染色。

本轮没有找到同时满足“扩散 + H&E→IHC + 官方代码 + 可直接复现”的强候选。

复现门槛

我重点核对：官方/非官方代码、训练脚本、配置文件、数据格式、checkpoint、评估脚本、许可、最近更新、数据获取限制、作者结果与复现结果差异。

3第一推荐：Star-Diff

3.1 它到底解耦了什么

Star-Diff 的核心不是经典的 content/style latent，而是把 H&E→IHC 改写成一个 restoration diffusion：

确定性结构路径 + 随机噪声路径
x_t = x_0 + ᾱ_t · ε + β̄_t · I_res

I_res = I_IHC − I_HE

Residual U-Net r_θ: 预测 H&E 与 IHC 之间的确定性结构残差
Noise U-Net ε_θ:    预测随机高斯噪声，建模 IHC 的随机性/多样性

反向过程：同时利用 r_θ 和 ε_θ，从 H&E 恢复 IHC

论文将其描述为structure-diversity-balanced：残差路径负责结构保持，噪声路径负责分子表达的随机变化。

因此它是：

  • 显式的结构—随机性解耦；
  • 不是显式的 content—style—physics 三因素解耦；
  • 没有独立的蛋白表达 latent、物理染色 latent 或 disentanglement loss；
  • 但它是目前我找到的、最接近“结构提取后再注入染色变化”的可复现扩散工作。

  • 原论文没有公开全部 architecture details；

它没有只展示一个漂亮结果，而是把差距、可能原因和限制都写出来了。对于你的研究，这提供了一个现实的可复现上限：你可以先复现到 21.6 PSNR 左右，再逐项做差距诊断，而不是陷入“为什么我永远达不到论文数字”的黑箱。

  ↓

  ↓

  ↓

最小实验目标：不要一开始追求论文全部表格；先确认能得到合理 IHC、PSNR 接近 21 dB、结构没有明显破坏，然后再接入 PALS/PCLS。

4第二推荐：DiffVS

4.1 为什么它非常值得先跑

DiffVS 是 AAAI 2026 的官方实现，和 Star-Diff 的定位不同：它不是结构—噪声解耦，而是同一个扩散模型通过 marker-wise condition 生成多个 marker。

适合作为“干净的扩散 baseline”

它的 Stage 1 是 Marigold-style paired latent diffusion；Stage 2 是 Diffusion-FT 单步推理和像素级微调。H&E latent 与 noisy target-stain latent 拼接，marker 用 learnable token/one-hot condition 指定。这个结构非常适合你之后增加“结构条件”和“蛋白/染色条件”对照。

5如果必须要显式“解耦”

目前没有找到一个完全满足条件的强候选

在本轮检索到的工作中，没有发现同时满足以下四项的公开工作：

  1. 扩散模型；
  2. H&E→IHC 虚拟染色；
  3. 明确 factorized structure/content 与 stain/protein/style latent；
  4. 官方代码、checkpoint、数据和完整运行说明均可获得。

所以建议把“显式 content/style disentanglement”作为你自己的研究改动，而不是强行寻找一个已经完成的同类工作。

最现实的研究路线
先复现，再做最小解耦改造
推荐
Baseline 1: PSPStain（非扩散，PALS/PCLS）
Baseline 2: Star-Diff（扩散，结构 residual ↔ noise path）
Baseline 3: DiffVS 或 HistDiST（官方扩散条件 baseline）

你的改造：
Star-Diff / DiffVS
  + H&E structure condition
  + target-stain / protein condition
  + 保留 FOD/PCLS
  + 物理输出头或 OD-space supervision

这比直接从零设计“两 encoder + 两 latent + 三个解耦 loss”更可复现。你的贡献可以清楚地定义为：在一个可复现扩散 baseline 上，将结构保持、蛋白表达监督和物理染色约束显式分开。

7最终推荐排序

排序工作代码/运行完整度与你的 H&E→IHC 接近度解耦相关度推荐用途
1Star-Diff高直接 BCI-HER2结构↔随机性现在开始复现；作为你的扩散主 baseline。
2DiffVS很高ORION/HEMITmarker condition作为官方扩散 baseline；验证多 marker 条件控制和训练流程。
3HistDiST高BCI/MIST/四 markerdual condition如果你优先重视官方代码、checkpoint 和 BCI/MIST 实际可运行性，选它。
4VSMT中高直接 H&E→IHCfeature alignment非扩散辅助对照；可借鉴错位配对与语义特征对齐。
5StainDiffuser低CD3/CK8-18双任务扩散阅读方法、等待代码或向作者索取数据/实现；暂不作为第一复现。
最终建议只有一个版本

第一周复现 Star-Diff；第二周用 DiffVS 或 HistDiST 做官方扩散交叉基线；第三步再把 PSPStain 的 FOD/PCLS 接到 Star-Diff 的干净输出上。

如果你更看重“代码官方、数据公开、无需机构 DTA”，则把顺序改成：DiffVS → HistDiST → Star-Diff。如果你更看重“与结构—染色解耦的研究问题最接近”，则保持：Star-Diff → HistDiST → DiffVS。

8下一步执行单

A. 今天就能执行：Star-Diff sanity check
优先级 1
git clone https://github.com/anomredux/Star-Diff.git
cd Star-Diff
pip install -e ".[dev]"
PYTHONPATH=. pytest tests/ -v

# 准备 BCI:
# data/train/A = H&E
# data/train/B = IHC
# data/val/A, data/val/B
# data/test/A, data/test/B

python main.py --config configs/BCI_StarDiff_512.yaml --train --gpu_ids 0

先不改任何代码。目标是验证：数据读取、forward、采样、checkpoint、评价链路都通。

B. 之后做：保留 Star-Diff 结构，接入 PSPStain supervision
优先级 2
Star-Diff baseline
  → x_hat_0 / predicted IHC
  → OD / DAB deconvolution
  → PALS/FOD loss
  → PCLS feature/prototype loss
  → compare: naive sum vs gated vs terminal denoising-only

先只加 FOD，再加 PCLS。不要两个 loss 同时接入，否则无法判断失败来自哪里。

C. 交叉核验：DiffVS 或 HistDiST
优先级 3

用一个官方实现确认你的数据、颜色归一化、评价指标和 diffusion parameterization 没有被 Star-Diff 的独立实现绑死。这里重点比较：

  • v-prediction / scheduler；
  • H&E 条件注入；
  • 单步或多步推理；
  • PSNR/SSIM 与蛋白表达指标之间的差异。
