HTML网页开发基础10大核心知识点逐点详解

知识点1：HTML基础语法与文档骨架

HTML全称超文本标记语言，不是编程语言（无逻辑、无变量），是给浏览器看的标记标签语言，文件后缀为.html/.htm。

<!DOCTYPE html>   <!-- 文档声明：告诉浏览器这是HTML5文档，不属于标签，是指令 -->
<html>            <!-- 根标签：整个网页的最外层容器，唯一根节点 -->
  <head>          <!-- 头部区域：存放网页配置，页面不直接显示 -->
    <title>网页标题</title> <!-- 浏览器标签栏文字 -->
    <!-- 还可放meta、link、style、JS等配置 -->
  </head>
  <body>          <!-- 主体区域：所有页面可见内容全部写在这里 -->
  </body>
</html>
  1. 单标签（自闭合标签）：只有开始，无闭合，<br>换行、<img>图片、<input>输入框
  2. 双标签（容器标签）：成对包裹内容，<p>段落</p>、<div></div>

<!-- 注释内容 -->，浏览器不渲染，仅给开发者看。

知识点2：段落、行内文本标签（块级/行内基础）

  • 独占一整行，自带上下间距，自动换行
  • 用法：<p>这是一个完整段落</p>
  • 不自动换行，只包裹一小段文字，专门用来给局部文字改样式

示例：<span style="color:red">红色文字</span>正常文字

手动强制换行，单独使用：第一行<br>第二行

通过属性设置文字： <font face="微软雅黑" size="5" color="blue">文字</font> 属性：face字体、size字号、color颜色，多个属性空格分隔。

浏览器会忽略不认识的标签，想在页面显示<abc>符号，必须写转义字符： <abc> < = < 、> = >；空格占位符  

知识点3：表格标签 & 单元格合并（网页布局老式方案）

<table border="1px" cellspacing="0" cellpadding="3" align="center">
  <tr>   <!-- tr = table row 代表一行 -->
    <td>单元格内容</td> <!-- td = table data 代表一列/单元格 -->
  </tr>
</table>

属性逐个解释

  1. border="1px"：表格边框粗细
  2. cellspacing="0"：单元格与单元格之间的外边距（间距）
  3. cellpadding="3"：文字距离单元格边框的内边距
  4. align="center"：表格整体在页面水平居中
  1. colspan 跨列合并（左右合并，合并列）

<td colspan="2">内容</td>：当前单元格占据同一行2列的宽度

  1. rowspan 跨行合并（上下合并，合并行）

<td rowspan="2">内容</td>：当前单元格占据竖直2行的高度

合并规则：合并掉多余的<td>标签，只保留写合并属性的单元格。

收集用户输入的数据（账号、密码、勾选、上传文件等），提交给服务器。

核心属性

方式特点优缺点

CSS四种引入方式完整讲解（对应你手写笔记）

CSS就是给HTML页面加样式（颜色、大小、布局），一共4种引入写法，考试、面试高频考点。

一、行内式（内联式）

直接写在HTML标签的 style 属性里面

<标签名 style="属性1:属性值1; 属性2:属性值2;">内容</标签名>

例子：

<p style="color:red; font-size:20px;">红色文字</p>
  • 缺点：没有做到结构（HTML）和样式（CSS）分离，代码耦合严重，后期极难维护
  • 特点：只对当前这一个标签生效，优先级最高，极少项目使用，仅临时调试用

二、内嵌式（内部样式表）

写在页面 <head> 标签内，用一对 <style> 标签包裹CSS代码

<head>
  <style type="text/css">
    /* 选择器 { css样式 } */
    p {
      color: blue;
    }
  </style>
</head>
  1. 实现了简单的结构与样式分离
  2. 只对当前这一个HTML文件生效，多个页面无法共用样式
  3. 适合单页面简单样式、课堂测试使用，正式项目不用

三、外链式（链接式，项目最推荐）

  1. 单独新建一个 .css 后缀的独立样式文件
  2. 在HTML的 <head> 中用 <link> 标签引入外部CSS文件
<head>
  <link href="css文件路径" type="text/css" rel="stylesheet" />
</head>
  • href：填写css文件相对/绝对路径
  • rel="stylesheet"：定义当前引入的文件是样式表文件，必须写
  • type="text/css"：声明文件MIME类型，HTML5可省略

✅ 解耦度最高、工程最实用 ✅ 真正实现 HTML结构 和 CSS样式完全分离 ✅ 多个HTML页面可以共用同一个CSS文件，复用性强、便于统一改版、减少代码冗余 ✅ 浏览器会缓存CSS文件，网页加载速度更快 企业开发100%使用这种方式

四、导入式 @import（极少使用）

必须写在 <style> 标签内部开头位置

/* 写法1 */
@import url(style.css);
/* 写法2 */
@import "style.css";

完整代码：

<head>
  <style type="text/css">
    @import url(css文件路径);
  </style>
</head>
  1. 加载机制差：先加载HTML页面，再去下载CSS文件，页面会先裸奔无样式，体验极差
  2. 兼容性、权重、优先级不如link外链式
  3. JS无法动态控制 @import，link 标签可以JS动态增删

仅做了解即可，项目一律不用。

四种方式优先级 & 使用场景一句话总结

  1. 行内式：优先级最高，临时调试
  2. 内嵌式：单页简单测试
  3. link外链式：✅ 正式项目标准写法（首选）
  4. @import导入式：淘汰，仅了解语法

整张手写笔记 HTML + CSS 完整逐点讲解

一、HTML 部分基础

超文本标记语言，文件后缀 .html，用来搭建网页结构骨架，CSS负责样式美化。

<!-- 老版HTML4文档声明，现在都用简写 <!DOCTYPE html> -->
<!DOCTYPE html PUBLIC "版本" "http://www.w3.org/TR/html4/loose.dtd">
<html>
<head>
    <title></title>    <!-- 浏览器标签页标题 -->
    <meta charset="UTF-8"> <!-- 设置网页编码，防止中文乱码 -->
    <!-- 禁止浏览器缓存页面（拓展） -->
    <meta http-equiv="Cache-Control" content="no-cache">
    <link> <!-- 引入外部CSS -->
    <style> <!-- 内嵌CSS样式 -->
</head>
<body>
    <!-- 页面所有可见内容写在这里 -->
</body>
</html>
  • HTML：搭建页面基础结构（盒子、文字、图片、表单、列表）
  • CSS：给结构设置样式（颜色、大小、边框、布局、间距）

二、CSS 核心语法规则

选择器 {
  属性1: 属性值1;
  属性2: 属性值2;
  属性3: 属性值3;
}
  • 大括号内部是一组一组 键值对，每组用分号结尾

举例（笔记里例子）

div {
  border: 1px solid red; /* 边框：1像素、实线、红色 */
  width: 600px;
  height: 400px;
}

三、CSS 四种引入方式（重点考点）

书写位置：直接写在HTML标签的 style 属性里

<标签名 style="属性1:值1; 属性2:值2;">内容</标签名>
<!-- 实例 -->
<p style="color:red;font-size:16px;">测试文字</p>
  • 缺点：结构和样式完全耦合，没有做到分离，维护极差
  • 特点：只对当前单个标签生效，优先级最高，仅临时调试使用

书写位置：写在页面 <head> 内的 <style> 标签中

<head>
  <style type="text/css">
    /* 这里写选择器+样式 */
    p { color: blue; }
  </style>
</head>
  • 优点：简单实现结构样式分离
  • 缺点：仅对当前这一个html文件生效，多页面无法复用
  1. 单独创建后缀为 .css 的外部样式文件
  2. 在head中用 <link> 标签引入
<head>
  <link href="css文件路径" type="text/css" rel="stylesheet"/>
</head>

属性解释（笔记红字标注）

  • href：外部css文件地址（相对/绝对路径）
  • rel="stylesheet"：声明引入的文件是样式表文件，必填
  • type="text/css"：文件类型，HTML5可省略

✅ 最大优势：

  • 结构与样式彻底分离，解耦度最高、工程最规范
  • 多个HTML页面共用一套CSS，便于统一改版、浏览器缓存提速

企业正式开发唯一推荐写法

写在 <style> 标签内部开头位置，两种写法：

@import url(样式文件路径);
/* 或者 */
@import "样式文件路径";

完整代码：

<style type="text/css">
  @import url(style.css);
</style>

致命缺点（笔记蓝色补充）

  1. 加载顺序问题：

link：HTML和CSS同时并行加载； @import：先加载完整个HTML页面，再去加载CSS，页面会短暂“裸奔无样式”，体验很差

  1. JS无法动态控制，兼容性不如link，项目完全不用

四、CSS 三大基础选择器（笔记底部）

直接用HTML标签名作为选择器，批量修改所有同类标签样式 语法：标签名 { 属性:值; }

div { width:100px; }
p { color:green; }

语法：点 . + 类名，给标签加 class="类名" 来引用

/* CSS */
.box { font-size:14px; }
<!-- HTML调用 -->
<div class="box">内容</div>

特点：同一个类可以给多个标签使用，灵活复用，开发最常用

语法：井号 # + id名

#box { background: pink; }
<div id="box"></div>

硬性规则：同一个页面内id名称必须唯一，不能重复使用，多用于JS获取元素，很少用来写CSS样式

* { margin:0; padding:0; }

* 代表选中页面所有标签，作用范围最大；一般用来全局初始化样式，不适合做差异化单独样式

五、整体记忆逻辑总结

  1. HTML：搭网页架子 → 标准骨架 + meta编码/缓存设置
  2. CSS：美化样式 → 语法规则（选择器{键值对}）
  3. CSS四种引入：行内式→内嵌式→link外链式（首选）→@import导入式（淘汰），重点区分加载差异
  4. 三大基础选择器：标签选择器、class类选择器、id选择器 + 通配符*

二、XML 全盘拆解（本章重中之重）

1. 什么是XML？

全称：可扩展标记语言 Extensible Markup Language 一句话定义： 用来存储数据、传递数据、做项目配置文件的标记语言 和HTML长得像，但用途完全不同。

  1. 标签成对出现，必须开始标签+结束标签；
  2. 标签自定义（可扩展，你想写<学生>、<订单>都可以）；
  3. 整个文件只能有唯一一个根标签（语法硬性规定）。

三、DTD 约束（难点：规范XML格式）

1. DTD 是干嘛的？

全称：文档类型定义，后缀 .dtd 作用：强制规定XML里面能写哪些标签、标签嵌套顺序、标签出现次数。 比如规定：书架里面必须放书，书里面必须有序号、书名、作者，少一个都报错。 开发工具：解析XML常用工具 dom4j。

2. DTD 两种引入方式（写在XML里）

自己项目里放一个book.dtd文件，相对路径引入

<!DOCTYPE 书架 SYSTEM "book.dtd">

SYSTEM = 本地文件。

互联网上公开的DTD规范，写绝对网址

<!DOCTYPE 书架 PUBLIC "标识名" "http://xxx/book.dtd">

PUBLIC = 公共网络资源。

<!ELEMENT 售价 (#PCDATA)>

  1. <!ELEMENT 书架 (书+)>

  1. <!ELEMENT 书 (书名,作者,售价)>

每一本<书>里面，必须按顺序写：书名→作者→售价，顺序不能乱，不能少；

  1. #PCDATA：代表标签里面放普通文本内容（字符串、数字）。

1. 与DTD相比的优点

（1）DTD采用的是非XML语法格式，缺乏对文档结构、元素、数据类型等全面的描述。 XML Schema采用的是XML语法格式，而且它本身也是一种XML文档，因此，XML Schema语法格式比DTD更好理解。

（2）XML有非常高的合法性要求，XML DTD对XML的描述，往往也被用作验证XML合法性的一个基础，但是XML DTD本身的合法性却缺少较好的验证机制，必需独立处理。XML Schema则不同，它与XML有着同样的合法性验证机制。

（3）XML Schema对名称空间支持得非常好，而DTD几乎不支持名称空间。

（4）DTD支持的数据类型非常有限。

2. Schema约束的文档

XML Schema的功能比DTD强大很多，但相应的语法也比DTD复杂很多。接下来看一个简单的Schema文档。

<?xml version="1.0"?>
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
</xs:schema>

Schema文档，以.xsd作为后缀名，以xs:schema作为根元素，表示模式定义的开始。

如果有两个URL，为名称空间唯一标识一个元素或者属性 并且其组成的字符串完全相同，就可认为它们标记的是同一个名称空间

声明名称空间的格式：<元素名 xmlns:前缀name="URI"> 指在那个元素上声明名称空间，适用于当前标记的元素和属性，以及在该元素中嵌套的所有元素及其属性。 前缀元素的属性名 用于标识该元素与前缀之间的地址。

<?xml version="1.1" encoding="UTF-8"?>
<ns315:书架 xmlns:ns315="http://www.ns315.org/xmlbook/schema">
    <ns315:书>
        <ns315:书名>Java基础案例教程</ns315:书名>
        <ns315:作者>黑马程序员</ns315:作者>
        <ns315:售价>54.00元</ns315:售价>
    </ns315:书>
</ns315:书架>

注意：在声明名称空间时，有两个前提是不允许使用的，它们是xml和xmlns。xml被硬定义为与名称空间名字http://www.w3.org/XML/1998/namespace绑定，只能用于XML 1.0规范中定义的xml:lang和xml:base属性。前缀xmlns仅用于声明名称空间的绑定，它被定义为与名称空间名字http://www.w3.org/2000/xmlns/绑定。

一、前置一句话总览

DTD是老一代XML约束，Schema（XSD，后缀.xsd）是升级版，完全解决DTD所有短板，Java项目现在主流用XSD做XML约束。

二、Schema对比DTD五大核心优势（考试简答题必背）

  • DTD：自成一套奇怪语法，不是XML格式，新手难记；
  • Schema：本身就是合法XML文件，标签嵌套结构和普通XML一致，看懂XML就能看懂XSD。

DTD本身没法校验自己写得对不对； Schema自身遵循XML规范，写的约束写错了编辑器直接报错，校验机制和XML完全统一。

这是非常重要的点： 一个XML如果引入多个约束文件，不同约束里出现同名标签（比如两个约束都有<book>），会冲突。 Schema通过命名空间+前缀区分：

<!-- 绑定前缀ns315到一个唯一网址URI -->
<ns315:书架 xmlns:ns315="http://xxx/book">
    <ns315:书></ns315:书>
</ns315:书架>

DTD几乎不支持命名空间，多约束共存直接崩。

DTD只能简单规定文本； Schema可以严格限制：整数、小数、日期、布尔值、长度、正则、枚举。 例：可以强制<售价>必须是数字，写汉字直接报错，DTD做不到。

Schema可以做精细化语义限制：比如数字范围0~100、字符串长度、标签出现精准次数，DTD约束能力很粗糙。

  2. 固定根标签：<xs:schema>，必须绑定W3C官方地址 xmlns:xs="http://www.w3.org/2001/XMLSchema"
<?xml version="1.0"?>
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">

</xs:schema>

四、核心概念：命名空间 xmlns（手写重点）

用唯一URI网址当做身份证，区分不同约束里的同名标签，避免重名冲突。

<根标签  xmlns:自定义前缀="唯一URL地址">
  • xmlns：固定关键字，代表声明命名空间
  • 自定义前缀：简写别名（例子里ns315），后续所有标签都要加前缀:标签名
  • URL：只是唯一标识，不用能打开，写网址格式即可

在哪一个标签上写的xmlns，当前标签+内部所有子标签全部生效。

关键字 xml、xmlns 系统保留，不能当做自定义前缀。

使用 xsi:schemaLocation="命名空间URI .xsd文件路径" 需要先引入xsi标准命名空间。

使用 xsi:noNamespaceSchemaLocation="book.xsd" 简单单个约束文件、不需要命名空间冲突处理时使用。

一、基础概念

XML 是可扩展标记语言，用于存储、传输数据； 约束文件作用：规范XML书写格式，非法格式直接校验报错。 两套约束规范：DTD（老式）、XSD(Schema，主流)

第一部分 DTD 约束

文件后缀 .dtd； 三种引入方式：内嵌DTD、外部本地DTD(SYSTEM)、公共DTD(PUBLIC)。

语法：<!ELEMENT 标签名 内容模型>

  1. #PCDATA：标签存放普通文本
  2. (子标签1,子标签2)：嵌套子标签，顺序固定
  3. EMPTY：空自闭合标签，无内容
  4. ANY：任意内容，不推荐使用
  • +：出现1次或多次
  • *：出现0次或多次（可选）
  • ?：出现0次或1次（最多1次）
  • ,：顺序出现
  • |：多选一
  • ()：分组

语法：<!ATTLIST 标签名 属性名 类型 默认规则> 属性常用类型：CDATA（字符串）、枚举、ID（全局唯一） 四种属性规则：

  1. #REQUIRED：属性必须填写
  2. #IMPLIED：属性可选，可写可不写
  3. #FIXED "值"：属性固定值，不能修改
  4. "xxx"：默认值，不填写自动填充，可手动覆盖
  1. 语法不属于XML，自成一套语法，学习成本高
  2. 数据类型极弱，仅能识别文本，无法区分数字、日期
  3. 几乎不支持命名空间，多约束文件共存易产生标签冲突
  4. 无法精细化限制（数值范围、正则、字符串格式）

超文本：不只是纯文字，包含文字、图片、视频、html网页等各类资源。

2. HTTP三大核心特点

  1. 基于TCP协议

TCP是可靠传输协议，先建立连接再传输数据，数据不会丢失、不会乱序，所以HTTP通信是安全的。

  1. 请求-响应模型（最重要）

一次请求，对应一次响应。 浏览器发【请求】→服务器接收→服务器返回【响应】。 服务器不会主动给浏览器发消息，永远是浏览器先发起请求。

  1. 无状态协议

服务器记不住你是谁。 每一次浏览器请求，服务器都当成全新的陌生人，不知道上一次你做过什么。 >例子：你登录网页，刷新页面网站又不认识你了。 >✅解决方案：Cookie、Session（笔记手写标注的后续知识点）

优点：服务器不用保存用户信息，速度快； 缺点：无法记忆用户会话，需要额外技术弥补。

3. HTTP/1.0 和 HTTP/1.1 版本区别（考试高频）

短连接：一次TCP连接，只能完成1次请求。 流程：建立连接 → 请求1个资源 → 收到响应 → 断开连接 如果网页有html、图片、css多个资源，就要反复建立、断开连接很多次，效率很低，性能差。

支持持久连接（长连接 keep-alive） 建立一次TCP连接之后，可以连续发送多次请求，不用每次都重新创建连接。 减少频繁创建、断开连接带来的开销，网页加载速度大幅提升。 >笔记手写：不用重新连接

GET = 你把纸条参数贴在信封表面发给服务器 POST = 信封表面干干净净，账号密码等私密纸条塞进到信封内部（请求体body）

五、考试&开发必背总结

  1. GET参数位于URL；POST参数位于请求体body
  2. POST依靠Content‑Type识别提交数据格式、Content‑Length识别大小
  3. POST适合提交密码、表单、文件这类敏感或者量大的数据
  4. 请求头可以携带浏览器信息、Cookie、语言、防盗链Referer等一大堆附属信息
请求参数存放位置适合场景
GET网址?后面查询数据、搜索，参数公开可见
POST请求体body登录密码、提交表单、上传文件，相对隐蔽
