模型设置问题

杂项/其他 · 6 条消息 · 来源：豆包分享
我问
/model

⎿ Set model to Haiku 4.5 and saved as your default for new sessions

你现在是什么模型啊

● API Error: 400 claude-sonnet-5-5 requires adaptive thinking or ***.type=between_tools; omit thinking or use one of those modes (request id: 202610080423108319893578268d9d69PZ3gamm) 这个是怎么回事啊

错误原因

claude-sonnet-5-5 不再支持旧版 thinking: enabled + budget_tokens 这种扩展思考，它只允许两种模式：

  1. thinking: {"type": "adaptive"}（自适应思考，默认）
  2. thinking: {"type": "between_tools"}（仅工具间推理，关掉前置思考）
你的请求里带了旧的thinking参数，所以API直接返回400报错：必须二选一，不能用老的thinking配置
另外你前面执行了 /model Set model to Haiku 4.5，但后续请求实际调用的是 sonnet-5-5，属于模型切换没生效，客户端仍然发sonnet5.5的请求，两个问题叠加了。

✅ 修复方案（三选一）

"thinking": {"type": "adaptive"},
"output_config": {"effort": "high"}
effort可选：low/medium/high/xhigh/max，替代以前的 budget_tokens
"thinking": {"type": "between_tools"}

Haiku4.5 用的是旧版 thinking: enabled + budget_tokens，不支持adaptive。 把请求model字段改成 claude-haiku-4-5，同时把thinking改回：

"thinking": {"type": "enabled", "budget_tokens": 1024}

快速排查要点

  1. 确认客户端实际请求model名字，看是不是还是 claude-sonnet-5-5（你虽然执行了/model切换，但客户端没刷新生效）
  2. Sonnet5.5 不能省略thinking字段同时又传旧思考参数；不传thinking时默认启用adaptive
  3. Sonnet5.5不支持 thinking: disabled，只能 adaptive / between_tools

最简测试请求（Sonnet5.5可用）

{
  "model": "claude-sonnet-5-5",
  "max_tokens": 8192,
  "thinking": {"type": "adaptive"},
  "output_config": {"effort": "medium"},
  "messages": [{"role":"user","content":"hello"}]
}

如果你用的是某个客户端（比如Claude Code / Trae / 自定义脚本），告诉我是哪个工具，我直接给你对应配置修改方式。

报错一句话解释

codex 不能在管理员权限（elevated）的PowerShell里启动守护进程(daemon)，你现在这个终端是管理员身份打开的，直接启动后台服务会权限冲突。

报错原文： start the Windows daemon from a non-elevated terminal; shared clients must not inherit administrator privileges 翻译：请在非管理员终端启动Windows守护程序；共享客户端不能继承管理员权限

两种解决办法（任选其一）

  1. 关掉当前这个管理员PowerShell
  2. 开始菜单搜索 PowerShell，不要右键“以管理员身份运行”，直接左键打开（普通用户权限）
  3. 再执行
codex

加 --no-daemon 参数，直接本地运行，不开启后台服务：

codex --no-daemon

⚠️ 缺点：每次都要加这个参数，没有常驻后台的daemon加速。

补充排查点

你现在路径是 C:\WINDOWS\system32>，这就是管理员终端的典型特征；正常普通PowerShell默认路径一般是 C:\Users\你的用户名>。

Windows PowerShell Copyright (C) Microsoft Corporation. All rights reserved. 加载个人及系统配置文件用了 3185 毫秒。 (base) PS C:\Users\hua> codex codex : 无法将“codex”项识别为 cmdlet、函数、脚本文件或可运行程序的名称。请检查名称的拼写，如果包括路径，请确保路径正 确，然后再试一次。 所在位置 行:1 字符: 1 + codex + ~~~~~ + CategoryInfo : ObjectNotFound: (codex:String) [], CommandNotFoundException + FullyQualifiedErrorId : CommandNotFoundException (base) PS C:\Users\hua> 不用管理员会报错的啊

错误原因

无法将“codex”项识别为xxx = PowerShell找不到 codex 这个命令。

管理员窗口能跑、普通用户窗口找不到，是典型：安装时只加到管理员的环境变量PATH，或者程序安装路径没有写入系统PATH，仅管理员会话能读到。

排查步骤

管理员PowerShell里执行下面这条，看路径：

where.exe codex

会输出类似 C:\xxx\codex.exe。复制这个完整路径。

方式A：临时直接用完整路径执行（立刻能用）

# 把下面换成你 where.exe 查到的真实路径
& "C:\xxx\codex.exe"

或者加 --no-daemon

& "C:\xxx\codex.exe" --no-daemon

方式B：永久加到PATH，普通PS直接敲 codex

  1. 复制 where.exe codex 返回的文件夹路径（去掉 codex.exe）
  2. Win 搜索：编辑系统环境变量 → 环境变量 → 用户变量里找到 Path → 编辑 → 新建 → 粘贴文件夹路径
  3. 完全关闭所有PowerShell窗口，重新打开普通PS，再输入 codex
注意：区分【用户变量Path】和【系统变量Path】。加到用户变量，普通用户终端才能识别；如果只加到系统Path有时需要注销重登。

补充说明

  • 管理员窗口能执行，普通窗口不行：就是PATH环境变量作用域问题，不是权限问题。
  • 之前的 daemon 限制：就算把命令修复了，普通窗口执行 codex 依然不能在管理员终端跑daemon，只能普通终端启动daemon，或者加 --no-daemon。

普通PS输入：

Get-Command codex

找不到就说明PATH没生效。

你先在管理员PS运行 where.exe codex，把返回结果发给我，我直接帮你配置PATH。
