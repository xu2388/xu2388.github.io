关于 Java 中的顺序输入流（SequenceInputStream），下列描述错误的是： A. 它继承自 java.io.InputStream 类。 B. 它可以将两个或多个输入流逻辑上连接成一个单一的输入流。 C. 当其中一个输入流读取完毕（返回 -1）时，它会自动关闭该流并切换到下一个流。 D. 它支持同时从多个输入流中并行读取数据，以提高读取效率。

答案：D 知识点： SequenceInputStream 的作用和特性。 解析：

  • SequenceInputStream 继承自 InputStream，A 正确。
  • 它可以把多个输入流按顺序串联起来，逻辑上像一个连续的流，B 正确。
  • 当当前流读取到末尾（read() 返回 -1）时，会自动关闭当前流并切换到下一个流，C 正确。
  • D 错误：它是顺序读取，不是并行读取，不能同时从多个流中读取数据。

代码运行结果：

ByteArrayInputStream b1 = new ByteArrayInputStream("Hello ".getBytes());
ByteArrayInputStream b2 = new ByteArrayInputStream("World!".getBytes());
SequenceInputStream sis = new SequenceInputStream(b1, b2);
int data;
while ((data = sis.read()) != -1) {
    System.out.print((char) data);
}
sis.close();

选项：A. Hello B. World! C. Hello World! D. 运行时异常

答案：C 知识点： SequenceInputStream 的顺序读取。 解析： sis 将 b1 和 b2 按顺序合并。读取时先读完 b1（输出 "Hello "），再读 b2（输出 "World!"），最后输出 Hello World!。

代码：

InputStream s1 = new ByteArrayInputStream("AB".getBytes());
InputStream s2 = new ByteArrayInputStream("CD".getBytes());
SequenceInputStream sis = new SequenceInputStream(s1, s2);
byte[] buf = new byte[5];
int count = sis.read(buf, 1, 3);
System.out.println("Read:" + count + ", Content:" + new String(buf).trim());

选项：A. Read:2, Content:AB B. Read:3, Content:ABC C. Read:3, Content:BCD D. Read:2, Content: AB（A前有空格）

答案：B 知识点： read(byte[], off, len) 与 SequenceInputStream 的配合，String 构造函数和 trim() 对 \0 的处理。 解析：

  • buf 长度为5，默认全是 0。
  • sis.read(buf, 1, 3) 从索引1开始写入，最多3个字节。流内容为 A, B, C, D，所以读取3个字节：buf[1]='A', buf[2]='B', buf[3]='C'，返回 count=3。
  • buf 实际为 [0, 'A', 'B', 'C', 0]。
  • new String(buf) 创建字符串 "\0ABC\0"，trim() 会去除 ASCII 码 ≤ 空格(32) 的字符，\0 会被去除，得到 "ABC"。
  • 最终输出 Read:3, Content:ABC。

关于管道流，说法错误的是： A. 管道流主要用于在不同的线程之间进行数据传输和通信。 B. PipedInputStream 必须与一个 PipedOutputStream 连接后才能正常使用。 C. 管道流可以实现在同一个线程中既发送数据又接收数据，且不会造成死锁。 D. 管道流的连接可以通过构造方法实现，也可以通过 connect() 方法实现。

答案：C 知识点： 管道流的使用场景与限制。 解析：

  • A 正确：管道流用于线程间通信。
  • B 正确：必须连接才能使用。
  • C 错误：同一线程中对管道流同时读写会导致死锁，因为 read() 会阻塞等待数据，而写操作无法执行。
  • D 正确：可通过构造器或 connect() 连接。

关于子类与父类序列化关系，错误的是： A. 子类实现 Serializable，为保证父类成员也序列化，父类应实现该接口。 B. 序列化子类对象时，系统自动将其关联的父类对象状态也序列化。 C. 父类没实现 Serializable，反序列化时会调用父类无参构造函数初始化父类成员。 D. 只要子类可序列化，父类就自动具备序列化能力，无需显式实现。

答案：D 知识点： 继承中的序列化规则。 解析：

  • A 正确：想让父类字段也序列化，父类必须实现 Serializable。

  • C 正确：父类未实现接口时，反序列化会调用父类无参构造初始化。
  • D 明显错误：子类可序列化并不意味着父类自动可序列化，父类需自行实现接口。

  • D 正确：正是通过编号机制避免循环引用无限递归。
