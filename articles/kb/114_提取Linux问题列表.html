1. 结合 inode 节点编号，辨析硬链接和软链接的区别

inode 是什么？ 每个文件（包括目录）都有一个 inode，里面存储文件的元信息（权限、大小、时间戳、数据块指针等），每个 inode 有唯一编号。文件名和 inode 的对应关系存储在目录文件中。

硬链接

  • 多个文件名指向 同一个 inode（inode 号相同）。
  • 删除一个文件名（链接）不会删除数据，只有当 inode 的链接计数变为 0 时才会释放。
  • 硬链接不能跨文件系统（因为 inode 号只在各自文件系统内唯一）。
  • 不能对目录建立硬链接（防止循环引用）。
  • 修改内容：无论通过哪个链接修改，其他链接看到的内容都会同步改变，因为它们指向同一份数据。

软链接（符号链接）

  • 是一个特殊的文件，里面存储的是 目标文件的路径（类似快捷方式）。
  • 有自己的独立 inode，链接计数为 1。
  • 可以跨文件系统，也可以链接目录。
  • 删除源文件后，软链接变成“悬空链接”，访问会报错。
  • 修改内容：通过软链接修改会直接影响源文件；但如果源文件被删除后新建同名文件，软链接会指向新文件（路径相同即可）。

示例：

echo "hello" > file1
ln file1 file2          # 硬链接，inode 相同
ln -s file1 file3       # 软链接，inode 不同
ls -li                  # 查看 inode 号

2. 查看自己系统的二级文件目录有哪些内容

二级文件目录 通常指根目录 / 下的第一层子目录（例如 /home、/etc 等）。要查看这些目录的内容，可以用：

ls /          # 列出根目录下的所有一级子目录和文件
# 或者更详细
ls -l /       # 显示权限、所有者等

如果你是指 当前工作目录下的二级目录（例如当前在 /home/user，二级目录就是 /home/user/某目录 下的子目录），可以这样：

ls */*        # 显示当前目录下所有子目录里的内容（仅二级）
tree -L 2     # 以树形结构显示两层目录（需要安装 tree）

不同 Linux 发行版的 / 下结构基本相似，典型有：/bin, /boot, /dev, /etc, /home, /lib, /media, /mnt, /opt, /proc, /root, /run, /sbin, /srv, /sys, /tmp, /usr, /var。

3. 利用 cd、ls、通配符、“” 等练习不同目录的操作及文件属性查看

  • 通配符

  • ? 匹配单个字符
  • [abc] 匹配 a/b/c 其中之一

  • 反引号 ` `：执行命令并替换输出（已过时，推荐 $()`）。

4. 什么是 Shell？具有什么功能？

Shell 是一个命令解释器，是用户与 Linux 内核交互的界面。它接收用户输入的命令，解析并执行，然后返回结果。

主要功能：

  • 命令解析与执行：内部命令（如 cd）直接执行，外部命令查找 PATH 并创建进程运行。
  • 变量与环境管理：定义、导出环境变量。
  • 输入输出重定向：>, >>, <, <<, | 等。
  • 通配符扩展：将 * 等通配符展开为匹配的文件名列表。
  • 作业控制：后台运行（&）、挂起（Ctrl+Z）、恢复（fg/bg）。
  • 脚本编程：写 Shell 脚本，支持循环、条件、函数等。
  • 历史命令、别名、快捷键（如 Ctrl+R 搜索历史）。

常见 Shell：bash（最常用）、zsh、fish、sh 等。

5. 简述文件的类型

Linux 中一切皆文件，类型由文件属性中的第一个字符标识（ls -l 查看）：

  • 普通文件 (-)：文本、二进制、数据等。
  • 目录文件 (d)：包含文件名和 inode 映射的表。
  • 符号链接文件 (l)：指向另一个文件或目录。
  • 设备文件
  • 字符设备 (c)：按字符流访问（如键盘、串口）。
  • 块设备 (b)：按块访问（如硬盘、U盘）。
  • 管道文件 (p)：用于进程间通信的 FIFO。
  • 套接字文件 (s)：用于网络或本地进程间通信。
  • 其他：如 Door 文件（某些 Unix 系统特有）。

7. Linux 下如何使用设备？常用设备名有哪些？

使用设备的方法：

  1. 设备文件：位于 /dev/ 下，应用程序通过 read/write 直接读写设备文件（如 /dev/sda）。
  2. 挂载文件系统：块设备（如硬盘分区）需要先挂载到一个目录才能以文件形式访问：
   mount /dev/sdb1 /mnt/usb
  1. 字符设备：直接操作（如 cat /dev/ttyS0 读取串口），或通过专用库（如 ALSA 操作声卡）。

常用设备名：

  • 硬盘/SSD：/dev/sda, /dev/sdb（SATA/SCSI），/dev/nvme0n1（NVMe）
  • 分区：/dev/sda1（第一个分区），/dev/sda2...
  • 终端/串口：/dev/tty（当前终端），/dev/ttyS0（串口0），/dev/pts/0（伪终端）
  • 输入设备：/dev/input/mouse0（鼠标），/dev/input/event0（键盘事件）
  • 随机数：/dev/random, /dev/urandom
  • 光驱：/dev/cdrom（通常软链接到 /dev/sr0）
  • 音频：/dev/dsp（旧 OSS），现在多用 ALSA 的 /dev/snd/*

9. Linux 的基本命令格式？常用通配符有哪些？

基本命令格式：

命令 [选项] [参数]
  • 命令：可执行程序名或内部命令。
  • 选项：以 - 短格式（如 -l）或 -- 长格式（如 --all）。多个短选项可合并：ls -la。
  • 参数：命令操作的对象（文件、目录、字符串等）。

示例：

cp -r source_dir/ dest_dir/

常用通配符（用于匹配文件名或路径）：

通配符含义示例
*匹配 0 个或多个任意字符*.txt 匹配所有 txt 文件
?匹配任意单个字符file?.log 匹配 file1.log，fileA.log
[abc]匹配方括号内的任一字符[aeiou]* 匹配元音开头的文件
[!abc] 或 [^abc]匹配除括号内字符之外的任意一个[!0-9] 匹配非数字开头的文件
{str1,str2}花括号扩展（不是通配符，但常用）{a,b}.txt 生成 a.txt b.txt

注意：通配符由 Shell 展开，不是命令本身解析。

第3题

题目：运行一个脚本，用户不需要什么样的权限（ ） A. read B. write C. execute D. browse on directory 答案：B（常见标准答案）

要成功运行一个 Shell 脚本（例如 ./script.sh），用户（或进程）需要具备以下权限：

  1. 对脚本文件本身的权限：
  • 读（read）：必须能够读取脚本文件的内容，因为 shell 需要读取其中的命令。
  • 执行（execute）：必须对脚本文件有执行权限，否则系统不会允许运行它。
  • 写（write）：不需要。运行脚本只是读取并执行其中的指令，并不会修改脚本文件本身。因此写权限不是必需的。
  1. 对脚本所在目录的权限：
  • 执行（execute） 权限（在目录上常称为“搜索/浏览”权限，即 browse on directory）：为了能够进入该目录并访问脚本文件，用户需要对该目录的每个祖先目录都有执行权限。这是必需的。

所以，用户运行脚本时，不需要的权限是“write”。 选项 D “browse on directory” 本质就是目录的执行权限，是需要的。

因此正确答案是 B。

补充说明：结合我们之前的讨论，Linux系统对文件总共有12位权限控制。除了我们熟悉的9位rwx（所有者/组/其他用户）基础权限外，还有3位特殊权限，也称“附加权限”[reference:0][reference:1]。理解这些，就能明白为什么系统的关键文件如此“特殊”。

Linux的用户和权限管理围绕几个核心文件展开，它们各自的权限及背后的机制构成了系统的安全基石。

🔑 /etc/passwd：用户账户信息库

这个文件是Unix/Linux系统中最重要的文本文件之一。它存储着所有用户账户的基本信息，包括用户名、UID、GID、家目录等，系统会用它来将UID映射为用户名[reference:2]。

  • 标准权限
    # 在大多数Linux系统中，您可能会看到如下输出
    $ ls -l /etc/passwd
    -rw-r--r-- 1 root root ... /etc/passwd
  • 所有者为 root，权限 rw-。
  • 所属组为 root，权限 r--。
  • 其他用户，权限 r--。
  • 为什么这样设置？
  • 所有用户可读 (r--)：很多基础命令（如 ls）需要读取它来将用户ID（UID）转换为用户名，这是系统正常运行所必需的[reference:3][reference:4]。
  • 仅有root可写 (rw-)：这是为了安全，防止普通用户修改关键账户信息（如将自己的UID改为0）从而非法提升权限[reference:5]。
  • 不可执行：它只是一个数据文件，不是脚本或程序。

🔒 /etc/shadow：密码的影子文件

为了进一步提高安全性，现代Linux系统将原本存放在/etc/passwd中的加密密码单独移到了/etc/shadow文件中，因此它也被称为“影子密码文件”[reference:6][reference:7]。

  • 标准权限
    $ ls -l /etc/shadow
    ---------- 1 root root ... /etc/shadow
  • 所有者和所属组都是 root。
  • 文件权限是----------（没有任何权限位），甚至root用户也没有明确的读写权限[reference:8]。
  • 为什么这么严格？
  • 仅超级用户(root)可访问：这是最关键的一点。/etc/shadow文件的rwx权限只对 root 用户生效，这也是你看到 ---------- 权限的原因。
  • 为什么用户还能改密码？：这个问题引出了Linux权限系统里一个最巧妙的设计—— SUID特殊权限。

✨ 解密普通用户修改密码的魔法：SUID 权限

普通用户没有权限直接修改/etc/shadow文件，却可以通过passwd命令成功修改自己的密码。其核心在于passwd命令程序文件上设置的特殊权限 SUID。

$ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root ... /usr/bin/passwd

注意所有者权限中的 s 字符[reference:9]。

  • SUID(Set User ID) 权限是一种特殊权限，它允许用户在执行该文件时，临时获得该文件所有者（这里是root）的身份和权限[reference:10][reference:11][reference:12]。
  • 工作流程
  1. 普通用户alice执行/usr/bin/passwd。
  2. 因为/usr/bin/passwd拥有SUID位，执行它的进程会临时将有效用户ID（EUID）从alice切换为root。
  3. passwd程序以root身份运行，从而获得了修改/etc/shadow文件的权限。
  4. 程序在修改完alice的密码后结束，alice又恢复了其普通用户的身份。
关键限制： SUID权限只对二进制可执行文件有效，对Shell脚本无效[reference:13]。 用户必须对该文件拥有执行权限，设置SUID才有效[reference:14]。 权限仅在程序执行过程中生效，是临时的[reference:15]。 如果文件本身没有执行权限，设置SUID后会出现大写S，这表示SUID设置无效。

👑 /etc/sudoers：授权管理的配置文件

sud o命令允许系统管理员授权特定用户或组以root或其他用户的身份执行特定命令。其行为由/etc/sudoers文件定义[reference:16][reference:17]。

  • 标准权限
    $ ls -l /etc/sudoers
    -r--r----- 1 root root ... /etc/sudoers
  • 所有者为 root，权限 r--。
  • 所属组为 root，权限 r--。
  • 其他用户，无任何权限[reference:18][reference:19]。
  • 为什么这样设置？
  • 必须使用 visudo命令来编辑此文件。该命令会进行语法检查，防止因配置错误导致无法使用sudo，最终无法管理系统[reference:20][reference:21]。直接用文本编辑器修改可能引发问题。
  • SGID (Set Group ID)：与SUID类似，但作用于文件或目录的组权限位。当用户对带SGID的目录有wx权限时，在该目录下创建的文件或目录，其属组将自动继承该目录的属组，而非用户自身的属组[reference:22][reference:23]。
  • 粘滞位 (Sticky Bit)：通常用于目录。当目录设置了粘滞位后，即使用户对该目录拥有wx权限，也只能删除、重命名或移动属于自己的文件，无法动别人的文件[reference:24][reference:25]。
  • 符号模式中的大/小写：
  • 在 ls -l 的输出中，所有者权限位出现 s，前提是该位置原本有 x（执行）权限。如果文件无执行权限就设置SUID，则会显示为大写 S，表示设置无效[reference:26][reference:27]。
  • 粘滞位同理，如果位置原无x权限就设置，会显示为大写T[reference:28]。
  • 数字模式：特殊权限也通过数字表示，可与基础权限组合成4位八进制数。
  • SUID = 4, SGID = 2, Sticky Bit = 1[reference:29]。
  • chmod 4755 filename：4代表SUID，755是基础权限。chmod 1777 directory：1代表粘滞位（就像/tmp目录，权限为drwxrwxrwt）[reference:30][reference:31][reference:32]。
  • ACL (Access Control List)：当基础权限和特殊权限不够用时，ACL可以为单个用户或组设置更灵活的权限[reference:33][reference:34]。使用 setfacl 和 getfacl 命令管理。
  • chattr (文件属性)：这是比 rwx 更底层的权限控制，通过 chattr 命令设置文件在文件系统层面的特殊属性，如 i（不可变，Immutable）、a（只可追加，Append Only）等，即使用root也无法轻易修改，需用 lsattr 查看[reference:35]。

运行级别名称 / 作用说明

Linux的0，1，2>的设备默认分别都是什么

在 Linux 中，每个进程启动时都会自动打开三个标准文件描述符（file descriptor），它们默认都指向当前的控制终端（通常是 /dev/tty 或伪终端如 /dev/pts/0），具体对应关系如下：

文件描述符数字默认对应设备/位置说明
标准输入 (stdin)0键盘（终端输入）读取用户输入
标准输出 (stdout)1显示器（终端屏幕）输出正常结果
标准错误 (stderr)2显示器（终端屏幕）输出错误信息
注意：虽然 1 和 2 都输出到屏幕，但它们是独立的流，可以分别重定向。

你写的 2> 是 重定向符号，用于将文件描述符 2（标准错误）重定向到文件。例如：

它本身不是一个设备，而是一个操作符。

你可以用 ls -l /proc/self/fd/ 查看当前进程的文件描述符指向哪里：

$ ls -l /proc/self/fd/
lrwx------ 1 user user 64 ... 0 -> /dev/pts/0
lrwx------ 1 user user 64 ... 1 -> /dev/pts/0
lrwx------ 1 user user 64 ... 2 -> /dev/pts/0

这里 /dev/pts/0 就是当前终端。

  • 0：/dev/tty 或当前终端（键盘输入）
  • 1：同上（屏幕输出）
  • 2：同上（屏幕输出）

但更准确地说，它们默认都“指向当前控制终端”，并不固定是某个设备文件。

  • 解压 → 用 x（extract）
  • gzip → z（像 zip 的 z）
  • bzip2 → j（记住 “bzip2” 里有 j？或者联想 “j” 是第二选择）
  • f 必须最后，因为它要 followed by filename。

把 tar czvf 当成一个固定词组记：c-z-v-f，对应 “创建、压缩、显示、文件”。类似地 tar xzvf 是 “解压、解gzip、显示、文件”。
