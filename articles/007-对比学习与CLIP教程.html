对比学习与 CLIP 机制解析：从"拉近推开"到虚拟染色的文本编码器选型

写于 2026-10-24 · 教程篇 · 原始来源：DeepSeek 对话 [074][233][082][137]

对比学习是我较晚掌握、回头却发现"项目中处处都在使用"的一块内容。值得注意的是，它在我的项目里以两个完全不同的身份出现：一半是 Stable Diffusion 中把文字转化为条件的 CLIP，另一半是 001/002 中保持结构的 CUT/PatchNCE。一个负责"生成什么风格"，一个负责"不让结构被破坏"，本质上却源自同一个朴素的思想——把相似的拉近，把不相似的推开。 本文即从这个思想出发，一直讲到选择"将 CLIP 换成 CONCH"的决策过程。

一、对比学习：把相似的拉近，把不相似的推远

为便于理解，采用如下例子说明对比学习的思想：教孩子认识苹果——先给他看同一个苹果切成的两半（告知"这是同一个"），再给他看一个橘子（"这不是苹果"），他便能逐渐抓住苹果的本质，而忽略光照、角度等无关因素。对比学习正是这一思路的数学化：使相似的样本在特征空间中彼此靠近，不相似的彼此远离。

核心机制 · 锚点、正样本、负样本 + InfoNCE

它需要三种样本：锚点（当前关注的样本）、正样本（与锚点同类的样本，例如同一张图的两种增强）、负样本（不同类的样本）。目标是使锚点与正样本的相似度最大、与负样本最小，相似度一般采用余弦相似度。最常用的损失是 InfoNCE：

L = −log [ exp(sim(zᵢ,zⱼ)/τ) / Σₖ exp(sim(zᵢ,zₖ)/τ) ]

直观地理解：它衡量的是在一组候选中，能否准确地把正样本挑选出来——本质上是一个分类问题。分类越准确，锚点与正样本越近、与负样本越远。τ 为温度系数，控制"拉近/推开"的力度。

正样本由数据增强构造（同一张图经裁剪/变色生成两个版本），负样本即同一批次中的其他样本——因此对比学习依赖较大的批量（SimCLR 使用 4096，负样本越多分类任务越难、表征学习效果越好；MoCo 则以动量记忆库规避大显存需求）。其最大优势是不依赖人工标签，是自监督表征学习的主力方法。

二、CLIP：把"对比"用在图和文字之间

CLIP 是将这一思想从"同一张图的两种增强"搬到图文之间：一张图与它的文字描述构成正样本，同一批次中的其他图文对均构成负样本。它训练两个编码器——一个将图像编码为向量，一个将文字编码为向量——迫使匹配的图文在同一空间中贴近，不匹配的推远。训练完成后，图像与文字落在同一个可相互比对的空间中，因此可以执行零样本分类、图文检索等任务。

接回上一篇 · CLIP 就是 SD 的"文本编码器" 在 Stable Diffusion 中，CLIP 的角色非常具体：输入的 prompt 经 CLIP 文本编码器，编码为一个 [77, 768] 的嵌入（77 是 CLIP 的 token 上限，768 是维度），这个嵌入就是上一篇讲解的 z_text——它作为 K/V 被送入 U-Net 的交叉注意力层，Q 则是正在去噪的图像特征。因此，006 中"文本怎么变成条件"这一问题的后半段答案是：CLIP 负责把一句话变成一个可被查询的向量，交叉注意力负责让图像在每一步去查询它。

三、原生 CLIP 的局限：无法精确理解病理图像

当时的设想是：用文本引导染色风格，同时保持结构一致。由此产生的疑问是——仅凭一句话，原生 CLIP 真的能让模型实现精确认知吗？ 当时的原话是："因为我的文本主要是用于风格的引导……但是还是要保持结构的一致性，所以我就好奇，就这一段话，真的用一个原生的 CLIP 就能实现让模型精准的认知？然后就能生成？" 答案是明确的「不能」。

关键认识 · CLIP 只知道"有什么"，不知道"在哪里"

原生 CLIP 是在自然图片上训练的，其强项是全局风格识别（"这张是粉色系""那张偏紫"），但细粒度结构（基底膜钉突、系膜增生）很弱、空间关系很弱。一句话概括：它给出的是全局的、统计性的表示，而不是空间布局的蓝图——"只知道有什么，不知道在哪里"。

这解释了一个早已观察到的现象：SD 生成的病理图，远观形态尚可，细看结构错误百出。 因为 SD 的结构能力并非来自 CLIP 对结构的理解，而是 U-Net 自己学到了统计规律，CLIP 仅对风格起"提示"作用。若要使文本真正约束染色的细节，就需要更换为在病理数据上训练过的文本/图像编码器。

四、编码器选型：CONCH / UNI / Phikon 的比较与决策

对症的方案是更换为在病理数据上预训练的编码器。当时的选型对比，核心在于"谁见过 PAS/Masson 这类特殊染色"：

整理归纳 · 病理编码器对比（基于当时掌握的信息）
编码器是什么对本任务的价值
CONCHMahmoodLab，CoCa 架构，117 万对病理图文训练，其中超 71 万对来自 IHC 和特殊染色（含 PAS/Masson/PASM），输出 512 维最为契合——它专门以对比学习训练过"病理图+文字描述"对，正对应"文本引导染色"的需求
UNI哈佛，ViT-L，超 1 亿张病理图块自监督预训练，输出 1024 维主要在 H&E 上表现强，偏向图像特征而非图文对齐
PhikonViT + iBOT/DINOv2，千万级病理图块，输出 768/1024 维HistDiST 以它替换 CLIP 作为条件源（见下）

当时的结论原话："我觉的还是要用 CONCH。" 因为它在训练中见过 PAS/Masson 的图文对，最可能正确理解"生成 PAS 染色"这类指令。

工程细节 · 维度不匹配时的适配层 CONCH 输出 512 维、CLIP(ViT-L) 是 768 维、UNI 是 1024 维——直接替换会导致维度不匹配。解决办法是加一个可训练的线性适配层（例如 nn.Linear(512, 768)）将维度对齐；且由于语义空间也不一致，这个适配层通常还需要微调。这与 006 中"HistDiST 用 Phikon 代替 CLIP，处理后的维度与 CLIP 相同"是同一操作——更换条件源后，对齐维度即可继续送入交叉注意力。

五、结构化 prompt：按染色类型显式描述特征

仅有 CONCH 还不够，喂入什么文本同样关键。当时的主张是："我觉得这个文本最好可以是结构化的吧，我感觉是格式化会更加的有效，另外需要都是英文的"，并且要"不同的染色突出的不同特征……每种染色特点都说明白，因为我要微调 SD v1.5 需要让 UNET 去学习这个部分的"。最终落地为按染色类型定制的键值对模板——每种染色只强调其应突出的特征：

结构化 prompt 设计 · 一种染色一套模板

· PASM（重点观察基底膜）：stain: pasm / gbm_thickness: [...] / gbm_spike: [...] / gbm_tram_track / mesangial_interposition / quality: highly_detailed, sharp_focus

· Masson（重点观察胶原纤维/纤维化/硬化）；· PAS（重点观察糖原/系膜基质/K-W 结节）。

可借助 LLaVA 一类模型批量生成，再辅以人工抽样检查。但存在一个硬性约束：CLIP/CONCH 均有 77 token 上限，键值对过长会被截断——因此策略是将最重要的信息（染色类型、主要病变）置于开头，且不修改 max_position_embeddings（存在风险）。

六、同一思想的另一条主线：以对比学习保持结构

值得强调的是：学习对比学习的初衷是文本编码器，但回看 001/002 中负责结构保持的 CUT，其内核同样是对比学习——只是正负样本的定义换了位置。CUT（Contrastive Unpaired Translation）处理无配对染色迁移：既要改变外观，又不能破坏结构，其 PatchNCE 损失将对比做到了块（patch）级：

PatchNCE · 用对比锁定结构

· 锚点：输出图中的某个小块（例如一块细胞边缘）；
· 正样本：输入图中相同位置的小块（内容一致、外观不同）；
· 负样本：输入图中其他位置的小块（内容不同）。

拉近同位置、推远其他位置——于是输出的每一块都被约束回输入的对应位置，只允许染色变化、不允许结构偏移。其优点在于无需跨图寻找负样本，单张图内部即可计算，训练稳定、结构保持效果好。这比 002 中讨论的循环一致性约束粒度更细。CUT 正是实现"只改染色、不改结构"的方法，而它的内核是对比学习。

此外，还考虑过将对比学习用于染色-结构解耦：以局部对比（PatchNCE）锁定结构，再以全局对比（监督对比，SupCon）约束染色特征——使同一染色域的图像（均为 H&E）的染色向量聚拢、不同域（Masson）推远，从而让染色编码器只学习颜色统计、不触及结构。当时的参考范本是 DCLGAN（PatchNCE 保结构 + 判别器侧全局对比分离风格）与 MUNIT（内容/风格双编码器，可将风格损失替换为对比损失）。这种"结构、染色各由一个约束负责、各司其职"的思路，值得记录。

当前结论 对比学习归根结底是：构造正负样本，把正的拉近、负的推远，迫使模型学到"不随无关变换改变的、有区分性的本质特征"。它在本项目中有两种角色：CLIP 对齐图文，充当 SD 的文本编码器（prompt → z_text → 交叉注意力，承接 006）；CUT/PatchNCE 对齐同位置块，充当无配对染色的结构保持器（承接 001/002）。而原生 CLIP 不理解病理（"只知道有什么，不知道在哪里"），因此选择换用 CONCH（训练中见过 PAS/Masson 图文对），并配合按染色定制的结构化英文 prompt，同时处理 77 token 截断与维度适配。同一个"拉近推开"的思想，同时约束了"风格"与"结构"——这是本项目方法设计中一次关键的融会贯通。
