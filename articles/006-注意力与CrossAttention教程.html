注意力与 Cross-Attention 机制解析：从"软查表"到 UNet 的条件注入

写于 2026-10-24 · 教程篇 · 原始来源：DeepSeek 对话 [065][002][137][216][060]

学习注意力机制时，我最初将其作为孤立的知识点逐个攻克——Q、K、V、缩放点积、多头、SENet、CBAM，抄写代码并请 AI 逐行注释。但坦率地说，当时只会"算"，不会"用"。真正使问题豁然开朗的，是回到自己的研究：针对虚拟染色任务中"生成图像具有平均色调、却缺乏实际结构"这一长期难点，DeepSeek 给出的诊断一语中的——"结构在哪里被控制？在跨注意力层里，以空间潜变量作为条件查询。" 至此才明确：注意力并非可选模块，而是条件进入模型的唯一通道。本文从"查表"这一最朴素的本质出发，逐步推导至交叉注意力，最后落回虚拟染色任务。

一、注意力的本质：一次"带着查询的软查表"

注意力机制的核心目标，是从一组信息中挑出对当前任务更关键的部分。它所做的，本质上是一次"软查表"：持有一个 Query（要查询什么），与一组 Key（每条信息的索引）比对相关性；匹配程度越高，对应 Value（真正的内容）被取用的权重越大，最后加权汇总。

为便于理解，采用如下例子：将中文"我"翻译成英文。

示例 · 机器翻译中的 Q/K/V

· Query = "我"——当前待查询的目标；
· Key = 每个英文词的关键特征——被检索的索引；
· Value = 每个英文词本身的内容。

以 Query 与所有英文词的 Key 计算相关性，结果显示其与 "me" 的 Key 最为匹配，注意力分数最高；再按该分数对所有 Value 加权求和，"me" 的内容占比最大，模型由此建立"我→me"的对应关系。反向验证：若不引入注意力、将所有词一视同仁地传递，下游无法区分哪个词与"我"相关——注意力正是为解决"谁更重要"这一问题而设计的。

相关性的算法有好几种（加性注意力、缩放点积注意力……），但最通用、也是 Transformer 和扩散 UNet 里用的，是缩放点积：

核心公式 · 缩放点积注意力

Attention(Q, K, V) = softmax( QKᵀ / √d ) · V

· QKᵀ：每个 Query 与每个 Key 做点积，得到相关性矩阵；
· / √d：除以维度的平方根——用于防止点积数值过大，数值过大时 softmax 会饱和、导致梯度消失；
· softmax：将相关性归一化为总和为 1 的权重；
· · V：按权重对 Value 加权求和，得到输出。

二、自注意力：序列内部的全局相关性计算

基础的注意力是"以一个 Query 检索一组 Key"（例如翻译中以"我"检索英文词）。自注意力（Self-Attention）更进一步：Query、Key、Value 全部来自同一串输入——序列中每个元素都与其他所有元素计算一遍相关性。为便于理解，采用"你好机车"这句话作为例子：

示例 · "你好机车"上的自注意力计算流程

先将每个字 Embedding 为向量 a¹,a²,a³,a⁴，然后每个 a 都经同一套矩阵分别投影出 q、k、v：

qⁱ = Wq·aⁱ , kⁱ = Wk·aⁱ , vⁱ = Wv·aⁱ

以计算"你"（a¹）与整句的关系为例：用 q¹ 分别与 k¹,k²,k³,k⁴ 做点积：α₁,ᵢ = q¹·kⁱ / √d，经 softmax 归一为权重，再加权求和 b¹ = Σ α̃₁,ᵢ · vⁱ。于是"你"位置的输出按相关性融合了整句信息——相关性越高的字，贡献越大。

概括而言：自注意力使每个位置都能"看到"整个序列，并按相关性聚合信息，因而天然擅长捕捉长程依赖（卷积只能关注邻域，自注意力则覆盖全局）。

另一项需要掌握的设计是多头（Multi-head），其思路相当直接：不只用一组 Q/K/V（即仅从一个角度度量相关性），而是并行使用多组，每组关注不同的子空间，最后将各头的结果拼接起来。类比观察一张图像：有人关注轮廓、有人关注颜色、有人关注纹理，合并后信息更完整。代码的核心步骤是将 Q/K/V 按头数切分、分别计算注意力、再拼接还原（学习时我曾请 AI 为 reshape→transpose→matmul→softmax→matmul→transpose→reshape 这段形状变换逐行注释，目的正是熟悉"切头—算分—加权—合头"的完整流程）。

三、关键分野：自注意力面向序列内部，交叉注意力面向外部条件

这一层在最初读代码时并未打通，后来靠项目实践才厘清。自注意力与交叉注意力的差别，仅在于 Q、K、V 的来源：

自注意力与交叉注意力的区分
Q 来自K / V 来自作用
自注意力序列自身序列自身序列内部通信：每个位置与所有其他位置交换信息
交叉注意力序列 A（主体）序列 B（条件）外部检索：A 携带自身查询，按相关性从 B 中提取信息

两者的公式完全相同（均为 softmax(QKᵀ/√d)V），但交叉注意力中 Q 与 K/V 来自两个不同的来源——这正是"条件注入"的数学开关。

理清这一点后，扩散模型中的条件机制便可贯通：SD 的 UNet 在每个 BasicTransformerBlock 中，实际是先自注意力、再交叉注意力——自注意力让图像特征内部先形成统一表征，交叉注意力再让图像特征去"查询"文本嵌入。文本/结构条件，正是从交叉注意力这一层注入 UNet 的。

四、交叉注意力：条件注入 UNet 的具体机制

阅读 StainExpert 时我有一个具体困惑："这个交叉注意力是在哪儿算的？VAE 刚刚压缩到 latent space 吗？" 答案是：不是压缩完成的那一步，而是在扩散 UNet 内部、每一个去噪步骤中都在计算。 具体分工如下：

条件注入的机制 · Q 是图，K/V 是条件

· Q 来自图像特征（正在去噪的那张 latent 的中间特征）——"当前图像的哪些位置需要查询"；
· K、V 来自条件——可以是文本 z_text（CLIP 编码）、结构潜变量 z_s（VAE 编码的 H&E）、或病理专用编码器（Phikon / UNI）提取的特征。

于是在 UNet 的每个去噪步，图像特征都"携带自身的空间位置"到条件中检索一遍：文本条件指出"该位置应为 MAS 染色的胶原"，结构潜变量指出"该位置对应源图的肾小球"，检索到的信息按权重融合进图像特征。VAE 压缩只是将图像搬入 latent 空间，交叉注意力才是把条件持续送入的通道，且每一步去噪都执行一次。

为什么必须"每一步都注入"？因为扩散模型通过多步迭代逐渐去噪，若条件仅在输入端拼接一次（concat），随着去噪推进其影响会被逐渐稀释；而交叉注意力使源结构/文本在整个去噪链条上持续可被查询，结构因此得以锁定。这正是 001 中那个结论的机制层面解释——结构保持不是依赖某个损失函数的"期望"，而是依靠一条贯穿全程的条件注入通道。

五、回到虚拟染色任务："有色调、无结构"的成因与对策

主线问题——"生成的图有一个平均色调，但没有实际结构"——的成因，现在可以用 DeepSeek 的诊断复述为：条件信号太弱、注入路径太间接。 若以整张 H&E 的全局嵌入作为条件，空间排列信息全部丢失，模型只能学到"平均色调"；对症的方案，是将带空间维度的结构特征通过交叉注意力作为 K/V 注入，使去噪每一步都能按位置检索到源图的结构。

本项目中的注意力 · 三条实证/路线

① 实验中观察到的正反馈：早期在 H&E 分支加入注意力后，观察到"生成图像的 SSIM 提升"——这很可能是因为注意力促使模型更聚焦于 H 通道主导的核结构。但它并不自动意味着 IHC 的染色特异性同样改善，指标与结构之间的差距仍然存在。

② HistDiST 的做法（本项目基线）：用预训练的病理模型 Phikon 提取 H&E 的形态特征，通过 cross-attention 注入 U-Net；VAE 编码的 H&E 特征再与噪声 latent 拼接。这是"结构特征作条件"的标准范式。

③ HistDiT 的启发：它揭示了一个权衡——现有 U-Net 扩散存在"结构-染色权衡"：要么结构相关但图像模糊，要么纹理真实但伴有伪影；其解法是以 VAE 潜变量作空间约束、以 UNI 嵌入作语义引导，二者均经多头跨注意力注入，并在不同去噪阶段动态关注结构以抑制幻觉。这几乎正是针对"有色调、无结构"问题的方案。

一个更精巧的变体 · PST-Diff 的不对称注意力 调研中，PST-Diff 的 AAM（不对称注意力模块）值得注意：源到潜在方向使用多头注意力（精细局部，用于守护源域结构），潜在到目标方向使用全局注意力（宏观，用于塑造目标域风格）。换言之——以细粒度注意力约束结构不偏移，以粗粒度注意力放开转换风格。这种"一细一粗、分别承担守护与塑造"的设计，优于对所有条件一律使用同一种交叉注意力，值得记录借鉴。
当前结论 注意力机制归结到最底层，就是"以 Query 与一组 Key 计算相关性、再按相关性加权提取 Value"——一次可微的软查表。自注意力实现序列内部的信息交换，多头使其从多个子空间观察，而交叉注意力（Q 来自图像、K/V 来自条件）是把文本/结构条件注入扩散 UNet 的通道。"有色调、无结构"问题的本质，是这条通道过窄或过于间接；将带空间信息的结构特征（VAE 潜变量 / Phikon / UNI）通过交叉注意力在每一步去噪中持续注入，是主线层面最对症的解法。从"逐行理解 QKV 代码"到"看懂条件如何进入模型"，是本次学习中最关键的一跃。
未解决问题 / 待核实
  • "加入注意力/约束后，图像肉眼可见更平滑、结构清晰度反而下降"——注入强度与结构保真之间的平衡一直未调好，这是下一步需要解决的问题。
  • HistDiST 在翻译任务中完全未使用文本条件（只用 Phikon + VAE 结构）；我计划将文本也融入（cross-attn 注入），但需先构造 (H&E, IHC, text) 三元组、文本还需病理专用编码器——尚未落地。
  • 通道级条件注入（输 H 通道 RGB、E 通道作监督）只是一个设想，未必可行，尚未验证。
  • 数据未配准（MIST）时，注意力/NCE 监督可能"把 A 位置结构对齐到 B 位置特征"，属于错误对齐——配准与注意力的相互作用尚未系统调研。
