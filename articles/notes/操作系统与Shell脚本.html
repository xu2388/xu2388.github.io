操作系统与 Linux 上机 · 进程、权限与 Shell 脚本

一、概述

本文是操作系统课程上机部分的系统笔记，与《Linux 本地存储管理》互为姊妹篇：那篇讲磁盘到挂载的纵向链路，本文覆盖同一门课的进程与作业、用户组与权限的题目层面、Shell 脚本编程；分区与 LVM、fstab、umask 推算、quota、tar 参数与 crontab 字段详解均见那篇，本文不重述。

原料为一份 Shell 速成计划及逐条追问、一组课堂黑板题与其订正过程、若干套自测卷，其中不少是笔者当时真正卡住之处：脚本挂进 crontab 后毫无输出、函数调用报 command not found、权限串读错一位致整题数值全错。题号与选项字母不再保留，只留判断依据；文中路径与账号名均为示例。

二、程序、进程与线程

2.1 静态的程序，动态的进程

程序是静态的、永久的指令集合，以二进制文件躺在磁盘上；进程是程序装入内存后的一次动态执行，有明确生命周期。二者是一对多关系：一个程序可对应多个进程，一个进程也可顺序执行多个程序。

对比维度程序进程
本质磁盘上的静态指令集合内存中的动态执行实例
存在性文件不删即永久存在有创建、运行、消亡的生命周期
资源占用仅占磁盘空间占用 CPU、内存、PID 等运行资源
结构代码段与数据段的静态存储含 PCB，记录状态、资源与上下文

Linux 实现多任务靠分时技术：CPU 以毫秒级粒度在任务间轮转，在单核上制造并发效果。系统第一个进程是 systemd，PID 恒为 1、由内核直接启动，是所有进程的祖先；除它以外每个进程都有父进程，记作 PPID。

2.2 进程的四类身份标识

  • 真实 ID（RUID/RGID）：谁真正启动了进程，等于发起者的 UID/GID，存续期间不变，用于统计与归属判定。
  • 有效 ID（EUID/EGID）：内核做文件权限检查时实际使用的 ID。默认 EUID = RUID、EGID = RGID；被执行的文件属主位有 s（SUID）则 EUID 变为文件属主 UID，属组位有 s（SGID）则 EGID 变为文件属组 GID。判分点几乎都在这里。
  • 保存型 ID：执行 SetUID 程序时内核复制保存 EUID，使进程可临时降权、必要时切回原有效身份。课程要求一般到有效 ID 一层为止。一句话记：真实 ID 是出身，有效 ID 决定权限检查。

2.3 分类、启动与状态

进程分交互进程（由 Shell 启动，可前后台切换）、批处理进程（无控制终端，入队列顺序执行）与守护进程（开机自启、常驻后台）；启动方式分手工启动（前台执行或末尾加 &）与调度启动（at/batch 一次性，cron 周期性）。状态模型是经典三态转换：创建后进就绪态，被调度即运行态，遇 I/O 或资源等待转阻塞态，条件满足回到就绪队列，最终终止释放资源。ps 的 STAT 列用字母表示且可叠加：

字母含义
R正在运行或在就绪队列；未拿到 CPU 也显示 R
S可唤醒的休眠，等待事件
D不可中断的 I/O 休眠，kill -9 也无法立即生效
T被停止或被追踪，由 Ctrl+z 挂起或调试器暂停产生
Z僵尸进程，子进程已退出而父进程未回收其退出信息
小于号、N高优先级、低优先级进程

须注意 T 的含义是「停止」而非「终止」：自测题曾把「终止态（T）」列为进程状态之一，那是把字母强行附会成中文词；反之就绪态不单列字母，与运行态共用 R。

线程对照：进程是资源分配的基本单位，有独立地址空间，切换开销大，进程间不共享内存；线程是 CPU 调度的基本单位，同进程内线程共享其资源与地址空间，只私有栈与程序计数器，开销小。故「现代系统可让不同进程轻易共享内存」「线程有独立地址空间」都不成立。语言层面的线程细节另见 Java 多线程笔记。

三、作业控制与进程查看管理

3.1 前台、后台与作业

前台进程独占终端输入输出，Shell 在此期间挂起，一个终端只允许一个前台进程；后台进程不占终端，一个终端可并行多个后台进程。

./prog                    # 前台运行，终端被占用直到结束
./prog &                  # 后台运行，关键就是末尾的 &
ps -u acct_a              # 查看示例账号名下所有进程
ps -u acct_a > /dev/null 2>&1 &   # 后台执行；> 把标准输出丢进 /dev/null，2>&1 把标准错误并入标准输出

作业控制管理当前 Shell 会话内的前台、后台与挂起任务，作业号统一写成 %数字：

# Ctrl+z        挂起当前前台进程，转为后台暂停状态
jobs            # 列出本会话的后台与挂起作业
bg %1           # 让 1 号暂停作业在后台继续运行
fg %1           # 把 1 号作业切回前台
kill %1         # 终止 1 号后台作业
nohup ./prog &  # 注销后保活，输出默认写 nohup.out

nohup 跨越注销这一默认规则；当前目录无写权限时 nohup.out 落到家目录。jobs 只看得见当前终端的作业，换一个终端即全空；看系统全部进程必须用 ps——「查看当前系统作业」与「查看系统进程」两问最易混处。

3.2 ps、top 与优先级

ps 是静态快照，top 是实时监控、动态刷新 CPU 与内存占用。判据很干脆：题干说「查看当前进程」用 ps，说「实时监控」用 top。

ps                      # 无参数仅显示当前终端的用户进程
ps -ef                  # 全部进程，完整格式，含 PPID
ps aux                  # 用户友好格式，含 CPU、内存占用
ps -H                   # 进程树形式
ps -u acct_a            # 指定账号的进程
pgrep -u acct_a         # 只输出 PID，便于脚本消费
pidof prog              # 按程序名直接取 PID
top -d 1 -n 5           # 每 1 秒刷新、5 次后自动退出；不加 -n 会一直跑，按 q 退出
top -u acct_a           # 只实时监控某账号进程
pstree                  # 进程父子关系

ps 选项记为 -e 所有进程、-f 完整、-H 进程树、a 所有终端、x 无终端的守护进程、u 用户格式、-u 指定用户、l 长格式、w 加宽、--sort 排序、o 自定义列；按名字搜进程即「ps aux 结果交给 grep 过滤」这类管道组合。共享实验机上排查自己的进程，难点往往不是不会敲 ps，而是同名解释器进程一大堆、显卡管理工具只给 PID 与被截断的路径；可靠做法是从 PID 反查归属——先 ps -u 列全，再用 ps -o 精确取列，或 pidof、pgrep 拿号，不要凭名字猜。

nice 值范围 -20 ~ 19、默认 0，数值越小优先级越高；内核动态分配的 PRI 满足 PRI(new) = PRI(old) + nice值，用户不能直接改 PRI。

nice 10 ./prog &        # 启动时设优先级，仅 root 可给负值
renice 5 -p 1234        # 按 PID 改
renice 5 -u acct_a      # 按用户批量改；-g 按组改

普通用户只能对自己的进程设正值以降低优先级，且降后无法自行恢复。

四、信号与进程终止

信号是软件层面对硬件中断的模拟，也是最基础的进程间通信方式；查看用 kill -l 或 man 7 signal。

信号名称行为
1SIGHUP重新加载配置、重启服务，并不终止进程
9SIGKILL强制立即终止，不能被捕获或忽略
15SIGTERM默认信号，正常终止，进程可自行清理后退出
kill 1234            # 不带信号即默认 15，优雅终止
kill -9 1234         # 对 PID 1234 发 SIGKILL，立即强制终止
killall prog         # 按进程名终止所有同名进程
pkill -u acct_a      # 按模糊匹配（如所属用户）批量发信号

三者分工是判断题常客：kill 认 PID、killall 认进程名、pkill 认匹配模式。业务环境应先用 15 让进程收尾，kill -9 会连带终止其所有子进程；D 状态卡在不可中断 I/O，kill -9 也无法立刻生效。

五、用户、组与四类账户文件

5.1 账户、UID 分段与组

账户是用户在系统中的唯一身份标识，系统据此区分各用户的文件、进程与任务，并给出独立家目录与 Shell，使工作彼此隔离。

UID类别说明
0超级用户UID=0、GID=0，管理普通用户与整个系统
1 至 999系统伪用户专供系统服务，不可交互登录；CentOS 6 及更早以 500 为普通起点，7 起系统用户占 1 至 999
1000 及以上普通用户日常账号，权限受限

组是多个用户的集合，用于统一分配权限。标准组可容纳多个用户；私有组默认只含用户自身，新建用户未指定组时系统自动创建同名私有组并加入，优点是新文件不归公共组，缺点是易留下全员可访问的开放文件。一个用户可同时归属多个组，其中主组（初始组） 是登录时默认所属组，附加组 是额外获得权限、登录后可切换的组。

5.2 四个账户文件与校验

文件内容字段数权限特点
/etc/passwd用户名、口令占位符 x、UID、GID、描述、家目录、登录 Shell7所有人可读，仅 root 可写
/etc/shadow加密口令与口令时效策略9仅 root 可读写
/etc/group组名、组口令占位符 x、GID、组成员列表4所有人可读，仅 root 可写
/etc/gshadow组名、加密组口令、组管理员、组成员4严格限制，仅特权用户可读

shadow 九字段依次为用户名、加密口令、最后改密距 1970 年的天数、最小改密间隔、最大有效期、警告天数、宽限天数、账户失效日期与保留位；默认 99999 天约合 273 年即永久有效，口令位出现 * 或 ! 表示无有效口令或已锁定，passwd 的登录 Shell 为 /sbin/nologin 即禁止交互登录。带 shadow 后缀的文件一律严格限权，此规律足以应对判断题；规范做法是不手工编辑这四个文件，一致性交 pwck 与 grpck 校验。

5.3 管理命令与口令策略

useradd -d /home/acct_a -s /bin/bash acct_a   # -d 家目录（绝对路径），-s 登录 Shell
useradd -g grp_main -G grp_a,grp_b acct_a     # -g 主组，-G 附加组
useradd -e 2026-12-31 -M acct_a               # -e 失效时间，-M 不建家目录
useradd -D                                    # 查看或修改默认配置
usermod -l new_name old_name                  # -l 改名；-L 锁定口令，-U 解锁
usermod -G grp_a acct_a                       # 改附加组，多组用逗号
userdel -r acct_a                             # -r 连带删家目录与邮件数据
groupadd -g 1001 grp_x                        # 指定 GID；-r 建系统组
groupmod -n new_grp old_grp                   # -n 改名，-g 改 GID
groupdel grp_x
gpasswd -a acct_a grp_x                       # 加成员；-d 移除，-A 设组管理员
passwd -S acct_a                              # 查口令状态；-l 锁，-u 解锁，-d 清空
chage -l acct_a                               # 查时效；-M 最大有效期，-E 失效日
chage -d 0 acct_a                             # 强制下次登录必须改口令
id                                            # 当前 UID、GID 与全部所属组
pwck                                          # 校验 passwd 与 shadow 的一致性
grpck                                         # 校验 group 与 gshadow 的一致性

useradd 的底层动作是一条链：写四个账户文件、创建家目录、复制 /etc/skel 骨架目录进去、建立用户邮箱；默认参数由 /etc/login.defs 与 /etc/default/useradd 决定。口令时效全局改 login.defs 的三个 PASS_ 参数，单用户用 chage，复杂度与弱口令校验由 PAM 管控。两个边界：不能删除被某用户设为私有组的组；删用户时同名私有组自动删除。身份切换：su 只换 root 身份而非登录 Shell，环境变量与 PATH 不变，su - 才完整重置；sudo 让普通用户以自身口令执行管理员命令，配置在 /etc/sudoers，必须用 visudo 编辑，因其自带语法检查。另注意：批量建用户没有一条直接命令，要么 for 循环，要么 newusers 配账号文件。

六、权限的题目层面：特殊权限、访问判定与 FACL

6.1 四位八进制与三类特殊权限

r、w、x 对应 4、2、1 的三组相加见存储篇，本文只补第四位：四位八进制结构为「特殊位 属主 属组 其他」，首位取值 0/1/2/4/5/6/7。

特殊权限符号位置数值生效范围与效果
SUID属主位 x 显示 s4，即 4000仅可执行文件；执行者临时获得属主权限，典型是 /usr/bin/passwd
SGID属组位 x 显示 s2，即 2000执行时临时获得属组权限；目录下新建对象自动继承目录属组
粘滞位其他位 x 显示 t1，即 1000仅目录；目录内文件只有其属主与 root 可删，典型是 1777 的 /tmp
chmod u+s prog          # 文字方式设 SUID
chmod g+s shared_dir    # 目录设 SGID，实现属组继承
chmod o+t shared_dir    # 目录设粘滞位
chmod 4755 prog         # 数字方式，四位八进制

6.2 一道判例的订正

真正反复出错的是读权限串。第一次拿到黑板题时笔者把它读成 drwxrwx-r-t，按属主 7、属组 7、其他 5 给出「普通 775、加粘滞位 1775」；核对原题才发现是 rwsrw-r-t，逐位重读才得正确值。订正后的推算：

# 拆位：类型位 d + 属主 rws + 属组 rw- + 其他 r-t
# 属主 rws：普通位 r+w+x = 7，且含 SUID → 4000
# 属组 rw-：6，无特殊权限
# 其他 r-t：普通位 r+x = 5，且含粘滞位 → 1000
# 特殊位 4+1 = 5 → 5000；普通 765 → 0765；合并 5765

能直接相加，是因为特殊权限落在千位、普通权限在百十个位，八进制下不同位互不干扰。同法可推 -rwsr-xr-x 为 4755；-rwsrwsrwt 则为 7777——属主 rws 是 $7+4=7$（含 SUID 的 4 进千位）、属组 rws 同理为 7（SGID 的 2 进千位）、其他 rwt 是 $r+w+x$ 加粘滞位即 7，普通位 $777$、特殊位 $4+2+1=7$，合并 $7777$。若末位写成大写 T（其他位无执行权限），才得到 7775。此题牵出三点：s 在属主位读 SUID（4）、在属组位读 SGID（2），同一字母靠位置区分；小写 t 表示有执行权限且开了粘滞位，大写 T 才是无执行权限却开了粘滞位，把 r-t 读成「无 x」就把其他位从 5 错算成 4；类型位 d 与 - 都不参与计算。

6.3 谁能访问：匹配顺序与 SGID 的无关性

判定走身份匹配：先看 UID 是否等于属主，命中取属主三位；否则看 GID 是否命中属组；都不匹配才落到「其他」。示例题中文件属主与属组的 UID/GID 均为 1001，另一账号两者均为 20，两组值互不相交，故该账号只能按「其他」段取值，结论为可读、不可写、不可执行。精细处在于该文件权限为 -rwxrws-r--、数值 2000 + 0774 = 2774，但 SGID 只改变进程运行时的有效组 ID，不影响用户对文件读写执行的判断——把特殊权限当作「多给一点权限」是常见推理错误。

进程侧判定随之而来：该账号执行此文件产生进程后，RUID 与 RGID 仍是 20 与 20，EUID 也仍是 20（属主位无 s），而 EGID 变为 1001（属组开了 SGID）；若同开 SUID，EUID 才会变成 1001。

链接要点只留一处提醒：软链接的标识位是 l 而非 d，有独立 inode、只记原文件路径、可跨分区，原文件删除即失效；硬链接才共用 inode、不能跨分区、不能对目录创建。完整对照见存储篇，「符号链接与原文件共用 inode」「其标识位为 d」均属错误表述。

6.4 FACL 与扩展属性

传统权限只有属主、属组、其他三档，无法为某个单独用户或多个不同组分别指派权限，也不支持继承。FACL（遵循 IEEE POSIX 1003.1e）补的正是这两处——可对任意指定用户或组单独分配 rwx，而不必把目录放开成 777，用户最终权限是传统权限与 FACL 的叠加。类型分存取 ACL（作用于单个文件目录）与默认 ACL（只对目录生效，其内新建对象自动继承），后者即「权限继承」需求的答复。文件系统须带 ACL 支持：发行版默认挂载多已开启，其他情形 mount -o acl 临时开启、写入 /etc/fstab 永久开启，默认选项可用 tune2fs -l 查看。

setfacl -m u:acct_b:rwx /home/prog          # -m 修改：给指定用户单授 rwx
setfacl -m g:grp_b:rx /home/prog            # 给指定组授权
setfacl -m d:u:acct_b:rwx /data/share       # 目录设默认 ACL，新文件继承
getfacl /home/prog                          # 查看 ACL 明细
setfacl -x u:acct_b /home/prog              # 删除其中一条
setfacl -b /home/prog                       # 清空全部 ACL

语法以冒号分段：u:用户名:权限、g:组名:权限，d: 前缀表默认 ACL，-R 递归。两个判定线索：配过 ACL 的文件 ls -l 权限串末尾多一个加号；mv 与 cp -p 都保留 ACL。相邻的扩展属性属内核级防护，补充而非替代 rwx：

lsattr -adR /data/conf              # 查看；-a 含隐藏，-d 只看目录本身，-R 递归
chattr +i /etc/critical.conf        # 不可变：禁改、删、重命名
chattr +a /var/log/append.log       # 只许追加，禁覆盖与删除
chattr -R =A /data/cache            # 不更新访问时间，降低 I/O；S 为写入立即同步

根目录与 /dev、/tmp、/var 等关键目录禁止设 i/a，否则会造成系统故障。

七、Shell 脚本的结构要素

7.1 骨架与三种执行方式

脚本由 Shebang、变量、流程控制与命令序列组成，后缀 .sh 是约定而非强制；创建后默认无执行权限见存储篇，此处补执行方式：

执行方式需执行权限特点
./script.sh需要，且路径必须写对以绝对或相对路径执行，另起子 Shell
bash script.sh 或 sh script.sh不需要直接调解释器，Shebang 被忽略
source script.sh不需要在当前 Shell 执行，脚本变量执行后仍在

三者差别不在能否跑，而在变量与环境的归属：前两种在子 Shell 里跑完即消失，第三种把结果留在当前会话。

7.2 变量、位置参数与扩展

注释以 # 开头；变量写成 name=value，等号两边不能有空格，否则被当成一条命令。引用用 $name 或 ${name}，字符串建议整体加双引号，以防变量为空或含空格时被拆成多参数。

name=John
echo "${name}"
file=${1:-"default_dir"}        # 位置参数为空时取默认值，不改变 $1
result=$(ls)                    # 命令替换
sum=$((a + b))                  # 算术扩展，另可用 expr 1 + 2
filename="file${i}.txt"         # 花括号显式划开变量边界
pids=($(ps -u $USER -o pid=))   # 把自己全部进程号收进数组

五种扩展形式是笔者当初只背下表、后来才理解用途的一组：

形式规则典型用途
${var} | 变量本身的值，未定义为空且不报错 | 基本引用，拼接与算术
${var:-hello} | 空或未定义时返回 hello，不改变 var | 参数兜默认值，避免未定义中断
${var:=hello} | 同上，并把 hello 真正赋给 var | 初始化配置项，取值同时落地
${var:?message} | 空或未定义时把 message 写标准错误并终止 | 强校验必选参数
${var:+hello} | 已定义且非空时返回 hello | 按变量是否设置标记状态

位置参数：$0 是脚本名，$1、$2 依次是参数，$# 是参数个数，$* 与 $@ 都表示全部参数，$? 取上一条命令或函数的退出状态码。数组分索引数组（下标默认从 0）与关联数组（需 Bash 4.0 及以上且必须先显式声明）：

arr=("a" "b" "c")
for i in ${arr[@]}; do echo "$i"; done
files=("one two" "three")       # 元素含空格时须用双引号包裹

7.3 条件测试：test、方括号与双方括号

test 是内置命令，不打印结果，只用退出状态码表真假：0 成立、非 0 不成立；if 判断的正是这个码。方括号是 test 的简写，[ -e ./a.sh ] 与 test -e ./a.sh 完全等价，且方括号内侧必须留空格。

类别算符
文件测试-e 存在、-f 普通文件、-d 目录、-r 可读、-w 可写、-x 可执行
字符串测试= 或 == 相等、!= 不等、-z 为空、-n 非空
整数测试-eq 等、-ne 不等、-gt 大、-lt 小、-ge 大等、-le 小等

组合用双与号（与）、双竖线（或）、感叹号（非）：

if [ $a -lt $b ] && [ $b -gt 15 ]; then echo "两个条件都成立"; fi
if [ ! $a -gt $b ]; then echo "条件取反后成立"; fi

这里有个笔者付出过代价的细节：数字比较要用 -eq 一类算符，字符串比较才用等号双写。同一等号形式在单括号里做字符串比较，若变量为空会因词法展开报错；写成 [ "$a" == "10" ] 或改用双括号才稳妥。双括号是 bash 关键字形式，不做词分割、支持正则匹配运算符 =~ 与短路逻辑，模式匹配和含空格变量都放得下：

read -p "请输入一个整数：" num
if [[ $num =~ ^[0-9]+$ ]]; then          # 整串至少一位数字
    if [ $((num % 2)) -eq 0 ]; then      # 取余判奇偶
        echo "$num 是偶数"
    else
        echo "$num 是奇数"
    fi
else
    echo "请输入有效的整数"
fi

echo 走标准输出（描述符 1），错误提示应走标准错误（描述符 2）：终端里两者都显示，重定向时互不干扰，${var:?message} 送错的正是后者。

7.4 流程控制

for 有两种写法——列表式与 C 风格三段式；case 的分支以双分号结束、* 是默认分支；while 在条件为真时持续执行，until 相反；while true 配 break 即成无限菜单，实验环节要求的正是这一组合。笔者当时踩了三个坑：某行 echo 字符串开头混入一个非法字符，不同环境下解析与显示都会出错；read -p 的提示信息引号未闭合且未指定接收变量，脚本于是卡住而非报错；until 的条件忘了引用变量，导致一次都不执行。菜单脚本（原料即为整段脚本，此处仅统一缩进）：

#!/bin/bash

while true; do
    echo "菜单:"
    echo "1. 显示当前日期和时间"
    echo "2. 显示当前工作目录"
    echo "3. 列出当前目录下的文件和文件夹"
    echo "4. 退出"
    read -p "请输入选项编号: " choice

    case $choice in
        1) date ;;
        2) pwd ;;
        3) ls ;;
        4) echo "退出菜单系统"; break ;;
        *) echo "无效的选项，请重新输入。" ;;
    esac
done

批量、累加与文件判定三段范式（原料原逻辑，参数未改）：

for i in {1..10}; do
    username=user$(printf "%02d" $i)
    useradd "$username"                                 # 批量建用户，需特权
    mkdir -p "/home/$username/data"                     # 父目录缺失时逐级创建
done

sum=0
for ((i = 1; i <= 50; i++))
do
    if [ $((i % 2)) -eq 0 ]; then
        echo $i
        sum=$((sum + i))
    fi
done
echo "1-50之间所有偶数的总和为：$sum"

echo "请输入要检查的文件路径："
read file_path
if [ -e "$file_path" ] && [ -f "$file_path" ]; then        # 存在且为普通文件
    if [ -r "$file_path" ] && [ -w "$file_path" ]; then    # 且可读可写
        new_file="${file_path}.copy"
        cp "$file_path" "$new_file"
        echo "文件内容已成功复制到 $new_file"
    else
        if [ ! -r "$file_path" ]; then echo "文件不可读"; fi
        if [ ! -w "$file_path" ]; then echo "文件不可写"; fi
    fi
else
    echo "文件不存在或不是普通文件"
fi

7.5 函数

函数是可重复调用的代码块，两种定义形式等价：function 名 { ... } 与 名() { ... }，调用只写函数名。函数内部用 $1、$2 引用传入参数，$# 是个数、$* 是全部参数，与脚本位置参数完全一致。

print_params() {
    echo "第一个参数: $1"
    echo "参数总数: $#"
}
print_params "apple" "banana"

is_even() {
    num=$1
    if [ $((num % 2)) -eq 0 ]; then return 0; else return 1; fi
}
is_even 6
result=$?
if [ $result -eq 0 ]; then echo "该数是偶数"; fi

test_scope() {
    global_var="函数外也能访问"
    local local_var="函数外访问不到"
}

return 只能回传 0 到 255 的整数，由 $? 取回，0 惯例表示成功；要回传字符串或数值结果，就让函数 echo 出来再由调用方做命令替换。函数内变量默认全局，必须 local 才限定作用域。

笔者第一次写函数脚本时报的是 Sun.sh: line 10: Sun: command not found，原因是定义名与调用名拼写不一致，Shell 便把调用当成一条命令去找。排查顺序：定义与调用是否逐字符相同、左花括号前后是否留空格、代码块是否闭合、符号是否英文半角、有漏写 Shebang。教训是 Shell 不会提示「函数未定义」，只会说「命令不存在」，见此类报错先查拼写而非环境。调试最小组合：bash -n script.sh 只查语法不执行，set -x 逐条打印实际执行的命令，再配 echo 输出关键变量。

八、文本处理三剑客与配套工具

grep "error" log.txt                 # 基本匹配
grep -i root /etc/passwd             # -i 忽略大小写
grep -n root /etc/passwd             # -n 附带行号
grep -v "success" log.txt            # -v 反向匹配，输出不含该串的行
grep -c "error" log.txt              # -c 只输出匹配行数
# 扩展正则：匹配 Henry、henry 或 Henrietta 任一形式的行，方括号是字符集合、竖线是「或」
grep -E '[Hh]enry|Henrietta' file    # -E 开启扩展正则
# 管道：前一命令的标准输出作为后一命令的标准输入
grep "error" /var/log/syslog | wc -l # 接 wc -l 统计匹配行数
cat file.txt | grep "error" | wc -l  # 多级管道同样成立

sed 's/old/new/g' file.txt           # 替换，g 为行内全部替换
sed -i 's/old/new/g' file.txt        # -i 直接写回文件
sed '/^$/d' file                     # 删除空行
sed -i "s/listen [0-9]\+;/listen $port;/" "$nginx_conf"   # 变量写进替换式

awk -F: '{print $1}' /etc/passwd             # -F 指定分隔符，取第一列
awk -F: '$3 > 1000 {print $1}' /etc/passwd   # UID 大于 1000 的用户名
awk '{sum+=$3} END {print sum}' file         # 第三列求和
free -h | awk 'NR==2{print $3}'              # 只取第二行第三列
df -h | awk '{gsub(/%/,"",$5)} $5+0 > 80 {print $1}'   # 先去掉 % 再按数值比较
awk '{ips[$1]++} END {for (ip in ips) print ip, ips[ip]}' access.log | sort -nrk2

三者的分工是：grep 选行、sed 改行、awk 切列统计。awk 里 $1、$3 指列，NR 指行号，END 块在所有行读完后执行一次；最后一条即日志分析通用范式——用关联数组按首列累加计数，END 遍历输出「键 计数」，再交 sort -nr 降序、head -10 取前十。

把这几条嵌进 while true 与 sleep 5 就是一个轮询式监控脚本：

#!/bin/bash
while true; do
    echo -e "\n系统监控："
    echo "内存使用：$(free -h | awk 'NR==2{print $3}')"
    echo "CPU负载：$(top -bn1 | grep "load average" | awk '{print $12}')"
    echo "磁盘空间：$(df -h | awk '{gsub(/%/,"",$5)} $5+0 > 80 {print $1}')"
    sleep 5
done

大量文件的清理同理靠命令而非图形界面：

ls /data/images                   # 删除前务必目视确认内容
find /data/images -type f | wc -l # 先数清个数再决定
find /data/images -type f -delete # 只删文件、保留目录

含数万文件的目录里，图形化传输工具要逐个发删除请求并同步界面，效率极低；命令行直接操作文件系统、批量清理索引，秒级完成。目录内只有待删内容时连目录一起删最快；需保留目录本身时用 find -type f -delete，比 rm 加通配更稳，不会因参数列表过长而报错。

九、定时任务：at、batch 与 crontab

三类定时是必考区分项：at 一次性任务（只执行一遍）、batch 在系统空闲且 CPU 低负载时执行单次任务（不指定时间）、crontab 周期性循环任务。

at 18:00 2025-6-10
> ls /tmp >> log
# 按 Ctrl+D 保存任务；at -l 查看排队任务；atrm 3 按编号删除
crontab -e         # 编辑定时任务
crontab -l         # 查看现有定时
crontab -r         # 删除全部定时

任务行五段依次为「分 时 日 月 周」，逐字段与取值范围见存储篇，此处只给两条最常写的表达式；星号表示该单位每一值都命中，全星号即每分钟一次：

* * * * * /usr/bin/date >> /tmp/time.log     # 每分钟追加一次时间戳
0 2 * * * /path/to/script.sh                 # 每天凌晨两点执行脚本

笔者第一次把备份脚本挂进 crontab 时，到点毫无输出，一度以为 cron 没生效。核对后落到两件事：脚本自身仍无执行权限——手工测试习惯用 bash script.sh 绕过执行位，cron 却按路径直接调用，权限不足便静默失败；任务行与脚本内部用了相对路径——cron 环境与登录 Shell 不同，路径解析到了别处。补 chmod +x 并改绝对路径后即正常，此后「可被绝对路径直接调用」成了进 cron 前的固定检查项。「配置后立即生效」的说法要谨慎：生效的是下一个匹配时刻，不补跑过去的时间点，写错一行也没有任何提示，只能靠 crontab -l 复查。

十、归档压缩与 gcc、make

gzip 只能压缩单个文件、不能打包目录；目录须先由 tar 归档再借 -z 走 gzip。tar 参数表见存储篇，此处补压缩侧与自动清理：

gzip file                    # 压缩为 file.gz，原文件被替换
gzip -d file.gz              # 解压还原
tar czvf backup_$(date +%Y%m%d).tar.gz /etc          # 打包目录并按日期命名
tar -xzvf /opt/test.tar.gz -C /home                  # 解压到指定目录，缺省为当前目录
find /backup -name "backup_*.tar.gz" -mtime +7 -delete

日期替换嵌进文件名是备份脚本日复一日运行的关键，配上按修改时间清理即成「生成—留存—过期删除」闭环；-mtime +7 是 7 天之前，-7 是 7 天以内，7 是正好 7 天，符号方向易错。

原料中 gcc 与 make 部分只留有题目与一个 Makefile 文本，但足以说明编译链与变量展开：

gcc -c my.c                      # 只编译，生成目标文件 my.o
gcc -S my.c                      # 编译到汇编，生成 my.s
gcc my.c -o myp                  # 编译并链接，生成可执行程序 myp
gcc -c c1.c c2.c
ar rcs libmyar.a c1.o c2.o       # 静态库：ar 打包，链接时代码嵌入可执行文件
gcc -c -fPIC c1.c c2.c
gcc -shared -o libmyar.so c1.o c2.o    # 共享库：位置无关码加 -shared，运行时动态加载

静态库产物 .a 由 ar 归档，共享库产物 .so 必须 -fPIC 再加 -shared，这是两条命令唯一的实质差异。原料给出的 Makefile 原文如下：

SRC = f1.c f2.c f3.c
all : libmys.so
TGT = $(SRC:.c=.o)
%.o : %.c
	cc -c $?
libmys.so : $(TGT)
	cc -shared -o $@ $(TGT)
clean :
	rm -f $(TGT)

它把若干 C 源文件编译成目标文件、链接为共享库，并提供 clean 清除目标文件。先说抄录本身：Makefile 的命令行必须以制表符开头，原料里这几行是顶格的，直接 make 会报 missing separator——上头已把 cc -c、cc -shared、rm -f 三行补回制表符，这也正是「Makefile 里空格与制表符不等价」这一考点的来源。变量展开的时序是这一组题真正想问的东西，而结论取决于用 = 还是 :=。$(SRC:.c=.o) 把 .c 后缀整体换成 .o；若 TGT = $(SRC:.c=.o) 用的是等号（递归展开式变量），赋值时只是记下右边的表达式，到引用 $(TGT) 时才求值，于是先写的 SRC = f1.c f2.c f3.c 与后追加的 SRC += f4.c 都算在内，最终得到 四个 .o、f4.o 也在其中；若写成 TGT := $(SRC:.c=.o)（立即展开式变量），赋值那一刻就完成展开，之后的 SRC += f4.c 不会回填，$(TGT) 才只有三个 .o 而 SRC 有四个 .c。两种口径在原料里被混为一谈，本文按 GNU make 实测区分：同一段脚本分别以 = 与 := 运行，输出依次为 f1.o f2.o f3.o f4.o 与 f1.o f2.o f3.o。命令里 $? 代表触发重编译的先决文件，$@ 代表当前目标名。原料未附「能否单独生成某个目标文件」这一小问的官方答案，本文只给依赖推导路径，不作结论断言。

十一、常见误区

  1. T 不是终止态：T 表示停止或被追踪；就绪与运行共用 R，D 状态卡在不可中断 I/O，kill -9 也无效。
  2. 真实 ID 不变、有效 ID 才随特殊权限改变：SUID 只影响 EUID，SGID 只影响 EGID；属主位无 s 时 EUID 仍等于 RUID。SGID 也不改变用户对文件能否读写执行的判断。
  3. s 与 t 要同时看位置和大小写：属主位的 s 是 4、属组位的 s 是 2；小写含执行权限、大写不含；类型位不参与数值计算。权限判断靠身份匹配顺序，不是取三段并集。
  4. 四个账户文件不得手工编辑，用 pwck、grpck 校验；userdel 不加 -r 只删账号、保留家目录，私有组随用户自动删除。
  5. 批量建用户没有单条命令；jobs 管会话内作业、ps 管系统进程，换终端后 jobs 必为空。
  6. kill 认 PID、killall 认名字、pkill 认模式；不带信号默认是 15 而不是 9。
  7. 赋值等号两边不能有空格、方括号内侧必须留空格、变量要加引号；数字比较用 -eq 系而非等号形式；source 与 bash 执行的差别在变量留存，不在能否运行。
  8. 函数名拼写不一致只会报 command not found；return 只能回传 0 到 255 的整数，函数内变量默认全局需 local。
  9. cron 不执行多为脚本权限与相对路径，而非 cron 故障；保存后只对下一个匹配时刻生效。
  10. gzip 不能打包目录；-mtime +7 与 -7 方向相反；Makefile 的命令行必须以制表符开头；变量是否「看到后追加的成员」取决于 = 还是 :=，不能一概说成按书写顺序求值。

十二、总结要点

进程与权限是一条因果链：程序装入内存成为进程，进程携带真实与有效两套 ID，文件上的 SUID/SGID 决定有效 ID 是否被临时替换，FACL 在三档权限之外补上单用户授权与继承，扩展属性在内核级冻结改动。作业控制与信号是同一件事的两个尺度：Ctrl+z 配 jobs、bg、fg 管本会话作业，ps、top、pgrep、kill 管全系统进程。Shell 脚本可压缩为四个动作——取值（变量与位置参数）、判定（test 算符与退出状态码）、重复（if、case、for、while、until）、复用（函数与 local）；三剑客各守一层，grep 选行、sed 改行、awk 切列统计。
