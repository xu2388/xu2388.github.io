数据结构与算法 · 树、森林与二叉树的转换

课程笔记 · 数据结构与算法

一、概述

线性表、栈和队列都只能表达“一个节点至多有一个直接前驱、一个直接后继”的关系，而文件目录、组织架构、表达式结构、决策过程都天然是分层的：一个节点可以有多个下属，下属之下还可以继续分叉。树与森林就是描述这类层次关系的抽象模型，二叉树则是其中指针操作最规整、最适合写代码的一种特例。

本笔记沿着一条主线展开：先厘清节点的度、树的度、层次、深度、高度、森林这些基础术语，避免后续公式建立在错误定义上；再说明树的三种常见存储方式，重点落在孩子兄弟表示法；随后给出树、森林与二叉树互相转换的机械规则，并从“两个指针如何装下任意多个孩子”的角度解释为什么偏偏是“左孩子、右兄弟”；在此基础上讨论遍历序列的对应关系，以及哪些遍历组合能够唯一还原一棵二叉树；最后整理二叉树的性质、完全二叉树的编号与高度、二叉排序树的查找、插入、删除和平均查找长度，并补充线索二叉树对空指针的利用。

需要先说明本笔记的约定：除非特别指出，节点的层次从 1 开始，根节点的层次为 1，树的高度等于最大层次；空树的高度记为 0，只有一个节点的树高度为 1。若采用“边数”口径，则高度会比层数口径小 1。两种口径本身没有对错，但同一道题里不能混用，这是初学阶段最常见的错误来源之一。

概念含义常见混淆点
节点的度该节点拥有的孩子个数与图论中“关联边数”的度不同
树的度所有节点度的最大值不是度的总和
叶节点度为 0 的节点也叫终端节点
分支节点度大于 0 的节点也叫非终端节点

森林若干棵互不相交的树的集合允许为空

二、树与森林的基本术语

2.1 节点的度与树的度

在树结构中，一个节点的度定义为它直接拥有的孩子数目。度为 0 的节点称为叶子，度大于 0 的节点称为分支节点。整棵树的度则是所有节点度的最大值，而不是所有节点度的和。这个区别看似细小，却直接决定了很多计数公式的写法。

考虑一棵具体的树：根节点 $A$ 有三个孩子 $B,C,D$；$B$ 有两个孩子 $E,F$；$C$ 有一个孩子 $G$；$D,E,F,G$ 都没有孩子。于是各节点的度为

$$ \deg(A)=3,\quad \deg(B)=2,\quad \deg(C)=1,\quad \deg(D)=\deg(E)=\deg(F)=\deg(G)=0. $$

整棵树的度为 $\max\{3,2,1,0,0,0,0\}=3$，节点总数 $n=7$，而所有节点的度之和为 $3+2+1+0+0+0+0=6=n-1$。这不是巧合：除根节点外，每个节点都恰好有一条边连向它的双亲，因此边的总数等于节点总数减一，而每条边又恰好贡献给双亲一个“度”。

设度为 $i$ 的节点有 $n_i$ 个，节点总数为 $n$，则有两个恒等式：

$$ n=\sum_{i\ge 0} n_i,\qquad \sum_{i\ge 0} i\,n_i=n-1. $$

把第一式代入第二式，得到

$$ n_0=1+\sum_{i\ge 2}(i-1)n_i. $$

这个公式说明：叶子数只由度为 2 及以上的节点数决定，与度为 1 的节点无关。例如一棵树中有 1 个度为 3 的节点、1 个度为 2 的节点，其余都是叶子，那么 $n_0=1+(3-1)\times 1+(2-1)\times 1=4$，与前面例子中的叶子数一致。

对于二叉树，由于度数最多为 2，公式退化为

$$ n_0=n_2+1. $$

这是二叉树最重要的一条计数关系。它与“$n=n_0+n_1+n_2$”“边数 $=n-1=n_1+2n_2$”三式联立，可以在已知部分信息时推出其余信息。例如已知一棵二叉树有 10 个度为 2 的节点，则叶节点必有 11 个，节点总数则为 $21+n_1$，其中 $n_1$ 可以是 0 或 1（完全二叉树情形）或其他非负整数（一般二叉树情形）。

2.2 层次、深度与高度

层次描述的是节点在纵向上的位置：根在第 1 层，根的孩子在第 2 层，依此类推。节点的深度就是它的层次，从根向下递增；节点的高度则是以该节点为根的子树的高度，从叶子向上递增。因此同一个节点可以“深度小、高度大”，例如根节点深度为 1，高度却等于整棵树的高度。

树的高度有两种常见口径。按层数计，只有一个节点的树高度为 1，空树高度为 0；按边数计，只有一个节点的树高度为 0，空树高度常记为 $-1$。国内数据结构教材多用层数口径，本笔记也采用这一口径。遇到题目时，先看它给出的空树高度或单节点高度，就能反推它使用哪种约定。

以前面的树为例，$A$ 在第 1 层，$B,C,D$ 在第 2 层，$E,F,G$ 在第 3 层。于是树高为 3；节点 $E$ 的深度为 3，节点 $B$ 的高度为 2（$B$ 到叶子的最长路径含 2 个节点），整棵树的高度为 3。

2.3 森林的定义

森林是 $m$ 棵互不相交的树的集合，其中 $m\ge 0$。$m=0$ 时称为空森林，$m=1$ 时森林退化为一棵树。把森林中所有树的根节点视为同一个“虚拟根”的孩子，森林就变成了一棵树；反过来，删去一棵树的根节点，它的各棵子树就构成一个森林。这个“加根”和“去根”的操作，是后面理解森林与二叉树转换的关键。

需要注意的是，森林中的树彼此不相交，指的是节点集合不相交，不能有一个节点同时属于两棵树。若只要求边集不相交而允许共享节点，那就变成了图论中的“森林图”，概念并不相同。

三、树的存储表示

3.1 双亲表示法

双亲表示法用一组连续空间存储节点，每个节点除数据外再保存一个指向双亲的下标，根节点的双亲下标记为 $-1$。这种结构最适合“找父亲”和“找根”的操作，时间复杂度为 $O(1)$；但找孩子必须扫描整个数组，复杂度为 $O(n)$。

typedef struct {
    char data;
    int parent;
} PTNode;

typedef struct {
    PTNode nodes[100];
    int n;
} PTree;

双亲表示法的优点是节省指针、结构紧凑，缺点是孩子关系被隐藏了。若在每个节点中再记录“第一个孩子”的下标，就得到“双亲加长子”的混合表示，找孩子和找父亲都能较快完成。

3.2 孩子表示法

孩子表示法把每个节点的孩子组织成一个线性表，所有节点的孩子表再组成一个数组。由于不同节点的孩子数差异很大，通常用“数组加链表”的方式：数组存放节点，每个节点挂一条孩子链表。

typedef struct ChildNode {
    int child;
    struct ChildNode *next;
} ChildNode;

typedef struct {
    char data;
    ChildNode *first;
} CTNode;

typedef struct {
    CTNode nodes[100];
    int n;
} CTree;

孩子表示法找孩子很方便，但找双亲仍需遍历所有孩子链表。若在链表中同时保存双亲下标，就能兼顾两个方向。孩子表示法本质上是把树看成“每个节点一张邻接表”，与图论中的邻接表存储同构。

3.3 孩子兄弟表示法

孩子兄弟表示法为每个节点设置两个指针：一个指向第一个孩子，另一个指向下一个兄弟。其节点结构为

typedef struct CSNode {
    char data;
    struct CSNode *firstchild;
    struct CSNode *nextsibling;
} CSNode, *CSTree;

这种表示法的妙处在于，它把“任意多个孩子”拆成了两条链：纵向的 firstchild 链负责“往下走一层”，横向的 nextsibling 链负责“在同一层里往右走”。每个节点仍然只有两个指针，于是任何树都可以被装进一个二叉树形状的结构里。这正是树与二叉树能够互相转换的存储基础。

以 $A(B(E,F),C(G),D)$ 为例，$A$ 的 firstchild 指向 $B$，$B$ 的 nextsibling 指向 $C$，$C$ 的 nextsibling 指向 $D$；$B$ 的 firstchild 指向 $E$，$E$ 的 nextsibling 指向 $F$；$C$ 的 firstchild 指向 $G$；$D,E,F,G$ 的两个指针都为空。

四、树、森林与二叉树的转换

4.1 转换规则

树转二叉树的机械规则可以概括为三步：

  1. 在所有相邻兄弟之间加一条连线；
  2. 对每个节点，只保留它与第一个孩子之间的连线，删去它与其余孩子之间的连线；
  3. 以根节点为轴，将整棵树顺时针旋转约 $45^\circ$，使原来的“第一条孩子边”变成左指针方向，“兄弟边”变成右指针方向。

转换后，原树的根就是二叉树的根；原树中每个节点的第一个孩子变成二叉树中该节点的左孩子；原树中每个节点的下一个兄弟变成二叉树中该节点的右孩子。由于根节点没有兄弟，转换得到的二叉树根节点没有右子树。

森林转二叉树时，先把森林中各棵树的根视为兄弟，在相邻根之间加连线，再按同样的规则处理。也可以想象在森林之上加一个虚拟根，把各棵树的根都变成虚拟根的孩子，转换完成后再去掉虚拟根。两种做法结果一致：第一棵树的根成为二叉树的根，其余各棵树的根依次挂在右链上。

4.2 为什么是“左孩子右兄弟”

二叉树每个节点只有两个指针，而树的节点可以有任意多个孩子。若直接把“左孩子、右孩子”照搬过来，第三个孩子就无处安放。孩子兄弟表示法换了一种编码：左指针不再表示“左孩子”，而表示“第一个孩子”；右指针不再表示“右孩子”，而表示“下一个兄弟”。这样一来，一个节点的所有孩子被组织成一条以左指针开头、沿右指针延伸的链，任意多的孩子都能容纳。

这种编码是一一对应。给定一棵树，转换得到的二叉树唯一；给定一棵由树转换而来的二叉树，把每个节点的左指针解释为“第一个孩子”、右指针解释为“下一个兄弟”，也能唯一还原原来的树。还原时，二叉树中每个节点沿右指针走到底，得到的是同一组兄弟；每组兄弟的第一个节点挂在双亲的左指针上。

需要强调的是，转换前后的“左、右”语义发生了变化。转换后的二叉树中，一个节点的右孩子并不是它在原树中的孩子，而是它的兄弟。很多错误就来自把转换后的二叉树仍按普通二叉树去理解亲子关系。

4.3 转换的互逆性

树转二叉树与二叉树转树互为逆操作。判断一个二叉树能否还原为普通树，可以看它的根是否有右子树：若根有右子树，说明它对应的是一个森林而不是单棵树；若根没有右子树，则可以还原为一棵树。

森林与二叉树之间也是双射。森林中树的棵数等于转换后二叉树根节点沿右指针链能走到的节点数。例如森林有两棵树，转换后二叉树根节点有右孩子，右孩子就是第二棵树的根。

4.4 遍历的对应关系

树的遍历有先根遍历和后根遍历两种：先根是先访问根，再依次先根遍历各棵子树；后根是先依次后根遍历各棵子树，最后访问根。树没有“中根遍历”，因为一个节点可能有多个孩子，“中间”无法唯一确定。

转换之后，遍历关系变得非常整齐：

原结构原遍历对应二叉树的遍历
树先根遍历先序遍历
树后根遍历中序遍历
森林先序遍历先序遍历
森林后序遍历中序遍历

原因可以从孩子兄弟结构看出：先根遍历先访问根，再进入第一个孩子并沿兄弟链处理，正好对应二叉树的“根、左、右”；后根遍历先把所有孩子（连同它们的兄弟链）处理完，再访问根，对应二叉树的“左、根、右”，也就是中序。

用前面的森林例子验证。森林由两棵树组成：第一棵是 $a$ 带一个孩子 $b$；第二棵是 $c$ 带两个孩子 $d$ 和 $e$，其中 $e$ 带一个孩子 $f$。森林的先序序列为

$$ a,\ b,\ c,\ d,\ e,\ f, $$

后序序列为

$$ b,\ a,\ d,\ f,\ e,\ c. $$

按孩子兄弟规则转换：$a$ 的左孩子为 $b$，右孩子为 $c$（第二棵树的根）；$c$ 的左孩子为 $d$，$d$ 的右孩子为 $e$；$e$ 的左孩子为 $f$。得到的二叉树可以写成 $a(b,\ c(d(-,\ e(f))))$。它的先序序列仍是 $a,b,c,d,e,f$，中序序列为 $b,a,d,f,e,c$，恰好等于森林的后序序列；它的后序序列为 $b,f,e,d,c,a$。这条后序序列既不等于森林的先序，也不等于森林的后序，说明“森林后序等于二叉树后序”是错误对应。

4.5 空指针的计数

一棵有 $n$ 个节点的二叉树共有 $2n$ 个指针域，其中非空指针有 $n-1$ 条（除根外每个节点被一条边指向），所以空指针总数为

$$ 2n-(n-1)=n+1. $$

在由森林转换得到的二叉树中，空指针还能对应回原结构的特征。左指针为空，说明该节点没有第一个孩子，也就是它在原森林中是叶节点。因此空左指针数等于原森林的叶节点数 $L$。右指针为空，说明该节点没有下一个兄弟，也就是它是某组兄弟中的最后一个；每组兄弟恰有一个最后者，组的数目等于“有孩子的节点数加 1”（虚拟根也算一个双亲）。因此空右指针数为

$$ (n-L)+1, $$

其中 $n-L$ 正是非叶节点数。两部分相加恰好为 $n+1$，与一般二叉树的结果一致。

以 $a(b,\ c(d(-,\ e(f))))$ 为例，节点数为 6，叶节点为 $b,d,f$ 共 3 个，于是空左指针为 3；非叶节点为 $a,c,e$ 共 3 个，空右指针为 $3+1=4$；总空指针为 7，等于 $6+1$。若把空右指针数误记成森林中树的棵数 2，就会与总数矛盾，这是原料中曾出现的计数错误，后文勘误会再次列出。

五、由遍历序列唯一确定二叉树

5.1 先序加中序

二叉树的先序序列给出“根在哪”，中序序列给出“根的左边有哪些节点、右边有哪些节点”。两者结合，就能在每一层递归地确定唯一的根和两棵子树的范围。

设先序序列为

$$ \text{pre}=A,B,D,E,C,F,G, $$

中序序列为

$$ \text{in}=D,B,E,A,F,C,G. $$

先序的第一个元素 $A$ 是根。在中序中找到 $A$，它左边是 $D,B,E$，右边是 $F,C,G$，于是左子树有 3 个节点，右子树有 3 个节点。先序中 $A$ 之后的 3 个元素 $B,D,E$ 属于左子树，剩下的 $C,F,G$ 属于右子树。

对左子树，先序首元素 $B$ 是根，中序中 $B$ 左边为 $D$、右边为 $E$，故 $B$ 的左孩子为 $D$、右孩子为 $E$。对右子树，先序首元素 $C$ 是根，中序中 $C$ 左边为 $F$、右边为 $G$，故 $C$ 的左孩子为 $F$、右孩子为 $G$。最终得到的二叉树为

$$ A\bigl(B(D,E),\ C(F,G)\bigr). $$

整个过程可以整理为下表。

步骤当前先序区间当前中序区间根左子树节点数右子树节点数
1$A,B,D,E,C,F,G$$D,B,E,A,F,C,G$$A$33
2$B,D,E$$D,B,E$$B$11
3$D$$D$$D$00
4$E$$E$$E$00
5$C,F,G$$F,C,G$$C$11
6$F$$F$$F$00
7$G$$G$$G$00

唯一性的前提是节点关键字互不相同。若允许重复关键字，中序中可能出现多个与根相同的元素，左右子树的划分不再唯一，构造结果也就不唯一。

5.2 后序加中序

后序序列的最后一个元素是根，其余逻辑与先序加中序完全对称。仍以上面的树为例，其后序序列为

$$ \text{post}=D,E,B,F,G,C,A, $$

中序序列仍为 $D,B,E,A,F,C,G$。后序末尾的 $A$ 是根，中序中 $A$ 左边 3 个、右边 3 个节点；后序中前 3 个 $D,E,B$ 属于左子树，接着 3 个 $F,G,C$ 属于右子树。对左子树，后序末尾 $B$ 是根，中序中 $B$ 左边 $D$、右边 $E$；对右子树，后序末尾 $C$ 是根，中序中 $C$ 左边 $F$、右边 $G$。结果与先序加中序一致。

先序加中序、后序加中序、层次加中序都能唯一确定一棵二叉树（关键字互异时）。它们的共同点是都含有中序，因为只有中序能够把“左、根、右”的边界切开。

5.3 先序加后序的反例

先序加后序一般不能唯一确定二叉树。最小的反例只有两个节点：

$$ \text{pre}=A,B,\qquad \text{post}=B,A. $$

第一种可能是 $A$ 只有左孩子 $B$：先序为 $A,B$，后序为 $B,A$。第二种可能是 $A$ 只有右孩子 $B$：先序仍为 $A,B$，后序仍为 $B,A$。两棵结构不同的二叉树给出了完全相同的先序和后序序列，因此仅凭这两个序列无法判断 $B$ 是左孩子还是右孩子。

反例的根源在于：先序只说明“$B$ 是 $A$ 的孩子”，后序只说明“$B$ 比 $A$ 先结束”，两者都没有说明 $B$ 位于 $A$ 的哪一侧。只有当 $A$ 有两个孩子时，先序中 $A$ 后面的第一个元素必是左子树的根，后序中 $A$ 前面的最后一个元素必是右子树的根，两个位置互相牵制，划分才被唯一确定。

由此得到结论：先序加后序能够唯一确定二叉树的充分必要条件是这棵二叉树是“正规二叉树”，即每个分支节点都恰好有两个孩子（不存在只有一个孩子的节点）。满足这一条件时，序列的递归划分唯一；不满足时，至少存在一个单孩子节点，把该孩子改到另一侧仍得到相同的先序和后序。

遍历组合是否唯一条件或反例
先序 + 中序唯一关键字互异
后序 + 中序唯一关键字互异
层次 + 中序唯一关键字互异
先序 + 后序一般不唯一单孩子节点处二义，如 pre=AB、post=BA
先序 + 后序唯一每个分支节点都有两个孩子

5.4 递归构造的实现

以先序加中序为例，递归函数接收两段下标区间：先序区间 $[pl,pr]$ 和中序区间 $[il,ir]$。先序首元素就是当前子树的根，在中序区间中定位该根的下标 $k$，则左子树节点数为 $k-il$，左子树的先序区间为 $[pl+1,pl+k-il]$，右子树的先序区间为 $[pl+k-il+1,pr]$。

typedef struct BTNode {
    char data;
    struct BTNode *lchild, *rchild;
} BTNode;

BTNode *Build(char pre[], char in[], int pl, int pr, int il, int ir) {
    if (pl > pr) return NULL;              /* 空子树 */
    BTNode *root = (BTNode *)malloc(sizeof(BTNode));
    root->data = pre[pl];
    int k = il;
    while (k <= ir && in[k] != pre[pl]) k++;   /* 在中序中定位根 */
    int leftLen = k - il;
    root->lchild = Build(pre, in, pl + 1, pl + leftLen, il, k - 1);
    root->rchild = Build(pre, in, pl + leftLen + 1, pr, k + 1, ir);
    return root;
}

若每次定位根都线性扫描中序区间，最坏情况下（树退化为链）总时间为 $O(n^2)$；若预先建立“关键字到中序下标”的哈希表，定位变为 $O(1)$，总时间降为 $O(n)$。递归深度等于树高，最坏为 $O(n)$，平均为 $O(\log n)$。

六、二叉树的性质与完全二叉树

6.1 节点数与度的关系

二叉树中每个节点最多有两个孩子，因此节点总数与度数为 0、1、2 的节点数满足

$$ n=n_0+n_1+n_2. $$

边数为 $n-1$，另一方面每条边都由一个非叶节点向下伸出，故边数又等于 $n_1+2n_2$。联立得

$$ n_0=n_2+1. $$

这三条关系是二叉树计数的基石。由此还能推出一些常用结论：若一棵二叉树有 $n$ 个节点，则空指针数为 $n+1$；若 $n$ 为奇数，则 $n_1$ 必为偶数，结合完全二叉树中 $n_1\le 1$ 可知 $n_1=0$；若 $n$ 为偶数，则 $n_1$ 必为奇数，故 $n_1=1$。

6.2 完全二叉树的编号性质

完全二叉树是把满二叉树按层序编号后，取前 $n$ 个节点得到的结构。它的形状约束很强：除最后一层外，每一层都是满的；最后一层的节点全部靠左连续排列。

若采用从 1 开始的层序编号，则对编号为 $i$ 的节点有：

关系公式适用条件
左孩子编号$2i$$2i\le n$
右孩子编号$2i+1$$2i+1\le n$
双亲编号$\lfloor i/2\rfloor$$i>1$
最后一个非叶节点$\lfloor n/2\rfloor$$n\ge 1$
叶节点编号范围$\lfloor n/2\rfloor+1$ 到 $n$$n\ge 1$

若采用从 0 开始的编号，则左孩子为 $2i+1$，右孩子为 $2i+2$，双亲为 $\lfloor (i-1)/2\rfloor$，最后一个非叶节点为 $\lfloor n/2\rfloor-1$。两种编号只差一个平移，公式不能混用。考试中若题目给出数组下标从 0 开始，却套用 $2i$ 和 $2i+1$，就会整体错位。

完全二叉树中度为 1 的节点至多一个，且只可能出现在最后一层的最左位置。由此可以推出叶节点数：

  • 当 $n$ 为偶数时，$n_1=1$，于是 $n_0=n/2$；
  • 当 $n$ 为奇数时，$n_1=0$，于是 $n_0=(n+1)/2$。

例如 $n=6$ 时叶节点为 3 个（编号 4、5、6），$n=5$ 时叶节点为 3 个（编号 3、4、5）。

6.3 高度与节点数

设完全二叉树的高度为 $h$，则前 $h-1$ 层是满的，共有 $2^{h-1}-1$ 个节点；第 $h$ 层至少有 1 个、至多有 $2^{h-1}$ 个节点。因此

$$ 2^{h-1}\le n\le 2^h-1. $$

对左边取对数得 $h-1\le \log_2 n$，对右边得 $n+1\le 2^h$，即 $\log_2(n+1)\le h$。结合 $h$ 为整数，得到

$$ h=\lfloor \log_2 n\rfloor+1=\lceil \log_2(n+1)\rceil. $$

例如 $n=1000$ 时，$2^9=512\le 1000<1024=2^{10}$，故 $h=9+1=10$。再如 $n=1$ 时 $h=1$，$n=2$ 时 $h=2$，都与直观一致。

利用高度公式还能解决“最后一层部分节点”的计数问题。设完全二叉树第 5 层有 8 个节点，则第 1 到第 4 层共有 $2^4-1=15$ 个节点，当前节点数为 $15+8=23$。第 5 层的 8 个节点最多能向下伸出 $2\times 8=16$ 个孩子，因此整棵树的最大节点数为

$$ 15+8+16=39. $$

这里容易犯的错误是把“第 5 层有 8 个节点”误当成“整棵树有 8 个节点”，或者忘记第 6 层还能补充孩子。完全二叉树的节点是“从上到下、从左到右”连续排列的，第 5 层有 8 个节点时，第 6 层可以挂在这 8 个节点之下，最多 16 个。

七、二叉排序树

7.1 定义与查找

二叉排序树（二叉搜索树，BST）或者为空，或者满足：左子树上所有节点的关键字都小于根，右子树上所有节点的关键字都大于根，且左右子树本身也是二叉排序树。这一定义是递归的，“所有节点”三个字不能漏，否则会出现“局部满足、整体不满足”的假 BST。

例如根为 50，左子树为 30（左 20、右 40），右子树为 70（左 60、右 80），这是合法的 BST。若把 55 放在 50 的右子树的左孩子的右孩子处，仍满足“比 50 大、比 60 小”，也合法；但若把 45 放在 70 的左孩子处，虽然 $45<70$，却违反了“右子树所有节点都大于 50”，因此不是 BST。

BST 的中序遍历序列严格递增（关键字互异时），这是判断一棵二叉树是否为 BST 的最简便方法，也是很多算法题的核心性质。

查找从根开始，待查关键字小于当前节点则走左子树，大于则走右子树，相等则命中，走到空指针则失败。

BTNode *Search(BTNode *t, int key) {
    while (t != NULL && t->data != key) {
        if (key < t->data) t = t->lchild;
        else t = t->rchild;
    }
    return t;                 /* 命中返回节点，失败返回 NULL */
}

查找过程中经过的节点数即为比较次数，最多等于树高。树越平衡，查找越快；树退化成单链时，查找退化为顺序查找。

7.2 插入

插入的前提是 BST 中不存在该关键字。插入过程与查找失败的过程一致：从根开始比较，小于当前节点则向左，大于则向右，直到遇到空指针，把新节点挂在该位置。

依次插入 $50,30,70,20,40,60,80$，得到的是一棵满形状的 BST：50 为根，30 和 70 为第二层，20、40、60、80 为第三层。若依次插入 $10,20,30,40$，则每次都在右链上追加，最终退化为一条单链，树高为 4，查找 40 需要 4 次比较。

插入序列决定树形，树形决定平均查找长度。这是 BST 与堆、完全二叉树的重要区别：BST 只约束中序有序，不约束形状；同样的关键字集合，不同插入顺序可以得到截然不同的树。

7.3 删除

删除分三种情况：

  1. 被删节点是叶子：直接删除，把双亲对应的指针置空。
  2. 被删节点只有一个孩子：用唯一的孩子顶替它的位置，即让双亲指向该孩子。
  3. 被删节点有两个孩子：用它的中序前驱或中序后继的关键字替换它，然后转为删除那个前驱或后继。中序后继是右子树中的最小节点，也就是右子树一路向左走到底的节点；中序前驱是左子树中的最大节点。

以 50 为根的 BST 为例，删 50 时，右子树最小节点为 60。把 60 复制到根位置，再删除原来的 60（它是叶子），得到新根 60，左子树仍为 30（20、40），右子树为 70（空、80）。删除后中序序列仍然递增。

采用中序后继的好处是“替换节点的关键字一定大于左子树全部节点、小于右子树其余节点”，BST 性质不会被破坏。若改用左子树最大节点（前驱），同样可行，但要保证实现一致，不能一半用前驱一半用后继。

7.4 平均查找长度

平均查找长度（ASL）是查找过程中比较次数的期望。对成功查找，若关键字等概率出现，则

$$ \text{ASL}_{\text{succ}}=\frac{1}{n}\sum_{i=1}^{n} d_i, $$

其中 $d_i$ 是第 $i$ 个节点在树中的层次（根为 1）。对 7 个节点的满形状 BST，第一层 1 个、第二层 2 个、第三层 4 个，于是

$$ \text{ASL}_{\text{succ}}=\frac{1\times 1+2\times 2+4\times 3}{7}=\frac{17}{7}\approx 2.43. $$

若树退化为 4 个节点的右链，则

$$ \text{ASL}_{\text{succ}}=\frac{1+2+3+4}{4}=2.5=\frac{n+1}{2}, $$

与顺序查找相同。一般情况下，随机插入构造的 BST 的平均查找长度为 $O(\log n)$，最坏为 $O(n)$。为了把最坏情况压回 $O(\log n)$，可以引入平衡机制，例如 AVL 树通过旋转维持左右子树高度差不超过 1，红黑树通过颜色约束维持近似平衡。

这里必须澄清一个常见误解：平衡二叉树并不要求必须是二叉排序树。“平衡”描述的是形状约束（左右子树高度接近），“排序”描述的是关键字约束（左小右大），两者相互独立。AVL 树是“平衡的二叉排序树”，但完全二叉树、堆也都是平衡形状的二叉树，却不是 BST。原料中“平衡二叉树一定是二叉搜索树、平衡二叉树是 BST 的子集”的说法是错误的。

八、线索二叉树

一棵有 $n$ 个节点的二叉树有 $n+1$ 个空指针。线索化就是把这些空指针利用起来，指向节点在某种遍历次序下的前驱或后继，从而在不开辟额外栈空间的情况下完成遍历。

节点中增加两个标志位：ltag=0 表示 lchild 指向左孩子，ltag=1 表示 lchild 指向前驱；rtag=0 表示 rchild 指向右孩子，rtag=1 表示 rchild 指向后继。以中序线索化为例，递归框架如下。

typedef struct ThrNode {
    char data;
    struct ThrNode *lchild, *rchild;
    int ltag, rtag;
} ThrNode;

void InThread(ThrNode *p, ThrNode **pre) {
    if (p == NULL) return;
    InThread(p->lchild, pre);          /* 递归左子树 */
    if (p->lchild == NULL) {           /* 当前节点无左孩子，建立前驱线索 */
        p->lchild = *pre;
        p->ltag = 1;
    }
    if (*pre != NULL && (*pre)->rchild == NULL) {
        (*pre)->rchild = p;            /* 前驱无右孩子，建立后继线索 */
        (*pre)->rtag = 1;
    }
    *pre = p;                          /* 前驱指针后移 */
    InThread(p->rchild, pre);          /* 递归右子树 */
}

这段代码的关键是“后继线索由前驱来建立”：访问到 $p$ 时，$p$ 的前驱 *pre 的右指针如果为空，就把它指向 $p$。原料中的写法直接把 $p$ 的右指针指向 pre，这建立的是“当前节点指向其前驱”的逆向线索，与 rtag=1 表示后继 的约定相反，会导致中序后继查找全部出错。此外，原料代码缺少 pre != NULL 的判断，在第一个节点处可能解引用空指针。

在中序线索二叉树中找后继：若 rtag=1，rchild 就是后继；若 rtag=0，后继是右子树中最左下的节点。找前驱对称：若 ltag=1，lchild 就是前驱；否则前驱是左子树中最右下的节点。线索化的时间与原遍历相同，为 $O(n)$，额外空间仅为递归栈；若改用 Morris 遍历，还能把空间降到 $O(1)$。

关于空右指针的计数，再给出一个独立验证。森林有两棵树，第一棵为 $a(b)$，第二棵为 $c(d,e(f))$，节点数 6，叶节点 $b,d,f$ 共 3 个，非叶节点 $a,c,e$ 共 3 个。按正确公式，空左指针 3 个、空右指针 4 个，合计 7 个，等于 $n+1$。若按“树的棵数”计算空右指针，只有 2 个，合计 5 个，与 $n+1=7$ 矛盾，错误立刻暴露。这个“总数校验”是检查此类计数是否可靠的有效手段。

把上述内容串起来，可以看到树、森林与二叉树并不是三种孤立结构，而是同一套“分层关系”在不同指针布局下的三种视图。孩子兄弟表示法是视图之间的转换器，遍历序列是视图之间的另一种投影，而节点计数公式则是不随视图改变的不变量。掌握这三类工具，遇到转换、还原、计数、查找的题目时，都能先判断它问的是“结构关系”“序列关系”还是“数量关系”，再选择对应的公式或算法，而不是凭印象套结论。
