大数据技术原理与应用 · 复习笔记

一、概述

Hadoop 是面向海量数据的开源分布式计算平台，其技术体系由分布式存储与分布式计算两条主线构成：HDFS 负责把大文件切块后分散存放在集群各节点，MapReduce 负责把大计算任务拆分为小任务并在多节点并行执行后汇总结果。二者共同支撑起"分而治之"的大数据处理范式，其余组件（Hive、HBase、Pig、Mahout、ZooKeeper、Flume、Sqoop、Ambari）均建立在这两大基石之上。

本笔记按"平台总体—存储层—计算层—运行环境"的顺序组织，重点掌握三类内容：HDFS 的角色分工与副本机制、MapReduce 的组件层级与调度关系、Shuffle 的分区排序归并过程。

二、核心知识点

2.1 Hadoop 的起源与特点

Hadoop 起源于全文检索工具 Lucene 面临的海量数据扩展难题。Doug Cutting 借鉴 Google 的 GFS（分布式文件系统）与 MapReduce（分布式计算模型）的设计思想，开发出开源分布式框架；2006 年他加入 Yahoo 后正式主导 Hadoop 的研发与迭代。核心框架以 Java 编写，同时支持其他语言调用。

五大核心特点：

  1. 高可靠性：默认假设节点会故障，通过多份数据副本在节点失效时自动切换数据、重新分配任务，保证服务不中断。
  2. 高扩展性：支持动态新增数千台普通服务器，存储与算力近似线性扩展。
  3. 高效性：并行计算加节点间动态负载均衡。
  4. 高容错性：副本丢失可自动重新复制，任务失败可自动重跑。
  5. 低成本：完全开源，仅依赖普通商用服务器，软硬件门槛低。

2.2 Hadoop 体系结构

自下而上分为四层：

层次组件职责
存储层HDFS分布式存储底座
计算引擎层MapReduce任务拆分、分发、并行执行（JobTracker + TaskTracker）
生态工具层Hive / Pig / Mahout / HBase / ZooKeeper数据仓库、数据流、数据挖掘、列式数据库、分布式协调
管理与接入层Ambari / Flume / Sqoop集群安装配置、日志采集、数据同步 ETL

2.3 HDFS 体系结构

HDFS（Hadoop Distributed File System）采用主从（Master/Slave）架构，集群包含 NameNode 与 DataNode 两类节点。

NameNode（主节点，默认 1 个）：元数据管家。管理文件系统命名空间（目录树、层级结构），处理客户端的创建、删除、查找等请求，维护"文件→数据块""数据块→DataNode"两类映射。只存元数据，不参与实际数据传输。早期 HDFS 只有单个 NameNode，存在单点故障：NameNode 宕机则整个 HDFS 不可用。

DataNode（从节点，多个）：数据仓库。实际存储数据块，直接响应客户端读写，执行 NameNode 下发的块创建、删除、复制指令。

三副本存放策略（默认 3 副本）：

  1. 第一副本：发起写入的客户端所在节点（客户端不在集群内则随机选择）；
  2. 第二副本：与第一副本不同机架的节点；
  3. 第三副本：与第二副本同机架、不同节点。

跨机架避免单机架故障导致副本全失，同机架利用机架内更高的传输带宽，兼顾可靠性与写入性能。该设计的前提假设是：机架内传输速度远快于跨机架传输。

心跳与块报告：DataNode 每 3 秒向 NameNode 发送一次心跳；每 10 次心跳（约 30 秒）上报一次本地全部数据块清单（块报告）。NameNode 据此更新元数据、核对副本数；长时间收不到心跳即判定节点故障，调度其他节点重新复制该节点上的块。

写数据流程：

  1. 客户端调用 open() 发起写入；
  2. 向 NameNode 申请创建文件，NameNode 校验路径重复与权限后建立元数据条目；
  3. 数据先写入客户端本地缓冲区，向 NameNode 申请首块存放节点，得到按副本策略排好的 DataNode 列表；
  4. 建立数据流管道（pipeline）：客户端把数据包发给第一个 DataNode，该节点落盘后转发给下一个，逐级复制；
  5. 确认（ack）由最后一个 DataNode 沿管道逐级回传，客户端收到全部副本确认后才发送下一个数据包；
  6. 全部块写完后调用 close()，NameNode 持久化块映射元数据，流程结束。

读数据流程：客户端 open() → 向 NameNode 请求块位置 → NameNode 返回按"距客户端由近到远"排序的 DataNode 列表 → 客户端直连最近的 DataNode 读取，逐块拼接 → 关闭数据流。

补充：默认块大小 64MB，块大小与副本数均可配置；节点间通信基于标准 TCP/IP；与 RAID 相比，HDFS 的副本跨节点、跨机架存放，容错能力远高于单机磁盘阵列。

2.4 MapReduce 体系结构（1.x）

采用主从架构，四个核心组件构成严格单向的三层结构：

Client → JobTracker → TaskTracker → Task
  • Client：作业提交入口。把用户代码与配置打包为 JAR 提交给 JobTracker，JAR 同时存入 HDFS 供各节点下载；可查询状态、终止作业。只与 JobTracker 交互。
  • JobTracker（Master，全集群唯一）：资源监控与作业调度中心。拆分 Job 为若干 Map Task 与 Reduce Task；接收 TaskTracker 心跳；通过可插拔的任务调度器（Task Scheduler）按空闲资源与优先级派发任务；任务失败或节点宕机时重新调度。
  • TaskTracker（Slave，每台工作节点 1 个）：单节点管理者。周期性心跳上报资源使用率与任务进度，接收指令启动或杀死任务。用 slot（槽位） 量化计算资源，分 Map slot 与 Reduce slot，互不通用，一个 Task 占用一个 slot，slot 总数决定单节点并行上限。
  • Task：最小执行单元，分 Map Task 与 Reduce Task，由本节点 TaskTracker 直接管理。

关键区分：block 是 HDFS 的物理存储单位（定长切块），split 是 MapReduce 的逻辑切分单位（只记录起始位置、长度、节点信息，不存数据），一个 split 对应一个 Map Task，一个分区对应一个 Reduce Task。

2.5 Map Task 与 Reduce Task 执行过程

Map Task：InputFormat 读取 split 并解析为 <k1,v1> → 调用 map() 输出 <k2,v2> → partition 按 key 分区 → 写入本地磁盘（不写 HDFS）。

Reduce Task：Shuffle（拉取各自分区的数据）→ Sort（按 key 归并排序，聚成 <k2, Iterable<v2>>）→ reduce() 聚合 → OutputFormat 写入 HDFS，每个 Reduce Task 产生一个 part-r-xxxxx 文件。

2.6 Shuffle 全流程

Shuffle 的范围是 map 输出结束到 reduce 函数开始之前，包含 Map 端本地处理、跨节点拷贝、Reduce 端归并三部分，并非只有网络传输。

Map 端：

  1. map() 输出先写入内存环形缓冲区（默认 100MB），减少磁盘 I/O；
  2. 达到阈值（默认 80%）触发溢写（spill），溢写前先分区（按 key 与 Reduce 数计算分区号，保证同 key 进同一 Reduce）再排序（分区内按 key 字典序）；
  3. 多次溢写产生多个临时文件，Map Task 结束前归并（merge）为一个按分区划分、分区内全局有序的大文件，存于 Map 节点本地磁盘。

中间环节：Reduce Task 启动 fetch 线程，从所有 Map 节点拉取属于自己分区的数据，这是 Shuffle 中网络开销最大的步骤。

Reduce 端：

  1. Copy：拉取的数据优先放内存，放不下则溢写磁盘；
  2. Sort：边拉取边归并，把多个有序小文件合并为全局有序的大文件，相同 key 的 value 自然连续，形成 <key, value 列表>；
  3. Reduce：把 <key, Iterable<value>> 交给 reduce() 聚合，结果写入 HDFS。

Shuffle 解决四个问题：分区决定"数据去哪个 Reduce"，拷贝解决"跨节点汇聚"，排序归并解决"全局有序"，分组解决"同 key 的 value 聚在一起"。

2.7 完整作业流程

  1. 提交：Client 打包 JAR 提交 JobTracker，原始数据已在 HDFS；
  2. 拆分：JobTracker 将作业拆为若干 Map/Reduce Task；
  3. 心跳：各 TaskTracker 周期上报空闲 slot 与任务进度；
  4. 分配：JobTracker 按空闲资源派发任务；
  5. 执行：TaskTracker 下载 JAR，在本机启动 Task 进程并监控；
  6. 同步：进度随心跳上报，JobTracker 更新作业状态；
  7. 容错：任务失败或 TaskTracker 宕机，JobTracker 重新分配；
  8. 完成：全部任务成功，标记作业完成，结果已在 HDFS，Client 可查询。

特殊情况：job.setNumReduceTasks(0) 时跳过 Shuffle 与 Reduce，Map 输出直接写 HDFS，适用于纯过滤、无需聚合的场景；但 Map 输出格式仍必须是键值对（无 value 时可用 NullWritable）。

2.8 WordCount 示例

输入三行文本：

Deer Bear River
Car Car River
Deer Car Bear

流程为 Input → Split → Map → Shuffle → Reduce → Output：每个 split 启动一个 Map Task，逐词输出 <单词,1>；Shuffle 把相同单词汇聚到同一 Reduce 并整理为 <单词,[1,1,...]>；Reduce 累加得到 <Car,3>、<Deer,2>、<Bear,2>、<River,2>，写回 HDFS。

WordCount 的业务规模很小，选用它是因为逻辑极简，可让学习者专注分布式运行机制；它是 MapReduce 的"HelloWorld"，真实场景的输入是几十 GB 至 TB 级日志。

2.9 运行环境与常用命令

大数据技术栈基于 Linux 部署，原因是服务器场景下的高稳定性、高性能、开源免费，以及完善的命令行与脚本生态、对分布式框架的原生支持。

# 列出 HDFS 根目录
hdfs dfs -ls /
# 递归列出全部目录与文件
hdfs dfs -ls -R /
# 查看 HAR 归档包内部文件
hdfs dfs -ls -har hdfs:///path/xxx.har

修改 NameNode 访问地址（core-site.xml）：

<property>
    <name>fs.defaultFS</name>
    <value>hdfs://Master:8088</value>
</property>

若题目要求修改的是 Web UI 端口，应改 dfs.http.address；注意 8088 本是 YARN ResourceManager 的默认端口。

2.10 易错点

  1. Shuffle 不等于网络拷贝，Map 端分区、排序、溢写、合并与 Reduce 端归并都属于 Shuffle。
  2. NameNode 只传元数据，真实数据由客户端与 DataNode 直接传输。
  3. block 是物理存储单位，split 是逻辑划分单位，二者不要混用。
  4. 副本 2 与副本 3 同机架但不同节点，不是同一节点。
  5. Map 输出必须是 <key,value>，因为分区、排序、分组全部依赖 key。
  6. HDFS 适合一次写入多次读取的大文件，不适合大量小文件与低延迟随机写。

三、典型例题或关键问答

例 1（填空） Hadoop 最核心的两大组件是 ______ 和 ______。 答：HDFS、MapReduce。

例 2（填空） HBase 是 ______ 式列数据库。 答：分布式。

例 3（填空） MapReduce 体系结构由 ______、______、______、______ 四部分组成。 答：Client、JobTracker、TaskTracker、Task。

例 4（判断） HDFS 可以在廉价服务器频繁故障的条件下可靠存储数据。（√） 解析：多副本机制正是为此设计。

例 5（判断） HFile 由不定长数据块组成。（×） 解析：HFile 由固定大小的数据块与块索引组成。

例 6（判断） Hive 有专属的数据存储格式。（×） 解析：Hive 支持 TextFile、SequenceFile、ORC、Parquet 等通用格式，本身不定义专属格式。

例 7（填空） HDFS 全集群共享 ______ 的文件命名空间；数据具有 ______ 特性；大文件被 ______ 分散存储。 答：唯一；冗余（多副本）；切分为固定大小 block。

例 8（填空） Master 节点上运行的两个核心进程是 ______ 与 ______，可用 jps 查看。 答：NameNode、SecondaryNameNode（后者辅助完成元数据检查点，合并 fsimage 与 edits）。

例 9（简答） 简述 HDFS 复制文件块的管道流程。 答：客户端向 NameNode 申请写入并创建元数据 → NameNode 返回副本节点列表 → 客户端建立管道，把数据包发给第一个 DataNode → 该节点落盘并转发下一节点，逐级复制 → ack 由末节点逐级回传 → 客户端收到全部确认后发送下一包 → 全部写完 close()，NameNode 持久化元数据。三副本分别位于客户端节点、不同机架节点、与副本 2 同机架的不同节点。

例 10（简答） 简述 MapReduce 的完整运行流程。 答：作业提交（Client 打包 JAR 至 HDFS 并提交 JobTracker）→ 全局调度（拆分 Map/Reduce Task，按心跳上报的空闲 slot 派发）→ Map 并行计算（InputFormat 解析 → map() → partition → 溢写排序 → 本地有序文件）→ Shuffle（Copy 拉取 + Sort 归并分组）→ Reduce 聚合（reduce() → OutputFormat 写 HDFS）→ JobTracker 标记作业完成。

四、小结

Hadoop 以"廉价机器 + 多副本 + 并行计算"实现高可靠、高扩展、高容错、低成本的大数据处理。HDFS 用 NameNode 管元数据、DataNode 存数据块、三副本跨机架保可靠、心跳与块报告保可运维；MapReduce 用 JobTracker 统一调度、TaskTracker 分节点执行、slot 量化资源，并以 Shuffle 完成"按 key 分拣、汇聚、排序、分组"的关键衔接。理解"谁是主、谁是从、数据在哪、按什么规则流动"这四条线索，即可串起全部考点。
