数据结构与算法 · 排序与查找方法对比

课程笔记 · 数据结构与算法 · 整理自豆包对话 豆包对话 · 快速排序中间元素枢轴 / 堆的插入和删除操作 / 大根堆构建步骤讲解 / 折半查找判定树高度计算及说明

一、概述

排序与查找是数据结构课程里最容易“背了表格却不会做题”的两章。原因通常不是算法本身复杂，而是几个关键量没有分清：比较次数与移动次数、平均情况与最坏情况、时间复杂度与空间复杂度、稳定性与有序性。把这些量分开记录，再放到具体数据上走一遍，表格才会变成可用的工具。

本笔记先给出八种内部排序的总表，再按插入、交换、选择、归并、基数五类逐一说明机制和典型步骤；快速排序部分重点讨论枢轴选择为什么会影响最坏情况，以及“取中间元素”到底解决了什么问题、又没有解决什么问题；堆部分完整走一遍建堆、插入、删除和堆排序；查找部分从折半查找判定树推出高度与平均查找长度，再补充分块查找和散列表，并比较散列表与折半查找的适用边界。

约定：排序一律按关键字非递减排列；讨论比较排序时，关键字互异，稳定性用相等关键字的相对次序是否改变来判断；平均查找长度按等概率计算。

二、排序算法总览

2.1 八种排序的分类

按工作机制，八种常用内部排序可以分成五类：

类别算法核心动作
插入类直接插入、折半插入、希尔把待排元素插入已排好的前缀
交换类冒泡、快速通过交换把逆序对消除
选择类简单选择、堆每趟选出当前最小或最大元素
归并类二路归并合并两个有序子序列
分配类基数按位分配到桶再收集

插入类维持“前缀有序”，交换类维持“局部有序并逐步扩大”，选择类维持“前缀已定稿”，归并类维持“若干有序段”，基数类则完全不做关键字比较。理解每种算法维持的不变量，比背代码更能应对变体题。

2.2 复杂度与稳定性总表

设元素个数为 $n$，基数排序的关键字位数为 $d$、每位的基数为 $r$（十进制时 $r=10$）。八种排序的对比如下。

这张表里有几个容易被忽略的细节。

第一，折半插入只减少比较次数，不减少移动次数。插入位置用折半查找确定后，仍然要把该位置之后的元素整体后移，所以总时间仍是 $O(n^2)$。把折半插入的时间复杂度写成 $O(n\log n)$ 是典型错误。

第二，希尔排序的时间复杂度依赖增量序列。采用 Shell 原始增量 $n/2,n/4,\dots,1$ 时，最坏可到 $O(n^2)$；采用 Hibbard 增量 $2^k-1$ 时可到 $O(n^{3/2})$。因此表中只能写“与增量有关”，不能给出一个固定的平均阶。

第三，堆排序的“建堆 $O(n)$”与“排序 $O(n\log n)$”要分开。建堆只需要从最后一个非叶节点向前逐个下沉，总代价是线性的；真正 $O(n\log n)$ 来自 $n-1$ 次“取堆顶并下沉”。

第四，归并排序的比较次数约为 $n\log_2 n-n+1$，这是比较排序在下界附近的常数级结论，不是 $n\log_2 n$ 的精确等号。实际比较次数与两个子序列的分布有关。

2.3 稳定性为什么重要

稳定性指排序前后关键字相等的元素相对次序不变。单看一个整数数组，稳定性似乎无关紧要；但在实际数据中，元素往往带有多个字段，排序只按其中一个字段进行，稳定性就决定了其他字段的次序是否被保留。

例如一批学生记录先按姓名排好，再按成绩排序。若成绩排序稳定，同分学生仍保持姓名的字典序；若不稳定，同分学生的姓名次序就被打乱，需要再排一次。这就是“多关键字排序”中常说的“从次要关键字到主要关键字依次稳定排序”。

判断稳定性可以从交换距离入手：只在相邻元素之间交换的算法（插入、冒泡）通常稳定；会跨越多个位置交换的算法（选择、快速、堆、希尔）通常不稳定；归并只要在合并时“相等取左边”就稳定；基数排序依赖每一位的稳定收集，因此本身必须稳定。

三、插入类排序

3.1 直接插入排序

直接插入排序把序列分成“已排好的前缀”和“未处理的后缀”。每趟取出后缀的第一个元素，在前缀中从后向前比较，比它大的元素依次后移，直到找到不大于它的位置并插入。

对序列 $5,2,4,6,1,3$ 的执行过程如下。

趟次待插入元素插入后的前缀说明
初始—$5$单个元素视为有序
1$2$$2,5$$5$ 后移
2$4$$2,4,5$$5$ 后移，$4$ 放在 $2$ 后
3$6$$2,4,5,6$不需移动
4$1$$1,2,4,5,6$四个元素全部后移
5$3$$1,2,3,4,5,6$$4,5,6$ 后移

最好情况是原序列已经有序，每趟只比较一次、移动零次，总比较 $n-1$ 次，时间 $O(n)$；最坏情况是原序列逆序，第 $i$ 趟比较 $i$ 次、移动 $i$ 次，总比较与总移动均为 $n(n-1)/2$，时间 $O(n^2)$。平均情况下约有一半元素需要后移，仍是 $O(n^2)$。

直接插入排序的优点是实现简单、常数小、对近乎有序的数据非常快，而且稳定。它也是希尔排序和某些快速排序小数组优化（如长度小于阈值时改用插入排序）的基础。

3.2 折半插入排序

折半插入排序把“在前缀中找插入位置”的过程从线性扫描改成折半查找。由于前缀已经有序，可以在 $O(\log i)$ 次比较内确定位置，但确定位置后仍要移动元素。

void BinaryInsertSort(int a[], int n) {
    for (int i = 1; i < n; i++) {
        int key = a[i];
        int low = 0, high = i - 1;
        while (low <= high) {              /* 找第一个大于 key 的位置 */
            int mid = (low + high) / 2;
            if (a[mid] <= key) low = mid + 1;
            else high = mid - 1;
        }
        for (int j = i - 1; j >= low; j--) a[j + 1] = a[j];
        a[low] = key;
    }
}

循环条件写成 a[mid] <= key 时，low 最终停在第一个大于 key 的位置，相等元素不会被越过，因此排序稳定。若写成 a[mid] < key，low 会停在第一个大于等于 key 的位置，相等元素被插到原相等元素之前，稳定性被破坏。稳定性不仅取决于算法思想，也取决于比较符号的细节。

折半插入的比较次数从 $O(n^2)$ 降到 $O(n\log n)$，但移动次数仍是 $O(n^2)$，所以总时间仍为 $O(n^2)$。它适合元素比较大、比较代价高于移动代价的场景。

3.3 希尔排序

希尔排序把序列按增量 $d$ 分成若干组，对每组做直接插入排序，然后缩小增量，直到 $d=1$。增量大于 1 时，元素可以一次跨过较远距离，快速减少逆序对；最后一趟 $d=1$ 时序列已经“基本有序”，插入排序的移动量很小。

以 $n=8$、增量取 $4,2,1$ 为例，序列为 $49,38,65,97,76,13,27,49'$（最后的 $49'$ 与前面的 $49$ 关键字相等，用来观察稳定性）。

第一趟 $d=4$，分组为 $(49,76)$、$(38,13)$、$(65,27)$、$(97,49')$，组内插入后得到 $49,13,27,49',76,38,65,97$。第二趟 $d=2$，分组为 $(49,27,76,65)$ 和 $(13,49',38,97)$，组内插入后得到 $27,13,49,38,65,49',76,97$。第三趟 $d=1$，整体插入排序得到 $13,27,38,49,49',65,76,97$。

观察两个 $49$：初始时 $49$ 在 $49'$ 之前，最终 $49$ 仍在 $49'$ 之前，这个例子恰好保持了次序。但希尔排序一般不稳定，因为不同组的元素可能跨组交换，相等元素的前后关系无法保证。例如在某些增量序列下，后面的相等元素可能被先移动到前面。判断稳定性不能只看一个例子，要看是否存在跨组交换破坏次序的可能。

希尔排序的性能与增量序列强相关。增量序列的最后一个必须是 1，否则不能保证整体有序；增量之间最好互质，避免同一元素被反复分到同一组而做无用功。Shell 原始序列简单但最坏 $O(n^2)$，Hibbard 序列、Sedgewick 序列能取得更好的理论界。

四、交换类排序

4.1 冒泡排序

冒泡排序反复比较相邻元素，逆序就交换。每一趟把当前未定稿部分的最大元素“冒”到末尾。若某一趟没有发生任何交换，说明序列已经有序，可以提前结束。

void BubbleSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int swapped = 0;
        for (int j = 0; j < n - 1 - i; j++) {
            if (a[j] > a[j + 1]) {
                int t = a[j]; a[j] = a[j + 1]; a[j + 1] = t;
                swapped = 1;
            }
        }
        if (!swapped) break;
    }
}

比较符号用 > 而不是 >=，相等元素不交换，因此冒泡排序稳定。最坏情况是逆序，比较次数为

$$ \sum_{i=1}^{n-1}(n-i)=\frac{n(n-1)}{2}, $$

交换次数同样为 $n(n-1)/2$。最好情况是已经有序，第一趟比较 $n-1$ 次、交换 0 次，随后因 swapped=0 退出，时间 $O(n)$。若去掉标志位，最好情况也要跑满 $n-1$ 趟，退化为 $O(n^2)$。

4.2 快速排序的划分机制

快速排序选一个枢轴，把序列划分成“不大于枢轴”和“不小于枢轴”两部分，再递归处理两部分。划分是整个算法的核心，常见写法有挖坑法、Hoare 双指针法、Lomuto 单指针法。下面采用 Hoare 双指针法，并把枢轴取在中间位置。

void QuickSort(int a[], int low, int high) {
    if (low >= high) return;
    int i = low, j = high;
    int pivot = a[(low + high) / 2];   /* 取中间元素的值作为枢轴 */
    while (i <= j) {
        while (a[i] < pivot) i++;      /* 从左找不小于枢轴的元素 */
        while (a[j] > pivot) j--;      /* 从右找不大于枢轴的元素 */
        if (i <= j) {
            int t = a[i]; a[i] = a[j]; a[j] = t;
            i++; j--;
        }
    }
    QuickSort(a, low, j);
    QuickSort(a, i, high);
}

这段代码有几个要点。枢轴保存的是“值”而不是“下标”，因为交换过程中枢轴元素本身可能被换走，若保存下标再去访问，可能读到已经被换走的值。外层循环条件是 i <= j，内层两个 while 不带等号，遇到与枢轴相等的元素就停下来交换，这样相等元素会被分散到两侧，避免所有相等元素集中到一边导致划分退化。递归区间是 $[low,j]$ 和 $[i,high]$，划分结束后 $j<i$，两个区间不重叠且覆盖除枢轴外的所有元素。

对序列 $5,2,9,4,7,6,1,3$ 走一遍首趟划分。中间下标为 $(0+7)/2=3$，枢轴值为 $4$。

步骤$i$$j$数组状态动作
初始07$5,2,9,4,7,6,1,3$枢轴 $4$
107$3,2,9,4,7,6,1,5$$5$ 与 $3$ 交换，$i=1,j=6$
226$3,2,1,4,7,6,9,5$$9$ 与 $1$ 交换，$i=3,j=5$
333$3,2,1,4,7,6,9,5$$4$ 与自身交换，$i=4,j=2$

首趟结束后左段为 $3,2,1$，右段为 $7,6,9,5$，枢轴 $4$ 落在最终位置。左段递归后变为 $1,2,3$；右段以 $6$ 为枢轴划分后变为 $5,6,9,7$，再递归得到 $5,6,7,9$。最终序列为 $1,2,3,4,5,6,7,9$。

4.3 枢轴选择与最坏情况

枢轴选择直接决定划分是否均衡。常见策略有以下几种。

策略做法优点风险
取首元素以 $a[low]$ 为枢轴实现最简单有序或逆序输入退化为 $O(n^2)$
取尾元素以 $a[high]$ 为枢轴与首元素对称同样怕有序输入
取中间元素以 $a[(low+high)/2]$ 为枢轴有序输入也能均分仍可构造最坏输入
随机枢轴随机选一个下标再交换到端点期望 $O(n\log n)$，不怕固定输入随机数有开销，仍可能极坏
三数取中取首、中、尾的中位数降低坏划分概率，常数小仍有针对性的“杀手序列”

“取中间元素”常被误解为“保证 $O(n\log n)$”。它解决的是“输入已经有序或逆序时，首元素枢轴每次划分都极不均衡”这一常见退化，但并没有改变快速排序的最坏情况。只要能够构造出“每次中间位置的元素恰好是当前区间的最小值或最大值”的输入，划分仍会退化成 $1$ 与 $n-1$，递归深度达到 $n$，总比较次数为

$$ (n-1)+(n-2)+\cdots+1=\frac{n(n-1)}{2}=O(n^2). $$

因此正确的表述是：中间元素枢轴改善了常见输入下的划分均衡性，降低了最坏情况出现的概率，但最坏时间复杂度仍是 $O(n^2)$。若要求最坏情况也稳定在 $O(n\log n)$，需要改用堆排序、归并排序，或使用能保证划分比例的选择算法（如中位数的中位数）来选枢轴。

快速排序的空间开销来自递归栈。平均划分下递归深度为 $O(\log n)$，最坏划分下为 $O(n)$。可以先递归较短的一侧、把较长的一侧用循环处理，把栈深度压到 $O(\log n)$，这是工程实现中的常用优化。

五、选择类排序

5.1 简单选择排序

简单选择排序每趟在未定稿区间中找最小元素，与区间首元素交换。无论输入如何，第 $i$ 趟都要扫描剩余 $n-i$ 个元素，因此比较次数恒为

$$ \sum_{i=1}^{n-1}(n-i)=\frac{n(n-1)}{2}, $$

时间复杂度恒为 $O(n^2)$，没有最好与最坏之分。移动次数很少，最多 $n-1$ 次交换，适合元素移动代价远高于比较代价的场景。

简单选择排序不稳定。例子：序列 $2a,2b,1$，第一趟找到最小值 $1$，与首元素 $2a$ 交换，得到 $1,2b,2a$，两个相等元素的相对次序被改变。不稳定的根源是交换跨越了多个位置，可能把后面的相等元素甩到前面。

5.2 大根堆的定义与存储

堆是一棵完全二叉树，且每个节点的关键字都不小于（大根堆）或不大于（小根堆）其孩子。堆只约束“双亲与孩子”之间的大小关系，不约束兄弟之间，也不约束左右子树的整体大小，因此堆不是二叉排序树。这一点在判断“某结构是否为堆”时非常关键：只要双亲不小于孩子即可，兄弟谁大谁小都合法。

堆通常用数组存储。采用 0 起下标时，下标 $i$ 的左孩子为 $2i+1$，右孩子为 $2i+2$，双亲为 $\lfloor (i-1)/2\rfloor$；最后一个非叶节点为 $\lfloor n/2\rfloor-1$。采用 1 起下标时，孩子为 $2i$ 和 $2i+1$，双亲为 $\lfloor i/2\rfloor$，最后一个非叶节点为 $\lfloor n/2\rfloor$。两种公式不能混用。

5.3 建堆

建堆从最后一个非叶节点开始，向前逐个下沉。对每个节点，比较它与两个孩子，若孩子更大就与较大的孩子交换，然后继续向下检查，直到满足堆性质或到达叶子。

以序列 $6,1,5,9,8,4,7$ 为例，$n=7$，最后一个非叶节点下标为 $\lfloor 7/2\rfloor-1=2$。

步骤处理节点操作数组状态
初始——$6,1,5,9,8,4,7$
1下标 2，值 5孩子 4、7，与 7 交换$6,1,7,9,8,4,5$
2下标 1，值 1孩子 9、8，与 9 交换$6,9,7,1,8,4,5$
3下标 0，值 6孩子 9、7，与 9 交换$9,6,7,1,8,4,5$
4下标 1，值 6孩子 1、8，与 8 交换$9,8,7,1,6,4,5$

最终得到大根堆 $9,8,7,1,6,4,5$。第 3 步交换后，下标 1 的子树可能被破坏，所以第 4 步要继续下沉；这正是“下沉要一直走到叶子或满足堆性质”的原因。

建堆的总时间不是 $O(n\log n)$。直观上，越靠近底层的节点越多，但它们能下沉的高度越小；把“节点数 × 可下沉高度”求和，得到

$$ \sum_{h=0}^{\lfloor\log_2 n\rfloor} \frac{n}{2^{h+1}}\,h < n\sum_{h\ge 0}\frac{h}{2^{h+1}}=n, $$

因此建堆是 $O(n)$。若改用“逐个插入并上浮”的方式建堆，每个元素最多上浮 $O(\log n)$，总时间才是 $O(n\log n)$。两者结果都是合法堆，但代价不同。

5.4 插入与删除

插入：把新元素放到数组末尾，然后与双亲比较，若大于双亲就交换，直到满足堆性质。上浮最多走一条从叶到根的路径，时间 $O(\log n)$。

以 $50,30,20,15,10$ 为例插入 $40$。先把 $40$ 放到下标 5，数组变为 $50,30,20,15,10,40$；其双亲下标为 $2$，值为 $20$，$40>20$，交换得到 $50,30,40,15,10,20$；再看下标 2 的双亲下标 0，值为 $50$，$40<50$，停止。最终数组为 $50,30,40,15,10,20$。

删除堆顶：把最后一个元素移到堆顶，堆长度减一，然后从堆顶下沉。以 $50,30,40,15,10,20$ 删除 $50$ 为例，把末尾的 $20$ 移到堆顶，得到 $20,30,40,15,10$；下标 0 的孩子为 $30$ 和 $40$，与较大的 $40$ 交换，得到 $40,30,20,15,10$；下标 2 已无孩子，停止。最终数组为 $40,30,20,15,10$。

删除任意元素时，先用末尾元素顶替，再根据它与双亲、孩子的关系决定上浮还是下沉；若只删除堆顶，则只需下沉。堆的插入和删除都只沿一条路径移动，因此都是 $O(\log n)$。

5.5 堆排序

堆排序分两阶段：先把数组建成大根堆，再反复把堆顶（当前最大值）与未定稿区间的末尾交换，缩小堆的范围并对新堆顶下沉。由于最大值被依次放到末尾，最终得到升序序列。

对已建好的大根堆 $9,8,7,1,6,4,5$ 执行堆排序，过程如下。

趟次交换下沉后已定稿后缀
1$9$ 与 $5$ 交换$8,6,7,1,5,4$$9$
2$8$ 与 $4$ 交换$7,6,4,1,5$$8,9$
3$7$ 与 $5$ 交换$6,5,4,1$$7,8,9$
4$6$ 与 $1$ 交换$5,1,4$$6,7,8,9$
5$5$ 与 $4$ 交换$4,1$$5,6,7,8,9$
6$4$ 与 $1$ 交换$1$$4,5,6,7,8,9$

以第 1 趟为例，交换后数组为 $5,8,7,1,6,4,9$，对下标 0 下沉：孩子 $8,7$，与 $8$ 交换得 $8,5,7,1,6,4,9$；下标 1 的孩子 $1,6$，与 $6$ 交换得 $8,6,7,1,5,4,9$。后续各趟同理，每次下沉最多 $O(\log n)$，共 $n-1$ 趟，总时间 $O(n\log n)$。

堆排序的优点是原地、最坏也能保证 $O(n\log n)$，适合内存紧张且不能接受快速排序最坏情况的场景。缺点是常数较大、不稳定、不能提前终止，而且对缓存不友好。

六、归并排序与基数排序

6.1 二路归并排序

归并排序把序列不断二分，直到每个子序列只有一个元素，再两两合并有序子序列。合并时用两个指针分别扫描左右两段，每次取较小者放入辅助数组；若相等，优先取左边，从而保持稳定。

对 $5,2,4,6,1,3$ 的归并过程：

阶段有序段
初始$5 \mid 2 \mid 4 \mid 6 \mid 1 \mid 3$
第一趟$2,5 \mid 4,6 \mid 1,3$
第二趟$2,4,5,6 \mid 1,3$
第三趟$1,2,3,4,5,6$

归并排序的最好、平均、最坏时间都是 $O(n\log n)$，递归深度为 $O(\log n)$，辅助数组需要 $O(n)$ 空间。若对链表排序，合并过程只改指针，不需要额外数组，空间可降为 $O(1)$（不计递归栈）。

归并排序的稳定性来自“相等取左”。若写成“相等取右”，相等元素的相对次序就会反转。此外，归并排序适合外部排序：数据量大于内存时，先把每块读入内存排序成顺串，再多路归并，这也是磁盘排序的常用框架。

6.2 基数排序

基数排序按关键字的每一位分配和收集。以十进制整数为例，准备 10 个队列，从最低位（个位）开始，依次把元素放入对应数字的队列，再按队列顺序收集；然后处理十位、百位，直到最高位。这种方法称为最低位优先（LSD）。

对 $170,45,75,90,2,24,802,66$ 按个位分配：

队列0123456789
个位$170,90$—$2,802$—$24$$45,75$$66$———

按 0 到 9 收集得到 $170,90,2,802,24,45,75,66$。再按十位分配、收集，最后按百位分配、收集，得到有序序列 $2,24,45,66,75,90,170,802$。

基数排序的时间为 $O(d(n+r))$，其中 $d$ 是位数、$r$ 是基数（十进制为 10），空间为 $O(n+r)$。它不做关键字比较，因此不受比较排序 $\Omega(n\log n)$ 下界的限制；但前提是关键字可以按位分解，且位数 $d$ 不能太大。若关键字是浮点数或字符串，需要先设计可分解的编码。

基数排序必须稳定。每一趟收集依赖“同一队列内先放入的元素先取出”，若某趟不稳定，之前低位排好的次序就会被破坏，最终结果错误。因此“基数排序稳定”不是附带优点，而是算法正确性的前提。

七、查找方法

7.1 顺序查找

顺序查找从表的一端逐个比较，直到命中或走到表尾。最好情况比较 1 次，最坏 $n$ 次，等概率成功时

$$ \text{ASL}_{\text{succ}}=\frac{1+2+\cdots+n}{n}=\frac{n+1}{2}. $$

顺序查找不要求有序，也不要求连续存储，链表也能用；缺点是 $O(n)$。它适合小表、无序表或频繁插入删除而不便维护有序性的场景。

7.2 折半查找与判定树

折半查找要求表有序且可以随机访问（通常是顺序表）。每次取中间位置比较，相等则命中，小于则去左半区，大于则去右半区。

折半查找的过程可以用一棵判定树表示：每个内部节点对应一个参与比较的元素，节点的左子树对应左半区，右子树对应右半区，空指针对应查找失败的区间。判定树是一棵平衡的二叉排序树，中序序列就是原有序表。

设表长为 $n$，判定树的高度为

$$ h=\lfloor\log_2 n\rfloor+1=\lceil\log_2(n+1)\rceil. $$

因此折半查找的最多比较次数为 $O(\log n)$。这个高度公式与完全二叉树的高度公式形式相同，但判定树不一定是一棵完全二叉树，只是它的节点分布满足“左右子树规模尽量均衡”。

以 $n=11$、关键字 $1$ 到 $11$、取 $\text{mid}=\lfloor(\text{low}+\text{high})/2\rfloor$ 为例，判定树如下：根为 $6$；第二层为 $3,9$；第三层为 $1,5,7,11$；第四层为 $2,4,8,10$。

成功查找的比较次数等于节点所在层次，故

$$ \text{ASL}_{\text{succ}}=\frac{1\times 1+2\times 2+4\times 3+4\times 4}{11}=\frac{33}{11}=3. $$

查找失败时，比较发生在内部节点上，走到空指针那一步不再比较关键字。失败区间对应 12 个外部节点：其中 4 个挂在第三层节点下，失败比较次数为 3；8 个挂在第四层节点下，失败比较次数为 4。于是

$$ \text{ASL}_{\text{fail}}=\frac{4\times 3+8\times 4}{12}=\frac{44}{12}\approx 3.67. $$

若把“最后探测到空指针”也算一次比较，则每个外部节点再加 1，得到 $(4\times 4+8\times 5)/12=56/12\approx 4.67$。两种口径只差最后一次空指针检查，答题时应先看题目对“比较次数”的定义。原料中给出的失败分布“2 个 2 次、4 个 3 次、6 个 4 次”在结构上不可能出现：一棵有 11 个内部节点的判定树只有 12 个外部节点，且其分布由树的形状唯一决定，不能随意凑成 $2,4,6$。

折半查找的优点是 $O(\log n)$ 且不需要额外空间；缺点是对插入删除不友好，因为顺序表插入删除需要移动元素，维护有序性代价高。它适合静态查找表，即建表后很少修改、查询频繁的场景。

7.3 分块查找

分块查找把表分成若干块，块间有序、块内可以无序。索引表为每块保存一个最大关键字和该块的起始地址；索引表按最大关键字有序。

查找分两步：先在索引表中确定关键字可能所在的块（索引表有序时可折半，否则顺序），再在块内顺序查找。设表长为 $n$，分成 $b$ 块，每块 $s$ 个元素，则 $n=bs$。若索引表和块内都用顺序查找，等概率下平均查找长度约为

$$ \text{ASL}=\frac{b+1}{2}+\frac{s+1}{2}. $$

由均值不等式，当 $b=s=\sqrt{n}$ 时取得最小值，约为 $\sqrt{n}+1$。例如 $n=18$、分成 6 块、每块 3 个元素，则 $\text{ASL}=(6+1)/2+(3+1)/2=3.5+2=5.5$。

分块查找的优点是兼顾了顺序表的灵活性和折半查找的效率：块内无序使插入删除只需在块内移动，块间有序使索引可以快速定位。缺点是索引表本身需要维护，且性能不如真正的平衡树或散列表。

7.4 散列表

散列表通过散列函数 $H(key)$ 直接把关键字映射到地址，理想情况下一次就能命中。冲突不可避免，常用线性探测、链地址法、再散列法等处理。线性探测在冲突时依次检查后继地址，直到找到空位。

下面用一个完整的例子说明构造与平均查找长度。关键字依次为

$$ 19,\ 1,\ 23,\ 14,\ 55,\ 20,\ 84,\ 27,\ 68,\ 11,\ 10,\ 77, $$

散列函数为 $H(key)=key\bmod 13$，表长为 19（地址 $0$ 到 $18$），采用线性探测。

插入 $84$ 时，地址 $6$ 被 $19$ 占用、地址 $7$ 被 $20$ 占用，直到地址 $8$ 才空，因此比较了 $6,7,8$ 三次。插入 $27$ 时，地址 $1,2,3$ 分别被 $1,14,55$ 占用，地址 $4$ 空，因此比较四次。插入 $68$ 时，地址 $3,4$ 被占，地址 $5$ 空，比较三次。插入 $10$ 时，地址 $10,11$ 被占，地址 $12$ 空，比较三次。把这些次数相加得

$$ 1+1+1+2+1+1+3+4+3+1+3+2=23, $$

$$ \text{ASL}_{\text{succ}}=\frac{23}{12}\approx 1.92. $$

原料在这个例子中把 $84$ 的比较次数记为 2，漏掉了被占用的地址 $7$；把 $27$ 记为 3，漏掉了地址 $3$；把 $68$ 记为 2，漏掉了地址 $4$；把 $10$ 记为 2，漏掉了地址 $11$。成功总次数因此被算成 19 而不是 23。失败查找中又把地址 $10,11,12$ 的路径分别少算了地址 $13$ 上的 $77$，得到 $4,3,2$ 而不是 $5,4,3$，总和 55 而不是 58。错误都来自“只数冲突的初始地址，不数沿途所有被占单元”。

散列表的装填因子定义为

$$ \alpha=\frac{n}{m}, $$

其中 $n$ 是已存关键字数，$m$ 是表长。本例 $\alpha=12/19\approx 0.63$。线性探测下，$\alpha$ 越大冲突越严重，成功与失败的查找长度都会上升；一般建议把 $\alpha$ 控制在 $0.5$ 到 $0.75$ 之间。链地址法对 $\alpha$ 的容忍度更高，且删除方便，但需要额外的指针空间。

选择哪一种，取决于操作组合。若只做“给定关键字找记录”，数据动态变化，散列表更合适；若要频繁查询“介于 $a$ 与 $b$ 之间的所有关键字”，或者需要按序输出，折半查找或平衡树更合适。散列表的 $O(1)$ 是平均意义上的，遇到大量冲突或恶意构造的键值，最坏会退化为 $O(n)$；折半查找的 $O(\log n)$ 则是稳定的上界。

关于“折半查找判定树是平衡二叉树”的表述，需要补一句：判定树确实是平衡的二叉排序树，但“平衡二叉树”并不蕴含“二叉排序树”。平衡描述形状，排序描述关键字约束。原料中把二者说成包含关系，是把两个独立维度混在了一起。

九、总结要点

主题核心结论使用要点
插入排序最好 $O(n)$，最坏 $O(n^2)$，稳定近乎有序时优先
折半插入比较 $O(n\log n)$，移动 $O(n^2)$只优化比较，不优化移动
希尔排序依赖增量，通常 $O(n^{1.3})$，不稳定增量最后必须为 1
冒泡排序最好 $O(n)$，最坏 $O(n^2)$，稳定用标志位提前结束
快速排序平均 $O(n\log n)$，最坏 $O(n^2)$，不稳定枢轴决定划分，递归先短后长
简单选择比较次数恒为 $n(n-1)/2$，不稳定移动少，适合大元素
堆排序建堆 $O(n)$，排序 $O(n\log n)$，不稳定升序用大根堆
归并排序恒为 $O(n\log n)$，稳定，空间 $O(n)$外部排序、链表排序
基数排序$O(d(n+r))$，稳定，不比较整数、定长字符串
折半查找$O(\log n)$，要求有序随机访问判定树高度 $\lfloor\log_2 n\rfloor+1$
分块查找块间有序、块内无序，最优块长约 $\sqrt{n}$兼顾动态修改
散列表平均 $O(1)$，最坏 $O(n)$，不要求有序装填因子控制在 0.75 以下

把排序与查找放在一起看，会发现它们共享同一套权衡：是否要求有序、是否允许额外空间、是否要求稳定、是否要求最坏情况有保证。快速排序用“平均快”换“最坏慢”，归并排序用“空间”换“稳定与最坏保证”，堆排序用“常数与缓存”换“原地与最坏保证”，散列表用“无序与空间”换“平均常数时间”。题目给出的约束不同，最优选择就不同；先认清约束，再查表，才不会把“平均”当成“最坏”，也不会把“比较次数”当成“总时间”。
