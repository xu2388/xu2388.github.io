肾脏病理分割这条线：从"急着交结果"到"回头磕边界"的一次绕远路

写于 2026-10-24 · 病理分割篇 · 原始来源：DeepSeek 对话 [233][234][244][215][194]

这条线我最开始的目的特别功利：手上有一批 Masson、PAS、PASM 三染色的肾脏病理切片，还带病灶的掩码图，我就想赶紧找个 SOTA 分割模型复现出来，把结果交上去。可它后来带我走了多远呢——先摸了一整圈分割模型，又为了扩充数据拐进了文本驱动的风格迁移，最后居然自己绕回了起点，卡在"边界到底怎么描"这个最土的问题上。这篇就把这几个月里思路怎么一步步挪的，原原本本记下来。

一、起点：一个特别具体的活儿

一切的开口都很直接，我在 233 那条对话（整整 617 条消息，是我最长的一条）开头是这么问的：

原始记录 · 我的第一个问题 [233] "我的任务是肾脏病理染色切片的病灶分割，我有 pas,pasm,masson 三类，然后我有病灶的掩码图，请问这个领域的 sota 模型是什么？我需要尽快复现出来作为结果提交。"

这里有个细节我后来反复强调，因为助手一开始总会理解偏：我要分割的是病灶，不是肾小球、不是器官。 到了 215 我又纠正过一次——"因为我做的是病灶的分割，不是简单的肾小球，或者什么器官的分割，但是我的数据是就是肾脏的 masson 切片。" 这句话是我这条线的锚：数据是肾脏的，但目标不是教科书里那种"把肾小球圈出来"，而是病灶区域。这个区分听着小，实际上直接决定了后面哪些模型能用、哪些公开权重根本不对口。

二、SOTA 全景：一圈模型摸下来，保底的和冲榜的不是一回事

为了回答"这个领域的 SOTA 是什么"，我连着扒了 233、234、244 三条对话，把肾脏/病理分割能碰到的模型梳理了一遍。我的结论是它们分成三层，各干各的活。

整理归纳 · 我梳理的模型清单（按用途分层）
层模型是什么 / 我的判断
保底黄金标准 nnU-Net（含 nnU-Net V2 for Pathology） 助手反复定位的"保底"选择。有实例：PTC Segmentation 用它做 PAS 染色肾小管周围毛细血管分割，Dice 0.751。凡是冲榜模型没权重，最后都退回它。
专用 / 冲 SOTA GloPath（arXiv:2603.02926） 肾小球病变评估的基础模型，100 万+ 肾小球、14049 份活检训练，52 项任务 80.8% 超 SOTA，AUC 91.51%。但当时代码未开源——直接排除。
Glo-Net（南京鼓楼） 分割+分类双任务，253 张 PAS WSI，硬化肾小球 mIoU>0.8。
MSMTSeg（山西省人民医院） 多染色（PASM/PAS/H&E/Masson）、少样本，每染色仅 25 张标注，CycleGAN+MoCo-v3+MAML。无开源权重，思路我认可但复现不了。
通用 Transformer Swin-UNETR BTCV Dice 0.918、肾脏 95.21%，MONAI/Zenodo 有开源权重、支持 LoRA 少样本。但标准版是 3D CT，和我的 2D 病理有模态差，得改 2D 或伪 3D。
通用 Transformer Swin-Unet / TransUNet / MedT 小鼠肾皮质（SPIE 2024）mIoU 92.2% / 91.9%。
WSI / 通用 Mask2Former-Swin-B、SegGPT、HoVer-Net 肾活检 WSI（肾小球/小管/动脉/间质）有公开权重；SegGPT 肾小球硬化 patch 级 0.74（BMC Nephrology 2025）。
轻量化 / 落地 V-SAM / ASRMU-Net / MGM-Unet V-SAM 基于 SAM 的 V 型适配器，HuBMAP F1 86.17%/95.54%；ASRMU-Net 间质纤维化 MDice 85.4%、AIDPATH 96.1%；MGM-Unet 用 MobileNetv3+Ghost，GFLops 降 424.26G、参数量降 19.43M。

上表所有指标均为对话中助手给出的数字，多为检索引用，属【待核实】，写进正式材料前我应当回原始论文核对一遍。

梳理的整个过程里我发过一次火，也学到一课。在 234 我坚持说"那类似于这种的模型肯定有很多吧，你怎么说没有呢"，助手才承认自己表述不准——它想说的是 MSMTSeg 这个特定框架没有开源权重，而不是"所有这类模型都没权重"。这个纠正对我很关键：我一开始被"没有 SOTA 能用"吓到了，其实通用模型（Swin-UNETR、Mask2Former）有大量现成资源，真正卡住的只是那几个最对口的专用框架。问题是"最想要的没有"，不是"什么都没有"。

三、我自己的架构偏见，以及它怎么一次次改的

这条线里我换过好几次架构立场，每次都不是无缘无故的，我把这个变化过程也留下来了，因为它本身说明我那时候有多摇摆。

历史观点 · 我的架构立场演变（按时间）

最早（215, 4 月初）：泛泛问 2D 分割，收敛到"肾脏三染色 + 病灶分割"，放话要"不基于卷积，或其他架构"——那会儿就是看衰 CNN，一心想上新结构。

接着（233/234, 3 月）：开始认真掂量 Transformer，一头扎进 Swin-UNETR，又被"它是 3D CT"卡住，在"改 2D 还是做伪 3D"之间反复纠结。

后来自己松口："CNN、mamba、transformer 架构都应该尝试一下。" 不再迷信单一架构，谁好用谁上。

最后（194, 4 月底-5 月初）：火力集中到频域——用小波（DWT/HWD）、多频率通道注意力（MFCA）去攻边界，这是后面第五章的主角。

至于轻量化这条支线（244），我真金白银下载训练过 E-SegNet，结论却有点打脸——"边缘精度其实不是很好"。这其实已经埋下了后面边界问题的伏笔：我早就撞上边界模糊了，只是那会儿还没把它当成主攻方向。

四、一次大跑偏：为了扩数据，拐进了文本驱动风格迁移

这条线最出人意料的一段：分割干着干着，我被"数据不够"逼向了生成。我的想法在 244 里说得很清楚：

原始记录 · 我转向生成式的动机 [244] "文本驱动的风格迁移，我需要用 diffusion 扩散模型来实现，我的输入就是目标风格的文本描述和需要被迁移的图片……生成原图片的目标风格图片。" 动机是扩充不同染色的数据——我手上三染色样本少，想靠生成补。

这里有个特别妙的闭环：分割本来是要交的结果，反过来成了生成的结构控制器。 我的设想是先用 nnU-Net 把肾小球、间质的轮廓分割出来，拿这个轮廓当 ControlNet 的结构引导，再用扩散模型按文本换染色风格；文本编码器我甚至想用病理专用的 CONCH 替换掉 SD 默认的 CLIP，英文文本按染色区分来写。我的原话假设是："不同染色突出不同特征……让 UNET 学习这个部分。" 换句话说，我打算让分割给生成让路，让生成反过来解决分割的数据荒。 这一段和我博客里虚拟染色的主线（001、002）是同一条河。

但我也不是没脾气。当助手建议我"复用 Stable Diffusion 别的域的 UNet"时，我直接炸了：

原始记录 · 我的一次强烈反对 [233] "卧槽你是傻逼吗，他的 UNET 的训练的图像和我的域不一样啊。" 这句话糙，但理不糙：预训练 UNet 见过的图像域和我的肾脏病理差得远，直接拿来微调未必靠谱。这个质疑我一直留着，也是后面我对"跨域预训练到底能迁移多少"始终保持警惕的起点。

五、绕回起点：边界模糊，这个真问题终于被正面刚

生成式那边还没落地，我在最晚的 194（4 月底-5 月初）又回到了分割本身，而且这次是从根上问问题：

原始记录 · 我对分割本质的追问 [194] "分割的本质，到底是检测边界，还是检测目标呢？" 以及我对自己模型的诊断——"我发现模型的问题了，就是边界清晰度不够""从纯白到纯黑中间存在很多灰色。" 这句"从纯白到纯黑中间有很多灰色"，是我对边界模糊最形象的描述：掩膜边缘不是干净的 0/1，而是一圈灰度过渡， Dice 就被这圈灰吃掉了。

我当时的实测指标是这样的（注意那个 Accuracy 很高、Dice 却只有 0.90 上下的反差，正是"整体对、边界糊"的典型特征）：

原始记录 · 我在 [194] 的实测指标
指标均值 ± 标准差
IoU0.8295 ± 0.1081
Dice0.9022 ± 0.0782
Recall0.8941 ± 0.0999
Accuracy0.9741 ± 0.0227
标准差偏大（Dice 抖到 ±0.078）说明不同样本间很不稳定，我认为瓶颈就在边界。

为了啃边界，我把宝押在了频域上。逻辑是：边界模糊是空间域的老大难，但频域（小波/DCT）能把高频的边缘信息单独拎出来处理。我在 194 开头就说"这几天希望可以在频域方向做一些工作直接提升精度"，甚至想拿 HWD（Haar 小波下采样）把 UNet 的下采样"全部替换掉"。我摸过的方法包括：

整理归纳 · 我碰过的频域 / 边界方法 [194]
  • 频域下采样/特征：MFR-UNet（小波频域）、MFCA（CVPR 2024 多频率通道注意力）、MSCWNet（我采用的）、HWD（Haar 小波下采样）。
  • 频-空双路径注意力：MADGNet、EGNet、FSA-Net；WBDM-ECRF（2026，小波+桥式扩散，mIoU 88.08%）。
  • 边界后处理（即插即用）：SegFix（边界修正）、Post-DAE（去噪自编码器学完美掩膜分布）。

但频域这条路我摔得挺惨，坑我都记着："加了模块效果就变弱了"——想给网络加频域分支，精度不升反降；"集成之后精度突然变低，正常吗"——多模块集成互相打架；小波替换下采样还撞上通道数变化的工程难题。到 194 结尾我蔫蔫地写了句"换一个方案吧"。可就算撞墙，我投入频域的真实动机也在 194 里说了，特别坦诚：

原始记录 · 我的真实动机 [194] "我需要系统帮助……我要答辩，需要言之有物……这个问题必须要解决出来。" 说白了，边界模糊不只是技术瓶颈，它还是我答辩时拿得出手的创新点——这解释了我为什么在频域上花了远超"交个结果"所需的时间。
当前结论 这条线真正的收获，不是某个 Dice 数字，而是我认清了两件事：其一，最对口的专用模型（GloPath、MSMTSeg）都没权重，落地只能靠通用模型（nnU-Net 保底、Swin-UNETR 改 2D）；其二，我模型的核心短板是边界模糊，不是架构不够新——Accuracy 0.97 而 Dice 只有 0.90，问题定位得很清楚。频域是我想赌的反转手段，但还没赌赢。而"分割→生成→再回到分割"这个环，说明分割这条线从来不是孤立的，它一直和虚拟染色的生成主线咬合在一起。
未解决问题 / 待核实
  • 频域分支"加了就变弱"的 bug 我还没定位——是梯度冲突、是通道没对齐、还是频域特征没接对地方，待查。
  • SegFix / Post-DAE 这两个边界后处理我只是列为候选，没实际跑，能否把那圈"灰色"收干净是未知的。
  • HWD 全替换下采样撞上的通道数问题没有解决方案。
  • 模型清单里所有指标都是对话引述，写进答辩材料前必须回原始论文核实（尤其 GloPath 的 arXiv 编号和 52 任务口径）。
  • 风格迁移那条支线（CONCH 换 CLIP、ControlNet 用肾小球轮廓）还停在设想，"推理时目标风格文本怎么配对"是我自己提出但没答案的问题。
  • 数据集的规模和划分方式我从没在这条线里写清楚，实验可复现性存疑。
