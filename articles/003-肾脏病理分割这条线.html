肾脏病理分割研究复盘：从复现 SOTA 到回归边界问题

写于 2026-10-24 · 病理分割篇 · 原始来源：DeepSeek 对话 [233][234][244][215][194]

这条线索的最初目的相当直接：我手上有一批 Masson、PAS、PASM 三染色的肾脏病理切片及对应的病灶掩码图，希望尽快找到一个 SOTA 分割模型复现，提交结果。但其后它带我走了很远——先系统调研了一圈分割模型，又为扩充数据转入文本驱动的风格迁移，最终回到起点，卡在「边界究竟如何刻画」这一最基础的问题上。本文完整记录这几个月中思路的逐步演变。

一、起点：一个具体的任务需求

一切的起点很直接，我在 233 那条对话（共 617 条消息，是我最长的一条）开头是这样提问的：

原始记录 · 我的第一个问题 [233] "我的任务是肾脏病理染色切片的病灶分割，我有 pas,pasm,masson 三类，然后我有病灶的掩码图，请问这个领域的 sota 模型是什么？我需要尽快复现出来作为结果提交。"

这里有一个细节我后来反复强调，因为助手最初总会理解偏差：我要分割的是病灶，不是肾小球、不是器官。 到 215 我又纠正过一次——"因为我做的是病灶的分割，不是简单的肾小球，或者什么器官的分割，但是我的数据是就是肾脏的 masson 切片。" 这句话是这条线索的锚点：数据是肾脏的，但目标不是教科书中「把肾小球圈出来」的任务，而是病灶区域。这一区分看似细微，实际上直接决定了后续哪些模型可用、哪些公开权重并不对口。

二、SOTA 全景：模型分层，保底与冲榜并非一事

为了回答「这个领域的 SOTA 是什么」，我先后查阅 233、234、244 三条对话，将肾脏/病理分割相关的模型梳理了一遍。结论是它们分为三层，各有分工。

整理归纳 · 我梳理的模型清单（按用途分层）
层模型是什么 / 我的判断
保底黄金标准 nnU-Net（含 nnU-Net V2 for Pathology） 助手反复定位的"保底"选择。有实例：PTC Segmentation 用它做 PAS 染色肾小管周围毛细血管分割，Dice 0.751。凡是冲榜模型没权重，最后都退回它。
专用 / 冲 SOTA GloPath（arXiv:2603.02926） 肾小球病变评估的基础模型，100 万+ 肾小球、14049 份活检训练，52 项任务 80.8% 超 SOTA，AUC 91.51%。但当时代码未开源——直接排除。
Glo-Net（南京鼓楼） 分割+分类双任务，253 张 PAS WSI，硬化肾小球 mIoU>0.8。
MSMTSeg（山西省人民医院） 多染色（PASM/PAS/H&E/Masson）、少样本，每染色仅 25 张标注，CycleGAN+MoCo-v3+MAML。无开源权重，思路我认可但复现不了。
通用 Transformer Swin-UNETR BTCV Dice 0.918、肾脏 95.21%，MONAI/Zenodo 有开源权重、支持 LoRA 少样本。但标准版是 3D CT，和我的 2D 病理有模态差，得改 2D 或伪 3D。
通用 Transformer Swin-Unet / TransUNet / MedT 小鼠肾皮质（SPIE 2024）mIoU 92.2% / 91.9%。
WSI / 通用 Mask2Former-Swin-B、SegGPT、HoVer-Net 肾活检 WSI（肾小球/小管/动脉/间质）有公开权重；SegGPT 肾小球硬化 patch 级 0.74（BMC Nephrology 2025）。
轻量化 / 落地 V-SAM / ASRMU-Net / MGM-Unet V-SAM 基于 SAM 的 V 型适配器，HuBMAP F1 86.17%/95.54%；ASRMU-Net 间质纤维化 MDice 85.4%、AIDPATH 96.1%；MGM-Unet 用 MobileNetv3+Ghost，GFLops 降 424.26G、参数量降 19.43M。

上表所有指标均为对话中助手给出的数字，多为检索引用，属【待核实】，写进正式材料前我应当回原始论文核对一遍。

梳理过程中我有过一次激烈质疑，也由此学到一课。在 234 我坚持说"那类似于这种的模型肯定有很多吧，你怎么说没有呢"，助手才承认自己表述不准确——它想表达的是 MSMTSeg 这个特定框架没有开源权重，而非「所有这类模型都没权重」。这一纠正对我很关键：我最初被「没有 SOTA 可用」的表述误导，实际上通用模型（Swin-UNETR、Mask2Former）有大量现成资源，真正受限的只是那几个最对口的专用框架。问题是「最想要的不存在」，而非「什么都不存在」。

三、我的架构偏好及其多次修正

这条线索中我数次改变架构立场，每次都有具体原因。这一变化过程同样记录在案，因为它反映了当时的判断轨迹。

历史观点 · 我的架构立场演变（按时间）

最早（215, 4 月初）：泛泛问 2D 分割，收敛到"肾脏三染色 + 病灶分割"，放话要"不基于卷积，或其他架构"——那会儿就是看衰 CNN，一心想上新结构。

接着（233/234, 3 月）：开始认真掂量 Transformer，一头扎进 Swin-UNETR，又被"它是 3D CT"卡住，在"改 2D 还是做伪 3D"之间反复纠结。

后来自己松口："CNN、mamba、transformer 架构都应该尝试一下。" 不再迷信单一架构，谁好用谁上。

最后（194, 4 月底-5 月初）：火力集中到频域——用小波（DWT/HWD）、多频率通道注意力（MFCA）去攻边界，这是后面第五章的主角。

至于轻量化这条支线（244），我实际下载并训练过 E-SegNet，结论与预期不符——"边缘精度其实不是很好"。这已经为后来的边界问题埋下伏笔：我早已遇到边界模糊，只是当时尚未将其作为主攻方向。

四、一次方向调整：为扩充数据转入文本驱动风格迁移

这条线索中最出乎意料的一段：分割工作进行中，我因「数据不足」转向了生成。我的想法在 244 中表述得很清楚：

原始记录 · 我转向生成式的动机 [244] "文本驱动的风格迁移，我需要用 diffusion 扩散模型来实现，我的输入就是目标风格的文本描述和需要被迁移的图片……生成原图片的目标风格图片。" 动机是扩充不同染色的数据——我手上三染色样本少，想靠生成补。

这里形成一个值得注意的闭环：分割本是需要提交的结果，反过来成为生成的结构控制器。 我的设想是先用 nnU-Net 分割出肾小球、间质的轮廓，以此作为 ControlNet 的结构引导，再用扩散模型按文本描述替换染色风格；文本编码器我甚至计划用病理专用的 CONCH 替换 SD 默认的 CLIP，英文文本按染色类型区分撰写。我的原始假设是："不同染色突出不同特征……让 UNET 学习这个部分。" 换句话说，我打算让分割为生成让路，让生成反过来解决分割的数据不足。 这一段与博客中虚拟染色的主线（001、002）属于同一条线索。

对此我也并非没有保留意见。当助手建议我「复用 Stable Diffusion 其他域的 UNet」时，我表示了强烈反对：

原始记录 · 我的一次强烈反对 [233] "卧槽你是傻逼吗，他的 UNET 的训练的图像和我的域不一样啊。" 这句话糙，但理不糙：预训练 UNet 见过的图像域和我的肾脏病理差得远，直接拿来微调未必靠谱。这个质疑我一直留着，也是后面我对"跨域预训练到底能迁移多少"始终保持警惕的起点。

五、回到起点：边界模糊这一核心问题得到正面处理

生成式方向尚未落地，我在最晚的 194（4 月底-5 月初）回到了分割本身，且这一次从根本层面提出问题：

原始记录 · 我对分割本质的追问 [194] "分割的本质，到底是检测边界，还是检测目标呢？" 以及我对自己模型的诊断——"我发现模型的问题了，就是边界清晰度不够""从纯白到纯黑中间存在很多灰色。" 这句"从纯白到纯黑中间有很多灰色"，是我对边界模糊最形象的描述：掩膜边缘不是干净的 0/1，而是一圈灰度过渡， Dice 就被这圈灰吃掉了。

我当时的实测指标如下（注意 Accuracy 很高而 Dice 仅 0.90 上下的反差，正是「整体正确、边界模糊」的典型特征）：

原始记录 · 我在 [194] 的实测指标
指标均值 ± 标准差
IoU0.8295 ± 0.1081
Dice0.9022 ± 0.0782
Recall0.8941 ± 0.0999
Accuracy0.9741 ± 0.0227
标准差偏大（Dice 抖到 ±0.078）说明不同样本间很不稳定，我认为瓶颈就在边界。

为解决边界问题，我将重点放在频域上。逻辑是：边界模糊是空间域的长期难题，而频域（小波/DCT）能将高频的边缘信息单独提取处理。我在 194 开头即写道"这几天希望可以在频域方向做一些工作直接提升精度"，甚至计划用 HWD（Haar 小波下采样）将 UNet 的下采样"全部替换掉"。我尝试过的方法包括：

整理归纳 · 我碰过的频域 / 边界方法 [194]
  • 频域下采样/特征：MFR-UNet（小波频域）、MFCA（CVPR 2024 多频率通道注意力）、MSCWNet（我采用的）、HWD（Haar 小波下采样）。
  • 频-空双路径注意力：MADGNet、EGNet、FSA-Net；WBDM-ECRF（2026，小波+桥式扩散，mIoU 88.08%）。
  • 边界后处理（即插即用）：SegFix（边界修正）、Post-DAE（去噪自编码器学完美掩膜分布）。

但频域这条路径的进展很不顺利，问题均有记录："加了模块效果就变弱了"——为网络添加频域分支后，精度不升反降；"集成之后精度突然变低，正常吗"——多模块集成之间相互干扰；小波替换下采样还遇到通道数变化的工程难题。到 194 结尾我写道"换一个方案吧"。尽管如此，我投入频域的真实动机在 194 中有坦率表述：

原始记录 · 我的真实动机 [194] "我需要系统帮助……我要答辩，需要言之有物……这个问题必须要解决出来。" 说白了，边界模糊不只是技术瓶颈，它还是我答辩时拿得出手的创新点——这解释了我为什么在频域上花了远超"交个结果"所需的时间。
当前结论 这条线索真正的收获不是某个 Dice 数字，而是认清了两件事：其一，最对口的专用模型（GloPath、MSMTSeg）均无开源权重，落地只能依靠通用模型（nnU-Net 作为保底、Swin-UNETR 改 2D）；其二，模型的核心短板是边界模糊，而非架构不够新——Accuracy 0.97 而 Dice 仅 0.90，问题定位清晰。频域是我尝试的反转手段，但尚未成功。而「分割→生成→再回到分割」这一循环说明，分割这条线索从来不是孤立的，它始终与虚拟染色的生成主线相互关联。
未解决问题 / 待核实
  • 频域分支「加上后效果变弱」的问题尚未定位——原因可能是梯度冲突、通道未对齐或频域特征接入位置不当，待查。
  • SegFix / Post-DAE 两个边界后处理方法仅列为候选，尚未实际运行，能否消除边缘的「灰色」过渡尚不可知。
  • HWD 全量替换下采样所遇到的通道数问题尚无解决方案。
  • 模型清单中所有指标均为对话引述，写入答辩材料前必须回原始论文核实（尤其 GloPath 的 arXiv 编号和 52 任务口径）。
  • 风格迁移支线（CONCH 替换 CLIP、ControlNet 使用肾小球轮廓）仍停留在设想阶段，「推理时目标风格文本如何配对」是我提出但尚未解决的问题。
  • 数据集的规模与划分方式在这条线索中从未写明，实验可复现性存疑。
