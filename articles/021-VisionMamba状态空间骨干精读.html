Vision Mamba：把状态空间模型做成视觉骨干——线性复杂度与病理图像的适配性

2026-10-25 · 研究文章 · 整理自研究笔记
论文：Vision Mamba: Efficient Visual Representation Learning with Bidirectional State Space Model 作者：Lianghui Zhu, Bencheng Liao, Qian Zhang, Xinlong Wang, Wenyu Liu, Xinggang Wang（作者所属机构从略，本文不做机构指认） 发表：ICML 2024；arXiv:2401.09417（v1 2024-01-17，v2 2024-02-10，v3 2024-11-14） 代码：https://github.com/hustvl/Vim （公开页面标注 Apache-2.0 许可） 方法名：Vim（Vision Mamba，双向状态空间模型驱动的纯 SSM 视觉主干） 本文材料来源：一条 90 轮的豆包对话《Vision Mamba 论文及获取渠道》。该对话后半段转向另一主题（归一化流与扩散的耦合），已由单独一篇处理，本文不涉及。

一、背景：骨干网络的二次复杂度，在病理图像上不是「效率问题」而是「可行性问题」

ViT 一系（ViT、DeiT）把图像切成 $16\times16$ 的非重叠 patch，展平成序列，再靠自注意力让每个 token 与全部 token 直接交互。这套机制在 ImageNet 尺度上很成功，但注意力的开销量级随序列长度平方增长——按论文给出的式子，单个注意力模块的浮点量是

$$\Omega(\text{self-attention}) = 4MD^{2} + 2M^{2}D$$

其中 $M$ 是 token 数，$D$ 是隐藏维度。第二项 $2M^{2}D$ 是「所有 token 两两算相似度」的代价，它决定了两个后果：计算量二次增长，以及中间激活（注意力矩阵）随 $M^2$ 膨胀。$224\times224$ 时 $M=196$，一切都很轻松；把输入推到 $1248\times1248$，$M$ 就变成 $6084$，二次项开始压倒一次项。

对一般自然图像，这还只是「慢一点、显存多占一点」。对全切片图像（WSI）则不同：一张 40× 放大的 WSI 通常在千兆像素量级（以 gigapixel 为标题词的公开工作不少，MCAT 一篇即以此命名），若按 tile 切成 patch 序列，长度量级会到 $10^{6}\sim10^{7}$（见第五节的推算）。此时二次复杂度不是效率优化题，而是能不能一次前向把一整片组织放进显存的可行性题。这也是笔者起初去找「替代骨干」的原因：主线任务里需要建模的空间范围远大于 ImageNet 尺度的方形输入。

Mamba 提供了另一条路线：用状态空间模型（SSM）做序列建模，隐藏状态只随「上一状态 + 当前输入」递推，计算量与 $M$ 成正比。原始 Mamba 论文报告其相对 Transformer 有约 5 倍的吞吐优势（该数字来自 Mamba 论文摘要，本文已核实），但它是为单向语言序列设计的：没有位置感知、只往前看。视觉数据两样都不接受——patch 无天然顺序，物体左右必须互参。Vim 要解决的，正是这两处适配。

笔者把这轮对话里反复追问的过程保留下来，因为其中几个困惑（「exp 是连续函数，凭什么叫离散化」「A、B、C 是不是对应 QKV」）恰好是 SSM 最容易被讲糊的地方。

二、SSM 原理：从连续系统到「内容感知的离散递推」

2.1 连续形式：一线性动态系统

SSM 的出发点不是深度学习，而是经典控制论里的线性时不变系统。它把「序列建模」写成状态随时间演化：

$$h'(t) = A\,h(t) + B\,x(t), \qquad y(t) = C\,h(t)$$

  • $x(t)$：时刻 $t$ 的输入标量（深度学习中换成向量，逐通道各有一套参数）；
  • $h(t)\in\mathbb{R}^{N}$：隐藏状态，历史信息的压缩载体；$N$ 称状态维度；
  • $A\in\mathbb{R}^{N\times N}$：状态演化矩阵，决定旧状态以什么速率衰减/放大；
  • $B\in\mathbb{R}^{N\times 1}$：输入投影，决定新信息写入状态的强度；
  • $C\in\mathbb{R}^{1\times N}$：输出投影，决定从状态里读出什么。

一句话理解三个矩阵的分工：$A$ 管「留多少旧的」，$B$ 管「加多少新的」，$C$ 管「怎么说出来」。

2.2 离散化：为什么会出现 $\overline{A}$、$\overline{B}$

神经网络处理的是一串离散的 token（或 patch），不是连续信号，于是需要把微分方程变成差分方程。标准做法是引入步长 $\Delta$（一个时间步覆盖多长），并用零阶保持（ZOH，即假定步长内输入不变）求精确解，得到论文给出的离散参数：

$$\overline{A} = \exp(\Delta A), \qquad \overline{B} = (\Delta A)^{-1}\big(\exp(\Delta A) - I\big)\cdot \Delta B$$

于是递推形式为：

$$h_{t} = \overline{A}\,h_{t-1} + \overline{B}\,x_{t}, \qquad y_{t} = C\,h_{t}$$

工程实现里常把 $\overline{B}$ 用一阶近似写成 $\overline{B}\approx \Delta B$（$\Delta A$ 很小时 $(\exp(\Delta A)-I)(\Delta A)^{-1}\to I$）；原料与后续 Mamba 材料的推导都采用这一近似写法，本文后文亦然。要注意：矩阵指数 $\exp$ 本身仍是精确离散化的求解工具，不是「把参数变成不连续」的手段。

笔者在这里卡了三轮才想通。当时的疑问是：「$\overline{A}=\exp(\Delta A)$ 明明是以 $e$ 为底的连续函数，怎么就叫离散参数？」——问题出在把「离散」理解成了「取值不连续」。准确的含义是：这个参数服务于第 $t$ 个离散时间步。它只在处理第 $t$ 个 token 时生效，处理第 $t+1$ 个 token 时会重新算一份新的 $\overline{A}_{t+1}$。参数值是连续的，参数被使用的时刻是离散的，两者不矛盾。把这一点想清楚之后，「离散化 → 选择性」的层次才不会串。

2.3 递推与卷积：两种等价算法形式

把 $h_0=0$ 代入递推展开（取 $M=3$ 手动验证一遍，是笔者确认自己没在背公式的常用办法）：

$$h_1 = \overline{B}x_1 \;\Rightarrow\; y_1 = C\overline{B}x_1$$

$$h_2 = \overline{A}\overline{B}x_1 + \overline{B}x_2 \;\Rightarrow\; y_2 = C\overline{A}\overline{B}x_1 + C\overline{B}x_2$$

$$h_3 = \overline{A}^{2}\overline{B}x_1 + \overline{A}\overline{B}x_2 + \overline{B}x_3 \;\Rightarrow\; y_3 = C\overline{A}^{2}\overline{B}x_1 + C\overline{A}\overline{B}x_2 + C\overline{B}x_3$$

系数可以整理成一个长度 $M$ 的结构化卷积核：

$$\overline{K} = \big(C\overline{B},\; C\overline{A}\overline{B},\; \dots,\; C\overline{A}^{M-1}\overline{B}\big), \qquad y = x * \overline{K}$$

第 $k$ 个抽头 $C\overline{A}^{k-1}\overline{B}$ 的含义是「$k-1$ 步之前的那个输入，绕过多少层状态衰减之后，对当前输出的贡献」。于是同一次 SSM 计算有两种算法形式：

形式计算图可得的量适用阶段
递推（recurrent）串行扫描，状态逐步更新每个时刻的中间状态 $h_t$自回归推理，常数显存、逐步输出
全局卷积与 $\overline{K}$ 做因果卷积，可并行整段输出 $y_{1:M}$，一次到位训练期并行化

这里要提醒一个容易记错的点：训练用卷积形式的前提是 $\overline{A},\overline{B},C$ 在整段序列上不变（时不变 SSM，S4 属于这一类）。Mamba 的选择性机制让参数逐 token 变化，此时卷积核不再全局共享，只能换成「输入依赖的并行扫描」来实现并行——原料一度把「结构化核」当作 Mamba 的实现方式，这是不准确的，两条并行化路线不是一回事。

表 1：自注意力与 SSM 的机制对照

维度自注意力（ViT/DeiT）SSM（Mamba/Vim）

线性复杂度是量级上的承诺，不是常数倍的承诺：$N$ 虽小但 $8MDN$ 里有 $D$ 与 $E=2D$ 的扩展开销，硬件上也远不止浮点量。第四节的实测数据会说明这个落差。

2.4 选择性机制：$\Delta(x)$ 才是 Mamba 的关键

时不变 SSM 的软肋很直白：$A,B,C$ 对所有 token 用同一套值。重要的 token 与噪声 token 以同样比例写入状态，模型无法「挑内容」。这正是它长期打不过 Transformer 的原因。

Mamba 的解法是把参数变成输入的函数。对第 $t$ 个 token 的特征 $x_t$：

$$B_{t} = \mathrm{Linear}_{B}(x_{t}), \qquad C_{t} = \mathrm{Linear}_{C}(x_{t})$$

$$\Delta_{t} = \mathrm{softplus}\big(\mathrm{Linear}_{\Delta}(x_{t}) + \mathrm{bias}_{\Delta}\big)$$

其中 softplus 保证 $\Delta_t>0$（步长必须为正）。再代入离散化：

$$\overline{A}_{t} = \exp(\Delta_{t}A), \qquad \overline{B}_{t} \approx \Delta_{t}B_{t}$$

选择性因此不是加了一个门，而是把「离散化步长」变成内容依赖的量：$\Delta_t$ 大，则 $\overline{A}_t$ 偏离单位阵的方式改变，当前输入写入状态的权重更大、历史被更快冲刷；$\Delta_t$ 小，则近似「这一段先记住、不吸收」。它起的作用与 LSTM 的遗忘门/输入门同构，但形式上仍是线性递推，所以能并行扫描、能保持线性复杂度。

笔者曾把 $A,B,C$ 直接类比成 Transformer 的 $Q,K,V$，被明确纠正：这组类比不成立。$Q,K,V$ 的产物是 token 之间的相似度权重（数量随 token 对数增长）；$A,B,C$ 的产物是 状态演化的规则（与 token 对数无关）。把两者画等号，会让人误以为 SSM 只是「隐式的注意力」，从而看不出它复杂度低的真正来源。

三、Vim 的架构设计：把单向、无位置感的 SSM 改造成视觉主干

3.1 序列化与位置标记

Vim 沿用 ViT 的入口：用一个 $16\times16$ 的投影层把图像变成非重叠 patch 序列，得到 $J=(H/16)\times(W/16)$ 个 $D$ 维向量，并追加一个可学习的分类 token：

$$T_{0} = \big[\,t_{cls};\ t_{p}^{1}W;\ t_{p}^{2}W;\ \dots;\ t_{p}^{J}W\,\big] + E_{pos}, \qquad E_{pos}\in\mathbb{R}^{(J+1)\times D}$$

$E_{pos}$ 的 $(J+1)\times D$ 中，$J$ 是 patch 数、$+1$ 留给 class token、$D$ 是隐藏维度；维度必须与序列逐项对齐，才能做逐元素相加。

这里笔者当时提过一个很自然的反驳：「patch 在图里的位置是显而易见的，位置嵌入凭什么是要学的参数，直接定义不行吗？」答案的关键在区分两件事：几何坐标是已知的，但「位置该如何影响 token 之间的关联方式」不是已知的。固定规则（如正弦编码）只能规定一种外推方式；可学习嵌入让数据去决定「哪些位置之间更值得互相参考」。这个疑问本身也暴露了一个更深的事实：SSM 是递归的，它对遍历顺序极其敏感——一旦把 2D 网格展成 1D，顺序就成了强归纳偏置，位置嵌入是把这份损失的空间信息尽量补回来的手段之一。

至于 class token：它不是 Vim 的发明，来自 ViT，本质是一个可学习参数向量，训练后经反向传播更新，在 Vim 里靠双向 SSM 逐步吸收全序列信息，最终取其输出接分类头。密集任务不用它，改用全部 patch 表征。

3.2 Vim block：双向扫描 + 门控 + 残差

Vim 的主干由 $L$ 个 Vim block 堆叠（三个尺寸变体 $L$ 均为 24，见配置表）。单个 block 内部按论文 Algorithm 1 的口径可写成：

$$x,\,z = \mathrm{Linear}_{x}\big(\mathrm{LN}(T_{l-1})\big),\;\; \mathrm{Linear}_{z}\big(\mathrm{LN}(T_{l-1})\big)$$

对扩展维 $E=2D$ 的特征 $x$ 走两条方向相反的支路（$o\in\{f,b\}$）：

$$x'_{o} = \mathrm{SiLU}\big(\mathrm{Conv1d}_{o}(x)\big), \qquad y_{o} = \mathrm{SSM}_{o}\big(x'_{o}\big)$$

$$y'_{f} = \mathrm{SiLU}(z)\odot y_{f}, \qquad y'_{b} = \mathrm{SiLU}(z)\odot y_{b}$$

$$T_{l} = \mathrm{Linear}_{T}\big(y'_{f} + y'_{b}\big) + T_{l-1}$$

其中 $\mathrm{SSM}_{o}$ 内部就是 2.4 节那套：由 $x'_o$ 生成 $B_o,C_o,\Delta_o$，离散化得 $\overline{A}_o,\overline{B}_o$，再沿该方向递推。扫描方向的关系可写成示意伪代码（只使用对话原料中确实出现的算子，不对应真实接口）：

# 双向扫描的骨架（示意，非官方接口）
x, z = Linear_x(Norm(T_prev)), Linear_z(Norm(T_prev))

x_f = SiLU(Conv1d_f(x))            # 正向支路：局部特征先聚一次
x_b = SiLU(Conv1d_b(flip(x)))      # 反向支路：序列反向

for t in range(M):                 # 正向：第 1 个 patch -> 第 M 个 patch
    B_f[t], C_f[t], Delta_f[t] = Linear_B_f(x_f[t]), Linear_C_f(x_f[t]), softplus(...)
    A_bar_f[t] = exp(Delta_f[t] * A_f)
    h_f[t]     = A_bar_f[t] * h_f[t-1] + Delta_f[t] * B_f[t] * x_f[t]
    y_f[t]     = C_f[t] * h_f[t]

# 反向支路流程完全相同，只是遍历顺序相反，最后再 flip 回来
y = Linear_T(SiLU(z) * y_f + SiLU(z) * y_b)
T_now = y + T_prev                 # 残差

双向设计的必要性由消融给出（见第四节）：单向 Mamba 在分割任务上明显吃不消。至于「为什么要给每路 SSM 前加一个 Conv1d」——因为 SSM 沿链传递信息，跨远距离的相邻 patch 关系在纯递推下表达得弱，一次 1D 深度卷积先把局部邻域揉一下，再交给长程递推，属于「局部 + 长程」的分工。

关于正反向的二维直觉，笔者当时的表述值得留档：反向不是「图像倒过来看」，而是同一展平序列的逆序遍历。行优先展平时，正向是「左上到右下」，反向是「右下到左上」；两路各自累积一条方向相反的状态链，再在门控下相加，于是每个 patch 的输出都同时带有「前方来的」与「后方来的」上下文。这也是 Vim 相对原始 Mamba 的核心增量。

表 2：Vim 与原始 Mamba 的差异（对话原料与论文口径一致）

除纯 Vim 之外，论文还给了一个分层变体（原料称 Hier-Vim）：把 Swin 式窗口注意力替换成双向 SSM 传播，按四个 stage 堆叠，Tiny 配置各 stage 块数为 2/2/5/2、通道 96/192/384/768，Small 把第三 stage 加深到 15 块（约 50M），Base 把通道扩到 128/256/512/1024。这组数字取自对话原料对论文配置段的转述，本文只核实到分层变体存在及其大致结构，未逐项复核每个 stage 的深度与通道数，引用时请按「待复核」对待。

值得注意的设计取向是：Vim 的纯 SSM 主干刻意不掺自注意力，也不引入 2D 归纳偏置（窗口、卷积核形状），这与同期「SSM + 注意力」混合路线是两条哲学。混合路线在密集任务上往往更稳，而纯 SSM 路线把赌注押在「扫描顺序 + 位置嵌入 + 双向」足以支撑视觉表征。这个取舍对病理图像的后果，第五节讨论。

三点判据层面的解读。

其一，分类精度不是 Vim 的卖点，长序列才是。 76.1% 对 72.2% 的差距固然可观，但 Vim-S/B 与 DeiT 同级模型的差距只有零点几到几个点，甚至出现论文表格与 README 的 80.3/80.5 这类小分歧。真正干净的优势证据是那条吞吐/显存数字：同一任务上 2.8 倍速度、86.8% 显存下降，且它只在 $M$ 很大时出现。$512\times512$ 起测、$1248\times1248$ 才拿到这个倍数，正是二次项开始主导的区间。

其二，消融把「双向」的价值定位在密集预测，而非分类。 单向到双向，ImageNet 只涨 0.7 个点（73.2→73.9），但 ADE20K mIoU 从 32.3 涨到 35.9（+3.6）。这个不对称很好解释：分类只需一个全局向量，单向递推到末端也能攒够信息；分割要每个位置都正确，只看「前方」的 patch 位置拿不到「后方」上下文，误差直接落到边界与前景上。读到这里可以得出一个对病理有用的判据：评估骨干是否适配 WSI，绝不能只看 tile 级分类准确率，要看像素级/区域级任务的 mIoU。

其三，class token 放中间最优（76.1）这条结论，透露了顺序敏感的本质。 放在序列头部时，它只在正向链的起点、反向链的终点，任何一层中「看过」的信息都不完整；放中间则双向链各覆盖一半序列，与「目标常在图像中央」的先验叠加。这属于典型的「架构约束反过来决定设计选择」，也印证 3.1 节的判断：扫描顺序不是实现细节，而是模型的主要归纳偏置来源。

关于「理论 $M/(4N)$ 量级、实测 2.8 倍」的巨大落差，笔者按论文的两个复杂度式做了一次自算：注意力 $4MD^{2}+2M^{2}D$、SSM $3M(2D)N+M(2D)N$，在 $M=6084$、$D=192$、$N=16$ 下比值约 $(2D+M)/(4N)\approx 100$。这是笔者的推演量级，不是论文结论。 实测只有 2.8 倍，说明浮点量之比远不等于墙钟时间之比：注意力是大矩阵乘、能被张量核心吃满，扫描是小规模逐元素与并行归约、更受内存带宽与核启动支配；加上卷积形式与扫描形式的实现差异，以及 kernel 融合的程度。结论是：线性复杂度的收益要用「能不能跑得下」来衡量，不要用「快多少倍」来衡量。

五、对病理图像分析的启示（本节以笔者推演为主）

先声明边界：论文本身没有做 WSI、没有做任何病理实验，原料提到的病理相关数字未能核实。本节全部内容属笔者基于已核实事实的外推，不构成文献结论。

可核实的事实只有三条：Vim 的序列开销随 $M$ 线性；同一批推理下它相对 DeiT 省 86.8% 显存、快 2.8 倍（$M=6084$）；双向与单向的差距主要显现在分割 mIoU 上。把这三条接到 WSI 上，可以做量级推算。

末行说明了两件事。第一，「把一整片 WSI 当成一个序列喂进去」这条路，线性复杂度也救不了：$10^{7}$ 个 token 就算开销只是线性，权重梯度、优化器状态与 patch 级标注仍然爆炸，一次前向在单卡上不成立。第二，$M$ 在 $10^{3}\sim10^{4}$ 这一段——也就是 tile 级或若干 tile 拼接的任务——恰好是 Vim 已经给出 2.8 倍 / 86.8% 证据的区间，这是病理工作真正能吃到红利的尺寸。

由此给出笔者在单卡显存受限条件下的可行性判断：

  1. 优先把 SSM 骨干放在 tile 级与区域级，而不是全片级。 $4096$ 到 $6084$ 的序列长度有实测的显存/吞吐优势支撑，全片级没有任何支撑，只能靠层级聚合（tile 编码 → slide 聚合）绕过，这是既有 MIL 范式的问题，与骨干选型无关。
  2. 像素级任务应作为主要验收判据。 依据是第四节的非对称消融：分类几乎不掉，分割掉 3.6 个 mIoU。若只报 tile 分类 AUC，很可能得到一个「看起来没问题」但定位能力差的选择。
  3. 扫描顺序需要针对组织结构重想。 Vim 的行优先双向扫描对自然图像够用，但病理结构常有强方向性（腺管排列、间质条带、切片长轴）。方向偏置带来的后果是「沿扫描方向连续的结构被充分建模，垂直方向靠反向链补」，这不是玄学问题，而是 3.1 节位置嵌入讨论过的顺序敏感性的直接放大。VMamba 式多向扫描是一个可核实的、更稳的替代选项。
  4. 线性复杂度让「大感受野 + 高分辨率」同时成立。 这是虚拟染色类任务真正的机会：需要区分染色质细节（要高分辨率）又需要判断区域语境（要大感受野）。用二次复杂度的骨干，这两者互斥；换成线性骨干，可以在同一 tile 上把感受野推到接近全局。但这条推演的强度只到「可能」，具体收益必须实验测。

六、局限与下一步

论文层面的局限（可从已核实内容读出）

  1. 与位置先验强绑定：class token 置中优于置首这类结论，依赖「目标在图像中央」的数据集先验，换成 WSI 这类目标分布极不均的输入并不必然成立。
  2. 纯 SSM 不含显式的 token-token 交互，隐式相关难以验证，因而难以诊断「哪一段上下文丢了」；后续出现的专门分析/修补这类问题的工作，原料曾列举数篇（如名为 Vision Mamba Mender 一类），笔者未能核实其存在与结论，本文不予采信。
  3. 吞吐优势只在高分辨率区间体现，中小分辨率下与高效 ViT 的差距有限；Vim-S/B 与 DeiT-S/B 的精度差就是这个证据。
  4. 分层变体的具体配置在本文里仍是「待复核」状态。

笔者下一步要做的事

  1. 在自己数据的 tile 尺寸（$1024\times1024$，$M=4096$）上，实测 Vim-Ti 与 DeiT-Ti 的峰值显存与吞吐，把 2.8 倍/86.8% 换成自己环境下的数，而不是照搬论文条件。
  2. 把双向扫描与多向扫描（VMamba 一类）在同一分割任务上做对照，检验第五节第 3 条关于方向偏置的推演。
  3. 复核 $\overline{B}\approx\Delta B$ 近似在代码里的实际实现（读 vim 目录与 mamba 依赖的状态更新核），确认本文用的递推式与实现一致。
  4. 关注 Mamba-2（Transformers are SSMs，arXiv:2405.21060）建立的注意力与 SSM 对偶关系：若两者在数学上同族，那么「注意力能做的事 SSM 做不了」这类担忧可以被更准确地刻画，对病理骨干选型的判断也会更清楚。
