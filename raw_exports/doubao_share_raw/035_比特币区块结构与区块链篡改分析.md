# 题目整体严谨分析
> 分为A、B两大任务，核心考察**比特币区块内部结构**、**区块链链式哈希绑定原理**、**篡改攻击与最长链规则**，属于区块链基础课程标准作业题。
> 你的学号尾号：**0（偶数）** → A部分目标区块区块体需要画 **8笔交易**，其中包含1笔coinbase交易。

## 任务A：比特币区块内部结构图分析
### 核心硬性要求逐条拆解
1. **整体是一张完整图，不是多张碎片图**
    整张图包含**连续3个区块：父区块、目标区块、子区块**，视觉重心放在【目标区块】。
2. 区块关系：
    - 标注3个区块各自**区块高度**；
    - 画出区块之间**逻辑链式关系+时间先后关系**：父区块（更早生成）→目标区块→子区块（后生成）。
    - 逻辑关系：**目标区块头内的父区块哈希 = 父区块的区块哈希**；子区块头内父区块哈希 = 目标区块的区块哈希。
3. **每个区块都要拆分：区块头 + 区块体（头体分离）**
    每个区块都要列出区块头全部字段，重点标注：
    > 父区块哈希值：位置、作用、跨区块联系
    - 区块头标准字段（比特币原生）：
      1. 版本号 Version
      2. 父区块哈希 Previous Hash（重点标注项）
      3. 默克尔根 Merkle Root
      4. 时间戳 Timestamp
      5. 难度目标 Bits
      6. 随机数 Nonce
    - 区块体：存放交易集合
    - 父区块哈希：**位于区块头第2项**
      - 作用：存储上一个区块的完整哈希摘要；
      - 区块联系：把当前区块和前置区块密码学绑定，一旦上一个区块内容改动，哈希改变，本区块父哈希校验失败，链条断裂。
4. 目标区块区块体：绘制**默克尔树**，标注coinbase交易
    - 你学号尾号偶数 → 一共**8笔交易**：Tx0=Coinbase交易（挖矿奖励交易，无输入），Tx1~Tx7共7笔普通转账交易。
    - 默克尔树规则：叶子节点=每一笔交易哈希；两两向上哈希，最终得到**默克尔根，写入区块头**。

> A图逻辑主线：
> 父区块（高度H-1）→【目标区块H（重点展示头体+6个头字段+8交易默克尔树）】→子区块（高度H+1）

## 任务B：比特币区块链篡改攻击示意图（多幅图，箭头串联变化前后）
一共4张子图，用箭头表达状态演变，可配色突出被篡改部分/断裂哈希：
1. **图1：正常主链，至少5个区块**
    区块高度：H1、H2、H3、H4、H5
    每个区块头标注：父区块哈希。
    正常状态：每个区块的`Previous Hash`严格等于上一区块哈希，链条完整。

2. **图2：黑客篡改第3区块（H3）内部交易数据**
    - 修改H3交易 → H3区块体变化 → H3默克尔根变化 → **H3区块整体哈希改变**
    - 但是H4的区块头里的父区块哈希仍然是**原来H3旧哈希**
    - 结果：H3和H4之间哈希校验不匹配，**链条直接断裂**；H4、H5不再属于篡改后的H3这条链。
    ✅重点：只改H3交易，不改后面区块，链在H3-H4处断开。

3. **图3：黑客继续修改后续H4、H5区块参数，尝试修复断裂**
    黑客手动修改H4区块头的父哈希，改成篡改后新H3哈希；
    再重新寻找Nonce，重新挖矿算出H4新哈希；
    再修改H5父哈希为新H4哈希，重新挖矿算出H5新哈希。
    > 此时黑客已经构造出一条**私有的备选链**，但是这条链长度暂时和主链一样或者更短。

4. **图4：黑客篡改成功，私链超越主链（最长链规则）**
    比特币共识：**最长有效链作为主链**。
    黑客需要：在全网正常矿工持续挖矿的同时，**算力超过全网50%（51%攻击）**，持续在私有链上打包新区块，让黑客的链长度超过原来全网主链。
    当黑客链更长，全网节点会切换主链，承认篡改后的链，篡改攻击生效。

### B任务核心考点总结
- 篡改任意区块交易 → 区块哈希改变，直接破坏后续所有区块的父哈希引用；
- 只改一个区块没用，必须**重新工作量证明（找到有效Nonce）**，逐个重算后面所有区块；
- 想要替换主链，必须算力优势，让恶意链变成最长链。

# 两个任务的内在关联
- A是**静态单区块+相邻区块的内部结构**，看懂区块内部字段、默克尔树、哈希链式绑定；
- B是**动态攻击演示**：利用A学到的「父哈希绑定、区块哈希依赖区块内容」原理，演示篡改会破坏链条，以及51%攻击原理。

# 额外注意易错点（写图注/答题时避免踩坑）
1. Coinbase交易**只能是区块第一笔交易**，默克尔树最左侧叶子节点，不能放在中间；
2. 默克尔树：交易数量为偶数（8笔），不需要复制叶子节点补齐；如果奇数才需要复制最后一笔；
3. 区块哈希≠默克尔根：默克尔根只是区块头的其中一个字段，区块哈希是**对整个区块头做哈希**；
4. 父区块哈希存放在**当前区块头**，不是存在上一个区块；很多同学容易画反；
5. B任务中：不是“修改参数就成功”，每修改一个区块，都要重新做PoW，找到合法Nonce，不是随便改数字。

## A. 比特币区块内部结构（文字作答）

### 1. 整体图形说明
整张图是**一幅完整的连续链结构图**（不是分散的多幅图）：从左到右依次画出**父区块 → 目标区块 → 子区块**三个首尾相连的区块，视觉重心放在中间的目标区块；目标区块下方单独展开它的**默克尔树**，树根（默克尔根）用连线指回目标区块头，使全图成为一个整体。

### 2. 三个连续区块：高度、时间关系、逻辑关系

设目标区块高度为 **H**，则：

| 位置 | 区块高度 | 时间戳（生成先后） | 在链中的角色 |
|---|---|---|---|
| 父区块 | H−1 | t₍H−1₎（最早） | 目标区块引用的上一个区块 |
| **目标区块** | **H** | t_H（居中，晚于父、早于子） | 重点展示对象 |
| 子区块 | H+1 | t₍H+1₎（最晚） | 引用目标区块的下一个区块 |

- **时间关系**：t₍H−1₎ < t_H < t₍H+1₎，区块按时间先后依次打包，后出块的排在右边。
- **逻辑关系（哈希链式绑定）**：
  - 目标区块 H 的「父区块哈希」= 父区块 H−1 的区块哈希，记为 `PrevHash(H) = Hash(H−1)`；
  - 子区块 H+1 的「父区块哈希」= 目标区块 H 的区块哈希，记为 `PrevHash(H+1) = Hash(H)`；
  - 每个新区块只向前引用紧邻的上一个区块，层层相扣，一直追溯到创世区块。

### 3. 每个区块：头体分离 + 全部参数字段

每个区块都分成**区块头（Header）**和**区块体（Body）**两部分。

**（1）区块头共 6 个字段：**

1. **Version 版本号**：协议版本，用于标识软件/规则版本。
2. **Previous Block Hash（父区块哈希 / 前一区块哈希）**【重点，见第 3 点专项说明】。
3. **Merkle Root（默克尔根）**：由区块体所有交易两两哈希算出的根哈希，写在头部，用于快速校验交易是否被篡改。
4. **Timestamp 时间戳**：矿工打包时的 Unix 时间，也是难度调整和出块时间判断的依据。
5. **Bits（难度目标）**：当前区块要求满足的难度阈值（目标值），决定 PoW 挖矿难度。
6. **Nonce（随机数）**：矿工不断尝试、直到区块头哈希满足 Bits 难度目标的那个随机值，即工作量证明（PoW）的解。

> 补充：**区块哈希 = 对整个区块头做双 SHA256（SHA256d）得到的摘要**，不是只哈希交易；默克尔根只是区块头中的一个字段。

**（2）区块体（Body）**：存放本区块打包的**全部交易列表**，第一笔固定是 Coinbase 交易，其余为普通转账交易。

#### 重点专项：父区块哈希（Previous Block Hash）

- **位置**：位于**当前区块自己的区块头第 ② 项**（注意：它存在于新区块里，而不是父区块里）。目标区块 H 的该项存放的是父区块 H−1 的哈希。
- **作用**：把本区块与前一区块**密码学绑定**。父区块任何内容（交易、默克尔根、Nonce、时间戳等）一旦改变，父区块哈希就会改变，本区块的 Previous Hash 立即校验失败，链条断裂。它是区块链「不可篡改」的技术根基。
- **与其他区块的联系（双向引用）**：
  - 向前：`PrevHash(H) = Hash(H−1)`，指向父区块；
  - 向后：目标区块自己的区块哈希 `Hash(H)`，又被子区块 H+1 的 Previous Hash 引用；
  - 沿此关系向前追溯，最终到达创世区块，创世区块的 Previous Hash 为全 0。

### 4. 目标区块体的默克尔树与 Coinbase 交易

**（1）交易笔数规则**
- 学号尾号**偶数**：区块体共 **8 笔**交易；
- 学号尾号**奇数**：区块体共 **7 笔**交易（奇数时需把最后一笔交易复制一份补齐到偶数层再合并）。

以下按**偶数 8 笔**作答：Tx0～Tx7。

**（2）Coinbase 交易标注**
- **Tx0 是 Coinbase 交易（挖矿奖励交易）**，固定排在交易列表第 0 位、默克尔树**最左侧叶子**；
- 它没有普通交易输入（输入为 Coinbase 特殊字段），输出为矿工获得的出块奖励＋手续费，是矿工挖矿的收益来源。

**（3）默克尔树构造（8 笔交易，H = SHA256d(左 ∥ 右)）**

- **叶子层（8 个交易哈希）**：
  `H(Tx0)`、`H(Tx1)`、`H(Tx2)`、`H(Tx3)`、`H(Tx4)`、`H(Tx5)`、`H(Tx6)`、`H(Tx7)`，其中 `H(Tx0)` 即 Coinbase。
- **第 1 层（两两合并，4 个节点）**：
  - `H1 = H(H(Tx0) ∥ H(Tx1))`
  - `H2 = H(H(Tx2) ∥ H(Tx3))`
  - `H3 = H(H(Tx4) ∥ H(Tx5))`
  - `H4 = H(H(Tx6) ∥ H(Tx7))`
- **第 2 层（2 个节点）**：
  - `H5 = H(H1 ∥ H2)`
  - `H6 = H(H3 ∥ H4)`
- **树根（默克尔根 Merkle Root）**：
  - `Merkle Root = H(H5 ∥ H6)`

**（4）树根去向**：算出的 Merkle Root 写入目标区块头第 ③ 字段；任何一笔交易改动，其叶子哈希改变，会逐层向上影响到默克尔根，进而被头部校验发现。

> 若为奇数 7 笔：叶子为 Tx0～Tx6，合并到只剩 `H(Tx6)` 单个节点时，将其**复制一份**再两两合并，补齐成偶数层，最后同样得到一个默克尔根写入区块头。
