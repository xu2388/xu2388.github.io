## 含义解释
> **问题：StainFuser 在推理时反复重试，但不会自动补全依赖包**
> 现象：模型一遍一遍启动 StainFuser 推理，**每次只碰到一个缺失依赖报错**，程序不会自动安装依赖，也不会重置环境，陷入循环重试。

### 原因
1. 环境缺少运行StainFuser所需的python包（比如某些torch、opencv、tifffile等病理图像相关依赖）
2. 代码的**异常捕获逻辑**写的有问题：捕获到`ImportError`之后，**没有终止流程、没有安装依赖，只是简单重试推理**，所以反复触发同一个类别的报错，一次只暴露一个缺失包。

### 解决办法
1. 手动提前一次性安装全部依赖，不要靠跑推理来碰缺包
```bash
pip install -r requirements.txt
```
2. 检查代码里的重试逻辑：**依赖缺失属于不可重试错误**，碰到ImportError应当直接退出，不要继续循环重试。
3. 你这个终端界面是某个AI助手/代理工具自动生成bug报告的交互窗口：
    - 按`1`：查看完整bug详情
    - 按`2`：提交这份bug报告
    - 按`0`：关掉这条提示

# ✅ 问题定位（你说的是 **Claude Code**，不是cludecode）
你截图就是 Claude Code 终端 agent 卡住的典型现象：
它在跑 StainFuser 推理脚本，**每次执行只遇到1个缺失依赖包 → 抛出异常 → 自动重试**，但**不会主动安装依赖**，无限循环，看起来就是“不干活”，一直在原地重试、反复触发同一个类型的错误，还自动生成bug报告。

## 为什么卡住不推进
1. **Agent默认重试机制**：Claude Code 遇到命令执行失败，默认会重试任务；它分不清「临时报错」和「环境缺包这种硬故障」，缺包属于**不可重试错误**，但它仍然反复启动推理。
2. 逻辑误区：它以为多跑几次推理就能好，但是不会自动执行 `pip install` 补依赖，所以每次只会爆出下一个缺失包，循环卡死。
3. 界面提示：`1 to review • 2 to send • 0 to dismiss` 是它内置bug报告弹窗，正在排队，阻塞下一步任务。

## 立刻修复方案（按顺序操作）
### 1. 先关掉这个bug弹窗
在当前终端直接按 `0` → dismiss（关闭bug报告），停止队列阻塞。

### 2. 终止卡死的agent任务
```bash
# 快捷键退出当前claude会话
Ctrl + C
```
> 如果还停不住，用 `Ctrl+X` 杀掉agent子进程（Claude Code专用）

### 3. 提前一次性装好StainFuser全部依赖（根治根源）
进入你的StainFuser项目环境，执行
```bash
pip install -r requirements.txt
```
> 这一步最重要，不要让Claude边跑边碰缺失包，环境预先准备好。

### 4. 限制Claude Code重试次数，防止再次死循环
启动Claude Code的时候，设置环境变量，减少重试次数：
```bash
# Linux / Mac 终端
export CLAUDE_CODE_MAX_RETRIES=1
claude
```
这个配置意思：**命令失败最多重试1次，不再无限重试**，碰到缺包直接停止，而不是原地循环。

### 5. 给Claude加指令约束（下次prompt开头加上）
> 任务规则：如果执行代码出现 ImportError / 缺失python包，**立刻停止任务，优先执行pip安装，禁止重复重试推理脚本**。

## 备选排查
- 检查虚拟环境：确认Claude使用的python环境，和你手动`pip`安装包的环境是同一个，经常出现**装到base环境，agent在conda子环境里运行**，包找不到。
- 权限：如果是AutoDL远程服务器，看pip有没有权限安装包。
