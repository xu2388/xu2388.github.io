### DeepSeek

目前，自回归模型在时序预测领域的研究正从传统的统计方法和专用深度学习模型，快速转向**大规模预训练时序基础模型**（Time Series Foundation Models）和**与大语言模型（LLM）的结合**。下面从科研方向、代表性模型以及权威公开数据集三个方面为你梳理。

---

### 一、前端科研方向

1. **时序基础模型（零样本/少样本预测）**  
   受NLP中GPT等自回归模型的启发，研究人员试图构建通用的时序预测模型：在海量、异构的时间序列上进行预训练，然后对未见过的数据进行零样本（zero-shot）或少量微调（few-shot）预测。核心是设计合适的序列分块（patch/token）策略，再用因果自回归Transformer进行生成式预测。

2. **大语言模型适配时序数据**  
   冻结部分预训练LLM（如Llama、GPT-2），仅训练轻量级的输入/输出映射层，将时间序列“翻译”成LLM能理解的形式；或对LLM进行全量/部分微调。这类工作通常保留自回归生成方式，让模型逐token预测未来序列。

3. **概率与生成式自回归预测**  
   不仅预测点值，还要输出概率分布（如DeepAR预测高斯/负二项分布参数）。前沿工作还包括将扩散模型与自回归结合、自回归归一化流等，用于刻画不确定性。

4. **多粒度、多通道的自回归架构改进**  
   - **多patch自回归**：一次预测一个patch（多个时间步），而非单个点，以提升长序列预测的效率和稳定性。  
   - **通道独立与通道混合**：如何在多变量时间序列中处理通道间依赖，同时保持自回归解码的高效性。  
   - **变长序列与多频率融合**：让同一自回归模型处理不同采样频率的数据。

5. **多模态/指令驱动的时序预测**  
   结合文本描述、新闻事件等，让自回归模型在预测时条件化于模态对齐后的上下文，实现可控生成。

### 二、代表性工作和模型

#### 新兴自回归基础模型
- **TimesFM (Google, 2024)**  
  解码器仅模型（decoder-only），将时间序列分割为固定长度patch，加入位置编码，以自回归方式逐patch预测未来。在大规模合成和真实数据上预训练，展示了出色的零样本长期预测能力。

- **Lag-Llama (2023)**  
  基于LLaMA结构，使用序列的滞后特征（lag features）作为输入，通过自回归解码输出下一时间步的分布参数。这是早期探索用开源LLM做时序基础模型的工作，支持概率预测。

- **Chronos (Amazon, 2024)**  
  将时间序列缩放并分箱（binning）为固定词汇量的token，然后直接以T5等语言模型的自回归训练方式学习序列生成。预训练集整合了大量公开数据，零样本性能优异。

- **Moirai (Salesforce, 2024)**  
  统一的掩码编码器与自回归解码器混合架构。用多patch投影层处理异频时序，构建大规模开源数据集LOTSA进行预训练，支持跨频率、跨领域的通用预测。

- **Timer (THU, 2024)**  
  以GPT风格的自回归Transformer直接生成未来序列的patch，用大规模时序数据集预训练，既可零样本预测，也能针对下游任务微调，强调可扩展性。

- **Time-MoE (2024)**  
  将混合专家（MoE）引入自回归时序基础模型，用稀疏激活的方式扩大模型容量，同时保持推理高效，旨在实现更具规模和多样性的通用预测。

#### 经典及深度学习自回归模型（仍常作比较基准）
- **DeepAR (Amazon, 2020)**  
  基于自回归循环网络（LSTM）的概率预测模型，逐时间步输出分布参数，广泛应用于电商供应链等场景。
- **Transformer自回归解码变体**  
  Informer、Autoformer等模型虽非纯粹自回归基础模型，但都采用逐步解码生成预测序列；**PatchTST**虽以编码器+线性头直出多步结果，但其通道独立/分patch思想极大影响了后续自回归基础模型的设计。

### 三、权威公开数据集

#### 常规基准（科研论文必测）
这些数据集规模中等，非常经典，几乎所有模型都会用来对比：

- **ETT (Electricity Transformer Temperature)**  
  包含4个子集：ETTh1, ETTh2, ETTm1, ETTm2，记录电力变压器的油温与外部特征，是最常用的长序列预测基准。
- **Electricity**  
  UCI发布的家庭用电负荷数据，321个客户，15分钟采样。广泛用于多变量预测。
- **Traffic**  
  PEMS系统采集的旧金山高速路网占用率数据，862个传感器，每小时采样，典型的高维序列。
- **Weather**  
  德国耶拿气象站的21项气象指标，10分钟采样，常用于多变量预测。
- **Exchange (Exchange Rate)**  
  8个国家货币兑美元的日汇率，适合做长序列自回归预测。
- **ILI (Influenza-like Illness)**  
  美国CDC流感样疾病周就诊比例，小样本，常用于测试模型小数据适应能力。

#### 竞赛与大规模数据集合
- **M4 Competition Dataset**  
  包含100,000条不同频率（年、季、月、周、日、时）的宏观/微观经济、金融、工业序列，是检验通用预测能力的金标准。
- **M5 Competition Dataset**  
  沃尔玛零售数据，包含42,840条分层的销售序列，适合多层级概率预测。
- **Monash Time Series Forecasting Archive**  
  由莫纳什大学整理，涵盖30个不同领域的公开数据集，包含交通、能源、销售、天气等，是目前最权威的时序预测基准集之一，很多自回归基础模型用它做预训练或评估。

#### 大规模预训练数据集（基础模型专用）
- **LOTSA (Large Open Time Series Archive)**  
  伴随Moirai模型发布，整合了来自能源、交通、气候、Web等领域的几十个公开数据集，统一处理后包含数十亿个时间点，是目前最大规模的开源时序预训练集。
- **GluonTS常用数据集集合**  
  Amazon GluonTS框架提供了一大批统一格式的数据集，包括很多上面提到的数据集以及Kaggle上的竞赛数据，Chronos等模型会直接使用这些集合进行预训练。
- **TimesFM的合成数据 + 内部数据**  
  TimesFM的预训练使用了大量合成生成的趋势、季节性序列和Google内部的真实时序数据（未完全开源），但官方提供了预训练权重及评估代码。

### 一、文本生成：用 RNN 做 Char-RNN
这是最经典的 RNN 生成实验，能帮你深刻理解“自回归”的每一步是怎么预测下一个 token 的。

- **任务描述**  
  给模型一段文本，让它以字符（或单词）为单位，学习 `P(下一个字符 | 历史字符)`，然后逐字符采样生成新文本。
- **推荐数据集**  
  - **莎士比亚作品集**（Tiny Shakespeare）  
    - Karpathy 的 Char-RNN 经典示例，整个文本才 1MB 左右。  
    - 你可以在网上搜 `tinyshakespeare.txt`，很多深度学习教程都会用到。  
  - **尼采文集**  
    - Keras 官方示例中的文本生成就用的尼采著作。
  - **自己的聊天记录 / 本地小说**  
    - 完全可以用几 MB 的纯文本文件上手，效果直观。
- **模型结构建议**  
  - 1~2 层 LSTM / GRU，隐层大小 256~512。  
  - 输入输出都是 one-hot 或 Embedding，交叉熵损失。  
  - 生成时：给定一个起始字符串，不断把预测的字符喂回模型，得到下一个字符。
- **可以直接跑的现成代码**  
  - Keras 官方示例：《Text generation with an RNN》
  - PyTorch 官方教程：NLP From Scratch - Classifying Names with a Character-Level RNN（可改成生成式）

### 二、时序预测：用 RNN 做单变量/多变量预测
这是 RNN 最擅长的领域之一，你可以从最简单的单步预测一直做到多步自回归预测。

#### 1. 入门必做：经典单变量预测
- **任务**：给定过去 12 个月的数据，预测未来 1 个月或多个月的值。
- **推荐数据集（全部公开，可直接下载）**
  - **Air Passengers**  
    1949-1960 年月度国际航空乘客数。只有一个序列，144 个时间点。最适合跑通第一个时序实验。
  - **Monthly Sunspots**  
    1749-1983 年月均太阳黑子数，有周期性，可考验模型捕捉长期模式的能力。
  - **Daily Minimum Temperatures**  
    墨尔本十年每日最低气温，3650 个点，有很强年周期性。
  - **所有上面这些数据，都可以在 `pmdarima` 库或 `statsmodels` 库中直接加载。**  
- **实验形式**
  - 单步预测：用 [t-11, t] 预测 t+1。
  - 多步自回归预测：训练时还是单步，测试时把预测的值作为输入，逐步滚出未来多步曲线。

#### 2. 进阶：多变量概率预测（DeepAR 风格）
如果你不满足于简单点预测，可以试试 RNN 的经典大作 **DeepAR**（自回归概率预测）。
- **核心思想**  
  LSTM 每步输出的是未来值的概率分布参数（如高斯分布的 μ 和 σ），然后用极大似然训练。测试时一步步采样得到多条未来轨迹，形成置信区间。
- **方便的工具**  
  - **GluonTS**（亚马逊）  
    一行代码加载 Air Passengers 等数据，内置 DeepAR 模型。你可以先用它的高层 API 调通，再细看 LSTM 自回归的实现细节。
- **推荐数据集**  
  - 依然可以从 Air Passengers 开始。  
  - 然后试试 **Electricity**（UCI，321条序列）或 `m4_hourly` 子集，这些都可以在 GluonTS 里直接 `get_dataset`。

### 一、时序预测：从 LSTM 到现代循环状态模型

虽然基础模型多基于 Transformer，但近年有一系列工作证明，改进的循环神经网络不仅能打，甚至在长序列预测上更高效。

#### 1. xLSTM-Time (2024)
这是最具代表性的工作之一，直接来自 LSTM 之父 Sepp Hochreiter 团队提出的 **xLSTM（Extended LSTM）**。
- **核心改进**：xLSTM 在原 LSTM 基础上引入了指数门控和矩阵记忆单元，推出了两种新变体：
  - **sLSTM**（标量记忆）：保留传统记忆模式，增加指数门控和状态更新，擅长处理非马尔可夫过程。
  - **mLSTM**（矩阵记忆）：用矩阵替代记忆细胞，具备并行计算和长期存储能力。
- **用于时序**：**xLSTM-Time** 将时间序列分 patch，然后送入 xLSTM 编码器，最后通过线性头预测。它在长序列预测基准上超越了 PatchTST、DLinear 等 Transformer 和线性模型，成为 2024 年时序领域的一大亮点。
- **意义**：证明了经过现代化改造的 LSTM 依然是时序预测的一线选手。

#### 2. 状态空间模型（SSM）的入侵：Mamba 和 S4
SSM 可视为连续信号下的循环网络。**Mamba**（带选择性扫描的状态空间模型）在 2023 年底引爆了线性复杂度序列建模。
- **S-Mamba (2024)**：将 Mamba 引入多变量时序预测，设计通道混合策略，在多个经典数据集上超越 Transformer 模型。
- **MambaStock、TimeMachine** 等：大量涌现的工作将 Mamba 用于金融、天气预报等时序任务，核心卖点是**训练和推理效率远超 Transformer**，且擅长捕获极长期依赖。
- **S4 及其变体**：此前，S4 系列（如 S4，S5）已被用于长距离时序分类和预测，可视为 Mamba 的前身。

#### 3. RWKV-TS (2024)
**RWKV** 本身就是一种结合 RNN 和 Transformer 优点的架构（线性注意力+循环推理），常被称为“RNN 式的 GPT”。  
- **工作**：研究者将 RWKV 适配到时序预测，通过分 patch 和修改位置编码，在长序列预测上取得有竞争力的结果，且与 RWKV 做文本一样，推理时是标准的自回归循环过程，占用恒定内存。

**小结趋势**：时序预测的前沿正在从“唯 Transformer”转向“高效循环状态模型”，xLSTM、Mamba、RWKV 是最值得关注的三驾马车。

### 二、对话补全：RNN 式大语言模型的逆袭

对话补全本质就是自回归文本生成。过去这完全是 Transformer Decoder（如 GPT）的领地。但现在，为了打破自注意力机制的二次复杂度和高昂推理成本，以下“循环式”架构正以 LLM 的形态直接做对话，效果惊人。

#### 1. RWKV（鹰眼）系列
是最早以 RNN 姿态正面挑战 Transformer 的 LLM。
- **核心思想**：将注意力分解为“接收”和“加权键值”，在训练时并行得像 Transformer，推理时却能转换为类似 RNN 的循环模式，逐 token 生成，内存和计算量恒定。
- **前沿版本**：RWKV-5/6（Eagle/Finch 架构）已发布 7B 到 14B 参数级别的模型，训练数据达数万亿 token。在对话、故事生成等任务上，其性能非常接近同规模的 LLaMA 等 Transformer 模型，但**推理速度更快、显存占用更低**，尤其擅长长文本对话。
- **开源生态**：有完备的 Chat RWKV 的微调方案，可以直接部署体验类 ChatGPT 的对话能力，完全基于类 RNN 架构。

#### 2. Mamba 及混合架构对话模型
- **Mamba-Chat**：社区迅速将 Mamba 架构用作对话模型的基座，比如训练 Mamba-2.8B 对话模型。Mamba 天生就是循环推理模式，处理长上下文非常高效。
- **Hawk/Griffin**：DeepMind 在 2024 年提出 **Griffin** 架构，混合了门控线性循环单元（Hawk，一种新型 RNN）和局部注意力，实现了强力语言模型。它完全能胜任对话补全，且被证实可以用极少的注意力层获得强劲的性能。
- **Jamba**：AI21 Labs 推出的混合 Transformer-Mamba 模型（SSM-Transformer 混合），同样是对话模型的有力竞争者，结合了两种架构的优势。

#### 3. xLSTM 做语言模型
Hochreiter 团队也已将 xLSTM 扩展到数十亿参数，训练语言模型，并进行对话和补全任务。他们证明了 mLSTM 在语言建模复杂度上已能匹配同规模的最佳 Transformer，验证了其作为下一代 LLM 骨干的潜力。

**小结趋势**：在对话补全领域，前沿正经历一场“去 Transformer 中心化”。**RWKV 和 Mamba 是当前类 RNN 架构中，最成熟、最接近实用对话系统的代表**。它们让端侧部署大模型成为可能，因为你可以像用传统 RNN 一样，恒定内存、一步一 token 地生成对话。

## 一、时序预测

### 1. 常用评价指标
- **MSE / RMSE**：均方误差 / 均方根误差，最基础。
- **MAE**：平均绝对误差。
- **MAPE / sMAPE**：平均绝对百分比误差 / 对称MAPE，对尺度不敏感。
- **MASE**：平均绝对尺度误差，常用于M4竞赛等。
- **CRPS** (连续分级概率评分)：用于概率预测，评价分布预测的好坏（DeepAR、Lag-Llama等常用）。
- **ND** (归一化偏差)：在电力、交通等多序列场景中偶尔出现。

### 2. 权威数据集
| 数据集 | 描述 | 常用场景 |
|--------|------|----------|
| **ETT (4个子集)** | 电力变压器温度，长序列预测标配 | 长序列自回归预测 |
| **Electricity** | 321个客户用电负荷，15分钟采样 | 多变量预测 |
| **Traffic** | 862个传感器的高速路占用率 | 高维多变量预测 |
| **Weather** | 21个气象指标，10分钟采样 | 多变量预测 |
| **Exchange Rate** | 8国日汇率 | 单步/长序列 |
| **ILI** | 美国流感周数据，小样本 | 少样本适应性 |
| **M4 Competition** | 10万条不同频率序列 | 通用预测能力金标准 |
| **Monash Archive** | 30个领域27个数据集 | 跨领域基准 |

### 3. RNN系列模型SOTA迭代史（含论文+GitHub）
从传统LSTM到现代循环状态模型，演进路径如下：

#### ① 奠基之作：LSTM与DeepAR
- **Vanilla LSTM/GRU**：简单编码器-解码器，单步/多步自回归预测。
- **DeepAR** (Amazon, 2020)  
  - **贡献**：引入概率预测，LSTM自回归输出分布参数（高斯/负二项），极大似然训练。  
  - **论文**：[DeepAR: Probabilistic forecasting with autoregressive recurrent networks](https://arxiv.org/abs/1704.04110)  
  - **GitHub**：官方实现在GluonTS：`https://github.com/awslabs/gluonts` (模型位于 `gluonts.model.deepar`)

#### ② 改进的多尺度RNN
- **LSTNet** (2018)  
  - **贡献**：结合CNN捕捉短期模式，LSTM捕捉长期趋势，加入跳层连接处理周期性。  
  - **论文**：[Modeling Long- and Short-Term Temporal Patterns with Deep Neural Networks](https://arxiv.org/abs/1703.07015)  
  - **GitHub**：`https://github.com/laiguokun/LSTNet`

#### ③ 当代RNN复兴：线性复杂度模型
**xLSTM-Time** (2024)  
- **核心**：基于xLSTM（指数门控+矩阵记忆），分patch时序预测，效果超越PatchTST等Transformer。  
- **论文**：[xLSTM-Time: xLSTM for Long-Term Time Series Forecasting](https://arxiv.org/abs/2405.10231)  
- **GitHub**：`https://github.com/NX-AI/xlstm` (包含xLSTM-Time代码，在 `xlstm` 项目内)

**S-Mamba** (2024)  
- **核心**：将选择性状态空间模型Mamba引入多变量时序，设计通道混合，效率与精度兼得。  
- **论文**：[S-Mamba: A Mamba-based Approach for Multivariate Time Series Forecasting](https://arxiv.org/abs/2402.05263)  
- **GitHub**：`https://github.com/wzhwzhwzh0921/S-Mamba`

**RWKV-TS** (2024)  
- **核心**：将RWKV的线性注意力+循环推理结构用于时序，实现高效长序列预测。  
- **论文**：[RWKV-TS: Beyond Transformers in Time Series Forecasting](https://arxiv.org/abs/2401.11442)  
- **GitHub**：`https://github.com/howardhuhwang/RWKV-TS`

#### ④ 概率/基础模型中的RNN精神
虽然Lag-Llama、Chronos等基础模型基于Transformer，但它们采用自回归解码，继承了RNN的生成范式。如果你想了解纯循环版本的基础模型，目前xLSTM-Time和RWKV-TS正在朝这个方向发展。

## 二、自回归文本生成（对话补全）

### 1. 常用评价指标
- **困惑度 (Perplexity, PPL)**：语言模型核心指标，越低越好。
- **BLEU / ROUGE**：用于参考文本与生成文本的重叠度，常用在对话评测。
- **F1 Score / Distinct-n**：对话特有的多样性、连贯性指标。
- **MT-Bench / Chatbot Arena**：用强LLM作为裁判打分的现代评估方式。
- **Human Eval**：人工评估流畅性、一致性等。

### 2. 权威数据集
- **语言建模基准**：
  - **WikiText-2 / WikiText-103**：维基百科文章，长依赖建模。
  - **Penn Treebank (PTB)**：经典小规模，快速实验。
  - **LAMBADA**：最后词预测，测试长期上下文。
- **对话/补全数据集**：
  - **DailyDialog**：日常多轮对话。
  - **PersonaChat**：带个性描述的对话。
  - **OpenWebText/WebText**：GPT-2风格大规模数据，用于预训练。
  - **The Pile**：包含多样化文本的大规模数据集，很多RNN类LLM在此上训练。

### 3. RNN系列模型SOTA迭代史（论文+GitHub）
这部分的演进完全围绕“用线性复杂度实现Transformer级质量”展开。

#### ① 传统RNN语言模型
- **LSTM/GRU LM**：逐token生成，受限于长序列梯度消失/爆炸。
- **AWD-LSTM** (2017)  
  - **贡献**：通过权重Dropout、自适应softmax等正则化技巧，将LSTM的PPL推到极致，一度是SOTA。  
  - **论文**：[Regularizing and Optimizing LSTM Language Models](https://arxiv.org/abs/1708.02182)  
  - **GitHub**：`https://github.com/salesforce/awd-lstm-lm`

#### ② 现代RNN革命：Transformer级性能
**RWKV系列** (2021-至今)  
- **核心**：线性注意力+循环推理，训练时并行如Transformer，推理时纯RNN恒定内存。最新RWKV-6 Finch架构。  
- **论文**：[RWKV: Reinventing RNNs for the Transformer Era](https://arxiv.org/abs/2305.13048) (RWKV-4)，后续版本见其官网。  
- **GitHub**：`https://github.com/BlinkDL/RWKV-LM` （包含预训练模型和对话微调）

**Mamba** (2023)  
- **核心**：选择性状态空间模型，线性时间复杂度，在许多语言任务上超越同规模Transformer。  
- **论文**：[Mamba: Linear-Time Sequence Modeling with Selective State Spaces](https://arxiv.org/abs/2312.00752)  
- **GitHub**：`https://github.com/state-spaces/mamba`  
- **对话版本**：社区发布过 `mamba-chat`，如 `https://github.com/havenhq/mamba-chat`

**xLSTM做语言模型** (2024)  
- **核心**：mLSTM（矩阵记忆）可扩展到数十亿参数，语言模型PPL匹敌Transformer。  
- **论文**：[xLSTM: Extended Long Short-Term Memory](https://arxiv.org/abs/2405.04517)  
- **GitHub**：`https://github.com/NX-AI/xlstm` (包含LM训练脚本)

**Griffin/Hawk** (DeepMind, 2024)  
- **核心**：Hawk纯线性RNN，Griffin混合门控线性循环与局部注意力，高效且强力。  
- **论文**：[Griffin: Mixing Gated Linear Recurrences with Local Attention for Efficient Language Models](https://arxiv.org/abs/2402.19427)  
- **GitHub**：`https://github.com/google-deepmind/recurrentgemma` (官方发布RecurrentGemma模型)

**Jamba** (AI21 Labs, 2024)  
- **核心**：Transformer+Mamba混合架构，兼顾质量和推理效率。  
- **论文**：[Jamba: A Hybrid Transformer-Mamba Language Model](https://arxiv.org/abs/2403.19887)  
- **GitHub**：`https://github.com/ai21labs/Jamba`

- **文本生成**：`LSTM → AWD-LSTM → RWKV → Mamba → xLSTM / Griffin / Jamba`

## 一、纯 RNN（LSTM/GRU）的内部结构：绝对没有卷积

一个标准的 RNN（包括基本 RNN、LSTM、GRU）在**单个时间步内部**的结构，本质上就是**几次矩阵乘法 + 激活函数（tanh/sigmoid） + 加法/逐元素乘法**，**完全没有卷积层**。

以 LSTM 为例，一个时间步内做的事情是：
1. 将当前输入 \(x_t\) 与上一个隐藏状态 \(h_{t-1}\) **拼接**起来，形成一个向量。
2. 用不同的**全连接层**（权重矩阵）分别算出：遗忘门、输入门、候选记忆、输出门。
3. 用这些门控信号更新长期记忆 \(c_t\) 和隐藏状态 \(h_t\)。

这里面每一步操作都是**矩阵乘法（全连接）**，没有滑窗、没有共享权重的卷积核。  
循环（Recurrent）指的不是内部结构有循环，而是指**整个单元在不同时间步之间，\(h_t\) 和 \(c_t\) 会循环传递给下一个时间步**。

---

## 二、为什么会有“RNN 里有卷积”的印象？

因为很多实际模型是 **“CNN + RNN” 的混合架构**，让你误以为 RNN 内部含卷积。主要有两种结合方式：

### 1. 前端用 CNN 提取局部特征，再送 RNN
这是时序和文本常见的操作：
- **时序**：先用一维卷积（Conv1D）在原始序列上滑窗，提取多个时间步的局部模式，然后将 CNN 的输出序列喂给 LSTM。LSTNet、TCN 等就是这样。
- **文本**：用 CNN 在词向量上提取 n-gram 特征，再送到 RNN 进行序列建模。

此时，**CNN 是 RNN 的预处理阶段**，并不是 RNN 单元内部的结构。

### 2. 循环单元内部嵌入“卷积操作”（很少见，但存在）
确实有论文把卷积塞进 LSTM 的门控计算里，比如 **ConvLSTM**（用于视频帧预测）：把全连接换成了卷积，这样就能同时保留空间和时序信息。但这已经是一种变体，不是标准的 LSTM，而且主要用于图像序列，不是我们讨论的普通时间序列预测。

---

## 三、你关心的 xLSTM、Mamba 里面有没有卷积？

- **xLSTM**：sLSTM 和 mLSTM 内部仍然是**全连接式的门控计算**，没有卷积。只是 mLSTM 把记忆细胞变成了矩阵，用矩阵乘法代替逐元素更新，提升记忆容量。
- **Mamba / S-Mamba**：属于**状态空间模型（SSM）**，它用一维卷积来做“局部状态扩展”，但卷积只在输入预处理阶段把当前 token 和周围几个 token 混合一下，核心的循环更新部分仍然不是卷积。

所以，你完全可以把标准 RNN 理解为：**一个通过循环连接实现时间记忆的全连接神经网络**，内部没有卷积层。你看到卷积的地方，一定是和 CNN 配合使用了。

### 一、CNN + RNN 做图像分类的几种方式

#### 1. 把图像当成“空间序列”来扫（注意力/顺序观察）
这是最经典的组合，模仿人眼看图的顺序：
- CNN 先提取图像的特征图（feature map）
- 将特征图按从左到右、从上到下切成一个个小块（patch），变成一个**空间序列**
- 用 LSTM/GRU 按顺序处理这个序列，最后输出分类结果

这种方式在早期被用于**街景门牌号识别（SVHN）**等多位数识别任务，效果很好。

#### 2. 多尺度特征序列化
CNN 不同层提取不同尺度的特征，将它们串联成一个“从局部到全局”的序列，再用 RNN 处理。

#### 3. 双向 RNN 捕捉全局上下文
图像不像文本有明确的单向顺序，所以常用**双向 LSTM（BiLSTM）**在 CNN 特征图上横向和纵向都扫一遍，让每个位置都能感知全局上下文。

### 二、这个组合的优势

| 优势 | 说明 |
|------|------|
| **捕捉空间依赖** | RNN 能看到 CNN 特征图上的长距离顺序关系 |
| **处理变长输入** | 图像尺寸不固定时，RNN 比全连接层更灵活 |
| **多标签分类** | RNN 自然输出一个标签序列，非常适合一张图有多个标签的场景 |

### 三、现代应用场景

虽然纯 CNN + RNN 在图像分类上已被 ViT、ConvNeXt 等超越，但在以下场景依然是首选：
- **多标签图像分类**：如一张电影海报要输出多个流派标签

- **医学影像**：病理切片常被切成 patch 序列，用 RNN 聚合信息
- **视频帧分类**：本质是图像序列，CNN 提取每帧特征，RNN 处理时间轴

---

## 二、模型架构

```
输入图像 (1,28,28)
  → CNN特征提取 (两层卷积+池化) → 特征图 (64,7,7)
  → 按行切分成空间序列：7 个时间步，每步 64×7 = 448 维向量
  → LSTM (隐藏层128) 处理序列
  → 取最后时间步的输出 → 全连接 → 10 分类
```

- **CNN 部分**：提取局部纹理、边缘
- **LSTM 部分**：按从上到下的顺序扫描图像行，捕捉空间依赖

---

## 三、可直接运行的代码

```python
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import DataLoader
import torchvision
import torchvision.transforms as transforms

# ------------------ 1. 模型定义 ------------------
class CNNLSTMClassifier(nn.Module):
    def __init__(self, cnn_feature_dim=64, lstm_hidden=128, lstm_layers=2, num_classes=10):
        super().__init__()
        # CNN 特征提取器
        self.cnn = nn.Sequential(
            nn.Conv2d(1, 32, kernel_size=3, padding=1),  # 28x28
            nn.ReLU(),
            nn.MaxPool2d(2),  # 14x14
            nn.Conv2d(32, cnn_feature_dim, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2)   # 7x7
        )
        # LSTM：输入是每行的特征向量
        self.lstm = nn.LSTM(input_size=cnn_feature_dim * 7,  # 每行 7 个像素，每个像素 64 维
                            hidden_size=lstm_hidden,
                            num_layers=lstm_layers,
                            batch_first=True)
        self.fc = nn.Linear(lstm_hidden, num_classes)

    def forward(self, x):
        # x: (batch, 1, 28, 28)
        batch_size = x.size(0)
        features = self.cnn(x)          # (batch, 64, 7, 7)
        # 重塑为序列：将高度视为时间步，每行拉平
        features = features.permute(0, 2, 1, 3)  # (batch, 7, 64, 7)
        features = features.reshape(batch_size, 7, -1)  # (batch, 7, 64*7)
        lstm_out, _ = self.lstm(features)  # (batch, 7, hidden)
        # 取最后一个时间步的输出
        last_out = lstm_out[:, -1, :]       # (batch, hidden)
        out = self.fc(last_out)             # (batch, 10)
        return out

# ------------------ 2. 数据加载 ------------------
transform = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize((0.5,), (0.5,))
])

train_set = torchvision.datasets.FashionMNIST(root='./data', train=True, download=True, transform=transform)
test_set = torchvision.datasets.FashionMNIST(root='./data', train=False, download=True, transform=transform)

train_loader = DataLoader(train_set, batch_size=64, shuffle=True)
test_loader = DataLoader(test_set, batch_size=64, shuffle=False)

# ------------------ 3. 训练 ------------------
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model = CNNLSTMClassifier().to(device)
criterion = nn.CrossEntropyLoss()
optimizer = optim.Adam(model.parameters(), lr=0.001)

epochs = 5
for epoch in range(epochs):
    model.train()
    total_loss = 0
    for images, labels in train_loader:
        images, labels = images.to(device), labels.to(device)
        optimizer.zero_grad()
        outputs = model(images)
        loss = criterion(outputs, labels)
        loss.backward()
        optimizer.step()
        total_loss += loss.item()
    print(f"Epoch {epoch+1}, Loss: {total_loss/len(train_loader):.4f}")

# ------------------ 4. 测试 ------------------
model.eval()
correct = 0
total = 0
with torch.no_grad():
    for images, labels in test_loader:
        images, labels = images.to(device), labels.to(device)
        outputs = model(images)
        _, predicted = torch.max(outputs, 1)
        total += labels.size(0)
        correct += (predicted == labels).sum().item()
print(f"Test Accuracy: {100 * correct / total:.2f}%")
```

## 五、扩展：换成更大的 RGB 图像（如 CIFAR-10）

只需修改 CNN 部分输入通道为 3，调整池化后尺寸，并确保序列长度合理。例如 CIFAR-10（32×32）可以这样改：

```python
self.cnn = nn.Sequential(
    nn.Conv2d(3, 32, 3, padding=1),  # 32x32
    nn.ReLU(), nn.MaxPool2d(2),      # 16x16
    nn.Conv2d(32, 64, 3, padding=1),
    nn.ReLU(), nn.MaxPool2d(2)       # 8x8
)
# LSTM 输入尺寸改为 64*8 = 512，时间步 = 8
self.lstm = nn.LSTM(input_size=64*8, hidden_size=128, num_layers=2, batch_first=True)
```

数据集换成 `torchvision.datasets.CIFAR10` 即可。
