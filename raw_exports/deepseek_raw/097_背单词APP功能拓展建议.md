以下是我的建议，分为几个方向，你可以根据开发资源逐步添加：

### 一、学（深化记忆）
单纯看中英文对照很容易忘，可以加入辅助记忆的手段：

- **词根词缀拆解**：比如 “unbelievable” 自动拆成 un-believ-able，并解释含义，帮用户举一反三。
- **图片/表情包联想**：给抽象词配上有趣的图，视觉记忆效果更强。
- **真人发音 + 口型视频**：除了标准读音，还可以提供自然例句的慢速/常速朗读。
- **语境记忆卡片**：每个单词配 1-2 个**高中真题原句**或经典电影台词，让用户在语境里记住用法，而不是孤零零的词。

### 二、练（即时检测）
避免“背了就是会了”的错觉，内置轻量级练习：

- **拼写模式**：听音拼词，或根据中文默写英文，很适合写作词汇训练。
- **选择/配对**：给释义选单词、近义词配对、完形填空式的四选一。
- **听音辨义**：播放单词读音，快速选择正确的中文意思，训练听力反应。
- **拼写竞赛/限时挑战**：比如 60 秒内尽可能多拼对单词，生成当日分数排行。

### 三、测（定位薄弱）
帮用户找到该重点背的，而不是 3500 词平铺直叙：

- **学前诊断测试**：随机抽取 100 个核心词，根据正确率初步划分“已掌握”“模糊”“未学”。
- **智能错词本**：所有练习中的错误自动收录，并按遗忘曲线提醒复习。
- **熟词生义检测**：高中常考“book 预定”“spring 泉水”这类，专门做一组释义测试，用户容易踩坑。
- **阶段模考**：按高考题型组卷，如语法填空、短文改错，所用单词都来自正在背的词库，直接感受背词效果。

### 四、拓（从词到用）
把单词串联成能考试、能写作的能力：

- **固定搭配/短语**：每个词展示常见搭配，比如 take 的 take off/over/up，并给出辨析。
- **写作语料库**：把 3500 词按“情绪描写”“环境描写”“连接过渡”分类，用户可以直接查用。
- **话题词包**：如“传统文化”“科技环保”，一键调取相关主题的必备词，适合考前突击。
- **AI 生句/对话**：接入 GPT 类接口，用当天背的 5 个词生成一段短文或对话，用户可以跟读或续写。

### 五、促活与留存（让用户坚持）
背词类 APP 最容易死于“三天热情”：

- **灵活的学习计划**：不是粗暴的“一天 30 词”，而是用户设定目标日期（比如“距离高考还有 200 天”），自动算出每天新学和复习量。
- **连续打卡+补签机制**：日历视图展示打卡记录，允许看广告或分享获得补签卡。
- **同桌/组队背词**：随机匹配或邀请好友，互相可见进度，一方掉队会提醒。
- **成就与徽章**：如“初出茅庐（连背 7 天）”“词汇收割机（正确率 95%）”“全勤学期”，可分享到朋友圈。
- **番茄钟/专注计时**：背词时打开专注模式，锁住其他娱乐 APP，攒专注时长兑换主题皮肤。

### 六、个性化与体验细节
- **词书切换皮肤**：高中词汇可以设计成“高考倒计时”主题皮肤，或者校园风界面。
- **单词本导出/打印**：支持导出 PDF 错词表或生词表，便于线下复习。
- **数据面板**：显示今日复习压力、累计学习时长、词汇量增长曲线等，用可视化的成就感留住用户。

**建议的开发优先级**：

下面帮你梳理一下落地路径和注意点：

---

### 1. 技术选型：别自己从零训练模型
个人开发者自己训练一个“发音评测模型”几乎不现实，因为需要海量非母语学习者的发音数据。推荐直接使用成熟的云端 API 或端侧 SDK：

- **云端方案（省事，依赖网络）**
  - **微软 Azure 发音评估**：专门针对语言学习，可以返回准确度、流利度、完整度分数，还能定位到哪个音素读错了，非常专业。
  - **讯飞语音评测**：国内做得早，支持中英文单词、句子评分，中小学场景覆盖广。
  - **腾讯云口语评测**：也是现成接口，返回总分和音素级错误。
- **端侧离线方案（反应快，无网可用）**
  - 可以找轻量化的开源发音评估模型，例如基于 **wav2vec 2.0** 或 **HuBERT** 做微调的开源项目，然后压缩成 TensorFlow Lite 或 ONNX 跑在手机上。这条路对 AI 工程化能力要求高一些。
  - 也有一些商业离线 SDK（如声网、驰声），需付费授权。

**建议**：先接云端 API 快速验证用户是否喜欢这个功能，效果好再考虑做离线版本。

---

### 2. 如何融入背词流程
这个功能最适合放在“跟读练习”环节，别让它打乱原本的背词节奏。

- **单词学习页**：展示单词、音标和发音按钮。在发音按钮旁边加一个**麦克风图标**，点击后跟读，读完马上显示得分和反馈。
- **评分呈现**：不要只给个冷冰冰的 85 分。可以拆成“准确度 90% | 流利度 80%”，并用颜色（绿/黄/红）标记发音不准的音节，例如“pron*unciation* 中的 ‘nun’ 读得不够清晰”。
- **闯关模式**：设置“发音挑战关”，必须单词发音得分超过 80 才能标记为“已掌握”，否则自动加入复习队列。
- **错音本**：把反复读错的音素汇总，比如总把 “th” 读成 “s”，就可以集中推送一批带 “th” 的词进行强化。

---

### 3. 必须避开的坑
- **录音质量要求别太高**：用户可能在教室、路上用，环境嘈杂。评测模型最好能有一定的噪音鲁棒性，或者在 UI 提示“请在安静环境下跟读”。
- **评分尺度要合适**：太严苛会打击信心，太松又没有提升效果。可以先拿一些真实高中生的发音测试，把及格线调到“有明显口音但可识别”的程度。
- **延迟感知**：录音上传 → 云端打分 → 返回结果，如果超过 2 秒用户就会觉得卡。可以加个波形动画缓解等待焦虑。
- **隐私提示**：收集录音数据需要合规，必须告知用户并获得同意，且说明录音用途（仅用于评分，不会他用）。

---

### 4. 和之前建议的组合玩法
你之前问的“还可以添加什么功能”，这个发音评估正好可以和很多功能联动：

- **听音辨义 + 跟读评分**：先听单词发音选正确意思，再跟读一遍巩固，读得不准自动加练。
- **组队背词**：队内可以互相发自己的“发音挑战”，看谁得分高，轻社交增加坚持动力。
- **AI 对话**：如果后面接入了对话功能，发音评估可以从单词扩展到整句，检查连贯性。

| 模式 | 行为 |
|---|---|
| `"default"` | 大多数工具调用需要你点确认 |
| `"auto"` | 安全的操作自动放行，敏感操作仍需确认 |

### 3. 编写评估器类

```kotlin
import ai.onnxruntime.*
import android.content.Context
import java.nio.FloatBuffer
import java.io.InputStream
import java.nio.ByteBuffer
import java.nio.ByteOrder

class PronunciationEvaluator(context: Context) {
    private var session: OrtSession? = null
    private val env = OrtEnvironment.getEnvironment()

    init {
        // 从 assets 加载模型
        val modelStream: InputStream = context.assets.open("pron_scorer.onnx")
        val modelBytes = modelStream.readBytes()
        session = env.createSession(modelBytes)
    }

    fun evaluate(audioData: FloatArray, targetText: String): Float {
        // 假设模型输入名字为 "audio" 和 "text"
        val audioTensor = OnnxTensor.createTensor(env, floatArrayToBuffer(audioData), longArrayOf(1, audioData.size.toLong()))
        val textTensor = OnnxTensor.createTensor(env, arrayOf(targetText))

        val inputs = mapOf("audio" to audioTensor, "text" to textTensor)
        val outputs = session?.run(inputs)

        val score = outputs?.get("score")?.floatBuffer?.get(0) ?: 0f
        return score
    }

    private fun floatArrayToBuffer(arr: FloatArray): ByteBuffer {
        val buffer = ByteBuffer.allocateDirect(arr.size * 4)
        buffer.order(ByteOrder.nativeOrder())
        buffer.asFloatBuffer().put(arr)
        return buffer
    }
}
```

**注意**：你的模型输入可能是**预处理后的特征**（如 `[batch, seq_len, feature_dim]`），而不是原始音频。需要你根据导出模型的输入要求，在移动端实现简单的**音频预处理**（比如用 TarsosDSP 做分帧加窗然后计算 MFCC，或者实现 FBank）。这部分代码比较固定，我可以提供示例。

```swift
import onnxruntime

class PronunciationEvaluator {
    private var session: ORTSession?
    
    init?() {
        guard let modelPath = Bundle.main.path(forResource: "pron_scorer", ofType: "onnx") else {
            return nil
        }
        let env = try? ORTEnv(loggingLevel: .warning)
        session = try? ORTSession(env: env!, modelPath: modelPath)
    }
    
    func evaluate(audioData: [Float], targetText: String) -> Float {
        // 构造输入张量
        let audioTensor = try? ORTValue(tensorData: Data(bytes: audioData, count: audioData.count * 4),
                                        elementType: .float,
                                        shape: [1, NSNumber(value: audioData.count)])
        let textTensor = try? ORTValue(tensorData: Data(targetText.utf8),
                                        elementType: .string,
                                        shape: [1])
        let inputs = ["audio": audioTensor!, "text": textTensor!]
        let outputs = try? session?.run(withInputs: inputs, outputNames: ["score"])
        if let rawData = try? outputs?["score"]?.tensorData() as? Data {
            return rawData.withUnsafeBytes { $0.load(as: Float.self) }
        }
        return 0
    }
}
```

## 四、性能与优化建议

- **模型量化**：在导出 ONNX 后可对模型进行 INT8 量化，体积可减少 70%，推理速度提升 2-3 倍，精度损失极小（发音打分通常可接受）。可以使用 `onnxruntime-tools` 或 `onnx.quantization`。
- **包体积**：原始 ONNX 可能 50-100MB，量化后约 20-30MB，可以接受。如果还想缩小，可考虑用知识蒸馏训练一个小模型。
- **实时性**：单次推理在主流手机上应 < 200ms，配合录音和预处理，整体体验流畅。
- **预处理实现**：如果模型不包含特征提取，你需要在客户端实现 FBank 或 MFCC。最简单的方式是用 FunASR 的 C++ 库 `funasr-onnx`，它已封装好完整流程（包含特征提取和打分）。在 Android 上可以通过 JNI 调用，iOS 上可以直接用 Objective-C++ 包装。

### 3.3 音频预处理工具类

```kotlin
// AudioFeatureExtractor.kt
import android.media.AudioFormat
import android.media.AudioRecord
import android.media.MediaRecorder
import kotlin.math.*
import java.io.ByteArrayOutputStream

class AudioFeatureExtractor {
    companion object {
        const val SAMPLE_RATE = 16000
        const val FRAME_LENGTH = 512  // 32ms @ 16kHz
        const val FRAME_SHIFT = 256   // 16ms @ 16kHz
        const val NUM_MEL_BINS = 80

        fun recordAudio(durationMs: Int = 3000): FloatArray {
            val bufferSize = AudioRecord.getMinBufferSize(SAMPLE_RATE, 
                AudioFormat.CHANNEL_IN_MONO, AudioFormat.ENCODING_PCM_16BIT)
            val audioRecord = AudioRecord(MediaRecorder.AudioSource.MIC, 
                SAMPLE_RATE, AudioFormat.CHANNEL_IN_MONO, 
                AudioFormat.ENCODING_PCM_16BIT, bufferSize)
            
            val byteBuffer = ByteArray(bufferSize)
            val outputStream = ByteArrayOutputStream()
            
            audioRecord.startRecording()
            val startTime = System.currentTimeMillis()
            while (System.currentTimeMillis() - startTime < durationMs) {
                val read = audioRecord.read(byteBuffer, 0, bufferSize)
                if (read > 0) outputStream.write(byteBuffer, 0, read)
            }
            audioRecord.stop()
            audioRecord.release()
            
            val shorts = ShortArray(outputStream.size() / 2)
            val bytes = outputStream.toByteArray()
            for (i in shorts.indices) {
                shorts[i] = ((bytes[i*2+1].toInt() shl 8) or (bytes[i*2].toInt() and 0xFF)).toShort()
            }
            return FloatArray(shorts.size) { shorts[it] / 32768f }
        }

        fun extractFBank(audioSignal: FloatArray): Array<FloatArray> {
            val frames = mutableListOf<FloatArray>()
            var start = 0
            while (start + FRAME_LENGTH <= audioSignal.size) {
                val frame = audioSignal.sliceArray(start until start + FRAME_LENGTH)
                frames.add(computeFBank(frame))
                start += FRAME_SHIFT
            }
            return frames.toTypedArray()
        }

        private fun computeFBank(frame: FloatArray): FloatArray {
            val windowed = frame.mapIndexed { i, v -> v * hammingWindow(i, frame.size) }.toFloatArray()
            val spectrum = fft(windowed)
            val melSpec = toMelSpectrum(spectrum)
            val logMelSpec = FloatArray(melSpec.size) { ln(max(melSpec[it], 1e-10f)) }
            return logMelSpec
        }

        private fun hammingWindow(index: Int, length: Int): Double {
            return 0.54 - 0.46 * cos(2.0 * PI * index / (length - 1))
        }

        private fun fft(input: FloatArray): FloatArray {
            val n = input.size
            val result = FloatArray(n / 2 + 1)
            for (k in 0..n/2) {
                var real = 0.0
                var imag = 0.0
                for (t in input.indices) {
                    val angle = -2.0 * PI * t * k / n
                    real += input[t] * cos(angle)
                    imag += input[t] * sin(angle)
                }
                result[k] = sqrt(real * real + imag * imag).toFloat()
            }
            return result
        }

        private fun toMelSpectrum(spectrum: FloatArray, numBins: Int = NUM_MEL_BINS): FloatArray {
            val melMax = hzToMel(SAMPLE_RATE / 2f)
            val melMin = hzToMel(0f)
            val melBins = FloatArray(numBins)
            for (i in 0 until numBins) {
                val melCenter = melMin + (melMax - melMin) * i / (numBins - 1)
                val hzCenter = melToHz(melCenter)
                val binIndex = hzCenter / (SAMPLE_RATE / 2f) * (spectrum.size - 1)
                val lower = floor(binIndex).toInt().coerceIn(0, spectrum.size - 1)
                val upper = ceil(binIndex).toInt().coerceIn(0, spectrum.size - 1)
                val frac = binIndex - lower
                melBins[i] = spectrum[lower] * (1 - frac) + spectrum[upper] * frac
            }
            return melBins
        }

        private fun hzToMel(hz: Float): Float = 2595f * log10(1f + hz / 700f)
        private fun melToHz(mel: Float): Float = 700f * (10f.pow(mel / 2595f) - 1f)
    }
}
```

```kotlin
    val fluency: Float

    private var session: OrtSession? = null
    private val env = OrtEnvironment.getEnvironment()
    
    init {
        context.assets.open("pron_scorer.onnx").use { inputStream ->
            val modelBytes = inputStream.readBytes()
            session = env.createSession(modelBytes)
        }
    }

    suspend fun evaluate(audioData: FloatArray, targetText: String): PronunciationResult = 
        withContext(Dispatchers.Default) {
            
            // 1. 提取特征
            val features = AudioFeatureExtractor.extractFBank(audioData)
            val flattenedFeatures = FloatArray(features.size * AudioFeatureExtractor.NUM_MEL_BINS) { i ->
                features[i / AudioFeatureExtractor.NUM_MEL_BINS][i % AudioFeatureExtractor.NUM_MEL_BINS]
            }

            // 2. 构造输入张量
            val shape = longArrayOf(1, features.size.toLong(), AudioFeatureExtractor.NUM_MEL_BINS.toLong())
            val audioTensor = OnnxTensor.createTensor(env, 
                floatArrayToBuffer(flattenedFeatures), shape)
            val textTensor = OnnxTensor.createTensor(env, arrayOf(targetText))

            // 3. 推理
            val inputs = mutableMapOf<String, OnnxTensor>()
            inputs["input_features"] = audioTensor
            inputs["text"] = textTensor

            val outputNames = setOf("overall_score", "word_scores", "accuracy", "fluency")
            val outputs = session?.run(inputs, outputNames)

            // 4. 解析输出（实际输出字段名需根据你的模型调整）
            val overallScore = outputs?.get("overall_score")?.floatBuffer?.get(0) ?: 0f
            val accuracy = outputs?.get("accuracy")?.floatBuffer?.get(0) ?: 0f
            val fluency = outputs?.get("fluency")?.floatBuffer?.get(0) ?: 0f

            // word_scores 的解析取决于模型输出格式，这里假设是字符串形式
            // 可能需要自行实现，或模型直接输出结构化数据
            val wordScores = listOf(WordScore(targetText, overallScore, emptyMap()))

            PronunciationResult(overallScore, wordScores, accuracy, fluency)
        }

    fun release() {
        session?.close()
    }

    private fun floatArrayToBuffer(arr: FloatArray): ByteBuffer {
        val buffer = ByteBuffer.allocateDirect(arr.size * 4)
        buffer.order(ByteOrder.nativeOrder())
        buffer.asFloatBuffer().put(arr)
        return buffer
    }
```

### 5.3 常见问题

**Q: 模型导出 ONNX 失败怎么办？**
A: 检查 FunASR 版本是否为最新（`pip install --upgrade funasr`），部分子模型可能不支持直接导出，需要手动 trace。可考虑使用 FunASR 官方移动 SDK 作为 fallback。

**Q: 移动端推理 crash？**
A: 检查 ONNX Runtime 版本与 ABI 是否匹配，确认输入 shape 与模型期望一致。

**Q: 打分不准确？**
A: 确认预处理（FBank）参数与训练时一致：16kHz 采样率、80 维 Mel、25-32ms 窗长、10ms 帧移。

## 一、扇贝单词的核心功能拆解

扇贝的核心理念是 **“学-练-用”闭环**，不是单纯让你背，是让你在语境里反复遇见这个词。

**对你 APP 的启示**：建一个积分体系，把用户所有行为串起来——背词、发音评测、字母游戏、打卡，都奖励积分，积分可解锁皮肤/主题/高级功能。

## 二、不背单词的核心功能拆解

不背单词的核心理念是 **“在真实语境中自然习得”**，设计上极度克制，甚至反“背单词”的焦虑感。

# 单词改错功能 - 移动端开发文档

> 本文档供 Claude Code 阅读并执行。目标：在现有背单词 APP 中新增**词语改错游戏**，用户在故意制造的拼写、释义、用法错误中找出正确写法，巩固词汇。

---

## 一、功能概述

- **题型 1：拼写改错**  
  展示一个拼写错误的单词，用户输入正确拼写。  
  例：`recieve` → 正确：`receive`

- **题型 2：释义改错**  
  展示一个单词 + 错误的中文释义，用户输入正确释义。  
  例：`apple (n.) 橙子` → 正确：`苹果`

- **题型 3：用法改错**  
  展示一个包含语法/搭配错误的英文句子，用户改写整个句子。  
  例：`He go to school yesterday.` → 正确：`He went to school yesterday.`

- **出题策略**：从用户当前学习或错词本中选词，基于预设规则和映射表生成错误项。
- **评分**：完全匹配给满分；拼写允许编辑距离 ≤1 得半分；释义允许模糊匹配。

---

## 二、错误生成逻辑

### 2.1 拼写错误生成规则

建立常见错误规则库，从正确单词变换得到错误拼写：

| 规则 | 示例 |
|---|---|
| ie ↔ ei 互换 | believe → beleive |
| 重复字母遗漏 | accommodation → acomodation |
| 元音混淆 a/e | separate → seperate |
| 辅音双写错 | necessary → neccessary |
| 静音字母遗漏 | government → goverment |
| 同音混淆 | their → there（不直接用于拼写题，可放在用法题） |

**实现**：维护一个 `spelling_error_map.json` 文件，包含 `{ "correct": "receive", "errors": ["recieve", "receve", "receeve"] }`，覆盖高频易错词，剩余词用通用规则随机生成。

### 2.2 释义错误生成

- **策略 A**：随机选取另一个单词的释义替换，例如把 `apple` 的释义换成 `banana` 的释义。
- **策略 B**：使用近义但有偏差的释义，如 `abandon` 正确是“放弃”，错误给“放纵”（混淆 `abandon` 和 `abundant`）。
- **策略 C**：对于多义词，给出一个冷门义项但却标成唯一释义，如 `book` 只给“预定”，考验用户是否知道还有“书”的意思。

**实现**：词库中每个单词存一个错误释义数组，或用规则从其他单词随机抽取。

### 2.3 用法错误生成

基于常见语法点和搭配错误模板，将正确句子变形：

| 错误类型 | 模板 | 示例 |
|---|---|---|
| 时态错误 | 将过去时改为现在时 | He went → He go |
| 主谓不一致 | 单数用复数动词 | She like → She likes (改为错误时用 likes→like) |
| 介词搭配 | 替换错误介词 | depend on → depend in |
| 冠词误用 | a/an 错用或遗漏 | a apple → an apple |
| 词性错误 | 形容词/副词混用 | He runs quick → He runs quickly |
| 固定搭配 | 拆散短语动词 | look after → look for |

**生成逻辑**：预制一个句子库（每词 1-3 个经典句），对句子自动施行一个错误变换。如从正确句子 `He went to school yesterday.` 通过时态变换得到 `He go to school yesterday.`

**句子库来源**：可用高中真题例句，或由 AI 批量生成正确句子，再人工审核。初始可内置 1000 句，覆盖核心 1000 词，其余词用句型模板填充。

## 三、数据结构设计

### 3.1 题目模型

```kotlin
data class CorrectionQuestion(
    val questionId: String,
    val type: QuestionType,      // SPELLING, MEANING, USAGE
    val prompt: String,           // 展示给用户的内容（含错误）
    val correctAnswer: String,    // 唯一正确答案
    val acceptableAnswers: List<String> = emptyList(), // 可接受的其他答案
    val explanation: String,      // 解析
    val difficulty: Int = 1       // 1-5
)

enum class QuestionType { SPELLING, MEANING, USAGE }
```

### 4.3 答题评估器

```kotlin
// AnswerEvaluator.kt
object AnswerEvaluator {
    fun evaluate(userAnswer: String, question: CorrectionQuestion): AnswerResult {
        val trimmedUser = userAnswer.trim()
        val correct = question.correctAnswer.trim()

        if (question.type == QuestionType.SPELLING) {
            return evaluateSpelling(trimmedUser, correct)
        }
        // 释义和用法允许一定的模糊
        return evaluateMeaningOrUsage(trimmedUser, correct, question.acceptableAnswers)
    }

    private fun evaluateSpelling(user: String, correct: String): AnswerResult {
        if (user.equals(correct, ignoreCase = true)) {
            return AnswerResult(true, 1.0f, "完全正确！")
        }
        val distance = levenshtein(user.lowercase(), correct.lowercase())
        return when {
            distance <= 1 -> AnswerResult(true, 0.5f, "基本正确，注意细节。")
            else -> AnswerResult(false, 0f, "错误，正确拼写为：$correct")
        }
    }

    private fun evaluateMeaningOrUsage(
        user: String,
        correct: String,
        acceptable: List<String>
    ): AnswerResult {
        if (user.equals(correct, ignoreCase = true) || acceptable.any { 
            it.trim().equals(user, ignoreCase = true) 
        }) {
            return AnswerResult(true, 1.0f, "完全正确！")
        }
        // 简单相似度判断（可扩展 NLP）
        val similarity = calculateSimpleSimilarity(user, correct)
        return if (similarity > 0.7) {
            AnswerResult(true, 0.5f, "意思接近，标准答案：$correct")
        } else {
            AnswerResult(false, 0f, "错误，正确答案：$correct")
        }
    }

    private fun levenshtein(s1: String, s2: String): Int {
        val dp = Array(s1.length + 1) { IntArray(s2.length + 1) }
        for (i in 0..s1.length) dp[i][0] = i
        for (j in 0..s2.length) dp[0][j] = j
        for (i in 1..s1.length) {
            for (j in 1..s2.length) {
                dp[i][j] = if (s1[i - 1] == s2[j - 1]) dp[i - 1][j - 1]
                else 1 + minOf(dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1])
            }
        }
        return dp[s1.length][s2.length]
    }

    private fun calculateSimpleSimilarity(s1: String, s2: String): Double {
        val maxLen = maxOf(s1.length, s2.length).toDouble()
        if (maxLen == 0.0) return 1.0
        return (maxLen - levenshtein(s1.lowercase(), s2.lowercase())) / maxLen
    }
}

data class AnswerResult(
    val isCorrect: Boolean,
    val score: Float,      // 0-1
    val feedback: String
)
```

### 4.4 游戏界面 ViewModel

```kotlin
// CorrectionGameViewModel.kt
import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.launch

data class GameState(
    val questions: List<CorrectionQuestion> = emptyList(),
    val currentIndex: Int = 0,
    val userAnswer: String = "",
    val lastResult: AnswerResult? = null,
    val totalScore: Int = 0,
    val isFinished: Boolean = false,
    val showExplanation: Boolean = false
)

class CorrectionGameViewModel(context: Context) : ViewModel() {
    private val questionLoader = QuestionLoader(context)
    private val _state = MutableStateFlow(GameState())
    val state: StateFlow<GameState> = _state

    init {
        loadGame()
    }

    fun loadGame(type: QuestionType? = null) {
        viewModelScope.launch {
            val questions = if (type != null) questionLoader.loadByType(type)
                            else questionLoader.loadQuestions()
            _state.value = GameState(questions = questions.shuffled())
        }
    }

    fun updateAnswer(answer: String) {
        _state.value = _state.value.copy(userAnswer = answer)
    }

    fun submitAnswer() {
        val currentState = _state.value
        val question = currentState.questions.getOrNull(currentState.currentIndex) ?: return
        val result = AnswerEvaluator.evaluate(currentState.userAnswer, question)
        val newScore = if (result.isCorrect) currentState.totalScore + (result.score * 100).toInt()
                       else currentState.totalScore
        _state.value = currentState.copy(
            lastResult = result,
            totalScore = newScore,
            showExplanation = true,
            userAnswer = ""
        )
    }

    fun nextQuestion() {
        val currentState = _state.value
        val nextIndex = currentState.currentIndex + 1
        if (nextIndex >= currentState.questions.size) {
            _state.value = currentState.copy(isFinished = true, showExplanation = false, lastResult = null)
        } else {
            _state.value = currentState.copy(
                currentIndex = nextIndex,
                lastResult = null,
                showExplanation = false
            )
        }
    }
}
```

```python
# generate_spelling_errors.py
import json

def generate_errors(word):
    errors = []
    # 规则 1: ie/ei 互换
    if 'ie' in word:
        errors.append(word.replace('ie', 'ei', 1))
    # 规则 2: 双写字母遗漏
    for i, ch in enumerate(word):
        if i > 0 and ch == word[i-1]:
            errors.append(word[:i] + word[i+1:])
            break
    # 更多规则...
    return errors

words = ["receive", "believe", "accommodation", "separate", "government"]
question_list = []
for w in words:
    errs = generate_errors(w)
    for e in errs:
        question_list.append({

            "correctAnswer": w,
            "acceptableAnswers": [],

            "difficulty": 1
        })
```

## 针对高中生的功能设计

### 第一层：提分刚需（不做不行）

**1. 高考真题实战渗透（深度升级版）📝**

之前提过真题标注，现在升级为完整闭环：

- **真题溯源系统**：每个单词页面直接展示**近 5 年高考真题中出现该词的句子**，标注省份、卷型、题号。
  - 例：`observe` 在 2024 年全国甲卷阅读理解 D 篇出现，考的是“遵守”而非“观察”。
- **熟词生义专项**：高中生最怕这个。整理 3500 词中所有“你以为你认识但其实不认识的”义项。
  - 例：`book` 预定、`spring` 泉水、`room` 空间、`present` 呈现
- **考点标签系统**：给每个词打考点标签：`[熟词生义]` `[固定搭配]` `[近义词辨析]` `[完形高频]` `[写作加分]`
- **考频排序模式**：让用户可以选择“按高考出现频率排序学习”，先把出现 50 次的词搞定，再去背出现 1 次的。

**2. 完形填空 / 语法填空专项训练 ✍️**

这是高考英语分数差距最大的题型，也是背词最直接的回报：

- 用 AI 自动生成完形填空文章，挖掉的空格都是用户正在学的单词。
- 生成逻辑：系统从用户学习列表中选 20 个词，调用大模型生成一篇 300 词的短文，把这些词自然地嵌入，然后挖掉。
- 也可以把错词本里的词集中编入一篇完形，反复强化。
- 做完后自动统计“你因为不认识该词丢了多少分”，直接换算成高考分差，触动极强。

**3. 写作语料库 / 作文救命词 🆘**

高中生英语作文最大的痛点是“有想法但不会用英语表达”：

- 按**高考作文常考场景**分类词汇和句型：
  - 建议信、申请信、感谢信、通知、议论文、记叙文
  - 环境描写、人物描写、情绪描写、过渡衔接
- 每个场景提供“30 秒速记模板”，比如：
  - 表达建议：`I strongly recommend that you (should) do...`
  - 转折过渡：`However, every coin has two sides.`
- **亮点替换功能**：用户写了一句简单句，系统自动推荐“用高考加分词替换”：
  - `I think` → `From my perspective` / `I am firmly convinced that`
  - `important` → `vital / essential / significant / crucial`

### 第二层：时间利用（碎片时间最大化）

**4. 锁屏背词 + 桌面小组件 🔔**

高中生不允许带手机？那是理想情况。实际上大部分学生有手机，但使用时间碎片化：

- **桌面小组件**：每 30 分钟自动更换一个单词卡片（释义、例句），放在手机桌面，解锁即看。
- **通知栏背词**：设置单词推送通知，用户可以在通知栏直接点击“认识/不认识”，无需进入 APP。
- **极简锁屏页**：锁屏显示今日待复习单词，滑动解锁前看一秒。
- **周报推送**：每周日晚推送本周学习报告，“你本周掌握了 85 个词，在班级排名前 20%”，学生最吃这套。

**5. 晨读/睡前 5 分钟模式 🌅🌙**

- **晨读模式**：早上 6:00-7:00 自动推送一组“今日必背”，配合清新界面和轻音乐，主打快速激活记忆。
- **睡前模式**：晚上 22:00-23:00 推送错词复习，心理学证明睡前记忆效果最好。
- **变速播放**：支持 1.0x/1.25x/1.5x，让高级学生可以快速刷词。

### 第三层：激励与社交（让坚持变得容易）

**6. 班级/年级排行榜 + 私密 PK 🏆**

高中生最在乎“班上谁谁谁又学了什么”：

- **班级排行榜**：支持创建班级，显示成员背词数、连续打卡天数、正确率排行。
  - 排行榜只显示前 10 名 + 用户自己的位置，避免打击末尾同学。
- **私密 PK**：两个同学之间可以发起“30 分钟背词挑战”，看谁在 30 分钟内掌握的词更多，输的请奶茶（玩笑）。
- **全校榜单**：如果推广到同一个学校，可以做年级排名，激发好胜心。

**7. 高考倒计时 + 每日宣言 💪**

- **高考倒计时小组件**：显示距高考还有多少天，每日自动更新。
- **每日一句励志语**：不是鸡汤，是真实的高考逆袭故事、上岸学长学姐的一句话，用同龄人的经历激发动力。
- **目标大学设定**：用户设定目标大学，APP 显示“距离 XX 大学还有 xx 分需要提升”，背词进度与目标挂钩。

### 第四层：家长和老师的角色

**8. 家长督学模式（轻打扰版）👨‍👩‍👧**

高中生反感被监视，但家长又需要知道孩子在学：

- **只推送关键信息**：家长端不显示排名、不显示分数，只显示“本周学习 6 天”“已坚持 45 天”。
- **阶段性报告**：每月生成一份“学习健康报告”，包含词汇量增长、薄弱环节、建议，家长可以和老师沟通。

**9. 教师端班级管理 👨‍🏫**

如果你们和学校合作，这个功能是壁垒：

- 老师可以**一键布置背词任务**：指定 50 个词，全班必须在三天内完成。
- **查看全班错误率最高的 10 个词**：老师上课直接重点讲解。
- **打印纸质测试卷**：系统根据班级易错词，自动生成一份纸质版单词测试卷（英译中 + 中译英 + 完成句子），老师可以直接打印。
