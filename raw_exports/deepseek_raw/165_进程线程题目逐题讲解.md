### 题目1

**知识点**  
- **进程**是操作系统资源分配的基本单位，拥有独立的地址空间和系统资源；进程间内存默认隔离，无法直接共享，需通过IPC机制。  
- **线程**是CPU调度的基本单位，同一进程下的线程共享该进程的地址空间和资源，但每个线程有自己的栈和寄存器上下文。  
- 创建进程的开销远大于创建线程，因为进程需要分配独立资源，线程只需少量私有结构。  

**题目**  
关于进程与线程的内存与资源分配，下列说法正确的是：  
A. 现代操作系统允许不同的进程之间直接且轻易地共享内存空间。  
B. 线程拥有自己独立的系统资源和私有的地址空间。  
C. 同一个进程下的多个线程共享该父进程所拥有的系统资源和地址空间。  
D. 创建一个新进程所需的系统开销远小于创建一个新线程。  

**答案与解析**  
正确答案是 **C**。  
- A 错误：不同进程拥有独立的地址空间，不能直接共享内存，必须使用共享内存、管道等IPC技术。  
- B 错误：线程共享进程的地址空间和大部分资源，只有栈、程序计数器等是线程私有的。  
- C 正确：同一进程内的线程共享进程持有的资源（文件句柄、内存等）及地址空间。  
- D 错误：创建进程的开销通常远大于创建线程。

### 题目2

**知识点**  
进程是操作系统中的独立实体，其核心特征包括：  
- 拥有独立的地址空间和系统资源。  
- 具有生命周期（创建、就绪、运行、阻塞、终止）。  
- 进程间相互隔离，一个进程崩溃一般不会直接导致其他进程终止。  

**题目**  
作为操作系统中的独立实体，进程的核心特征是什么？  
A. 一个进程内部只能包含一个顺序执行流。  
B. 进程拥有自己私有的地址空间和独立的系统资源。  
C. 一个并发进程的异常崩溃会导致其他并发进程直接终止。  
D. 进程在系统中是静态存在的，没有生命周期和状态变化。  

**答案与解析**  
正确答案是 **B**。  
- A 错误：一个进程可以包含多个线程（多个执行流）。  
- B 正确：独立的地址空间和资源是进程的根本特征。  
- C 错误：进程间隔离性好，一个进程崩溃通常不会直接终止其他进程。  
- D 错误：进程是动态的，有完整的生命周期和状态变化。

### 题目3

**知识点**  
- Java线程创建方式之一：继承`Thread`类并重写`run()`方法。  
- `run()`是线程执行体，定义线程任务；`start()`启动新线程，JVM会调用`run()`。  
- 若直接调用`run()`，不会启动新线程，只是在当前线程顺序执行。  
- Java单继承限制：继承了`Thread`就不能再继承其他类。  
- 创建线程实例不会立即分配操作系统资源，真正分配发生在`start()`调用后。

**题目**  
分析以下符合 Java 语法且仅能单继承的线程创建代码，下列关于其核心步骤的说法正确的是：  
```java
class MyThread extends Thread {
    public void run() {
        System.out.println("Thread running");
    }
}
public class Main {
    public static void main(String[] args) {
        MyThread t = new MyThread();
        t.start();
    }
}
```
A. MyThread 成功继承了 Thread 类，因此该类未来还可以继承其他自定义父类。  
B. 代码中的 run() 方法被称为线程执行体，负责定义线程的顺序执行流。  
C. 若将 t.start() 改为 t.run()，在 Java 中依然可以正常启动一个独立的新线程。  
D. 创建 t 实例时，操作系统就已经自动为其分配了独立的系统资源和私有地址空间。  

**答案与解析**  
正确答案是 **B**。  
- A 错误：Java单继承，继承了`Thread`不能再继承其他类。  
- B 正确：`run()`是线程执行体。  
- C 错误：直接调用`run()`不会启动新线程，仅是普通方法调用。  
- D 错误：`new`只是创建Java对象，线程资源和地址空间在`start()`后由操作系统分配。

### 题目5

**知识点**  
- 实现`Runnable`接口是创建线程的另一种方式，避免了单继承限制。  
- 用`Thread(Runnable target, String name)`构造器可指定线程名。  
- `Runnable`实例不是`Thread`子类，不能直接调用`start()`，需包装到`Thread`中。  
- `t.start()`启动后，`run()`在新线程异步执行，不会阻塞主线程。

**题目**  
分析以下基于 Runnable 接口创建线程的代码，下列说法中完全正确的是  
```java
class MyTask implements Runnable {
    public void run() {
        System.out.println(Thread.currentThread().getName());
    }
}
public class Main {
    public static void main(String[] args) {
        MyTask task = new MyTask();
        Thread t = new Thread(task, "Download-Thread");//8 line
        t.start();
    }
}
```
A. 代码第 8 行利用了 Thread(Runnable target, String name) 构造函数，在创建线程的同时为其指定了名字。  
B. 因为 Java 只支持单继承，MyTask 实现了 Runnable 接口后就无法再继承其他任何自定义类。  
C. 代码中 task 属于 Thread 类的子类实例，因此可以直接调用 start() 方法来启动。  
D. 执行 t.start() 后，程序会立即在当前主线程中按顺序同步执行 run() 方法体内的代码。  

**答案与解析**  
正确答案是 **A**。  
- A 正确：使用的正是该构造器。  
- B 错误：实现接口同时仍然可以继承类，没有冲突。  
- C 错误：task是`MyTask`实例，不是`Thread`子类，不能直接调用`start()`。  
- D 错误：`start()`后新线程异步执行，主线程继续向下。

### 题目7

**知识点**  
- `FutureTask`同时实现了`Runnable`和`Future`接口。  
- 可以包装`Callable`对象，通过`get()`获取结果，`get()`会阻塞直到计算完成。

**题目**  
关于 Java 中的 FutureTask 类，下列说法【错误】的是？

D. FutureTask 的构造方法 new FutureTask(Callable callable) 可以将一个 Callable 对象包装起来。

### 题目8

**知识点**  
- `Callable`可以返回结果并抛出检查异常。  
- `Callable`不能直接传给`Thread`，需用`FutureTask`包装（`FutureTask`实现了`Runnable`）。  
- `FutureTask.get()`会阻塞等待结果。

**题目**  
分析以下利用 Callable 与 FutureTask 创建线程的代码，下列说法中完全正确的是：  
```java
import java.util.concurrent.*;
class MyCall implements Callable<Integer> {
    public Integer call() throws Exception {
        return 100;
    }
}
public class Main {
    public static void main(String[] args) throws Exception {
        FutureTask<Integer> task = new FutureTask<>(new MyCall());
        new Thread(task).start();
        System.out.println(task.get());
    }
}
```
A. MyCall 实现了 Callable 接口，因此可以直接作为参数传给 new Thread(new MyCall()) 来启动线程。  
B. FutureTask 实现了 Future 接口，但未实现 Runnable 接口，所以必须依赖 Thread 类做二次包装。  
C. 即使 call() 方法中发生了逻辑异常，该方法也绝对不允许使用 throws 声明抛出任何检查异常。  
D. 最终调用 task.get() 方法可以阻塞当前主线程，并成功获取到 call() 方法返回的整数 100。  

**答案与解析**  
正确答案是 **D**。  
- A 错误：`Callable`不是`Runnable`，不能直接传。  
- B 错误：`FutureTask`实现了`RunnableFuture`，它继承了`Runnable`和`Future`。  
- C 错误：`call()`声明了`throws Exception`，允许抛出检查异常。  
- D 正确：`get()`阻塞并获取返回值100。

### 题目10

**知识点**  
线程生命周期：新建 → 就绪 → 运行 → 阻塞/等待 → 终止。  
- `yield()`让出CPU，线程回到就绪状态，不是阻塞。  
- `sleep()`、等待锁等会使线程进入阻塞状态，但不是唯一途径。  
- 阻塞结束后线程先进入就绪状态，重新竞争CPU。  
- `start()`后进入就绪，获得CPU后才运行。

**题目**  
根据 “线程的生命周期”状态转换图，下列关于线程状态转换触发条件的说法中完全正确的是：  
A. 处于“运行”状态的线程一旦调用了 Thread.yield() 方法，将会直接进入“阻塞”状态。  
B. 导致线程从“运行”状态进入“阻塞”状态的原因，只有调用 Thread.sleep(long) 这一种情况。  
C. 处于“阻塞”状态的线程在“获得同步监视器”或“sleep 时间到”后，会直接回到“运行”状态。  
D. 线程调用 start() 方法后进入“就绪”状态，此时只有“获得 CPU 资源”才能进入“运行”状态。  

**答案与解析**  
正确答案是 **D**。  
- A 错：`yield()`进入就绪态。  
- B 错：进入阻塞的原因还有等待I/O、等待锁等。  
- C 错：阻塞结束后先到就绪态，再竞争CPU。  
- D 正确：`start()`后进入就绪，需调度分配CPU才运行。

### 题目11

**知识点**  
- `isAlive()`：线程启动后到终止前返回true，新建和终止状态返回false。  
- `interrupt()`：给线程设置中断标志。若线程在阻塞状态（如`sleep`、`wait`），会抛出`InterruptedException`并清除标志；若在运行中，不会立刻中断，需自行检查标志。  
- `getName()`是实例方法，`Thread.currentThread().getName()`；`isInterrupted()`也是实例方法，静态方法为`interrupted()`。

**题目**  
下列关于线程状态判断与中断机制的说法中完全正确的是：  
A. 当一个线程刚被 new 出来（处于新建状态）或刚执行完任务（处于结束状态）时，调用 isAlive() 方法都会返回 True。  
B. 对一个正在运行（处于运行状态）的线程调用 interrupt() 方法，该线程会立刻中断并抛出 InterruptedException。  
C. 当线程处于阻塞状态时，如果调用了它的 interrupt() 方法，该线程会抛出 InterruptedException 异常。  
D. getName() 方法和 isInterrupted() 方法都是静态（static）方法，必须通过 Thread 类名直接调用。  

**答案与解析**  
正确答案是 **C**。  
- A 错：新建或结束状态`isAlive()`返回false。  
- B 错：运行时中断不会立刻抛异常，只会置中断标志。  
- C 正确：阻塞状态被中断会抛`InterruptedException`。  
- D 错：`getName()`和`isInterrupted()`是实例方法；静态的为`interrupted()`。

### 题目12

**知识点**  
- `yield()`：暗示调度器让出CPU，线程进入就绪状态，不会阻塞。  
- `join()`：调用者线程等待被调用线程执行完毕，即主线程调`t.join()`会使主线程阻塞直到t完成。  
- `sleep(long millis)`：是静态方法，让当前执行线程休眠指定时间。  
- 优先级高的线程更可能获得CPU，但不保证，仍可能主动放弃（如调用`yield()`）。

**题目**  
下列关于线程调度与执行顺序控制的说法中完全正确的是：  
A. 正在运行的线程如果调用了静态方法 yield()，会直接进入阻塞状态并设置睡眠时间。  
B. 在主线程中调用了线程对象 t 的 t.join() 方法，会导致线程 t 暂停执行，让主线程优先执行。  
C. 静态方法 sleep(long millis) 的功能是用来设置当前正在运行的线程的睡眠时间。  
D. 通过 setPriority(int newPriority) 提高某线程的优先级后，该线程在运行时便无法再主动放弃 CPU 资源。  

**答案与解析**  
正确答案是 **C**。  
- A 错：`yield()`进入就绪，不阻塞也不设置睡眠。  
- B 错：`t.join()`使主线程等待t，而非t暂停。  
- C 正确：`Thread.sleep(long)`使当前线程休眠。  
- D 错：仍可调用`yield()`、`sleep()`等主动放弃CPU。

### 题目15

**知识点**  
线程安全需保证复合操作的原子性。这里“读取-计算-写入”若只有写入加锁，读取和计算在锁外则可能读取到脏数据，导致更新丢失。  
必须将整个“读取-计算-写入”放入同步块才能保证安全性。

**题目**  
阅读以下代码，多线程并发执行 run() 后，最终余额必定是 2000 吗？  
```java
class Account { int balance = 0; }
public void run() {
    int next = account.balance + 1000;
    synchronized (account) {
        account.balance = next;
    }
}
```
选项：  
A. 必定是 2000，因为写入操作已经加锁排队了。

**题目**  
请编写一个完整的 Java 类，并在 main 方法中实现以下多线程协作逻辑。已给骨架，需补全代码。

public class ThreadPriorityExam {
    public static void main(String[] args) throws InterruptedException {
        // 1. 创建“普通任务”线程并将其设置为最低优先级
        Thread normalWorker = new Thread(() -> {
            System.out.println("普通任务正在运行...");

        normalWorker.start();
