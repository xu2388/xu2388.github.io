## 1. 选择程序设计语言通常考虑哪些因素？

PPT给出两类标准：

**理想标准：**
1. 高级语言应有理想的模块化机制，以及可读性好的控制结构和数据结构，使程序容易测试和维护，降低软件总成本；
2. 语言特点应使编译程序尽可能多地发现程序中的错误，便于调试、提高可靠性；
3. 应有良好的独立编译机制，降低开发和维护成本。

**实用标准：**
1. 待开发软件的应用领域；
2. 用户的要求；
3. 软件的运行环境；
4. 软件开发人员的知识；
5. 软件的可移植性要求。

## 3. 什么是程序设计风格？应注意事项？

**程序设计风格**：源程序代码的逻辑简明、易读易懂，是好程序的一个重要标准。编码风格直接影响软件的可读性、可维护性和可移植性。

应注意以下方面：

1. **程序内部文档**：标识符选取、程序注解、程序布局；
2. **数据说明**：说明次序标准化；多个变量按字典顺序排列；复杂数据结构应加注解；
3. **语句构造**：不要多语句写同一行；避免复杂条件测试，减少“非”条件测试；避免大量循环和条件嵌套；利用圆括号使运算次序清晰；变量说明完整、类型长度存储初始化正确；心理换位——“如果我不是编码人，我能看懂它吗？”
4. **输入输出**：所有输入数据要校验；检查输入项重要组合合法性；输入格式简单；一批数据用结束标志而非计数控制；交互输入说明选择范围和边界值；输入格式与输入语句要求一致；输出报表符合用户要求，尽量表格化、图形化，加标志和注解；
5. **效率**：效率应在需求分析阶段确定；良好设计可提高效率；提高效率不能牺牲程序清晰性和可读性。包括代码效率、存储效率、输入输出效率。

## 4. 表达式可读性分析

题面三个表达式：
- (a) `-6**A/3*B`
- (b) `-(6**A/3)*B`
- (c) `+((6**A)/(-3))*x)`（题面疑似笔误，x应为B，且括号不匹配）

### （1）哪一种可读性最好？哪一种最差？

- **可读性最好：一般认为是(b)**。它用括号明确了`6**A/3`的运算顺序，再取负、再乘B，歧义较少。
- **可读性最差：(c)**。括号层数多，且题面中还有`+`号、`x`与前面不一致、括号不匹配等问题，容易误解。
- (a)中负号与乘方`**`、乘除混用，优先级容易让人混淆，可读性也不够好。

### （2）书写表达式的指导原则

可列出：
1. 运算符数量尽量少，但不能以牺牲清晰性为代价；
2. 括号层数不宜过多，一般控制在较少层数内；
3. 用圆括号明确运算次序，避免依赖记忆优先级；
4. 避免同一表达式中混用过多不同类型运算符；
5. 负号与乘方、乘除等易混处应加括号；
6. 复杂表达式可拆成中间变量，分步书写；
7. 避免括号不配对、符号不一致等错误。

### 5.2 结构化程序设计的基本要点是什么?
**结构化程序设计（SP）的基本要点（见PPT Page 8、9）：**
1. **经典定义**：如果一个程序的代码块仅仅通过**顺序、选择和循环**这3种基本控制结构进行连接，并且每个代码块**只有一个入口和一个出口**，则称这个程序是结构化的。
2. **更全面的定义**：尽可能少用 GOTO 语句，最好仅在检测出错误时才使用 GOTO，且应总是使用前向 GOTO。
3. **四个特征**：一个入口、一个出口、程序中无死语句、程序中无死循环。

### 5.3 使用流程图、PAD图、N-S图和PDL语言描述下列程序的算法

#### (1) 在数据 A(1)—A(10) 中求最小数和次小数。
**PDL语言描述（参考）：**
```text
BEGIN
  min1 = A(1);  min2 = A(2);
  IF min1 > min2 THEN 交换 min1 和 min2;
  FOR i = 3 TO 10 DO
    IF A(i) < min1 THEN
      min2 = min1;
      min1 = A(i);
    ELSE IF A(i) < min2 THEN
      min2 = A(i);
    ENDIF
  ENDFOR
END
```
*图形结构提示：*
*   **N-S图**：外层为一个顺序结构（先初始化），下接一个 `DO-WHILE` 或 `FOR` 循环框。循环内是一个 `IF-THEN-ELSE` 分支结构，判断 `A(i) < min1`，内部再嵌套一个判断。
*   **PAD图**：左侧主干向下，先写初始化，再画 `FOR` 循环，循环右侧引出一条线画 `IF` 选择，再在分支右侧画子判断。
*   **流程图**：标准的菱形判断与平行四边形输入输出结合，注意结构化的回环。

#### (2) 输入三个正整数作为边长，判断构成的三角形是直角、等腰或一般三角形。
**PDL语言描述（参考）：**
```text
输入 a, b, c (正整数)
IF (a+b>c) AND (a+c>b) AND (b+c>a) THEN
  IF (a*a + b*b == c*c) OR (a*a + c*c == b*b) OR (b*b + c*c == a*a) THEN
    输出 "直角三角形"
  ELSE IF (a==b) OR (a==c) OR (b==c) THEN
    输出 "等腰三角形"
  ELSE
    输出 "一般三角形"
  ENDIF
ELSE
  输出 "不能构成三角形"
ENDIF
```
*图形结构提示：*
*   **PAD图**：首层判断“能否构成三角形”，能则向右伸出分支，进行“是否直角”判断，否则继续“是否等腰”，最后输出一般。
*   **N-S图**：大型的 `IF-THEN-ELSE` 嵌套。外层判断能否构成三角形，THEN部分内嵌新的 `IF` 分支判断直角三角形。

### 5.4 任选一种排序 (从大到小) 算法，分别用流程图、N-S图和PDL语言描述其详细过程。
*(PPT Page 33/34 给出了选择排序的 PAD 图，此处以**选择排序**为例解答)*

**PDL语言描述：**
```text
PROCEDURE sort(A, n)
  FOR i = 1 TO n-1 DO
    max_index = i;
    FOR j = i+1 TO n DO
      IF A(j) > A(max_index) THEN
        max_index = j;
      ENDIF
    ENDFOR
    IF max_index != i THEN
      交换 A(i) 和 A(max_index)
    ENDIF
  ENDFOR
END
```
*图形结构提示：*
*   **N-S图**：一个外层循环框（`i=1 to n-1`），里面包含一个内层循环框（`j=i+1 to n`），内层循环里面是一个 `IF` 选择框（判断 `A(j) > A(max)`），内层循环下方是一个 `IF` 选择框（判断 `max_index != i`，若是则交换）。
*   **流程图**：两个嵌套的菱形判断框（代表循环），内部有更新最大索引和交换数据的操作。

### 5.6 程序流程图、N-S图、PAD图和PDL语言的特点各是什么？你认为这四种详细设计工具哪一种最好？为什么？
**各自特点：**
1. **程序流程图**：易学、直观；但不够规范，箭头容易导致非结构化程序（随意转移控制），不易表示数据结构。
2. **N-S图（盒图）**：强制结构化设计，功能域明确，无箭头，不能随意转移控制；缺点是嵌套层次多时方框变小，影响清晰度，修改麻烦。
3. **PAD图**：结构十分清晰（竖线条数即层次数），强制结构化，易读易懂，且很容易转换成高级语言源代码（方便自动化）；支持自顶向下逐步求精。
4. **PDL语言**：类似于伪码，外层语法固定（控制结构），内层用自然语言描述（灵活）。可作为注释直接插在源程序中；缺点是作为文本不如图形直观。

**哪一种最好（参考PPT Page 40）：**
**PDL语言**相对比较令人满意（在英语国家中最为流行）。
**原因**：它不仅是语言形式，易于被计算机处理，同程序同结构，易于自动产生代码，而且可以直接作为注释嵌入源程序，保持文档与程序的一致性。当然，如果从直观性考虑，**PAD图**也是极佳的选择，因为它既保证了结构化，又非常直观且易于自动化转换。实际工程中，通常结合使用（如用PAD图理清逻辑，用PDL写具体步骤）。
