## 1. 整个程序像一栋楼，分了5层（系统架构设计）
你的程序是一个用Java写的**本地浏览器**（类似Edge、Chrome的简化版）。为了让代码不混乱，它仿照盖楼一样分成了5层，每一层只干自己的活。

- **用户界面层（UI层）**：就是你能看见的窗口、按钮、地址栏、网页显示区。负责“长什么样”和“接收你的点击”。
- **业务逻辑层（Service层）**：负责“怎么处理事情”。比如你要收藏一个网页，它就帮你把网址存起来，它不管存到哪，也不管按钮怎么变色。
- **数据访问层（DAO层）**：专门和数据库打交道。业务层说“存个书签”，它就去把数据塞进SQLite数据库里。
- **工具层（Utility层）**：像工具箱，里面有主题颜色管理、页面保存、加密等通用功能，谁需要谁就拿来用。
- **模型层（Model层）**：只是些单纯装数据的小盒子，比如“一个书签”包含网址、标题、创建时间，没有任何复杂逻辑。

**你可以这样记：**
UI层 → 用户点按钮  
业务层 → 知道该干什么  
DAO层 → 去数据库里存取  
工具层 → 提供锤子扳手  
模型层 → 装数据的塑料袋

## 2. 数据库部分（数据表设计）
你的浏览器需要记住：用户账号、收藏的书签、看过的网页历史、个人设置。所以创建了一个本地数据库文件 `browser.db`（SQLite数据库，就是一个文件，不需要额外安装数据库软件）。

**4张表的意思：**
- **users 表**：存用户名和加密后的密码（密码不会明文存，是SHA-256哈希，防止泄露）。
- **bookmarks 表**：存书签的网址、标题，以及这个书签是谁的（通过user_id关联用户）。
- **histories 表**：存你什么时候访问了什么网址。
- **preferences 表**：存你的设置，比如主题是暗黑还是亮色，默认搜索引擎等。

**关系图里的 1:N**：一个用户可以有多个书签、多条历史、多项设置。就像一个人可以有多件衣服一样。

## 3. 重要的类（核心类设计）
这里说的是Java里面具体干活的“角色”是谁，每个角色有什么能力和工具。

- **BrowserFrame（主窗口）**：整个浏览器的“大本营”，它负责把菜单栏、工具栏、地址栏、网页显示区组装起来，并响应你的所有操作（点后退、刷新、切换全屏等）。
- **ThemeManager（主题管理器）**：负责切换暗黑/亮色主题。它像一个广播站，一切换模式，所有注册了“收听”的窗口都会自动变色。
- **HistoryManager（历史管理器）**：用两个栈（像两摞盘子）记住你浏览过的网页，一个栈存后退记录，一个存前进记录。
- **DatabaseManager（数据库管理器）**：管理数据库连接的单例（全局只有一个），负责建表、获取连接。
- **SourceCodeViewer（源代码查看器）**：一个弹出的小窗口，可以显示当前网页的HTML源码，还可以复制或保存。

**注意：** 这里的 **DJ Native Swing** 的 `nativeBrowser` 是一个真正能渲染现代网页的浏览器内核（相当于内嵌了一个Chrome组件），而 `JEditorPane` 只能显示最简单的老式HTML页面。你的程序会根据网址智能选择用哪个渲染引擎。

## 4. 界面长什么样（界面设计）
报告里画了窗口的布局图，从上到下是：
1. **菜单栏**：文件、编辑、视图三个菜单。
2. **第一排工具栏**：保存、后退、前进、查看源码、退出、刷新、主页、书签 这些按钮。

此外还规定了每个按钮的大小、颜色（暗黑模式用深紫灰色，亮色模式用浅灰）、字体等，这是为了做出来之后界面统一好看。

## 5. 几个关键技术是怎么实现的
### （1）双引擎智能切换
程序判断你输入的网址，如果是百度、B站、QQ这些现代网站，就用内嵌的**DJ Native Swing**浏览器（能运行JavaScript和CSS3）；如果是简单页面，就用Java自带的简陋渲染器。这样能兼顾兼容性和资源占用。

### （2）异步加载
网页加载不能卡住界面，否则按钮都点不动。所以用了 `SwingWorker`，让加载过程在后台线程悄悄进行，完成后自动更新界面。就像下载东西不影响你同时聊微信一样。

### （3）观察者模式切换主题
只要 `ThemeManager` 说“换主题！”，所有注册过的窗口（BrowserFrame、源代码查看器等）都会收到通知，然后立即把背景、文字、按钮颜色全部换掉。不用一个一个手动去改。

### （4）数据库安全操作
存数据时用 `PreparedStatement` 和参数绑定的方式，而不是直接把用户输入拼接到SQL语句里，能防止黑客用SQL注入攻击。同时用了事务，保证多条相关操作要么全成功，要么全失败（比如转账不能只扣钱不到账）。

## 3.5 详细设计

### 3.5.1 系统架构设计

系统采用经典的MVC（Model-View-Controller）架构模式，并结合DAO（Data Access Object）模式进行数据持久化。整体架构分为五层：用户界面层、业务逻辑层、数据访问层、工具层、模型层。

**分层架构说明：**

1. **用户界面层（UI Layer）**
   - 职责：负责与用户交互，展示数据，接收用户操作
   - 核心组件：BrowserFrame（主窗口）、菜单栏、双工具栏、JEditorPane渲染区
   - 特点：与业务逻辑解耦，通过事件触发业务操作

2. **业务逻辑层（Service Layer）**
   - 职责：处理核心业务逻辑，协调数据访问
   - 核心服务：BookmarkService、HistoryService、UserService、PreferenceService
   - 特点：封装业务规则，不直接操作用户界面

3. **数据访问层（DAO Layer）**
   - 职责：封装数据库操作，提供数据CRUD接口
   - 核心组件：DatabaseManager（连接管理）、各DAO类
   - 特点：使用PreparedStatement防止SQL注入

4. **工具层（Utility Layer）**
   - 职责：提供通用工具方法，供各层调用
   - 核心工具：DeepSeekTheme（主题常量）、ThemeManager（主题切换）、PageSaver（页面保存）、SecurityUtil（安全加密）
   - 特点：无状态，可复用

5. **模型层（Model Layer）**
   - 职责：定义数据实体，封装数据结构
   - 核心实体：Bookmark、BrowsingHistory、User
   - 特点：纯数据类，不含业务逻辑

**架构层次关系：**
```
用户界面层 (UI Layer)
    ↓ 调用
业务逻辑层 (Service Layer)
    ↓ 调用
数据访问层 (DAO Layer)
    ↓ 操作
SQLite数据库 (Data Layer)

工具层 (Utility Layer) ← 被各层调用
模型层 (Model Layer) ← 在各层间传递
```

### 3.5.2 数据库设计

系统使用SQLite嵌入式数据库进行数据持久化，无需安装数据库服务器，随程序运行自动创建。

**数据库文件：** browser.db

#### 3.5.2.1 数据表设计

**（1）用户表（users）**

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键，自增 |
| username | VARCHAR(50) | NOT NULL UNIQUE | 用户名 |
| password_hash | VARCHAR(64) | NOT NULL | SHA-256密码哈希 |
| created_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

**建表SQL：**
```sql
CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE,
    password_hash VARCHAR(64) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**（2）书签表（bookmarks）**

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键，自增 |
| url | VARCHAR(500) | NOT NULL | 书签URL |
| title | VARCHAR(200) | | 书签标题 |
| created_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| user_id | INTEGER | FOREIGN KEY | 所属用户ID |

**建表SQL：**
```sql
CREATE TABLE IF NOT EXISTS bookmarks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    url VARCHAR(500) NOT NULL,
    title VARCHAR(200),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    user_id INTEGER,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**（3）历史记录表（histories）**

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键，自增 |
| url | VARCHAR(500) | NOT NULL | 访问的URL |
| title | VARCHAR(200) | | 页面标题 |
| visit_time | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | 访问时间 |
| user_id | INTEGER | FOREIGN KEY | 所属用户ID |

**建表SQL：**
```sql
CREATE TABLE IF NOT EXISTS histories (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    url VARCHAR(500) NOT NULL,
    title VARCHAR(200),
    visit_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    user_id INTEGER,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**（4）偏好设置表（preferences）**

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键，自增 |
| setting_key | VARCHAR(50) | NOT NULL | 设置项名称 |
| setting_value | VARCHAR(200) | | 设置值 |
| user_id | INTEGER | FOREIGN KEY | 所属用户ID |

**建表SQL：**
```sql
CREATE TABLE IF NOT EXISTS preferences (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    setting_key VARCHAR(50) NOT NULL,
    setting_value VARCHAR(200),
    user_id INTEGER,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**常用设置项：**
- theme_mode：主题模式（dark/light）
- default_search_engine：默认搜索引擎（baidu/bing/google）
- homepage：首页地址

```java
           url.contains("qq.com") ||
           url.endsWith(".com") ||
           url.endsWith(".cn");
}

private void loadUrl(String url, boolean addToHistory) {
    if (nativeReady && isModernWebsite(url)) {
        loadUrlWithNative(url, addToHistory);
    } else {
        // 使用JEditorPane

    }
}
```

**使用SwingWorker实现异步加载：**

```java
SwingWorker<Boolean, Void> worker = new SwingWorker<>() {

    protected Boolean doInBackground() throws Exception {
        // 在后台线程执行网络请求
        editorPane.setPage(urlObj);
        return true;
    }
    
    @Override
    protected void done() {
        // 在EDT线程更新UI
```

### 第一步：先创建第一个表格（以“数据持久化与实体”为例）

1. 打开 Word，光标放在你想插入表格的地方。
2. 点击顶部菜单的 **“插入”** → **“表格”** → 在网格里拖动选择 **5 行 × 4 列**（为什么是5行？因为第1行是表头，下面要放4个文件，所以总共5行）。  
   - 行数后面可以随时增减，别担心。
3. 表格就出现在文档里了。

---

### 第二步：填写表头

点击第一行的四个单元格，依次输入：
- **包路径**
- **文件名**
- **功能描述**
- **代码行数**

选中这第一行，在 **“表格设计”**（或“表格工具 - 设计”）里勾选 **“标题行”**，也可以加个底色（比如浅灰色），让表头更明显。

---

### 第三步：填写内容

从第二行开始，把数据敲进去。例如：

| 包路径 | 文件名 | 功能描述 | 代码行数 |

| com.browser.db | DatabaseManager.java | SQLite数据库连接管理和表初始化 | ~150 |
| com.browser.model | Bookmark.java | 书签实体类 | ~80 |
| ... | ... | ... | ... |

敲的时候如果某个单元格字数多，列宽会自己变化，不用管它，后面统一调。

### 第四步：调整列宽，让表格更漂亮

- 把鼠标放到两列的竖线上，鼠标会变成左右箭头，按住拖动就可以调整宽度。
- 建议宽度分配：
  - **包路径**：约 4 厘米（太宽浪费）
  - **文件名**：约 5 厘米（留够空间给长文件名）
  - **功能描述**：约 7-8 厘米（内容最多的列）
  - **代码行数**：约 3 厘米

选中整个表格，在 **“布局”**（表格工具 - 布局）里点击 **“自动调整”** → **“根据窗口自动调整表格”**，然后再手动微调。

- 将表格**居中对齐**（选中表格 → “开始”菜单里的居中对齐按钮）。

### 一个提速小技巧：在Word里也能用“文字转表格”

如果你觉得一个一个敲很累，可以先在记事本里用制表符（Tab）把每列内容隔开，像这样：

```
com.browser.db	DatabaseManager.java	SQLite数据库连接管理和表初始化	~150
com.browser.model	Bookmark.java	书签实体类	~80
```

然后把这段文字复制到 Word 里，选中它们，点 **“插入” → “表格” → “文本转换成表格”**，分隔符选“制表符”，点确定，表格瞬间生成。  
之后再用“表格设计”美化。
